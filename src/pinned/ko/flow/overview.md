**현장을 배선하세요. 코드처럼 검토하세요.**

HotLoop Flow는 Go로 작성된 생산 현장용 시각적 플로 엔진입니다. 캔버스에서 센서, 브로커, PLC, 데이터베이스를 연결하면, Pi에도 들어갈 만큼 작은 정적 바이너리 하나가 그 연결을 실행합니다. 센서가 읽는 쪽보다 빠르게 데이터를 쏟아내도 스케줄러가 무너지지 않습니다.

최악의 밤에 이것이 의미하는 바는 다음과 같습니다.

- **모든 큐에는 상한이 있고, 담기지 않는 메시지는 모두 집계됩니다.** 느린 히스토리안 앞의 빠른 센서는 정해 두신 정책에 따라 쌓이거나, 대기시키거나, 버려지며, 로그에 아무 흔적도 없는 OOM kill로 나타나기 전에 그래프에 먼저 보입니다.
- **히스토리안이 한 시간 멈춰도 한 시간을 잃지 않습니다.** 연결을 지속형으로 표시해 두면, 뒤쪽 노드가 메시지를 받지 못할 때 메시지가 순서대로 디스크에 저장되고 `kill -9` 이후에도 그대로 남아 있습니다. 정상일 때는 아무것도 쓰지 않습니다. [저장 후 전달](/ko/flow/store-and-forward/)은 10분 동안 중지시킨 실제 InfluxDB로 검증했습니다.
- **모든 노드는 각자 실행됩니다.** 노드마다 goroutine 하나가 돌기 때문에, 큰 페이로드를 처리하는 Function 노드가 차지하는 것은 코어 하나이며 편집기나 같은 장비의 다른 플로에는 영향이 없습니다.
- **플로 파일은 검토할 수 있습니다.** 바이트 단위로 그대로 불러오고 저장하며, 속성 하나를 바꾸면 한 줄짜리 diff가 되고, 저장할 때마다 백업 세 개가 뒤에 남는 원자적 저장입니다. 모든 배포는 [하나의 기록](/ko/flow/deploys/)입니다. 누가, 언제, 왜, 정확히 어떤 바이트였는지 남고, 두 기록은 API, 명령줄, `git diff` 안에서 [노드 단위로 비교](/ko/flow/deploys/#차이는-리뷰처럼-읽힙니다)할 수 있습니다. 어느 기록이든 자격 증명까지 포함해 [되돌릴 수](/ko/flow/deploys/#되돌리기) 있습니다.
- **잠기지 않은 상태로는 시작하지 않습니다.** 인증이 없으면 기본값이 아니라 시작 오류가 됩니다. `exec` 노드는 꺼진 채로 출하되고, 파일 노드는 데이터 디렉터리 안에 갇히며, 자격 증명은 Argon2id 키 아래 AES-256-GCM으로 암호화됩니다.

기존 플로도 그대로 실행합니다. 이것은 핵심이 아니라 기능이므로 [아래](/ko/flow/migrating-from-node-red/)에서 다룹니다.

현재 릴리스는 `2.16.8`입니다. 이미지는 amd64용 `ghcr.io/hotloop-io/hotloop-flow:2.16.8`(arm64는 2.16.9에서 제공)이고, Helm 저장소는 `https://hotloop.io/hotloop-flow/`이며, [Flow 배포](/ko/flow/deploying/)에 Kubernetes, Podman, Quadlet이 있습니다. 메시지용 노드 유형이 117개, FlowLab 다이어그램용이 39개 있습니다. 가정과 실험실에서의 사용은 무료이고, 학교, 비영리 단체, 정부 기관의 사용도 무료이며, 파트너 플랫폼인 EmberNet을 통한 사용은 업무용 사용을 포함해 제한이 없고, HotLoop Source License Agreement를 따릅니다.

## 수치

절대 수치만 싣습니다. 직접 하드웨어에서 확인하실 수 있도록 각 항목은 세 번씩 실행했고 범위를 표기했습니다.

| 항목 | 결과 |
|---|---|
| 바이너리, linux/amd64, 정적 | **41.7 MB** |
| 이미지, amd64 | **45.64 MB** |
| 시작부터 첫 요청 응답까지 | **0.05 s** |
| RSS, 유휴 | **16.4 ~ 16.7 MiB** |
| RSS, 아래 HTTP 부하에서의 최고치 | **26.4 ~ 28.5 MiB** |
| HTTP, 노드 다섯 개 플로, 연결 8개 | **13.0k ~ 15.3k req/s** |
| HTTP 지연 시간 p50 / p99 | **0.39 ~ 0.41 ms / 1.78 ~ 4.03 ms** |
| 엔진, 노드 다섯 개 체인, I/O 없음 | **메시지당 2.20 ~ 3.11 µs**, 3.9 KB 할당 |

이 수치가 무엇이 아닌지 알아 두십시오. HTTP 수치는 플로를 쓰는 클라이언트가 보는 것이 그것이기 때문에 일부러 HTTP 스택 전체를 거칩니다. 그리고 포화 상태에서는 모든 런타임이 대기열을 만들고 꼬리 구간은 대기열이 좌우하므로, 실행마다 p99가 p50보다 더 크게 흔들립니다.

### Raspberry Pi 5에서

같은 플로와 같은 명령으로, 2026-10-22에 Raspberry Pi 5 Model B(8 GB, Cortex-A76 코어 네 개)에서 클럭을 2.0 GHz로 제한하고, 게시된 arm64 이미지 `2.2.0`을 파드로 실행했습니다. 노드에는 클러스터 DaemonSet 외에 다른 것이 없었습니다. 세 번 실행했고 범위를 표기했습니다.

| 항목 | 결과 |
|---|---|
| 시작부터 첫 요청 응답까지 | **0.10 ~ 0.46 s** |
| RSS, 유휴 | **88.0 ~ 88.3 MiB** |
| RSS, HTTP 부하에서의 최고치 | **40.3 ~ 40.5 MiB** |
| HTTP, 노드 다섯 개 플로, 연결 8개, 30 s | **13.2k ~ 13.4k req/s** |
| HTTP 지연 시간 p50 / p99 | **0.48 ms / 2.72 ~ 2.78 ms** |
| 엔진, 노드 다섯 개 체인, I/O 없음 | **메시지당 7.74 ~ 8.15 µs**, 4.0 KB 할당 |
| HTTP, 같은 명령을 600 s 유지 | **11.4k req/s**, p50 0.58 ms, p99 3.00 ms |

부하가 계속 걸리는 장비에는 마지막 행이 정직한 수치입니다. 보드는 1분이 채 되기 전에 소프트 온도 한계에 닿았고, 약 2분부터 성능이 제한되었으며, 나머지 시간 동안 83 ~ 86 C에서 클럭 1.5 ~ 1.7 GHz로 유지되었습니다. [벤치마크 페이지](/ko/flow/benchmarks/#raspberry-pi-5-결과)에 Pi 실행 전체가 있습니다.
