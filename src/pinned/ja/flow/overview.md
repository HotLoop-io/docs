**現場を配線する。コードのようにレビューする。**

HotLoop Flow は、Go で書かれた現場向けのビジュアルなフローエンジンです。センサー、ブローカー、PLC、データベースをキャンバス上で配線すると、Pi に収まるほど小さい静的バイナリ1つがその配線を実行します。センサーが読み取り側より速く話し始めても、スケジューラは崩れません。

最悪の夜に、これが何を意味するかを挙げます。

- **すべてのキューに上限があり、収まらなかったメッセージはすべて数えられます。** 遅いヒストリアンの手前にある速いセンサーは、選んだポリシーに従って滞留、ブロック、破棄のいずれかになり、ログに何も残らない OOM kill として現れる前に、グラフに表示されます。
- **ヒストリアンが1時間止まっても、1時間分を失いません。** 配線を永続にしておけば、その先のノードがメッセージを受け取れなくなったとき、メッセージは順番どおりにディスクへ書かれ、`kill -9` のあとも残っています。正常なあいだは何も書き込みません。[保存と転送](/ja/flow/store-and-forward/)は、10分間停止させた実際の InfluxDB を相手に検証済みです。
- **すべてのノードは単独で動きます。** ノードごとに goroutine が1つなので、大きなペイロードを処理する Function ノードが使うのはコア1つで、エディタや同じマシン上の他のフローには影響しません。
- **フローファイルはレビューできます。** バイト単位でそのまま読み込み、保存し、プロパティ1つの変更は1行の diff になり、保存のたびに3つのバックアップを残すアトミックな保存です。デプロイはすべて[1件の記録](/ja/flow/deploys/)になります。誰が、いつ、なぜ、正確にどのバイトかが残り、任意の2件を API、コマンドライン、`git diff` の中で[ノード単位で比較](/ja/flow/deploys/#差分はレビューのように読める)できます。どの記録も、認証情報を含めて[元に戻せます](/ja/flow/deploys/#元に戻す)。
- **ロックなしでは起動しません。** 認証がない状態は、既定値ではなく起動エラーです。`exec` ノードは無効の状態で出荷され、ファイルノードはデータディレクトリの中に閉じ込められ、認証情報は Argon2id の鍵のもとで AES-256-GCM により暗号化されます。

既存のフローもそのまま実行できます。これは要点ではなく機能のひとつなので、[後ほど](/ja/flow/migrating-from-node-red/)説明します。

現在のリリースは`2.16.8`です。イメージはamd64向けの`ghcr.io/hotloop-io/hotloop-flow:2.16.8`（arm64は2.16.9で提供）、Helmリポジトリは`https://hotloop.io/hotloop-flow/`で、[Flowのデプロイ](/ja/flow/deploying/)にKubernetes、Podman、Quadletがあります。メッセージ用のノードタイプが117、FlowLabの図用が39あります。家庭と研究室での利用は無料で、学校、非営利団体、官公庁の利用も無料です。パートナープラットフォームであるEmberNet経由の利用は、業務利用を含めて制限がなく、HotLoop Source License Agreementに基づきます。

## 数値

絶対値だけを載せていますので、ご自身のハードウェアで確かめられます。各項目3回ずつ実行し、範囲を表示しています。

| 項目 | 結果 |
|---|---|
| バイナリ、linux/amd64、静的 | **41.7 MB** |
| イメージ、amd64 | **45.64 MB** |
| 起動から最初のリクエストに応答するまで | **0.05 s** |
| RSS、アイドル時 | **16.4 ~ 16.7 MiB** |
| RSS、下記の HTTP 負荷時のピーク | **26.4 ~ 28.5 MiB** |
| HTTP、5ノードのフロー、接続8 | **13.0k ~ 15.3k req/s** |
| HTTP レイテンシ p50 / p99 | **0.39 ~ 0.41 ms / 1.78 ~ 4.03 ms** |
| エンジン、5ノードのチェーン、I/O なし | **1メッセージあたり 2.20 ~ 3.11 µs**、3.9 KB 割り当て |

これらの数値が何でないかは押さえておいてください。HTTP の数値は、フローを使うクライアントが見るのがそこだからこそ、HTTP スタック全体を通しています。そして飽和状態ではどのランタイムもキューに溜め、末尾はキューイングが決めるため、実行のたびに p99 は p50 より大きくぶれます。

### Raspberry Pi 5 では

同じフローと同じコマンドで、2026-10-22 に Raspberry Pi 5 Model B(8 GB、Cortex-A76 コア4つ)のクロックを 2.0 GHz に抑えて測りました。公開済みの arm64 イメージ `2.2.0` をポッドとして実行し、ノード上にはクラスタの DaemonSet 以外は何も置いていません。3回実行し、範囲を表示しています。

| 項目 | 結果 |
|---|---|
| 起動から最初のリクエストに応答するまで | **0.10 ~ 0.46 s** |
| RSS、アイドル時 | **88.0 ~ 88.3 MiB** |
| RSS、HTTP 負荷時のピーク | **40.3 ~ 40.5 MiB** |
| HTTP、5ノードのフロー、接続8、30 s | **13.2k ~ 13.4k req/s** |
| HTTP レイテンシ p50 / p99 | **0.48 ms / 2.72 ~ 2.78 ms** |
| エンジン、5ノードのチェーン、I/O なし | **1メッセージあたり 7.74 ~ 8.15 µs**、4.0 KB 割り当て |
| HTTP、同じコマンドを 600 s 維持 | **11.4k req/s**、p50 0.58 ms、p99 3.00 ms |

負荷がかかり続けるマシンでは、最後の行が正直な数値です。ボードは1分足らずでソフトな温度上限に達し、約2分からスロットリングが入り、その後は 83 ~ 86 C、クロック 1.5 ~ 1.7 GHz のままでした。Pi での実行の全体は[ベンチマークのページ](/ja/flow/benchmarks/#raspberry-pi-5-での結果)にあります。

測定方法と注意点は[ベンチマークのページ](/ja/flow/benchmarks/)にあります。

工場でお使いになりますか。ライセンスと連絡方法は[企業で HotLoop を使う](/ja/business/)にあります。
