HotLoop Flow {{flow}} मौजूदा संस्करण है। यह `ghcr.io/hotloop-io/hotloop-flow:{{flow}}` के रूप में आता है, amd64 और arm64 के लिए एक इमेज (amd64 इमेज 2.8.0 में Podman के अनुसार 45.64 MB की थी), साथ में एक Helm चार्ट और वह सोर्स जिसे आप ख़ुद बिल्ड कर सकते हैं। 2.9.0, 2.9.1, 2.10.0, 2.11.0, 2.12.0, 2.13.0, 2.14.0, 2.15.0, 2.16.0, 2.16.2, 2.16.3, 2.16.4, 2.16.5 और {{flow}} केवल amd64 हैं, और 2.10.2, 2.11.1, 2.12.1, 2.13.1, 2.14.1, 2.15.1 और 2.16.1 amd64 और arm64 दोनों के लिए बनी हैं (2.10.1 का चार्ट है पर इमेज नहीं, इसलिए उसे कभी पिन न करें), इसलिए 2.13.1 पर रुका Pi या arm64 बॉक्स 2.16.1 पर जा सकता है। इमेज distroless है, बिना root वाले यूज़र से चलती है और उसमें शेल नहीं है, इसलिए भीतर जाने को कुछ नहीं है, न आपके लिए और न किसी ऐसे के लिए जिसे वहाँ नहीं होना चाहिए। इस पेज पर Docker या Compose का रास्ता नहीं है: एक मशीन के लिए Podman, उसे सर्विस बनाने के लिए Quadlet, क्लस्टर के लिए Helm।

Flow लॉक होकर शुरू होता है। यह एडमिन अकाउंट के बिना चलने से मना करता है, क्योंकि फ़्लो कमांड चला सकता है। और यह क्रेडेंशियल सीक्रेट के बिना भी चलने से मना करता है, जो आपके फ़्लो के साथ सहेजे गए हर ब्रोकर और डेटाबेस पासवर्ड को एन्क्रिप्ट करता है। नीचे का हर रास्ता दोनों सेट करता है।

2.2.0 से कॉन्टेक्स्ट और टिकाऊ कनेक्शन डेटा वॉल्यूम पर एक SQLite फ़ाइल `state.db` में रहते हैं, इसलिए रीस्टार्ट उन्हें अब नहीं मिटाता। उस वॉल्यूम को बनाए रखें। चार्ट में `persistence.enabled` false हो तो वह कंटेनर के रीस्टार्ट में बचता है, पॉड बदलने में नहीं।

## Podman

पहले पासवर्ड हैश बनाएँ। इमेज में शेल नहीं है, इसलिए हैशिंग ख़ुद बाइनरी का एक सबकमांड है, और वह आठ अक्षर से कम कुछ भी अस्वीकार करता है।

```bash
podman run --rm ghcr.io/hotloop-io/hotloop-flow:{{flow}} hash-password -password 'something-long'
```

फिर क्रेडेंशियल सीक्रेट बनाएँ, और उसे कहीं ऐसी जगह सहेजें जहाँ वह साल भर बाद भी मिल जाए:

```bash
openssl rand -hex 32
```

फिर उसे चलाएँ। दोनों मान सिंगल कोट्स में जाते हैं, क्योंकि bcrypt हैश डॉलर चिह्नों से भरा होता है और वरना आपका शेल उन्हें खा जाएगा।

```bash
podman run -d --name hotloop-flow -p 1880:1880 -v hotloop-flow-data:/data \
  -e HOTLOOP_FLOW_ADMIN_USER=admin \
  -e HOTLOOP_FLOW_ADMIN_PASSWORD_HASH='<the hash>' \
  -e HOTLOOP_FLOW_CREDENTIAL_SECRET='<the secret>' \
  ghcr.io/hotloop-io/hotloop-flow:{{flow}}
```

`http://localhost:1880/` खोलें और `admin` के रूप में साइन इन करें। प्रोसेस चालू होते ही `/health` संस्करण के साथ जवाब देता है, और `/ready` बताता है कि रनटाइम सचमुच शुरू हुआ या नहीं।

उस सीक्रेट को सँभालकर रखें। Flow वॉल्यूम पर जो कुछ एन्क्रिप्ट करता है वह केवल उसी से पढ़ा जा सकता है। कंटेनर को किसी और के साथ दोबारा बनाएँगे तो सहेजा हर ब्रोकर पासवर्ड चला जाएगा, और यह ठीक साफ़ शुरुआत जैसा दिखता है, जब तक MQTT प्रमाणीकरण करना बंद नहीं कर देता।

## Quadlet

उस सर्विस के लिए जो बूट पर शुरू होती है और ख़ुद रीस्टार्ट होती है। इसके लिए Podman 4.4 या नया चाहिए। सीक्रेट ऐसी फ़ाइल में रखें जिसे केवल आप पढ़ सकें:

```bash
mkdir -p ~/.config/hotloop-flow ~/.config/containers/systemd
umask 077
cat > ~/.config/hotloop-flow/hotloop-flow.env <<'EOF'
HOTLOOP_FLOW_ADMIN_USER=admin
HOTLOOP_FLOW_ADMIN_PASSWORD_HASH=<the hash>
HOTLOOP_FLOW_CREDENTIAL_SECRET=<the secret>
EOF
```

फिर systemd को कंटेनर का वर्णन दें। इसे `~/.config/containers/systemd/hotloop-flow.container` के रूप में सहेजें:

```ini
[Unit]
Description=HotLoop Flow
After=network-online.target
Wants=network-online.target

[Container]
Image=ghcr.io/hotloop-io/hotloop-flow:{{flow}}
ContainerName=hotloop-flow
PublishPort=1880:1880
Volume=hotloop-flow-data:/data
EnvironmentFile=%h/.config/hotloop-flow/hotloop-flow.env

[Service]
Restart=always

[Install]
WantedBy=default.target
```

```bash
systemctl --user daemon-reload
systemctl --user start hotloop-flow
```

यूज़र सर्विस तभी बूट पर शुरू होती है, और आपके लॉगिन के बाद भी तभी चलती है, जब आपके अकाउंट के लिए lingering चालू हो: `loginctl enable-linger`। इसे छोड़ दें तो वह तब तक ठीक चलती है जब तक आप लॉग आउट नहीं करते या बॉक्स रीबूट नहीं होता।

## Helm

यह चार्ट किसी भी Kubernetes पर चलता है, k3s समेत।

```bash
helm repo add hotloop-flow https://hotloop.io/hotloop-flow/
helm install line3-flows hotloop-flow/hotloop-flow
```

चार्ट पहली इंस्टॉल पर एडमिन पासवर्ड और क्रेडेंशियल सीक्रेट बनाता है, और हर अपग्रेड पर दोनों को मौजूदा Secret से वापस पढ़ता है, इसलिए अपग्रेड कभी आपके सहेजे क्रेडेंशियल के नीचे से सीक्रेट नहीं बदलता। इंस्टॉल नोट्स बताते हैं कि पासवर्ड कैसे पढ़ें। ऊपर की रिलीज़ के लिए:

```bash
kubectl get secret line3-flows-auth -o jsonpath='{.data.admin-password}' | base64 -d
kubectl port-forward svc/line3-flows 1880:8080
```

यूज़र `admin` है। 2.0.2 से पहले वह बनाया गया पासवर्ड कभी नहीं चला, क्योंकि ऐप जो हैश जाँचता था वह चार्ट के सहेजे पासवर्ड से अलग किसी रैंडम पासवर्ड से बना था। इस तरह इंस्टॉल हुई रिलीज़ को अपग्रेड करने से यह वहीं ठीक हो जाता है, और न पासवर्ड बदलता है और न क्रेडेंशियल सीक्रेट।

एक रिलीज़ एक इंस्टेंस है, और चार्ट जान-बूझकर `replicaCount: 1` पिन करता है। हर इंस्टेंस फ़्लो की स्थिति और ब्रोकर तथा PLC से जीवित कनेक्शन रखता है। एक Service के पीछे दो पॉड दोनों सब्सक्राइब करेंगे और दोनों लिखेंगे, और InfluxDB चुपचाप हर रीडिंग दो बार सहेज लेगा। और चलाने के लिए अपने फ़्लो वाली दूसरी रिलीज़ इंस्टॉल करें। दो रिलीज़ एक काम भी साझा कर सकती हैं, एक लीज़ के साथ जो एक समय में केवल एक को उपकरणों पर लिखने देती है: [लीज़ के साथ वार्म स्टैंडबाय](/hi/flow/failover/)।

यह जान-बूझकर छोटा भी है। डिफ़ॉल्ट `resources.preset` `small` है, जो 10m CPU और 64Mi मेमोरी माँगता है। Flow की प्रोसेस निष्क्रिय अवस्था में 16.6 MiB रेज़िडेंट मापी गई, इसलिए वह 64Mi बचे हुए एज नोड पर शेड्यूल हो जाती है, जहाँ node-red चार्ट का डिफ़ॉल्ट 512Mi अनुरोध Pending में पड़ा रहता।

पॉड रीड-ओनली रूट फ़ाइल सिस्टम पर uid 65532 से चलता है, बिना प्रिविलेज एस्केलेशन, `RuntimeDefault` seccomp और हर Linux capability हटाकर, डिस्कवरी समेत। 2.0.4 तक डिस्कवरी चालू होने पर चार्ट `NET_RAW` और `NET_ADMIN` जोड़ता था, ARP स्वीप के लिए जो किसी ने कभी लिखे नहीं। 2.0.5 ने यह बंद किया, और आपने जो सेट किया है उसमें कुछ बदलना नहीं पड़ता।

चार्ट में तीन नेटवर्क मोड हैं:

| मोड | क्या मिलता है | प्रति नोड इंस्टेंस |
|---|---|---|
| `cluster` | एक ClusterIP, और जो क्लस्टर रूट करता है। डिफ़ॉल्ट, और सही उत्तर जब तक आपको लेयर 2 न चाहिए। | असीमित |
| `host` | होस्ट के इंटरफ़ेस, ARP टेबल और ब्रॉडकास्ट डोमेन। | एक, क्योंकि पोर्ट नोड का है |
| `macvlan` | लक्ष्य VLAN पर अपना MAC और IP, PLC वाले सेगमेंट पर ही बैठा। Multus चाहिए। | असीमित |

`macvlan` की वजह से ही मोड हैं, क्योंकि PLC नेटवर्क को स्कैन करना ऐसे पॉड से बेमतलब है जो केवल वही देखता है जो क्लस्टर उस तक रूट करता है। यह कई इंस्टेंस के लिए सुरक्षित है और ठीक उसी सेगमेंट पर बैठता है, बिना पोर्ट टकराव के क्योंकि हर इंस्टेंस का अपना पता है। [Flow README](https://github.com/HotLoop-io/hotloop-flow#deploying-on-kubernetes) में मोड और रिसोर्स प्रीसेट पूरे दिए हैं।

:::note[चार्ट कहाँ चलाया गया है]
चार्ट चार नोड वाले k3s क्लस्टर पर डिफ़ॉल्ट `cluster` नेटवर्क मोड में इंस्टॉल करके परखा गया है: लॉगिन, API से डिप्लॉय हुआ फ़्लो, पॉड रीस्टार्ट में बचा वही फ़्लो, अपग्रेड, और Fleet के ज़रिए EmberNet App Store से डिप्लॉय। `host` और `macvlan` मोड रेंडर होते हैं, lint पास करते हैं, ग़लत कॉन्फ़िगर होने पर अस्वीकार होते हैं, और असली हार्डवेयर पर चलाए गए हैं (2026-11-17)।
:::

## हर टैब के लिए एक VLAN

2.9.0 एक टैब, सबफ़्लो या अकेले नोड को अपने कनेक्शन किसी नेटवर्क इंटरफ़ेस से बाँधने देता है, ताकि एक Flow ऐसे बॉक्स पर हर मशीन के लिए एक टैब रख सके जिसका एक पोर्ट हर एक के लिए एक VLAN ढोता है, तब भी जब हर VLAN का सबनेट और डिवाइस पते एक जैसे हों। टैब वाला तरीक़ा टैब पर `FLOW_NETWORK_INTERFACE` एनवायरनमेंट वेरिएबल है, और उस पर हर क्लाइंट नोड उसे विरासत में लेता है। 2.9.1 वही फ़ील्ड `modbus-server` नोड में जोड़ता है, ताकि दो सर्वर एक ही पते और पोर्ट पर सुन सकें, हर VLAN पर एक।

पॉड को VLAN इंटरफ़ेस दिखना चाहिए, इसलिए उसे होस्ट के नेटवर्क के साथ चलाएँ: चार्ट में `network.mode: host`, या Quadlet यूनिट में `Network=host`। किसी सॉकेट को इंटरफ़ेस से बाँधने के लिए Linux 5.7 और नए में कोई capability नहीं चाहिए। पुराने कर्नेल पर `CAP_NET_RAW` चाहिए, और चार्ट मान `bindToInterface.netRaw` (डिफ़ॉल्ट `false`) बस वही एक capability जोड़ता है और कुछ नहीं। इसे `192.168.1.0/24` साझा करने वाले दो नेटवर्क नेमस्पेस की प्रयोगशाला में परखा गया, और किसी प्लांट के अपने नेटवर्क पर कुछ नहीं चलाया गया।

## EmberNet App Store से

आपको इसकी ज़रूरत नहीं है, और Flow चलाने के लिए कहीं कोई EmberNet चरण नहीं है। पर चार्ट वे लेबल रखता है जिन्हें EmberNet App Store ढूँढता है, इसलिए अगर आप पहले से EmberCORE चलाते हैं तो Flow उसके कैटलॉग में है और टाइल के रूप में दिखता है।

अपने क्लस्टर वाले टेनेंट के लिए EmberCORE इसे Fleet से डिप्लॉय करता है, जिसे EmberCORE 4.9.37 या नया चाहिए। पहले के संस्करण ऐसा Fleet बंडल बनाते थे जो कुछ इंस्टॉल नहीं करता था। Flow 2.0.3 से चार्ट जो कुछ बनाता है उस पर EmberCORE के टेनेंट लेबल लगाता है।

2.0.4 से डिप्लॉय हुई टाइल का नाम और आइकन सही आता है। पॉड और Service पर `embernet.ai/app-icon` एनोटेशन है, जिसका डिफ़ॉल्ट चार्ट का अपना आइकन है, इसलिए EmberCORE रिलीज़ के नाम से आइकन का अंदाज़ा लगाना बंद कर देता है, जो कभी मेल नहीं खाता था। अपना आइकन इस्तेमाल करने के लिए `embernet.appIcon` सेट करें, और उसे `Access-Control-Allow-Origin` के साथ परोसें, वरना टाइल ख़ाली आती है। `embernet.ai/app-name` लेबल अब चार्ट का नाम है, रिलीज़ का नहीं। इंस्टेंस अब भी `app.kubernetes.io/instance` और Service के नाम में है, और कोई सिलेक्टर नहीं बदला, इसलिए जगह पर ही अपग्रेड करना ठीक है।

[रिलीज़ नोट्स](https://hotloop.io/releases/flow/) में 0.1.0 तक हर संस्करण है।

## सोर्स से

आपको Go और Node चाहिए। एडिटर पहले बिल्ड होता है और `go:embed` से बाइनरी में जुड़ता है, इसलिए उसके बिना Go बिल्ड बिना एडिटर वाली बाइनरी थमाने के बजाय किसी पैटर्न के न मिलने पर विफल हो जाता है।

```bash
git clone https://github.com/HotLoop-io/hotloop-flow.git
cd hotloop-flow
(cd web && npm ci && npm run build)
go build -o hotloop-flow ./cmd/hotloop-flow
```

डिफ़ॉल्ट डेटा डायरेक्टरी `/data` है, जो कंटेनर में सही है और आपके लैपटॉप पर शायद वह नहीं जो आप चाहते हैं, इसलिए उसे कहीं और दिखाएँ:

```bash
export HOTLOOP_FLOW_DATA_DIR=./data
export HOTLOOP_FLOW_ADMIN_USER=admin
export HOTLOOP_FLOW_ADMIN_PASSWORD_HASH="$(./hotloop-flow hash-password -password 'something-long')"
```

## Emberwire 0.1.0 से आ रहे हैं तो

2.x जान-बूझकर किया गया साफ़ विच्छेद है: 0.1.0 के कोई उपयोगकर्ता नहीं थे जिन्हें तोड़ा जाता, और बिना उपयोगकर्ताओं वाली कम्पैटिबिलिटी परत बस बग के रहने की जगह है। `EMBERWIRE_*` वेरिएबल अब `HOTLOOP_FLOW_*` हैं, दोनों डेटाबेस कॉन्फ़िग नोड प्रकार `hotloop-flow-influxdb` और `hotloop-flow-postgres` हैं, WASM मॉड्यूल `hotloop_flow_*` एक्सपोर्ट करते हैं, मेट्रिक्स `hotloop_flow_*` हैं, और डिप्लॉय हेडर `HotLoop-Flow-Deployment-Rev` है।

0.1.0 की क्रेडेंशियल फ़ाइल पढ़ी नहीं जा सकती। 2.0.1 से Flow शुरू होते समय यह बता देता है: वह फ़ाइल का नाम बताता है, कहता है कि Emberwire ने उसे लिखा था, और आपसे उसे अलग रखकर क्रेडेंशियल दोबारा डालने को कहता है। 0.1.0 इमेज अब भी `ghcr.io/embernet-ai/emberwire:0.1.0` पर है, और [रिलीज़ नोट्स](https://hotloop.io/releases/flow/) हर विच्छेद की सूची देते हैं।
