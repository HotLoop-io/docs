Това е списъкът на направеното и на оставащото, в реда, в който се върши. Не обещава нищо, което го няма в кода или в тестов план, а [Състояние](/bg/codesys/where-it-stands/) казва докъде е изпълнено.

## Построено

- [x] Chart около HotLoop Edge със стойности по подразбиране за runtime на възел: SQLite, една реплика, толерации, които запазват и двата pod-а при загубена контролна равнина.
- [x] Provisioner, който прилага профил и го поддържа правилен, с ревизия, която защитава променено от човек.
- [x] Профил, който носи списък от устройства от всеки протокол, който HotLoop говори, така че слушател да се връща конфигуриран без нужда от PLC.
- [x] Устройството, таговете, аварията и екранът, създадени без ръчна стъпка, срещу runtime CODESYS Control for Linux SL 4.22.0.0 в контейнер.
- [x] Възстановяване след рестарт на runtime без намеса, за около 88 секунди.
- [x] Подписан вход от таблото на EmberCORE, с отказите.

## Издадено

- [x] HotLoop 4.22.0, изданието, което chart обвива.
- [x] Chart, публикуван на `https://hotloop.io/hotloop-codesys/`, като 0.3.8 е най-новият.
- [x] Образът на provisioner е публичен, така че се тегли без вход, 0.3.3.
- [x] Многоархитектурен образ на provisioner, amd64 и arm64, от 0.3.3 и chart 0.3.8.
- [x] Два OPC UA PubSub слушателя на един UDP порт, с HotLoop 4.22.0 и chart 0.3.7.
- [x] [Бележки към изданието](/bg/releases/codesys-0-3-8/) за всеки chart, от 0.3.0 до 0.3.8.

## Доказано на голям хардуер

- [x] Изпълнено на голям хардуер без операционна система (2026-11-17), включително инсталиране от истинската страница в App Store така, както го правят служителите, k3s v1.35.7, възел, който наистина губи връзката си с контролната равнина със запазени pod-ове, изтегляне от IDE на CODESYS, докато runtime остава работещ, runtime в собствената мрежа на хоста до pod-а на HotLoop на един възел, и runtime с включено управление на потребители и OPC UA крайна точка, защитена със сертификат.
