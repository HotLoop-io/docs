Ένας κανόνας είναι τρία πράγματα: κάτι συμβαίνει, μια συνθήκη ισχύει, εκτελούνται ενέργειες.

Οι κανόνες μπορούν να χειρίζονται εξοπλισμό, οπότε δύο ιδιότητες δεν είναι διαπραγματεύσιμες.

**Οι συνθήκες μεταγλωττίζονται όταν αποθηκεύεται ο κανόνας, όχι όταν ενεργοποιείται.** Ένα συντακτικό σφάλμα το βλέπει ο δημιουργός όσο κοιτάζει ακόμη τον επεξεργαστή, αντί για έναν κανόνα που σιωπηλά δεν τρέχει ποτέ ή, χειρότερα, που αποτυγχάνει στις 3 τα ξημερώματα στη μέση μιας ακολουθίας που έχει ήδη εκτελεστεί κατά το ήμισυ. Ο επεξεργαστής επικυρώνει καθώς πληκτρολογείς· ένας κανόνας που δεν μεταγλωττίζεται απορρίπτεται κατά την αποθήκευση.

**Οι συνθήκες αξιολογούνται σε απομονωμένο περιβάλλον.** Το [expr-lang](https://expr-lang.org) δεν έχει είσοδο/έξοδο, δεν φτάνει στο σύστημα αρχείων ή στο δίκτυο, ελέγχει τους τύπους κατά τη μεταγλώττιση και είναι εγγυημένο ότι τερματίζει. Η τελευταία ιδιότητα μετράει περισσότερο: μια συνθήκη αξιολογείται στη διαδρομή που οδηγεί σε εγγραφή, και μια γλώσσα εκφράσεων που μπορεί να κάνει βρόχο για πάντα είναι μια γλώσσα που μπορεί να μπλοκάρει τον κινητήρα που κρατά το κλείδωμα εγγραφής.

## Σκανδαλιστές

Αρκεί να ενεργοποιηθεί ένας οποιοσδήποτε σκανδαλιστής για να τρέξει ο κανόνας.

| Τύπος | Ενεργοποιείται όταν | Βασικά πεδία |
|---|---|---|
| `tag_change` | αλλάζει η τιμή ενός tag | `deviceId`, `tagName` |
| `threshold` | μια τιμή **διασχίζει** ένα όριο | `deviceId`, `tagName`, `threshold`, `direction`, `hysteresis` |
| `state` | αλλάζει η κατάσταση μιας οντότητας ή κρατά μια κατάσταση για κάποιο διάστημα | `entityId`, `from`, `to`, `forSec` |
| `schedule` | έρχεται η ώρα μιας έκφρασης cron | `cron` |
| `interval` | κάθε N δευτερόλεπτα | `intervalSec` |
| `alarm` | ένας συναγερμός μπαίνει σε μια κατάσταση | `alarmId`, `alarmState` |
| `device_state` | μια συσκευή συνδέεται ή πέφτει | `deviceId`, `toState` |
| `webhook` | φτάνει ένα εισερχόμενο POST | `webhookPath` |
| `mqtt` | ένα μήνυμα φτάνει σε ένα θέμα | `topic` |
| `startup` | ξεκινά η διεργασία | n/a |
| `sun` | αυγή, ανατολή, ηλιακό μεσημέρι, ηλιοβασίλεμα ή σούρουπο στην εγκατάσταση, με μια μετατόπιση αν θέλεις | `event`, `offsetSec` |

### Τα κατώφλια ενεργοποιούνται στη διέλευση

Το `threshold` ενεργοποιείται όταν μια τιμή *διασχίζει* το όριο, όχι όσο παραμένει από πάνω. Η ενεργοποίηση στο "η τιμή είναι πάνω από 200" σημαίνει ότι ο κανόνας ενεργοποιείται σε κάθε σάρωση που η τιμή μένει ψηλά, κάτι που για έναν κανόνα που χειρίζεται κάτι είναι καταιγισμός εντολών.

Το `hysteresis` εμποδίζει μια τιμή που ταλαντεύεται πάνω στο όριο να οπλίζει ξανά τον κανόνα σε κάθε κλονισμό: όταν βρεθεί πάνω, η τιμή πρέπει να πέσει κάτω από `threshold - hysteresis` πριν ο σκανδαλιστής μπορέσει να ενεργοποιηθεί ξανά.

```json
{
  "type": "threshold",
  "deviceId": "press-01", "tagName": "Zone1_Temp",
  "threshold": 200, "direction": "rising", "hysteresis": 5
}
```

Το `direction` είναι `rising`, `falling` ή `either`. Η πρώτη ανάγνωση μετά την εκκίνηση καθορίζει μια βάση και δεν ενεργοποιεί, αλλιώς κάθε κανόνας κατωφλίου θα ενεργοποιούνταν μία φορά στην εκκίνηση, ανεξάρτητα από την τιμή.

### Οι σκανδαλιστές κατάστασης ακολουθούν τις οντότητες

Το `state` ενεργοποιείται όταν αλλάζει η συμβολοσειρά κατάστασης μιας οντότητας: `off` σε `on`, `212.5` σε `213`, `on` σε `unavailable`. Τα `from` και `to` το περιορίζουν. Αν παραλείψεις και τα δύο, ενεργοποιείται σε κάθε αλλαγή, μαζί με τις αλλαγές προς και από `unavailable`, που συνήθως είναι αυτό που θέλεις για το "ειδοποίησε κάποιον" και ποτέ αυτό που θέλεις για το "χειρίσου κάτι". Πες `to`.

```json
{
  "type": "state",
  "entityId": "binary_sensor.press_01_run",
  "from": "off", "to": "on"
}
```

Ενεργοποιείται στην κατάσταση και σε τίποτε άλλο. Μια αλλαγή χαρακτηριστικού, ή η ποιότητα που γίνεται κακή ενώ η κατάσταση κρατά την τελευταία καλή τιμή της, δεν είναι αλλαγή κατάστασης.

Να πότε ακριβώς ενεργοποιείται, γιατί ένας κανόνας που χειρίζεται εξοπλισμό αξίζει να το ξέρει. Ο σκανδαλιστής ακολουθεί το δικό του αρχείο του κινητήρα οντοτήτων για το τι άλλαξε, όχι τον δίαυλο των tag. Ο κινητήρας υπολογίζει την κατάσταση μιας οντότητας καθώς φτάνουν οι αναγνώσεις και μία φορά το δευτερόλεπτο ξαναϋπολογίζει τα πάντα ως δίχτυ ασφαλείας για μια παρτίδα που δεν πρόλαβε. Κάθε αλλαγή που υπολογίζει την αναφέρει μία φορά, με τη σειρά, και ο σκανδαλιστής τις βλέπει όλες. Άρα:

- **Ενεργοποιείται μία φορά ανά αλλαγή.** Ο επανυπολογισμός κάθε δευτερολέπτου αναφέρει μόνο ό,τι κινήθηκε από την τελευταία φορά που κοίταξε ο κινητήρας, άρα δεν μπορεί να αναφέρει μια αλλαγή δύο φορές, και η επαναφόρτωση ενός κανόνα δεν μηδενίζει τίποτε από όσα εξαρτάται ένας σκανδαλιστής κατάστασης.
- **Δεν χάνει μια αλλαγή που είδε ο κινητήρας.** Ένας αργός δίαυλος κοστίζει ένα δευτερόλεπτο καθυστέρηση, όχι την αλλαγή.
- **Δεν μπορεί να δει μια αλλαγή που δεν είδε κανείς.** Ένα πηνίο που πηγαίνει off, on, off ανάμεσα σε δύο ερωτήσεις δεν άλλαξε ποτέ όσον αφορά το εργοστάσιο. Ένας σκανδαλιστής κατάστασης είναι τόσο καλός όσο η σάρωση πίσω του και όχι καλύτερος. Αν χρειάζεσαι κάθε ακμή ενός γρήγορου σήματος, κλείδωσέ το στο PLC.
- **Η εκκίνηση είναι βάση.** Κάθε οντότητα που εμφανίζεται όταν ξεκινά το Gateway, ή όταν ενεργοποιείται μία, δεν είναι αλλαγή και δεν ενεργοποιεί.

Αν οι κανόνες μείνουν ποτέ 10.000 αλλαγές πίσω (η βάση δεδομένων πολύ αργή για να καταγράψει τις εκτελέσεις που ξεκινούν), οι παλαιότερες απορρίπτονται, μετριούνται και καταγράφονται, και το `GET /api/diagnostics` δείχνει `stateChangesPending` και `stateChangesDropped` κάτω από `automations`.

Μετονόμασε μια οντότητα και κάθε κανόνας που αναφέρει το παλιό της `entity_id` σταματά να ενεργοποιείται. Αυτό είναι το τίμημα των ονομάτων που σημαίνουν κάτι· μετονόμαζε σκόπιμα και ψάξε πρώτα τους κανόνες.

### Κράτημα κατάστασης: forSec

Το "η αντλία δουλεύει πέντε λεπτά" είναι σκανδαλιστής κατάστασης με `forSec`. Η αλλαγή ξεκινά ένα χρονόμετρο αντί να ενεργοποιήσει τον κανόνα· ο κανόνας ενεργοποιείται όταν η κατάσταση στην οποία άλλαξε έχει κρατήσει τόσα δευτερόλεπτα.

```json
{
  "type": "state",
  "entityId": "binary_sensor.press_01_run",
  "from": "off", "to": "on",
  "forSec": 300
}
```

- **Κάθε αλλαγή κατάστασης το ακυρώνει.** Από on σε off και πίσω σε on μέσα στα πέντε λεπτά είναι δύο αλλαγές: η πρώτη τελειώνει το κράτημα, η δεύτερη ξεκινά νέο από το μηδέν. Δεν προσθέτει χρόνο. Μια πτώση σε `unavailable` είναι κι αυτή αλλαγή κατάστασης, οπότε μια συσκευή που σωπαίνει στη μέση του κρατήματος το ακυρώνει.
- **Μετράει μόνο η κατάσταση.** Μια αλλαγή χαρακτηριστικού, ή η ποιότητα που γίνεται κακή ενώ η κατάσταση κρατά, δεν το ακυρώνει, όπως δεν ενεργοποιεί έναν απλό σκανδαλιστή κατάστασης. Αν ένα κράτημα δεν πρέπει να επιβιώνει μιας κακής ανάγνωσης, φύλαξε τη συνθήκη του κανόνα με `qualities`.
- **Ενεργοποιεί μία φορά ανά κράτημα.** Ένα κράτημα μιας ώρας ενεργοποιεί έναν κανόνα πέντε λεπτών μία φορά, στα πέντε λεπτά, όχι κάθε πέντε λεπτά.
- **Κάθε κανόνας έχει το δικό του χρονόμετρο**, ένα ανά σκανδαλιστή. Δύο κανόνες στην ίδια οντότητα με διαφορετικό `forSec` ενεργοποιούνται ο καθένας στη δική του ώρα.
- **Το ίχνος το λέει.** Μια εκτέλεση που ενεργοποίησε ένα κράτημα γράφει `binary_sensor.press_01_run changed from off to on and held for 300s`, και τα `fromState`, `toState` και `entity` είναι της αλλαγής που ξεκίνησε το κράτημα.
- **Ένα κράτημα δεν επιβιώνει της επανεκκίνησης.** Κρατιέται στη μνήμη και τίποτα δεν το οπλίζει ξανά: τα λεπτά που είχε κρατήσει μια πρέσα πριν την επανεκκίνηση δεν μετρούν μετά. Αυτό που βλέπει η διεργασία όταν επιστρέφει είναι κάθε οντότητα να εμφανίζεται (μια βάση, όχι αλλαγή), συνήθως ως `unknown`, και μετά η πρώτη ανάγνωση της συσκευής να την κινεί σε ό,τι διαβάζει. Με `"from": "off"` αυτό δεν ταιριάζει, οπότε μια πρέσα που δούλευε πριν την επανεκκίνηση δεν ξεκινά κράτημα, και ο κανόνας ενεργοποιείται την επόμενη φορά που η πρέσα περνά από off σε on και δουλεύει πέντε λεπτά. Χωρίς `from` εξαρτάται από έναν αγώνα που δεν ελέγχεις. Αν η πρώτη ανάγνωση φτάσει αφού οι κανόνες ακούνε, είναι αλλαγή, `unknown` σε `on`, και ξεκινά κράτημα από το μηδέν: ο κανόνας ενεργοποιείται πέντε λεπτά μετά, και το ίχνος του λέει `changed from unknown to on`. Αν η συσκευή απαντήσει πιο γρήγορα από ό,τι σηκώνεται το Gateway, η πρέσα είναι απλώς `on` από την αρχή, τίποτα δεν άλλαξε, και τίποτα δεν ενεργοποιείται μέχρι να αλλάξει ξανά. Πες `from` όταν μια επανεκκίνηση δεν πρέπει να μετράει ως εκκίνηση, και μη γράφεις κανόνα που το χρειάζεται. Η επεξεργασία, ο αφοπλισμός ή η διαγραφή του κανόνα απορρίπτει και τα κρατήματά του· η αποθήκευση άλλου κανόνα όχι.
- **Μια οντότητα που εξαφανίζεται στη μέση του κρατήματος** (απενεργοποιημένη ή διαγραμμένη μαζί με τη συσκευή της) δεν το ενεργοποιεί ποτέ.

Το `forSec` είναι το πολύ μία ημέρα (86400) και μόνο ένας σκανδαλιστής `state` το δέχεται. Ελέγχεται κατά την αποθήκευση όπως όλα τα άλλα.

### Ηλιακοί σκανδαλιστές

Φωτισμός αυλής, θερμική ταινία, ένα πάρκινγκ, ό,τι νοιάζεται αν είναι σκοτάδι έξω. Το `sun` ενεργοποιείται στα `dawn`, `sunrise`, `noon`, `sunset` ή `dusk` σε αυτήν την εγκατάσταση, μετατοπισμένο κατά `offsetSec`: το αρνητικό σημαίνει πριν, οπότε αυτό είναι μισή ώρα πριν από το ηλιοβασίλεμα.

```json
{"type": "sun", "event": "sunset", "offsetSec": -1800}
```

- **Υπολογίζεται στο κουτί.** Από το γεωγραφικό πλάτος και μήκος της εγκατάστασης (`HOTLOOP_SITE_LATITUDE`, `HOTLOOP_SITE_LONGITUDE`), με τις ηλιακές εξισώσεις της NOAA, χωρίς υπηρεσία και χωρίς διαδίκτυο. Ένα εργοστάσιο που έχασε τη σύνδεσή του ανάβει παρ' όλα αυτά τα φώτα στο σούρουπο. Δες [τον ήλιο](/el/iot/sun/).
- **Χωρίς τοποθεσία, δεν οπλίζει.** Ένας κανόνας με ηλιακό σκανδαλιστή σε εγκατάσταση χωρίς γεωγραφικό πλάτος και μήκος δεν είναι οπλισμένος, και το αρχείο καταγραφής συστήματος λέει ποιες δύο μεταβλητές να ορίσεις. Ήταν από αυτά που μένουν οπλισμένα και βουβά για πάντα, και κανείς δεν το μαθαίνει μέχρι να σκοτεινιάσει η αυλή.
- **Ενεργοποιείται μία φορά ανά συμβάν της ημέρας,** στην ώρα εκείνης της ημέρας. Τα ηλιοβασιλέματα του Οκτωβρίου έρχονται περίπου ένα λεπτό νωρίτερα κάθε βράδυ και ο σκανδαλιστής τα ακολουθεί.
- **Η αυγή και το σούρουπο είναι το πολιτικό λυκόφως**, με το κέντρο του ήλιου 6 μοίρες κάτω από τον ορίζοντα. Αυτή είναι η γραμμή "είναι αρκετά σκοτεινά για φώτα" γύρω από την οποία γράφεται ο εξωτερικός φωτισμός.
- **Κάτω από τον ήλιο του μεσονυχτίου δεν υπάρχει ηλιοβασίλεμα για να ενεργοποιήσει**, οπότε ένας σκανδαλιστής ηλιοβασιλέματος περιμένει το επόμενο, όσες εβδομάδες κι αν απέχει, και ενεργοποιείται τότε.
- Το `offsetSec` είναι το πολύ έξι ώρες προς κάθε πλευρά (21600). Πέρα από αυτό είναι `schedule`.

Το ίχνος λέει τι το ενεργοποίησε και πότε: `30m before sunset at 2026-10-01T22:38:00Z`, και το `trigger` είναι `sun` στη συνθήκη.

## Συνθήκες

Μια έκφραση που επιστρέφει λογική τιμή. Κενή σημαίνει άνευ όρων.

Τι μπορεί να δει μια έκφραση:

| Όνομα | Σημασία |
|---|---|
| `value`, `string`, `quality` | η ανάγνωση που ενεργοποίησε τον κανόνα |
| `previous` | η ανάγνωση πριν από αυτήν |
| `tag`, `device` | αυτό που τον ενεργοποίησε |
| `tags["device/tag"]` | κάθε τρέχουσα αριθμητική ανάγνωση |
| `strings["device/tag"]` | κάθε τρέχουσα ανάγνωση κειμένου |
| `qualities["device/tag"]` | κάθε τρέχουσα ποιότητα |
| `states["sensor.x"]` | η κατάσταση κάθε ενεργοποιημένης οντότητας, ως συμβολοσειρά |
| `attrs["sensor.x"]["unit_of_measurement"]` | τα χαρακτηριστικά κάθε ενεργοποιημένης οντότητας |
| `qualities["sensor.x"]` | η ποιότητα κάθε οντότητας, δίπλα σε αυτή των tag (το κλειδί ενός tag έχει `/`, ένα entity_id ποτέ) |
| `entity`, `fromState`, `toState` | η αλλαγή κατάστασης που ενεργοποίησε τον κανόνα |
| `alarm`, `alarmState` | ο συναγερμός που ενεργοποίησε τον κανόνα |
| `deviceState` | η κατάσταση συσκευής που τον ενεργοποίησε |
| `now`, `hour`, `minute`, `weekday` | το ρολόι· το weekday 0 είναι Κυριακή |
| `trigger` | ποιος σκανδαλιστής ενεργοποιήθηκε |
| `vars` | τιμές που συνδέθηκαν από προηγούμενα βήματα |

```
value > 200
value > 200 and quality == 'good'
tags['press-01/Zone1_Temp'] > 200 and tags['press-01/Pressure'] < 50
hour >= 6 and hour < 18 and weekday != 0 and weekday != 6
qualities['press-01/Zone1_Temp'] == 'good'
strings['cnc-01/Program'] == 'PART_4471.NC'
value > previous
states['switch.press_01_pump'] == 'off' and toState == 'on'
float(states['sensor.press_01_zone1_temp']) > 200 and qualities['sensor.press_01_zone1_temp'] == 'good'
attrs['switch.press_01_pump']['armed'] == true
```

**Φύλαξε με την ποιότητα.** Το `value > 200` είναι αληθές για μια κακή ανάγνωση 250, και μια κακή ανάγνωση είναι αυτή που το σύστημα σου λέει ότι δεν γνωρίζει. Σε οτιδήποτε χειρίζεται εξοπλισμό, γράψε `value > 200 and quality == 'good'`. Το ίδιο ισχύει για τις οντότητες: μια κακή οντότητα εξακολουθεί να δείχνει την τελευταία καλή τιμή της, και το `qualities['sensor.x']` είναι ο τρόπος να το καταλάβει ένας κανόνας.

**Μια κατάσταση είναι συμβολοσειρά.** Είναι `"212.5"`, `"on"` ή `"unavailable"`, ποτέ αριθμός, οπότε το `states['sensor.x'] > 200` απορρίπτεται κατά την αποθήκευση ως σφάλμα τύπου αντί να αποθηκευτεί ως σύγκριση που σιωπηλά είναι πάντα ψευδής. Γράψε `float(states['sensor.x']) > 200` και φύλαξέ το: το `float('unavailable')` είναι σφάλμα, και μια συνθήκη που βγάζει σφάλμα αποτυγχάνει την εκτέλεση.

Το `string` είναι η ανάγνωση που ενεργοποίησε τον κανόνα, που σημαίνει ότι δεν είναι και η συνάρτηση `string()` του expr-lang. Για να βάλεις έναν αριθμό σε συμβολοσειρά, χρησιμοποίησε `toJSON(value)`.

Μια συνθήκη πρέπει να επιστρέφει λογική τιμή. Μια που επιστρέφει αριθμό ή συμβολοσειρά απορρίπτεται κατά την αποθήκευση αντί να εξαναγκαστεί σε μια αληθοφάνεια που κανείς δεν σκόπευε.

## Ενέργειες

Οι ενέργειες εκτελούνται με τη σειρά. Ένα αποτυχημένο βήμα σταματά τον κανόνα εκτός αν ορίζει `continueOnError`· ένα βήμα που έπρεπε να κλείσει μια βάνα και δεν το έκανε δεν πρέπει να ακολουθείται από βήματα που υποθέτουν ότι η βάνα είναι κλειστή.

### write_tag

```json
{
  "type": "write_tag",
  "params": {
    "deviceId": "press-01", "tagName": "Cooling",
    "value": true
  }
}
```

Ή υπολογισμένο:

```json
{
  "type": "write_tag",
  "params": {
    "deviceId": "press-01", "tagName": "Setpoint",
    "expression": "tags['press-01/Zone1_Temp'] - 10"
  }
}
```

**Αυτό περνά από την ίδια πύλη με όλα τα άλλα.** Ένας αυτοματισμός δεν παίρνει περισσότερο προνόμιο από έναν άνθρωπο: οι εγγραφές πρέπει να είναι ενεργοποιημένες, το tag πρέπει να είναι σημειωμένο ως εγγράψιμο, η τιμή πρέπει να είναι εντός εύρους, και η απόπειρα ελέγχεται ως `automation:<rule-id>`.

### call_service

Χειρίζεται μια οντότητα μέσω της υπηρεσίας της, όπως κάνουν το `POST /api/services/...` και το εργαλείο MCP `call_service`. Δες [Οντότητες](/el/iot/entities/#services) για το τι δέχεται κάθε τομέας.

```json
{
  "type": "call_service",
  "params": {
    "entityId": "switch.press_01_pump",
    "service": "switch.turn_on"
  }
}
```

Με δεδομένα, κυριολεκτικά ή υπολογισμένα:

```json
{
  "type": "call_service",
  "params": {
    "entityId": "number.press_01_zone1_sp",
    "service": "number.set_value",
    "dataExpressions": {"value": "float(states['sensor.press_01_zone1_temp']) - 10"}
  }
}
```

Το `service` είναι `domain.service` και ο τομέας του πρέπει να είναι της οντότητας, οπότε ένας κανόνας που ονομάζει έναν αριθμό με την υπηρεσία ενός διακόπτη απορρίπτεται κατά την αποθήκευση. Το ίδιο και μια υπηρεσία που ο τομέας δεν δέχεται, και η λίστα με όσα δέχεται κάθε τομέας προέρχεται από το ίδιο το επίπεδο οντοτήτων: όταν ένας τομέας αποκτά υπηρεσία εκεί, οι κανόνες μπορούν να τη χρησιμοποιήσουν χωρίς καμία αλλαγή εδώ. Το `data` είναι τα κυριολεκτικά δεδομένα της υπηρεσίας· τα `dataExpressions` αξιολογούνται κατά την εκτέλεση και συγχωνεύονται από πάνω.

Είναι το `write_tag` με ένα όνομα πάνω του. Η κλήση γίνεται εγγραφές tag μέσω της ίδιας πύλης, που ελέγχονται ως `automation:<rule-id>` με την οντότητα, την υπηρεσία και το αναγνωριστικό κλήσης σε κάθε γραμμή. Μια άρνηση (εγγραφές κλειστές, το tag αφοπλισμένο, μια τιμή εκτός του βήματος της οντότητας) αποτυγχάνει το βήμα και την εκτέλεση, με την άρνηση στο ίχνος, ακριβώς όπως ένα απορριφθέν `write_tag`, και κάθε εγγραφή που έκανε η κλήση ή της απορρίφθηκε βρίσκεται στην έξοδο του βήματος. Μια κλήση δεν αναιρείται ποτέ: ένα σύνθετο που πέρασε δύο εγγραφές από τρεις σταματά εκεί και το λέει.

### condition

Μια συνθήκη στη μέση μιας ακολουθίας. Όταν είναι ψευδής, η ακολουθία τελειώνει εκεί, και η εκτέλεση **πέτυχε**: ο κανόνας έκανε αυτό για το οποίο γράφτηκε, που ήταν να σταματήσει. Η έξοδος του βήματος λέει `false; the steps after this one did not run`.

```json
{
  "type": "condition",
  "params": {
    "expression": "states['binary_sensor.press_01_run'] == 'on' and qualities['binary_sensor.press_01_run'] == 'good'"
  }
}
```

Δεν είναι η `condition` του κανόνα. Εκείνη ελέγχεται μία φορά, πριν τρέξει οτιδήποτε, απέναντι στο εργοστάσιο όπως ήταν όταν ενεργοποιήθηκε ο σκανδαλιστής, και μια ψευδής καταγράφει την εκτέλεση ως παραλειφθείσα. Ένα βήμα συνθήκης διαβάζει το εργοστάσιο **όπως είναι όταν τρέχει το βήμα**, που είναι το νόημα μιας μετά από ένα `delay` ή ένα `wait`: "δουλεύει ακόμη η πρέσα, τριάντα δευτερόλεπτα μετά;" Τα `entity`, `toState`, `value` και τα υπόλοιπα από όσα ενεργοποίησαν τον κανόνα μένουν όπως ήταν, και το ίδιο τα `vars`.

Μια συνθήκη που δεν μπορεί να αξιολογηθεί (`float('unavailable')`) αποτυγχάνει το βήμα και την εκτέλεση, όπως η συνθήκη του κανόνα. Το `continueOnError` απορρίπτεται σε μια συνθήκη κατά την αποθήκευση: το να συνεχίσεις πέρα από μία θα σήμαινε ότι δεν σταματά ποτέ τίποτα.

### wait

Κρατά την ακολουθία μέχρι μια έκφραση να γίνει αληθής, το πολύ για `timeoutSec`.

```json
{
  "type": "wait",
  "params": {
    "expression": "states['binary_sensor.press_01_valve_closed'] == 'on'",
    "timeoutSec": 30
  }
}
```

Κοιτάζει αμέσως, ξανά **κάθε φορά που αλλάζει μια οντότητα που κατονομάζει η έκφραση** (η κατάστασή της, η ποιότητά της ή ένα χαρακτηριστικό), και μία φορά το δευτερόλεπτο ούτως ή άλλως. Οι οντότητες που παρακολουθεί είναι αυτές που γράφονται ως κυριολεκτικά στα `states['...']`, `attrs['...']` και `qualities['...']`· μια ανάγνωση tag, το ρολόι ή μια οντότητα που κατονομάζεται αλλιώς πιάνονται από το βλέμμα του δευτερολέπτου. Μια αναμονή σε πηνίο Modbus είναι λοιπόν τόσο γρήγορη όσο η ερώτηση πίσω της, όχι ένα δευτερόλεπτο αργά.

Όταν γίνει αληθής, τρέχει το επόμενο βήμα, και τα βήματα μετά βλέπουν το εργοστάσιο όπως το είδε τελευταία η αναμονή. Όταν λήξει πρώτα το χρονικό όριο, το βήμα **αποτυγχάνει**, και η εκτέλεση μαζί του, λέγοντας `still false after 30s`, εκτός αν η αναμονή λέει να συνεχιστεί:

```json
{
  "type": "wait",
  "params": {
    "expression": "float(states['sensor.press_01_zone1_temp']) < 60",
    "timeoutSec": 240,
    "continueOnTimeout": true
  }
}
```

Έτσι κι αλλιώς το `vars.wait.completed` είναι αληθές ή ψευδές μετά, και το `vars.wait.waitedSec` είναι πόσο περίμενε, ώστε ένα βήμα συνθήκης μετά από μια αναμονή με συνέχιση να μπορεί να αποφασίσει: `vars.wait.completed == true`.

Το `timeoutSec` είναι υποχρεωτικό και το πολύ μία ώρα. Μια αναμονή χωρίς τέλος κρατά τη θέση εκτέλεσής της μέχρι να της την πάρει ο προϋπολογισμός της εκτέλεσης, που υπό `skip` σημαίνει ότι ο κανόνας σταματά να ενεργοποιείται. Πρέπει επίσης να χωρά στον προϋπολογισμό της εκτέλεσης (`maxRuntimeSec`, πέντε λεπτά από προεπιλογή): μια αναμονή δέκα λεπτών χρειάζεται `"maxRuntimeSec": 900` περίπου στον κανόνα της, και χωρίς αυτό ο κανόνας απορρίπτεται κατά την αποθήκευση αντί να λήξει ως εκτέλεση. Μια έκφραση που βγάζει σφάλμα όσο περιμένει αποτυγχάνει το βήμα.

### stop

Τερματίζει την ακολουθία. Το `reason` είναι υποχρεωτικό και δέχεται αντικατάσταση `{{ expression }}`· το ίχνος το δείχνει.

```json
{
  "type": "stop",
  "params": {"reason": "pump already running, nothing to do"}
}
```

Χωρίς `error` η εκτέλεση πέτυχε. Με `"error": true` η εκτέλεση απέτυχε, με τον λόγο ως σφάλμα της, και καταγράφεται και μετριέται ως αποτυχία όπως κάθε άλλη:

```json
{
  "type": "stop",
  "params": {"reason": "valve did not close in time", "error": true}
}
```

Το `continueOnError` απορρίπτεται σε ένα stop κατά την αποθήκευση.

### call_script

Τρέχει ένα [σενάριο](/el/iot/scripts/): μια ονομασμένη ακολουθία που κάποιος έγραψε μία φορά ώστε κάθε κανόνας που χρειάζεται έναν κύκλο CIP ή μια εκκένωση γραμμής να καλεί το ίδιο αντί να κουβαλά δικό του αντίγραφο. Τα `fields` είναι οι είσοδοί του, τα `fieldExpressions` αξιολογούνται όταν τρέχει το βήμα και συγχωνεύονται από πάνω, και το σενάριο ελέγχει το σύνολο απέναντι στα δικά του πεδία ακριβώς όπως σε μια εκτέλεση από την οθόνη. Μια τιμή που απορρίπτει αποτυγχάνει αυτό το βήμα· δεν μετακινείται ποτέ για να ταιριάξει.

```json
{
  "type": "call_script",
  "params": {
    "scriptId": "cip_cycle",
    "fields": {"circuit": "tank_2"},
    "fieldExpressions": {"minutes": "states['input_number.cip_minutes']"},
    "wait": true
  }
}
```

Με `"wait": true` το βήμα κρατά μέχρι να τελειώσει η εκτέλεση του σεναρίου και παίρνει το αποτέλεσμά της: ένα σενάριο που αποτυγχάνει αποτυγχάνει το βήμα, και ο κανόνας σταματά εκεί εκτός αν το βήμα πει `continueOnError`. Η εκτέλεση του σεναρίου είναι μέρος αυτής: αν αυτή η εκτέλεση ακυρωθεί ή εξαντλήσει τον προϋπολογισμό της, το ίδιο ισχύει και για το σενάριο. Χωρίς `wait`, το σενάριο ξεκινά και ο κανόνας συνεχίζει· το σενάριο τελειώνει μόνο του.

Το σενάριο τρέχει ως `script:<id>`, με την πηγή αυτού του κανόνα, `automation`, σε κάθε εγγραφή που κάνει, και η εκτέλεσή του λέει ότι το `automation_run:<id>` ήταν ο γονέας της. Ένα σενάριο που είναι απασχολημένο και του οποίου ο τρόπος απορρίπτει άλλη εκτέλεση αποτυγχάνει ένα βήμα που περιμένει (`script busy`) και σημειώνεται, δεν αποτυγχάνει, από ένα που δεν περιμένει. Σενάρια που καλούν σενάρια φτάνουν το πολύ πέντε επίπεδα βάθος, και ένα σενάριο που θα καλούσε τον εαυτό του απορρίπτεται όταν αποθηκεύεται.

### apply_recipe

Εφαρμόζει μια [συνταγή](/el/iot/recipes/): ένα σύνολο τιμών ρύθμισης που φεύγουν μαζί, μια ποιότητα προϊόντος ή μια αλλαγή παραγωγής. Τα `params` είναι οι παράμετροί της και τα `paramExpressions` αξιολογούνται όταν τρέχει το βήμα και συγχωνεύονται από πάνω· το `version` εφαρμόζει σκόπιμα παλαιότερη έκδοση, και αν παραλειφθεί σημαίνει την τρέχουσα.

```json
{
  "type": "apply_recipe",
  "params": {
    "recipeId": "grade_a",
    "params": {"line_speed": 120},
    "paramExpressions": {"batch": "states['input_number.next_batch']"}
  }
}
```

Η συνταγή κάνει ό,τι κάνει από την οθόνη Συνταγές, με αυτόν τον κανόνα ως αυτόν που την εφαρμόζει. Ελέγχεται πρώτα ολόκληρη, και αν οποιοσδήποτε στόχος θα απορριπτόταν δεν γράφεται τίποτα και το βήμα αποτυγχάνει με όλους τους λόγους. Έπειτα οι στόχοι της φεύγουν με τη σειρά κάτω από ένα αναγνωριστικό κλήσης, ως `automation:<id>` με την πηγή `automation`, και ο πρώτος που αποτυγχάνει σταματά τους υπόλοιπους και αποτυγχάνει το βήμα· ό,τι γράφτηκε μένει γραμμένο. Το βήμα πετυχαίνει μόνο όταν γράφτηκε κάθε στόχος. Μια τιμή που έφυγε και δεν διαβάστηκε πίσω από τη συσκευή δεν είναι αποτυχία, γιατί όντως έφυγε, αλλά το ίχνος λέει `NOT confirmed by read-back`, και το ίδιο η εφαρμογή. Ο γονέας της εφαρμογής είναι αυτή η εκτέλεση, `automation_run:<id>`.

### Τα υπόλοιπα

| Ενέργεια | Κάνει |
|---|---|
| `mqtt_publish` | δημοσιεύει στην υπάρχουσα σύνδεση μιας συσκευής MQTT |
| `http_request` | καλεί ένα τελικό σημείο· το `bindTo` αποθηκεύει το σώμα στα `vars` |
| `raise_alarm` / `clear_alarm` | οδηγεί έναν συναγερμό που ο κινητήρας δεν μπορεί να δει μόνος του |
| `log_event` | γράφει στο αρχείο καταγραφής συστήματος |
| `set_variable` | δένει μια τιμή για μεταγενέστερα βήματα |
| `delay` | κάνει παύση, έως μία ώρα |
| `mcp_call` | καλεί ένα εργαλείο σε έναν ρυθμισμένο διακομιστή MCP |

Τα `mqtt_publish`, `http_request`, `log_event` και `stop` υποστηρίζουν αντικατάσταση `{{ expression }}` στις συμβολοσειρές τους.

```json
{
  "type": "mcp_call",
  "params": {
    "server": "maintenance",
    "tool": "create_work_order",
    "args": {"priority": "high"},
    "argExpressions": {"note": "'Zone 1 reached ' + toJSON(value)"},
    "bindTo": "workOrder"
  }
}
```

## Τρόποι εκτέλεσης

Τι συμβαίνει όταν ένας κανόνας ενεργοποιείται ενώ μια προηγούμενη εκτέλεση τρέχει ακόμη.

| Τρόπος | Συμπεριφορά |
|---|---|
| `skip` | απορρίπτει τον νέο σκανδαλιστή, **η προεπιλογή**, και η σωστή απάντηση κοντά σε μια συσκευή |
| `queue` | τον εκτελεί μετά, το πολύ ένα σε ουρά |
| `restart` | εγκαταλείπει την τρέχουσα εκτέλεση και ξεκινά ξανά |
| `parallel` | εκτελεί και τα δύο |

Η `queue` περιορίζεται σε μία εκκρεμή εκτέλεση επίτηδες. Ένας κανόνας που δεν προλαβαίνει θα συσσώρευε αλλιώς μια ουρά εντολών που θα εκτοξεύονταν όλες εναντίον ενός εργοστασίου του οποίου η κατάσταση έχει προχωρήσει.

Το `minIntervalSec` περιορίζει τον ρυθμό ανεξάρτητα από τον ρυθμό των σκανδαλιστών, μια δικλείδα απέναντι σε ένα tag που τρέμει και δουλεύει μια συσκευή μέχρι να καταστραφεί. Μια χειροκίνητη εκτέλεση από το UI ή το MCP παρακάμπτει τον περιορισμό ρυθμού (κάποιος το εννοούσε) αλλά όχι τον τρόπο εκτέλεσης (δύο ταυτόχρονες εκτελέσεις είναι εξίσου επικίνδυνες όποιος κι αν τις ξεκίνησε).

Το `maxRuntimeSec` οριοθετεί μια ολόκληρη εκτέλεση· η προεπιλογή είναι πέντε λεπτά. Χωρίς αυτό ένας κανόνας κολλημένος σε ένα απρόσιτο τελικό σημείο κρατά τη θέση εκτέλεσής του για πάντα, και υπό `skip` αυτό σημαίνει ότι δεν ενεργοποιείται ποτέ ξανά. Μια εκτέλεση που το εξαντλεί καταγράφεται ως λήξασα, είτε ήταν ανάμεσα σε βήματα είτε στη μέση ενός `delay` ή ενός `wait`.

### Αναμονές, καθυστερήσεις και τρόποι εκτέλεσης

Μια εκτέλεση που βρίσκεται σε `wait` ή `delay` είναι εκτέλεση σε εξέλιξη, και ο τρόπος εκτέλεσης αποφασίζει τι κάνει ένας σκανδαλιστής σε αυτήν:

| Τρόπος | Ένας σκανδαλιστής ενώ μια εκτέλεση περιμένει |
|---|---|
| `skip` | απορρίπτεται και καταγράφεται ως παραλειφθείς. Η εκτέλεση που περιμένει συνεχίζει. |
| `queue` | τρέχει όταν τελειώσει η εκτέλεση που περιμένει, όπως κι αν τελείωσε. |
| `restart` | ακυρώνει την εκτέλεση που περιμένει εκεί που είναι και ξεκινά νέα. Η παλιά εκτέλεση καταγράφεται ως **ακυρωμένη**, `a newer trigger restarted the rule`. Αυτό είναι το μοτίβο του "φωτός κίνησης": κάθε σκανδαλιστής σπρώχνει το τέλος πιο πέρα. |
| `parallel` | ξεκινά άλλη εκτέλεση, που περιμένει μόνη της. |

Μια εκτέλεση ακυρώνεται εκεί που είναι, αναμονή ή καθυστέρηση συμπεριλαμβανομένης, και καταγράφεται ως **ακυρωμένη** με τον λόγο, όταν:

- **ο κανόνας της αφοπλίζεται ή διαγράφεται**: `the rule was disarmed or deleted`. Η εκτέλεσή της σε ουρά και τα κρατήματά της `forSec` απορρίπτονται κι αυτά.
- **ο κανόνας της επεξεργάζεται**: `the rule was edited`. Μια εκτέλεση που περιμένει μια συνθήκη που ο δημιουργός μόλις άλλαξε δεν συνεχίζει σαν να μην έγινε τίποτα· ο επεξεργασμένος κανόνας ξεκινά καθαρά. Η αποθήκευση *άλλου* κανόνα δεν αγγίζει τίποτα: εκτελέσεις, κρατήματα, εκτελέσεις σε ουρά, η θέση εκτέλεσης και τα χρονόμετρα διαστήματος κάθε αμετάβλητου κανόνα συνεχίζουν όπως ήταν.
- **η διεργασία σταματά**: `the process is stopping`. Ο τερματισμός δεν περιμένει να τελειώσει μια αναμονή. Τίποτα δεν συνεχίζει την εκτέλεση στην επόμενη εκκίνηση· μια εκτέλεση που η διεργασία δεν μπόρεσε να καταγράψει ως ακυρωμένη (κατάρρευση, διακοπή ρεύματος) σημειώνεται ως ακυρωμένη στην επόμενη εκκίνηση.

Ένα βήμα που ακυρώθηκε ή εξάντλησε τον προϋπολογισμό του σταματά την εκτέλεση ακόμη και με `continueOnError`: αυτή η σημαία είναι για ένα βήμα που απέτυχε, όχι για μια εκτέλεση που σταμάτησε κάποιος. Ό,τι είχε ήδη κάνει το βήμα παραμένει όπως έγινε: μια εγγραφή που έφυγε πριν την ακύρωση δεν αναιρείται, και βρίσκεται στο ίχνος.

## Ιστορικό εκτελέσεων

Κάθε εκτέλεση καταγράφεται με ένα ίχνος ανά βήμα: τις **επιλυμένες** εισόδους, τις εξόδους, τις διάρκειες και τα σφάλματα. Όχι τα πρότυπα: όταν ένας κανόνας αστοχεί στις 3 τα ξημερώματα, το `wrote 212.5 to press-01/Setpoint` είναι αυτό που αξίζει να ξέρεις και το `wrote {{expression}}` όχι.

Άνοιξε μια εκτέλεση στην οθόνη Αυτοματισμοί για να δεις τα βήματά της. Μια εκτέλεση που ήταν ακόμη σε εξέλιξη όταν σταμάτησε η διεργασία ακυρώνεται καθώς σταματά, και μια που η διεργασία δεν πρόλαβε να καταγράψει (κατάρρευση) σημειώνεται ως ακυρωμένη στην επόμενη εκκίνηση, αντί να φαίνεται ότι εκτελείται από την περασμένη Τρίτη.

## Ένα ολοκληρωμένο παράδειγμα

Ξεκίνα την ψύξη όταν μια ζώνη ζεσταίνεται κατά τη διάρκεια μιας βάρδιας, το πολύ μία φορά κάθε δέκα λεπτά, και ειδοποίησε κάποιον.

```json
{
  "id": "cool-zone-1",
  "name": "Cool zone 1 when hot",
  "enabled": true,
  "mode": "skip",
  "minIntervalSec": 600,
  "triggers": [{
    "type": "threshold",
    "deviceId": "press-01", "tagName": "Zone1_Temp",
    "threshold": 200, "direction": "rising", "hysteresis": 5
  }],
  "condition": "quality == 'good' and hour >= 6 and hour < 18",
  "actions": [
    {"type": "write_tag", "params": {
      "deviceId": "press-01", "tagName": "Cooling", "value": true}},
    {"type": "delay", "params": {"seconds": 30}},
    {"type": "log_event", "params": {
      "severity": "warning",
      "message": "Cooling started, zone 1 at {{ value }}"}}
  ]
}
```

Διάβασε τις δικλείδες με τη σειρά: ενεργοποιείται στη διέλευση και όχι συνεχώς· η υστέρηση εμποδίζει να οπλίσει ξανά σε έναν κλονισμό· η συνθήκη αρνείται να δράσει σε μια ανάγνωση που δεν μπορεί να εμπιστευτεί και τρέχει μόνο κατά τη βάρδια· και ο περιορισμός ρυθμού σημαίνει ότι ακόμη κι αν όλα τα άλλα είναι λάθος, δεν μπορεί να χειριστεί το εργοστάσιο πάνω από μία φορά κάθε δέκα λεπτά.

Η ίδια ιδέα με οντότητες: ξεκίνα τον ανεμιστήρα απαγωγής όταν η πρέσα αρχίσει να δουλεύει, αλλά μόνο αν κανείς δεν έχει αφοπλίσει τον ανεμιστήρα.

```json
{
  "id": "fan-with-press",
  "name": "Extraction fan follows the press",
  "enabled": true,
  "mode": "skip",
  "triggers": [{
    "type": "state",
    "entityId": "binary_sensor.press_01_run",
    "from": "off", "to": "on"
  }],
  "condition": "qualities['binary_sensor.press_01_run'] == 'good' and attrs['switch.press_01_fan']['armed'] == true",
  "actions": [
    {"type": "call_service", "params": {
      "entityId": "switch.press_01_fan", "service": "switch.turn_on"}},
    {"type": "log_event", "params": {
      "message": "{{ entity }} went {{ toState }}, fan started"}}
  ]
}
```

Τα `from` και `to` σημαίνουν ότι μια επανασύνδεση (`unavailable` σε `on`) δεν ξεκινά μόνη της τον ανεμιστήρα· η συνθήκη σημαίνει ότι ένας αφοπλισμένος ανεμιστήρας είναι μια παραλειφθείσα εκτέλεση και όχι μια απορριφθείσα εγγραφή στο ίχνος ελέγχου κάθε φορά που ξεκινά η πρέσα.

Και μία που χρησιμοποιεί τα βήματα ακολουθίας: όταν η πρέσα δουλεύει δέκα λεπτά, άνοιξε τη βάνα ψύξης αν δεν είναι ήδη ανοιχτή, περίμενε τον τερματικό διακόπτη της και αποτύχε θορυβωδώς αν δεν κάνει ποτέ επαφή.

```json
{
  "id": "cool-after-warmup",
  "name": "Open cooling after ten minutes of running",
  "enabled": true,
  "mode": "restart",
  "maxRuntimeSec": 120,
  "triggers": [{
    "type": "state",
    "entityId": "binary_sensor.press_01_run",
    "from": "off", "to": "on",
    "forSec": 600
  }],
  "actions": [
    {"type": "condition", "params": {
      "expression": "states['valve.press_01_cooling'] != 'open'"}},
    {"type": "call_service", "params": {
      "entityId": "valve.press_01_cooling", "service": "valve.open"}},
    {"type": "wait", "params": {
      "expression": "states['valve.press_01_cooling'] == 'open'",
      "timeoutSec": 60, "continueOnTimeout": true}},
    {"type": "condition", "params": {
      "expression": "vars.wait.completed == false"}},
    {"type": "stop", "params": {
      "reason": "cooling valve did not open within 60s, it is {{ states['valve.press_01_cooling'] }}",
      "error": true}}
  ]
}
```

Διάβασέ την από πάνω προς τα κάτω: το κράτημα σημαίνει ότι μια πρέσα που κόβει μετά από δύο λεπτά δεν ανοίγει ποτέ τη βάνα, και το `from` σημαίνει ότι μια επανεκκίνηση του Gateway δεν είναι εκκίνηση πρέσας· η πρώτη συνθήκη κάνει μια ήδη ανοιχτή βάνα επιτυχημένη εκτέλεση που δεν χειρίζεται τίποτα· η αναμονή ξυπνά τη στιγμή που αλλάζει η οντότητα της βάνας· και όταν δεν ανοίξει ποτέ, η δεύτερη συνθήκη αφήνει την εκτέλεση να προχωρήσει σε ένα stop που την αποτυγχάνει, με την πραγματική κατάσταση της βάνας στον λόγο και μια προειδοποίηση στο αρχείο καταγραφής συστήματος. Όταν η βάνα ανοίξει, αυτή η ίδια συνθήκη είναι ψευδής και η εκτέλεση τελειώνει εκεί, επιτυχημένη.

## Webhooks

Ένας σκανδαλιστής `webhook` καταχωρεί το `POST /api/webhook/<path>`. Το σώμα είναι διαθέσιμο ως `vars.body`. Μια διαδρομή που δεν διεκδικεί κανένας κανόνας επιστρέφει 404 αντί να δέχεται σιωπηλά· ένα webhook που στέλνει στο κενό μοιάζει ακριβώς με ένα που δουλεύει.

Δύο κανόνες δεν μπορούν να διεκδικήσουν την ίδια διαδρομή· ο δεύτερος απορρίπτεται κατά τη φόρτωση με μια γραμμή καταγραφής που κατονομάζει και τους δύο.

## Όταν ένας κανόνας δεν οπλίζει

Ένας κανόνας που είναι ενεργοποιημένος αλλά δεν μεταγλωττίστηκε εμφανίζεται ως **NOT ARMED** στην οθόνη Αυτοματισμοί, με κόκκινη τελεία και εξήγηση, και ένα σφάλμα στο αρχείο καταγραφής συστήματος. Αυτή είναι η κατάσταση για την οποία αξίζει να φωνάζεις πιο δυνατά: ο δημιουργός πιστεύει ότι τρέχει.

Ένας κακός κανόνας δεν αφοπλίζει τους άλλους. Η επαναφόρτωση απορρίπτει αυτόν που απέτυχε και οπλίζει όλα τα υπόλοιπα.
