Μια συνταγή είναι ένα σύνολο τιμών που πηγαίνουν μαζί προς το εργοστάσιο. Οι θερμοκρασίες ζωνών, η ταχύτητα γραμμής και το διάκενο μήτρας της ποιότητας Α. Η αλλαγή στο μπουκάλι των 500 ml. Η νυχτερινή μείωση. Κάθε εργοστάσιο τα έχει αυτά, και κάθε εργοστάσιο έχει κάπου ένα πλαστικοποιημένο φύλλο με τους αριθμούς και έναν χειριστή να τους πληκτρολογεί έναν έναν, και κάθε εργοστάσιο έχει την ιστορία της νύχτας που ένας από αυτούς πληκτρολογήθηκε λάθος.

Έτσι οι αριθμοί ζουν εδώ, και φεύγουν μονομιάς: πρώτα ελεγμένοι ολόκληροι, σταλμένοι με σειρά, διαβασμένοι πίσω από τη συσκευή μετά, ο καθένας καταγεγραμμένος. Κάθε συνταγή είναι επίσης μια οντότητα, `scene.<id>`. Είναι φτιαγμένη για εξοπλισμό που μπορεί να βλάψει κάποιον, και γι' αυτό το μεγαλύτερο μέρος αυτής της σελίδας αφορά το τι συμβαίνει όταν κάτι πάει στραβά.

## Πώς μοιάζει μία

```json
{
  "id": "grade_a",
  "name": "Grade A",
  "description": "The 2pm run. Die at 210, line at whatever the order says.",
  "equipment_id": 7,
  "apply_permission": "recipes.apply",
  "params": [
    {"name": "speed", "label": "Line speed", "type": "number", "min": 0, "max": 400, "step": 10, "unit": "rpm", "required": true}
  ],
  "precondition": "states['input_boolean.line_ready'] == 'on'",
  "targets": [
    {"entity_id": "loop.line_02_die_tic", "service": "set_mode", "data": {"mode": "auto"}},
    {"entity_id": "loop.line_02_die_tic", "service": "set_setpoint", "data": {"value": 210}},
    {"entity_id": "number.line_02_speed", "service": "set_value", "data_expressions": {"value": "vars.speed"}},
    {"entity_id": "switch.line_02_heater", "service": "turn_on"},
    {"entity_id": "input_select.product", "service": "select_option", "data": {"option": "Grade A"}}
  ],
  "verify_sec": 10
}
```

- Το **`id`** είναι πεζά γράμματα, ψηφία και κάτω παύλες, με πρώτο ένα γράμμα. Είναι το id αντικειμένου της οντότητάς της, `scene.grade_a`, και δεν αλλάζει ποτέ.
- Το **`equipment_id`** είναι ο κόμβος του δέντρου εξοπλισμού στον οποίο ανήκει η συνταγή, για να βρίσκεται. Η οθόνη Συνταγές ομαδοποιεί με βάση αυτό. Παραλείψτε το για συνταγή ολόκληρου του εργοστασίου.
- Τα **`params`** είναι αυτά που δέχεται μια εφαρμογή: τα ίδια τυποποιημένα πεδία που έχει ένα script (`model.Field`: `number` με `min`, `max`, `step` και `unit`, `text`, `boolean`, `select`, `entity`, `duration`, `alarm`, `tag`). Ένας προορισμός διαβάζει ένα ως `vars.<name>` σε μια εγγραφή του `data_expressions`.
- Η **`precondition`** είναι μια έκφραση στη γλώσσα των αυτοματισμών που πρέπει να ισχύει για να ξεκινήσει η συνταγή. Παραλείψτε την και δεν υπάρχει καμία.
- Τα **`targets`** είναι οι τιμές, **με τη σειρά που φεύγουν**. Καθεμία είναι μια οντότητα, η υπηρεσία που τη ρυθμίζει και τα δεδομένα αυτής της υπηρεσίας, ως τιμή (`data`) ή υπολογισμένα από τις παραμέτρους (`data_expressions`). Έως 200.
- Το **`verify_sec`** είναι ο χρόνος που δίνεται σε κάθε γραμμένη τιμή για να εμφανιστεί σε μια ένδειξη από τη συσκευή. 1 έως 600, προεπιλογή 10.

### Τι μπορεί να είναι ένας προορισμός

Μια συνταγή **ρυθμίζει τιμές**. Οι υπηρεσίες που δέχεται είναι αυτές που αφήνουν τον εξοπλισμό να κρατά μια τιμή:

| Domain | Υπηρεσίες |
|---|---|
| `switch`, `input_boolean` | `turn_on`, `turn_off` |
| `number`, `input_number`, `input_counter` | `set_value` |
| `text`, `input_text` | `set_value` |
| `select`, `input_select` | `select_option` |
| `valve` | `set_position` |
| `motor` | `set_speed` |
| `loop` | `set_setpoint`, `set_mode` |

Το πάτημα ενός κουμπιού, η εκκίνηση ενός κινητήρα, ο μηδενισμός ενός μετρητή, η διακοπή μιας βαλβίδας: απορρίπτονται κατά την αποθήκευση. Αυτά είναι ενέργειες, όχι τιμές, και ανήκουν σε ένα [script](/el/iot/scripts/). Το «Εφαρμογή ποιότητας Α» που πατά ένα κουμπί μηδενισμού κάθε φορά που κάποιος το εφαρμόζει δεν είναι αυτό που εννοεί κανείς με τη λέξη συνταγή, και η μέρα που θα συμβεί μέσα σε μια παραγωγή είναι η μέρα που θα το μάθετε. Απορρίπτεται και το toggle: μια συνταγή που αναστρέφει έναν διακόπτη κάνει το αντίθετο μία στις δύο φορές.

Η οντότητα ενός προορισμού πρέπει να υπάρχει κατά την αποθήκευση, οι εκφράσεις του πρέπει να μεταγλωττίζονται, και η ίδια οντότητα δεν μπορεί να ρυθμιστεί δύο φορές από την ίδια υπηρεσία (δύο τιμές για μία ρύθμιση, και ποια θα επικρατούσε θα εξαρτιόταν από μια σειρά που δεν διαβάζει κανείς). Η λειτουργία και η τιμή ρύθμισης ενός βρόχου είναι δύο ρυθμίσεις και μπορούν να ρυθμιστούν και οι δύο· ρυθμίστε πρώτα τη λειτουργία, γιατί μια τιμή ρύθμισης για αυτόματο δεν σημαίνει τίποτα για έναν βρόχο που έμεινε σε χειροκίνητο.

## Εφαρμογή μίας

Από την οθόνη Συνταγές, το πλακίδιο της συνταγής στην οθόνη Οντότητες, ένα βήμα `apply_recipe` ενός κανόνα ή ενός script, το `apply_recipe` του MCP, ή το `POST /api/services/scene/turn_on`. Καθένα από αυτά κάνει ακριβώς το εξής:

### 1. Ελεγμένη ολόκληρη, απορριμμένη ολόκληρη

Πριν πάει οποιαδήποτε τιμή οπουδήποτε:

- Οι παράμετροι ελέγχονται σε σχέση με τα πεδία τους. **Μια τιμή δεν μετακινείται ποτέ για να ταιριάξει.** Το 450 σε πεδίο με μέγιστο 400 απορρίπτεται, δεν περιορίζεται σε
  400. Το `"250"` για αριθμό απορρίπτεται, δεν αναλύεται. Το 255 σε βήμα 10 απορρίπτεται, δεν στρογγυλοποιείται. Ο αριθμός που πηγαίνει στο εργοστάσιο είναι ακριβώς αυτός που πληκτρολόγησε κάποιος, αλλιώς δεν πηγαίνει τίποτα.
- Το δικό της δικαίωμα της συνταγής, όταν κατονομάζει κάποιο (παρακάτω), και οι διακόπτες εγγραφής του MCP, για έναν πράκτορα.
- Η προϋπόθεση αξιολογείται σε σχέση με το εργοστάσιο όπως είναι τώρα.
- Κάθε έκφραση δεδομένων αξιολογείται. Μία που αποτυγχάνει απορρίπτει τη συνταγή· ένας προορισμός δεν στέλνεται ποτέ χωρίς την τιμή που έπρεπε να έχει.
- Τίποτα άλλο σε αυτή τη διεργασία δεν μπορεί να γράφει σε μία από τις οντότητές της (παρακάτω).
- **Κάθε προορισμός υποβάλλεται στους δικούς του ελέγχους του φράγματος εγγραφής**, τους ίδιους που θα συναντήσει η εγγραφή του: οι εγγραφές ενεργές, το tag εγγράψιμο, η τιμή εντός του εύρους του tag, η οντότητα ενεργοποιημένη και ικανοποιημένη με την τιμή (το βήμα της, οι επιλογές της, ένας βρόχος σε χειροκίνητο για την έξοδό του), η συσκευή συνδεδεμένη. `Services.Check`, που για ένα tag είναι `runtime.Manager.CheckWrite`. Τίποτα δεν γράφεται και δεν καταγράφεται για έλεγχο.

**Αν αποτύχει οτιδήποτε, ολόκληρη η συνταγή απορρίπτεται και δεν γράφεται τίποτα.** Όχι οι πρώτοι δέκα προορισμοί και μετά μια απόρριψη. Τίποτα. Και παίρνετε κάθε λόγο, όχι μόνο τον πρώτο: ένας χειριστής στον οποίο λέγεται ένα πρόβλημα το διορθώνει και του λέγεται το επόμενο, και μια συνταγή σαράντα προορισμών πρέπει να διορθώνεται μονομιάς. Κάθε προορισμός λέει ποιος ήταν: `would_write`, `refused` με τα λόγια του φράγματος, ή `not_sent`.

### 2. Γραμμένη με σειρά, ένα id κλήσης, ποτέ δεν αναιρείται

Έπειτα οι προορισμοί φεύγουν με σειρά, ο καθένας μέσω του `Services.Call` και άρα μέσω του `runtime.Manager.Write`, του ενός φράγματος εγγραφής. Δεν υπάρχει πλαϊνή πόρτα. Κάθε εγγραφή φέρει το **id κλήσης** της εφαρμογής, άρα ολόκληρη η εφαρμογή είναι `GET /api/writes?call=<id>`, στο ίχνος ελέγχου, δίπλα σε κάθε άλλη εγγραφή που δέχτηκε ποτέ το εργοστάσιο.

Ένας έλεγχος μπορεί να περάσει και η εγγραφή να αποτύχει μια στιγμή αργότερα. Ένα PLC απαντά σε μια εγγραφή με εξαίρεση. Κάποιος κλωτσά ένα καλώδιο. Κάποιος αφοπλίζει ένα tag ανάμεσα στον έλεγχο και την εγγραφή. **Ο πρώτος προορισμός που δεν περνά σταματά την εφαρμογή.** Οι επόμενοι δεν στέλνονται και λένε `skipped`.

**Τίποτα που έχει ήδη γραφτεί δεν αναιρείται.** Αυτό είναι σκόπιμο, και είναι ο κανόνας που ακολουθεί κάθε εγγραφή του HotLoop. Η αναίρεση είναι η ίδια εγγραφή: γίνεται χωρίς να τη ζητήσει κανείς, σε εξοπλισμό που έχει ήδη κινηθεί, με βάση αυτό που πιστεύουμε ότι ήταν η τιμή πριν, τη στιγμή ακριβώς που κάτι μόλις απέδειξε ότι το εργοστάσιο δεν συμπεριφέρεται όπως περιμέναμε. Έτσι μια μισοεφαρμοσμένη συνταγή γίνεται μια εντελώς μπερδεμένη γραμμή. Η απόφαση για το τι θα γίνει με μια μισοεφαρμοσμένη συνταγή είναι δουλειά του χειριστή, και παίρνει ακριβώς τις πληροφορίες για να την κάνει:

```text
PARTIAL v3: 2 of 5 written before one failed, nothing undone
  1. set_mode loop.line_02_die_tic: written, verified
  2. set_setpoint loop.line_02_die_tic: written, verified
  3. set_value number.line_02_speed: failed: the device answered the write with an exception
  4. turn_on switch.line_02_heater: skipped
  5. select_option input_select.product: skipped
```

Ένας προορισμός είναι `written`, `failed` (έφυγε και η συσκευή είπε όχι, ή δεν είπε τίποτα, άρα δεν είναι γνωστό αν πέρασε), `not_sent` (το φράγμα τον απέρριψε την τελευταία στιγμή) ή `skipped`. Η εφαρμογή είναι `applied` (κάθε προορισμός γραμμένος), `partial` (κάποιοι ήταν) ή `failed` (ο πρώτος δεν ήταν).

Η οθόνη Συνταγές προσφέρει τότε **Εφαρμογή των υπόλοιπων προορισμών**. Είναι μια νέα εφαρμογή, των προορισμών που δεν γράφτηκαν, με την ίδια έκδοση και παραμέτρους, ελεγμένη ξανά ολόκληρη πρώτα, με έλεγχο υπό δικό της id κλήσης, με `application:<id>` ως γονέα ώστε οι δύο να βρίσκονται μαζί. Δεν είναι ποτέ αυτόματη. Κάποιος κοιτάζει τι συνέβη, διορθώνει ό,τι τη σταμάτησε και πατά το κουμπί.

### 3. Διαβασμένη πίσω

Γραμμένο δεν σημαίνει ότι έγινε δεκτό. Ένα PLC μπορεί να δεχτεί μια εγγραφή και η δική του λογική να την αντικαταστήσει στην επόμενη σάρωση. Ένας κλιμακωμένος καταχωρητής μπορεί να πάρει 12,34 και να κρατήσει 12,3. Έτσι, μετά την τελευταία εγγραφή, κάθε γραμμένη τιμή διαβάζεται πίσω:

- για έναν προορισμό σε μια συσκευή, μόνο από μια ένδειξη **που ελήφθη μετά την εγγραφή του**, ώστε η κρυφή μνήμη που θυμάται τι είχε πει η συσκευή πριν να μη μπορεί να επιβεβαιώσει τίποτα·
- από την κατάσταση της οντότητας ή, για μια βαλβίδα, έναν κινητήρα και έναν βρόχο, το χαρακτηριστικό που ρυθμίζει η υπηρεσία (`current_position`, `speed`, `setpoint`, `mode`)·
- ένας αριθμός εντός ενός εκατομμυριοστού του εαυτού του (ένας καταχωρητής κινητής υποδιαστολής επιστρέφει το 0,1 ως 0,10000000149, που είναι η ίδια τιμή ρύθμισης), οτιδήποτε άλλο ακριβώς.

Κάθε γραμμένος προορισμός είναι **`verified`** μόλις διαβαστεί πίσω, ή **`unconfirmed`** αν δεν έχει γίνει εντός `verify_sec`, με ό,τι διαβάστηκε αντί γι' αυτό:

```text
  3. set_value number.line_02_speed: written, unconfirmed (not confirmed within 10s: read back 240, not 250)
```

Το μη επιβεβαιωμένο εμφανίζεται **κεχριμπαρένιο**, ποτέ πράσινο, στην οθόνη Συνταγές, και είναι προειδοποίηση στο ημερολόγιο συμβάντων και στο ημερολόγιο συστήματος. Δεν είναι αποτυχία: η τιμή έφυγε και η συσκευή την αποδέχτηκε, και η εφαρμογή παραμένει `applied`. Είναι μια σημαία που λέει πηγαίνετε να δείτε, γιατί μπορεί να μην πέρασε. Ένας βοηθός κρατά τη δική του τιμή, άρα ένας προορισμός βοηθού επαληθεύεται κατευθείαν από αυτόν.

Η απάντηση επιστρέφει όταν τελειώσει η ανάγνωση πίσω, άρα η εφαρμογή μιας συνταγής διαρκεί έως `verify_sec`.

## Επικάλυψη

Δύο συνταγές που αναμειγνύουν τις εγγραφές τους στην ίδια τιμή ρύθμισης την αφήνουν σε όποια προσγειώθηκε τελευταία, που δεν είναι η συνταγή κανενός. Έτσι, όσο μια εφαρμογή γράφει και διαβάζει πίσω, κρατά κάθε οντότητα που στοχεύει, και μια άλλη εφαρμογή που στοχεύει οποιαδήποτε από αυτές απορρίπτεται, `409`, με το ποια συνταγή εμποδίζει. Περιμένετε την, και μετά εφαρμόστε.

Αυτό κρατιέται μέσα στη διεργασία: μια εφαρμογή από το Gateway και μια από μια διεργασία `--mcp-stdio` δίπλα του δεν κρατούν η μία την άλλη. Τρέξτε έναν εγγραφέα, ή κρατήστε τις συνταγές του πράκτορα και των χειριστών σε διαφορετικό εξοπλισμό.

## Εκδόσεις

Το όνομα, η περιγραφή, ο κόμβος εξοπλισμού και το δικαίωμα μιας συνταγής είναι της συνταγής και αλλάζουν επιτόπου. **Αυτό που γράφει είναι μια έκδοση, και μια έκδοση δεν αλλάζει ποτέ.** Η αποθήκευση άλλων προορισμών, άλλων παραμέτρων, άλλης προϋπόθεσης ή άλλου `verify_sec` αποθηκεύει την επόμενη έκδοση και την κάνει τρέχουσα. Η έκδοση 3 είναι ακριβώς ό,τι ήταν την ημέρα που αποθηκεύτηκε, για πάντα, και κάθε εφαρμογή καταγράφει την έκδοση και τις παραμέτρους με τις οποίες έτρεξε. Ό,τι πήγε στο εργοστάσιο την περασμένη Τρίτη έχει πάντα απάντηση.

- Η αλλαγή μόνο του ονόματος, ή μόνο της σημείωσης, δεν δημιουργεί έκδοση.
- Μια αποθήκευση που έγινε σε έκδοση που κάποιος άλλος έχει στο μεταξύ αντικαταστήσει απορρίπτεται, `409`, αντί να πετάξει σιωπηλά την αλλαγή του. Ο επεξεργαστής στέλνει την έκδοση που επεξεργαζόταν.
- Μια παλαιότερη έκδοση μπορεί να εφαρμοστεί επίτηδες: επιλέξτε την στο συρτάρι εφαρμογής, ή `"version": 2`. Η εφαρμογή λέει ότι ήταν η έκδοση 2.
- Το συρτάρι Εκδόσεις δείχνει κάθε έκδοση με το ποιος την αποθήκευσε, τη σημείωσή του και τι άλλαξε από την προηγούμενη, προορισμό προς προορισμό.

Η διαγραφή μιας συνταγής διαγράφει τις εκδόσεις της. Οι εφαρμογές της κρατούνται: είναι αυτό που στάλθηκε στο εργοστάσιο, και αυτό το ιστορικό επιζεί της συνταγής.

## Καταγραφή μίας

Κανείς δεν γράφει με το χέρι μια συνταγή σαράντα προορισμών όταν η γραμμή ήδη τρέχει ποιότητα Α. Η **Καταγραφή** παίρνει τις οντότητες που διαλέγετε και συντάσσει μια συνταγή που ρυθμίζει καθεμία ξανά σε ό,τι κρατά αυτή τη στιγμή, με τη σειρά που τις διαλέξατε: την τιμή ενός αριθμού, το ανοιχτό ή κλειστό ενός διακόπτη, την επιλογή ενός επιλογέα, τη θέση μιας βαλβίδας, την ταχύτητα ενός κινητήρα, τη λειτουργία ενός βρόχου και μετά την τιμή ρύθμισής του. Της δίνετε όνομα, την κλαδεύετε, κάνετε παραμέτρους τους αριθμούς που αλλάζουν ανά παραγγελία, και αποθηκεύετε.

Μια οντότητα της οποίας η τιμή δεν είναι γνωστή, ή δεν είναι αξιόπιστη, **απορρίπτεται, δεν καταγράφεται**: μια ένδειξη με ποιότητα άλλη από καλή, `unknown`, `unavailable`, μια απενεργοποιημένη οντότητα. Μια συνταγή φτιαγμένη από κακή ένδειξη γράφει την κακή ένδειξη πίσω στο εργοστάσιο, κάθε φορά που κάποιος την εφαρμόζει.

## Ποιος μπορεί να εφαρμόσει μία

Οι χειριστές εφαρμόζουν συνταγές (`recipes.apply`)· οι διαχειριστές τις γράφουν (`recipes.write`)· όλοι τις διαβάζουν (`recipes.read`). Η φόρτωση της ποιότητας Α είναι αυτό για το οποίο είναι εκεί ο χειριστής. Η απόφαση για το τι είναι η ποιότητα Α είναι απόφαση μηχανικού.

Μια συνταγή μπορεί να κατονομάσει ένα στενότερο δικό της δικαίωμα: `"apply_permission": "recipes.apply.night_setback"`. Τότε η εφαρμογή της απαιτεί και αυτό, που ο ρόλος του χειριστή δεν έχει. Δώστε το στα άτομα που μπορούν να εφαρμόσουν εκείνη τη συνταγή μέσω της δικής τους λίστας δικαιωμάτων:

```json
["recipes.read", "recipes.apply", "recipes.apply.night_setback"]
```

Το `recipes.apply.*` δίνει αυτό κάθε συνταγής, και ένας διαχειριστής κατέχει τα πάντα. Ένας χρήστης χωρίς αυτό απορρίπτεται, και **η απόρριψη καταγράφεται**: μια απορριμμένη εφαρμογή στο ιστορικό της συνταγής, με το όνομά του, όπως κάθε άλλη. Το ίδιο ισχύει μέσω της οντότητας scene.

Ένας πράκτορας δεν κατέχει τα δικαιώματα κανενός χρήστη, άρα **ένας πράκτορας δεν εφαρμόζει ποτέ συνταγή που κατονομάζει δικό της δικαίωμα**. Μπορεί να τη διαβάσει και να ρωτήσει αν θα εφαρμοζόταν· η απάντηση λέει γιατί όχι.

## Η προϋπόθεση

```json
"precondition": "states['input_boolean.line_ready'] == 'on' and float(states['sensor.line_02_die_temp']) < 250"
```

Η γλώσσα των αυτοματισμών, αξιολογημένη σε σχέση με το εργοστάσιο όπως είναι όταν κάποιος πατά Εφαρμογή, με τις παραμέτρους ως `vars`. Το ψευδές απορρίπτει τη συνταγή, λέγοντάς το. Είναι προστασία από την εφαρμογή των σωστών αριθμών τη λάθος στιγμή, όχι interlock: ένα interlock ζει στο PLC, όπου εξακολουθεί να λειτουργεί όταν το δίκτυο δεν λειτουργεί.

## Από κανόνα, script ή πράκτορα

Ένας κανόνας ή ένα script εφαρμόζει μία με ένα βήμα `apply_recipe` (δείτε [Αυτοματισμοί](/el/iot/automations/)):

```json
{"type": "apply_recipe", "params": {"recipeId": "grade_a", "params": {"speed": 250}}}
```

Την εφαρμόζει ως ο κανόνας, `automation:<id>`, ή το script, `script:<id>`, με την πηγή εκείνης της εκτέλεσης σε κάθε εγγραφή, και ο γονέας της εφαρμογής είναι η εκτέλεση. Το βήμα αποτυγχάνει εκτός αν γράφτηκε κάθε προορισμός· μια μη επιβεβαιωμένη τιμή δεν το αποτυγχάνει, και το ίχνος λέει `NOT confirmed by read-back`. Η δοκιμαστική εκτέλεση ενός script ελέγχει και τη συνταγή.

Μέσω MCP, το `list_recipes` δείχνει κάθε συνταγή με τους προορισμούς και τις παραμέτρους της, το `validate_recipe` ρωτά αν μία θα εφαρμοζόταν τώρα, και το `apply_recipe` την εφαρμόζει, με **υποχρεωτικό** λόγο. Οι εγγραφές ενός πράκτορα φέρουν την πηγή `mcp`, άρα το φράγμα ισχύει για καθεμία, και με τις εγγραφές κλειστές (`HOTLOOP_ALLOW_WRITES`) το `apply_recipe` απορρίπτεται πριν ελεγχθεί οτιδήποτε. Δείτε [MCP](/el/iot/mcp/#recipes).

## Η οντότητά της

Κάθε συνταγή είναι μια οντότητα `scene`, `scene.<id>`. Η κατάστασή της είναι πότε εφαρμόστηκε τελευταία φορά (μια εφαρμογή που έγραψε κάτι), ως χρονική σήμανση, και `unknown` μέχρι να έχει εφαρμοστεί ποτέ. Τα χαρακτηριστικά της λένε πώς πήγε η πιο πρόσφατη εφαρμογή: `last_result`, `last_version`, `last_applied_by`, `last_application`, και `unconfirmed` όταν τόσες τιμές μιας εφαρμοσμένης δεν διαβάστηκαν πίσω. Το πλακίδιό της έχει κουμπί Εφαρμογή. Το `scene.turn_on` την εφαρμόζει, με `params` και `version` στα δεδομένα. Ένας κανόνας μπορεί να ενεργοποιείται από την κατάστασή της, που κινείται μία φορά ανά εφαρμογή που έγραψε κάτι.

Η διαγραφή μιας συνταγής ορφανεύει την οντότητά της, όπως η διαγραφή ενός script.

## Η καταγραφή

Κάθε εφαρμογή, μαζί με τις απορριμμένες, είναι μια γραμμή του `recipe_applications`: η συνταγή, η έκδοση, οι παράμετροι, ποιος, από πού, γιατί, το id κλήσης, τι απέγινε κάθε προορισμός και αν διαβάστηκε πίσω. Ανοίγει πριν από την πρώτη εγγραφή και ολοκληρώνεται μετά την ανάγνωση πίσω, ώστε μια στη μέση της οποίας πεθαίνει η διεργασία να λέει παρ' όλα αυτά ότι ξεκίνησε. Η επόμενη εκκίνηση του Gateway τη σημειώνει `failed`, `interrupted by restart`, με παραπομπή στο id κλήσης της στον έλεγχο εγγραφών. Τίποτα δεν τη συνεχίζει.

Κάθε εφαρμογή είναι μία γραμμή στο ημερολόγιο συστήματος κάτω από τη σκηνή, και μία καταχώριση στο [ημερολόγιο συμβάντων](/el/iot/logbook/), είδους `recipe`, δίπλα στις εγγραφές που έκανε. Το ιστορικό μιας συνταγής κρατά τις 5000 νεότερες εφαρμογές της.

## Περισσότερες από μία διεργασίες

Κάθε αλλαγή σε μια συνταγή και κάθε εφαρμογή ανακοινώνεται σε κάθε διεργασία πάνω στη βάση δεδομένων, άρα μια συνταγή που αποθηκεύτηκε σε ένα pod είναι αυτή που εφαρμόζει το άλλο, και μια εφαρμογή που κάνει μια διεργασία `--mcp-stdio` κινεί την οντότητα scene του Gateway.

## Αντίγραφα ασφαλείας

Οι συνταγές, κάθε έκδοση και κάθε εφαρμογή περιλαμβάνονται στα αντίγραφα ασφαλείας και επιστρέφουν ακριβώς όπως ήταν. Μια εφαρμογή που το αντίγραφο έπιασε στη μέση επιστρέφει ως `applying` και σημειώνεται `failed` στην πρώτη εκκίνηση, όπως μια κατάρρευση. Δείτε [Αντίγραφα ασφαλείας και επαναφορά](/el/iot/backup/).

## Το API

Το [HTTP API](/el/iot/api/#συνταγές) έχει κάθε διαδρομή. Εν συντομία:

| <span class="sr-only">Λεπτομέρειες</span> | <span class="sr-only">Λεπτομέρειες</span> |
|---|---|
| `GET /api/recipes` | κάθε συνταγή, το τρέχον περιεχόμενό της και η τελευταία εφαρμογή της |
| `POST /api/recipes` | δημιουργία μίας, ως έκδοση 1 |
| `POST /api/recipes/capture` | ένα προσχέδιο από αυτά που κρατούν οι οντότητες τώρα |
| `PUT /api/recipes/{id}` | αποθήκευση· νέο περιεχόμενο είναι νέα έκδοση |
| `GET /api/recipes/{id}/versions` | κάθε έκδοση, όπως αποθηκεύτηκε |
| `POST /api/recipes/{id}/validate` | θα εφαρμοζόταν τώρα; δεν γράφεται τίποτα |
| `POST /api/recipes/{id}/apply` | εφαρμογή: `200` εφαρμόστηκε, `409` απορρίφθηκε, `502` μερική ή αποτυχημένη |
| `GET /api/recipes/{id}/applications` | κάθε εφαρμογή, μαζί με τις απορρίψεις |
