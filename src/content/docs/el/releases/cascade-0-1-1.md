## Τι είναι αυτό

Το 0.1.1 είναι η πρώτη έκδοση που δεν είναι υποψήφια. Υπήρξε μια ετικέτα 0.1.0 που δεν δημοσίευσε ποτέ τίποτα: ακυρώθηκε πριν φτάσει οτιδήποτε στο μητρώο. Μια ετικέτα μένει εκεί που είναι, οπότε αυτός είναι ο ίδιος κώδικας, πλέον δημοσιευμένος.

Τι είναι: η μηχανή ροών εργασίας που θέλαμε για ένα εργοστάσιο. Ένα στατικό δυαδικό Go, SQLite σε ένα μηχάνημα ή Postgres με workers όταν χρειάζεστε περισσότερα, και ο επεξεργαστής ενσωματωμένος στο δυαδικό, οπότε δεν υπάρχει τίποτα άλλο να τρέξει.

## Τι περιλαμβάνει

Η μηχανή, με κάθε βήμα αποθηκευμένο ως σημείο ελέγχου, ώστε ένα `kill -9` στη μέση μιας εκτέλεσης να συνεχίζει από εκεί που έμεινε. Ανθεκτικές αναμονές, επαναλήψεις, θύρες σφάλματος και ροές εργασίας σφάλματος. Εκφράσεις και ένα βήμα Κώδικα που τρέχει JavaScript απομονωμένο, στη δική του διεργασία.

Webhooks με ανθεκτικό εισερχόμενο, χρονοπρογραμματισμοί που ενεργοποιούνται ακριβώς μία φορά ανά χρονική θέση όσοι κύριοι κόμβοι κι αν παρακολουθούν, MQTT και ένας ενεργοποιητής για αρχεία που φτάνουν σε έναν κατάλογο. Ένα βήμα HTTP για ό,τι έχει API και συνδέσεις για HotLoop, Postgres, EmberOps, email, ntfy, Gotify και Discord. Καμία άλλη, επίτηδες.

Ένα χρηματοκιβώτιο διαπιστευτηρίων με εναλλαγή κλειδιών, OAuth2 για κάθε τύπο εξουσιοδότησης που χρειάζεται ένα εργοστάσιο, σύνδεση με κωδικό, TOTP, passkeys ή τον δικό σας πάροχο OpenID Connect, υποχρεωτικό MFA, έργα και ρόλους, ένα αρχείο ελέγχου που μπορείτε να επαληθεύσετε, κάθε αποθήκευση διατηρημένη ως έκδοση και ένα API με πεδία πρόσβασης και έγγραφο OpenAPI. Μετρικές, ίχνη και probes, ώστε να μπορεί κάποιος εκτός από εμένα να καταλάβει πότε κάτι έχει κολλήσει.

## Πώς τρέχει

Το image είναι amd64 και arm64. Τραβήξτε το με το digest που αναφέρεται παραπάνω αν θέλετε μια ανάπτυξη που δεν μπορεί να μετακινηθεί.

Σε k3s: το Helm chart, αυτόνομο ή χωρισμένο σε server και workers.

Σε ένα απλό μηχάνημα: οι μονάδες Quadlet στο `deploy/quadlet`, SQLite σε ένα μηχάνημα ή Postgres με επιπλέον workers. Ακολουθούν το `:stable` και το χρονόμετρο αυτόματης ενημέρωσης του Podman τις μετακινεί. Μια ενημέρωση που δεν ξεκινά υγιής επιστρέφει στο image που έτρεχε. Το τρέξαμε στην πράξη, και τις δύο παραλλαγές, σε Podman 5.8.7 υπό systemd: η εκκίνηση περιμένει να γίνει υγιής, ένα container που σκοτώθηκε επιστρέφει, μια καλή ενημέρωση περνά, μια κακή αναιρείται και μια ροή εργασίας τρέχει μετά από καθεμία.

## Τι πρέπει να ξέρετε

Οι μεταναστεύσεις πηγαίνουν μόνο προς τα εμπρός. Μια επαναφορά βάζει πίσω το παλιό image, δεν αναιρεί τη μετάβαση της βάσης δεδομένων σας, οπότε κάντε αντίγραφο ασφαλείας πριν ενεργοποιήσετε τις ενημερώσεις.

Το μητρώο ήταν ιδιωτικό για αυτή την έκδοση, γι' αυτό χρειαζόταν πρώτα ένα `podman login ghcr.io` ως root. Το image και το chart είναι δημόσια από το 0.1.2 και μετά και τραβιούνται χωρίς σύνδεση.

Αν χάσετε το κλειδί που σφραγίζει τα αποθηκευμένα διαπιστευτήρια, κάθε αποθηκευμένο διαπιστευτήριο γίνεται αδιάβαστο. Κρατήστε ένα αντίγραφο κάπου που δεν είναι το μηχάνημα.
