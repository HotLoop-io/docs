Το HotLoop Flow 2.14.0 αφήνει έναν πράκτορα να φτάσει στο υπόλοιπο Flow μέσω MCP και αδειάζει μια συσσώρευση μετά από μια διακοπή σε παρτίδες αντί για ένα μήνυμα τη φορά. Προσθέτει 22 εργαλεία MCP, μια σελίδα που απαριθμεί και τα 29, και έναν ταχύτερο τρόπο για μια ανθεκτική σύνδεση να προλάβει έναν InfluxDB που έλειπε. Κυκλοφορεί πρώτα σε amd64, με το arm64 να ακολουθεί στο 2.14.1.

## Τι νέο υπάρχει

- **Εργαλεία MCP για το υπόλοιπο API διαχείρισης.** Τα δικά του εργαλεία του Flow κάλυπταν τις ροές και τίποτα γύρω τους: απαρίθμηση, ανάγνωση, ανάπτυξη, επαναφορά και πάτημα ενός κόμβου inject. Υπάρχουν 22 ακόμη, ώστε ένας πράκτορας να μπορεί να διαβάσει τις ρυθμίσεις, την παλέτα και τα πρόσθετα, να διαβάσει το αρχείο ελέγχου, να διαβάσει μια ανάπτυξη και τι άλλαξε ανάμεσα σε δύο, να συγκρίνει και να ελέγξει τους τύπους ενός προχείρου σε σχέση με ό,τι τρέχει, να εξαγάγει τις ροές, να διαβάσει, να αντικαταστήσει και να προσθέσει δοκιμές ροών και να τις τρέξει, να διαβάσει τα ίχνη μηνυμάτων και να συντάξει μια δοκιμή από ένα, να επαναλάβει ένα ίχνος, να διαβάσει τα νούμερα του runtime και να απενεργοποιήσει τον δεύτερο παράγοντα ενός χρήστη (`reset_mfa`, που απαιτεί `auth.admin`). Κάθε εργαλείο είναι μια διαδρομή διαχείρισης που τρέχει από τον δικό της χειριστή, με το δικαίωμα που ζητά αυτή η διαδρομή, οπότε μια άρνηση επιστρέφει με τα λόγια της ίδιας της διαδρομής και κάθε κλήση καταγράφεται στο αρχείο ελέγχου με το όνομα του καλούντος. Η σύνδεση, ο δεύτερος παράγοντας ενός ατόμου και το ζωντανό socket του επεξεργαστή δεν είναι εργαλεία, και η σελίδα MCP λέει γιατί. Αυτή η σελίδα απαριθμεί και τα 29 εργαλεία με τις διαδρομές και τα δικαιώματά τους.
- **Μια ανθεκτική σύνδεση αδειάζει σε παρτίδες.** Μετά από μια διακοπή, το `influxdb out` γράφει μια συσσώρευση έως 256 μηνυμάτων ανά αίτημα αντί για ένα. Με έναν historian που χρειάζεται 8 ms για να απαντήσει σε μια εγγραφή, ένα εργοστάσιο που στέλνει 100 μετρήσεις το δευτερόλεπτο και 2.000 μετρήσεις στην ουρά, η ίδια δοκιμή άδειαζε σε 2 λεπτά και 38 δευτερόλεπτα πριν και σε 2,7 δευτερόλεπτα τώρα, κάθε μέτρηση μία φορά και με τη σειρά.

## Τι άλλαξε

- Μια ανθεκτική σύνδεση προς έναν κόμβο που δέχεται παρτίδες διεκδικεί έως 256 μηνύματα τη φορά. Αν μια παρτίδα δεν γίνει δεκτή, τα μηνύματα πριν από το πρώτο που απέτυχε σημειώνονται ως ολοκληρωμένα, εκείνο ξαναδοκιμάζεται μόνο του με την επανάληψη και την παραίτηση που είχε πάντα η σύνδεση, και τα υπόλοιπα στέλνονται ξανά, οπότε τίποτα δεν χάνεται ούτε αναδιατάσσεται. Κάθε άλλος προορισμός εξακολουθεί να παίρνει ένα μήνυμα τη φορά. Η παράδοση εξακολουθεί να είναι τουλάχιστον μία φορά, και ένα μήνυμα που ήταν σε πτήση όταν σκοτώθηκε η διεργασία μπορεί να ξανάρθει όπως πριν. Για έναν προορισμό με παρτίδες αυτό είναι έως μία παρτίδα, έως 256 μηνύματα, αντί για ένα, και η σήμανση `_queuedAt` κάνει μια επανάληψη προς το InfluxDB αντικατάσταση όπως πριν.
- Η γραμμή Licensed Work του αρχείου `LICENSE` κατονομάζει μόνο το HotLoop Flow, επειδή τα άλλα προϊόντα περνούν στη δική τους άδεια. Οι όροι δεν αλλάζουν.
- Τίποτα δεν άλλαξε στον επεξεργαστή.
- Τίποτε άλλο δεν συμπεριφέρεται διαφορετικά από την 2.13.1.

## Νέες ρυθμίσεις

Καμία.

## Αναβάθμιση

Ένα απλό `helm upgrade` στην εικόνα και το chart του 2.14.0, ή το νέο tag στη μονάδα Quadlet σας. Τίποτα δεν συμβαίνει στην πρώτη εκκίνηση και τίποτα δεν χρειάζεται μετάβαση. Ένας πράκτορας που συνδέεται στο `/mcp` βλέπει τα νέα εργαλεία και μόνο εκείνα που επιτρέπουν τα δικαιώματα του διακριτικού του. Αυτή η έκδοση είναι μόνο amd64: τα μηχανήματα arm64 μένουν στο 2.13.1 μέχρι το 2.14.1, που είναι ο ίδιος κώδικας με προστιθέμενη την εικόνα arm64.

Εικόνα: `ghcr.io/hotloop-io/hotloop-flow:2.14.0`, πρώτα linux/amd64, με το arm64 να ακολουθεί στην 2.14.1. Chart: `https://hotloop.io/hotloop-flow/`. Το README σε αυτό το tag έχει τα υπόλοιπα, με εικόνες: https://github.com/HotLoop-io/hotloop-flow/blob/v2.14.0/README.md
