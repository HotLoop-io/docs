---
title: "Το API διαχείρισης"
description: "Οι κλήσεις HTTP και websocket που χρησιμοποιούν ο επεξεργαστής και η γραμμή εντολών, τι χρειάζεται η καθεμία και τι επιστρέφει."
---

| Μέθοδος και διαδρομή | Δικαίωμα | Σημειώσεις |
|---|---|---|
| `GET /health` | κανένα | Ζωντάνια. Το kubelet δεν φέρει διακριτικό, και η ταυτοποίηση σε αυτή τη διαδρομή θα έβαζε το pod σε ατέρμονο βρόχο επανεκκινήσεων. |
| `GET /ready` | κανένα | Ετοιμότητα, αναφέρεται ξεχωριστά, ώστε ένας χρόνος εκτέλεσης που απέτυχε να ξεκινήσει να φεύγει από το Service χωρίς το kubelet να σκοτώνει το pod. |
| `POST /auth/token` | κανένα | Σύνδεση. Ένα 429 με `Retry-After` όσο υπάρχει κλείδωμα. |
| `POST /auth/revoke` | κανένα | Αποσύνδεση. |
| `GET /auth/mode` | χωρίς σύνδεση | Αν αυτός ο χρόνος εκτέλεσης ανοίγει από τον πίνακα ελέγχου του EmberCORE: `{"dashboard": bool, "hideLogin": bool}`. Ο επεξεργαστής το ρωτά πριν συνδεθεί οποιοσδήποτε. |
| `GET /auth/mfa`, `POST /auth/mfa/setup`, `/confirm`, `/disable` | συνδεδεμένος χρήστης | Η δική σας σύνδεση δύο παραγόντων. Το setup επιστρέφει το κλειδί, τον σύνδεσμο `otpauth://` και τον κωδικό QR. Τα confirm και disable δέχονται `{"code": ...}`. |
| `POST /auth/mfa/reset` | `auth.admin` | Απενεργοποιεί τη σύνδεση δύο παραγόντων κάποιου άλλου: `{"username": ...}`. |
| `GET /metrics` | κανένα | Prometheus. Μόνο μετρητές και αναγνωριστικά κόμβων, ποτέ περιεχόμενο μηνυμάτων ή ρυθμίσεις. |
| `GET /settings` | `settings.read` | |
| `GET /nodes` | `nodes.read` | Το μητρώο, που τροφοδοτεί την παλέτα του επεξεργαστή και τα παράθυρα διαλόγου του. |
| `GET /plugins` | `nodes.read` | Τα πρόσθετα που φορτώθηκαν, τι ζητά το καθένα και τι του έχει χορηγηθεί, και όσα απορρίφθηκαν με τον λόγο. |
| `GET /flows` | `flows.read` | |
| `GET /flows/export` | `flows.read` | Το αρχείο ροών ακριβώς όπως βρίσκεται στον δίσκο, για το git. |
| `POST /flows` | `flows.write` | Ανάπτυξη. Δέχεται προαιρετική σημείωση για το αρχείο καταγραφής αναπτύξεων. |
| `GET /deployments` | `flows.read` | Το αρχείο καταγραφής αναπτύξεων, με τις νεότερες πρώτες, χωρίς τα περιεχόμενα. Το `?limit=N` το περιορίζει. |
| `GET /audit` | `audit.read` | Ποιος έκανε τι και από πού, με τα νεότερα πρώτα. `?event=`, `?user=`, `?since=`, `?limit=`. |
| `GET /deployments/{seq}` | `flows.read` | Μία εγγραφή, με τις ροές της αναλυμένες. Ποτέ τα διαπιστευτήριά της. |
| `GET /deployments/{seq}/flows` | `flows.read` | Το αρχείο ροών εκείνης της ανάπτυξης, byte προς byte. |
| `GET /deployments/{from}/diff/{to}` | `flows.read` | Διαφορά κόμβο προς κόμβο ανάμεσα σε δύο αναπτύξεις, δομημένη και ως κείμενο. |
| `POST /flows/diff` | `flows.read` | Η διαφορά ανάμεσα σε ό,τι τρέχει και στο έγγραφο του σώματος. Δεν αναπτύσσει τίποτα. |
| `POST /flows/types` | `flows.read` | Ο έλεγχος των τυποποιημένων καλωδίων που κάνει μια ανάπτυξη, στο έγγραφο του σώματος: `{"wires": [...]}`, κενό όταν δεν υπάρχει τίποτα λάθος. Ο επεξεργαστής σχεδιάζει την απάντηση. Δεν αναπτύσσει τίποτα. |
| `POST /deployments/{seq}/rollback` | `flows.write` | Αναπτύσσει ξανά τις ροές και τα διαπιστευτήρια εκείνης της εγγραφής ως νέα ανάπτυξη. Δέχεται την κεφαλίδα rev και ένα προαιρετικό `{"note": ...}`. |
| `GET /tests` | `flows.read` | Η σουίτα δοκιμών της ροής που φυλάσσεται δίπλα στο αρχείο ροών, το όνομα του αρχείου της και αν οι αναπτύξεις εξαρτώνται από αυτήν. |
| `PUT /tests` | `flows.write` | Αντικαθιστά τη σουίτα. Το σώμα είναι το YAML· ένα που δεν αναλύεται δίνει 400 με τον λόγο. |
| `POST /tests/run` | `flows.read` | Εκτελεί τη σουίτα, ή τα `"tests"` από το σώμα, απέναντι στα `"flows"` από το σώμα ή σε ό,τι τρέχει. Επιστρέφει την αναφορά. Δεν αναπτύσσει τίποτα. |
| `POST /tests/from-debug` | `flows.read` | Συντάσσει μια δοκιμή από το `{"node", "msgId"}`, ένα μήνυμα που έδειξε ένας κόμβος Debug. Δεν αποθηκεύει τίποτα. |
| `POST /tests/cases` | `flows.write` | Προσθέτει τις δοκιμές του σώματος, ένα δικό τους αρχείο δοκιμών, στο τέλος της σουίτας. |
| `GET /traces` | `flows.read` | Τα ίχνη που διατηρούνται, με τα νεότερα πρώτα, με ό,τι κρατά ο buffer και τα όριά του. `?limit=N`. 404 με `trace.enabled: false`. |
| `GET /traces/find` | `flows.read` | Το ίχνος στο οποίο βρέθηκε ένα μήνυμα, από τα `?msgId=` και `?node=`, το αναγνωριστικό και ο κόμβος Debug που δείχνει η πλαϊνή στήλη. Επιστρέφει κάθε άλμα και τη διαδρομή προς αυτό που ζητήθηκε. |
| `GET /traces/{id}` | `flows.read` | Ένα ίχνος, κάθε άλμα με τον χρόνο του και το μήνυμα όπως το παρέλαβε ο κόμβος. |
| `POST /traces/{id}/test` | `flows.read` | Συντάσσει δοκιμή ροής από το ίχνος. Δεν αποθηκεύει τίποτα. |
| `POST /traces/{id}/replay` | `flows.read` | Βάζει το μήνυμα που ξεκίνησε το ίχνος στα `"flows"` από το σώμα, ή σε ό,τι τρέχει, σε θυγατρική διεργασία, και επιστρέφει πού καταλήγει σε σύγκριση με το πού κατέληξε. Δεν αναπτύσσει τίποτα. |
| `GET /runtime/stats` | `status.read` | |
| `POST /inject/{id}` | `inject.write` | Πυροδοτεί έναν κόμβο Inject. |
| `GET /comms` | `status.read` | Το websocket κατάστασης και αποσφαλμάτωσης του επεξεργαστή. Στείλτε το διακριτικό ως υποπρωτόκολλο `hotloop-flow.bearer.<token>`, που προσφέρεται δίπλα στο `hotloop-flow`. Αυτό κάνει ο επεξεργαστής. Το `?access_token=<token>` στο URL εξακολουθεί να λειτουργεί για σενάρια που ήδη το χρησιμοποιούν, και καταγράφει μια προειδοποίηση για κάθε σύνδεση που το κάνει, επειδή ένα URL καταλήγει στα αρχεία καταγραφής proxy και πρόσβασης. |
| `POST /mcp` (και `GET` και `DELETE`, για τις παλαιότερες αναθεωρήσεις του πρωτοκόλλου) | `mcp.call` | Το [σημείο MCP](/el/flow/mcp/), όπου οι ροές προσφέρονται ως εργαλεία. Ένα διακριτικό συνεδρίας ή API όπως κάθε άλλο. Τα εργαλεία που προσφέρονται σε έναν καλούντα, και μπορεί να καλέσει, είναι εκείνα που φτάνουν τα δικαιώματά του. 403 με απενεργοποιημένη ταυτοποίηση. |

Το ότι τα `/metrics` και `/health` είναι χωρίς ταυτοποίηση είναι απόφαση και όχι παράλειψη. Ένας συλλέκτης Prometheus δεν φέρει διακριτικό κομιστή, οπότε το να απαιτηθεί ένα σημαίνει είτε να δώσετε διαπιστευτήριο στη στοίβα παρακολούθησης είτε να μην έχετε παρακολούθηση.

Ένας χρήστης με ενεργή σύνδεση δύο παραγόντων στέλνει `"code"` μαζί με το όνομα χρήστη και τον κωδικό στο `POST /auth/token`. Χωρίς αυτό η απάντηση είναι 401 με `"mfa": "required"`.

Τα δικαιώματα είναι `"*"` για όλα, μια ακριβής συμβολοσειρά όπως `flows.read`, ή μια χορήγηση με πρόθεμα όπως `flows.*`. Ένας πράκτορας που καλεί ροές ως εργαλεία MCP χρειάζεται `mcp.call`. Ένας λογαριασμός μόνο για ανάγνωση σε έναν πίνακα ελέγχου που θέλει απλώς να δείχνει την κατάσταση των ροών είναι `["flows.read", "status.read"]` και τίποτα παραπάνω.

Οι αναπτύξεις δέχονται μια προαιρετική κεφαλίδα `HotLoop-Flow-Deployment-Rev`. Στείλτε την αναθεώρηση που διαβάσατε τελευταία και μια ανάπτυξη που ανταγωνίζεται άλλον επεξεργαστή απορρίπτεται με 409 αντί να αντικαταστήσει σιωπηλά τη δουλειά κάποιου, που είναι η αποτυχία για την οποία μαθαίνετε μόνο από εκείνον που έχασε το απόγευμά του.

Μια ανάπτυξη επανεκκινεί μόνο ό,τι αλλάξατε. Ένας κόμβος μένει ενεργός όταν δεν κινήθηκε τίποτα από όσα στηρίζεται: οι ρυθμίσεις του, η καρτέλα του, η ομάδα του, το περιβάλλον του, τα διαπιστευτήριά του και κάθε κόμβος ρύθμισης που κατονομάζει. Το να τον σύρετε στον καμβά ή να τον ξανασυνδέσετε δεν μετρά, επειδή τα νέα καλώδια μπαίνουν στον κόμβο που τρέχει. Έτσι η διόρθωση ενός τυπογραφικού σε έναν κόμβο συνάρτησης δεν ρίχνει πια όλες τις συνεδρίες MQTT του κουτιού, και ένας κόμβος Delay που κρατά δέκα λεπτά μετρήσεων συνεχίζει να τις κρατά. Αυτός είναι ολόκληρος ο λόγος ύπαρξής του: όταν κάθε αποθήκευση κουνά το εργοστάσιο, οι χειριστές σταματούν να αποθηκεύουν σε βάρδια και η διόρθωση περιμένει το Σάββατο.

Επιλέξτε πόσα επανεκκινούν με μια κεφαλίδα `HotLoop-Flow-Deployment-Type`. Το `Node-RED-Deployment-Type` του Node-RED λειτουργεί επίσης, ώστε ένα σενάριο ανάπτυξης που ήδη έχετε να παίρνει την επανεκκίνηση που ζητά.

| Τύπος | Τι επανεκκινεί |
|---|---|
| `nodes` (προεπιλογή) | Οι κόμβοι που αλλάξατε, συν ό,τι κατονομάζει έναν κόμβο ρύθμισης που αλλάξατε. |
| `flows` | Κάθε κόμβος σε οποιαδήποτε ροή έχει αλλαγή. |
| `full` | Τα πάντα. Το ίδιο με επανεκκίνηση της διεργασίας. |

Η απάντηση λέει τι έκανε: `type`, `started`, `restarted`, `stopped` και `unchanged`. Τίποτα από ό,τι βρίσκεται εν κινήσει δεν χάνεται στον δρόμο. Η δουλειά που ήδη περιμένει σε ουρά σε έναν κόμβο που αντικαθίσταται ολοκληρώνεται στο παλιό στιγμιότυπο, ό,τι εμφανιστεί κατά την εναλλαγή περιμένει το νέο, και ένα μήνυμα προς έναν κόμβο που διαγράψατε μετριέται και εμφανίζεται ως απόρριψη αντί να εξαφανιστεί.
