---
title: "Δύο sandbox στο HotLoop Flow"
description: "Πώς περιορίζονται ο κόμβος Function και το sandbox WebAssembly, τι μπορεί να αγγίξει το καθένα και πώς τρέχει ένα plugin στο δεύτερο."
---

Ο κόμβος Function τρέχει στον διερμηνέα JavaScript (δείτε το [Στάση ασφαλείας](/el/flow/security/)). Μια κλήση κοστίζει 11.6 έως 13.7 µs. Δεν είναι όριο απέναντι στη μνήμη: μια συνάρτηση που δεσμεύει μνήμη σε βρόχο μεγαλώνει το heap της Go ώσπου να πεθάνει το pod, και το μόνο που μπορεί να κάνει ο διερμηνέας JavaScript γι' αυτό είναι ένα χρονικό όριο πραγματικού χρόνου.

Αυτό κοστίζει 184 έως 196 µs ανά κλήση, δεκαπέντε έως δεκαέξι φορές μια κλήση του διερμηνέα JavaScript. Αξίζει ακριβώς όταν τρέχετε κώδικα που δεν εμπιστεύεστε πλήρως, και όχι αλλιώς.

Μια ροή τρέχει έναν φιλοξενούμενο WASM μέσω ενός plugin: μια υπογεγραμμένη ενότητα με έναν περιγραφέα από τον οποίο ο επεξεργαστής σχεδιάζει το παράθυρό του, που δεν παίρνει πρόσβαση στον host εκτός αν τη ζητήσει και πείτε ναι. Η μνήμη περιορίζεται ανά κόμβο, ένα μήνυμα παίρνει χρονικό όριο, και ένας φιλοξενούμενος που ξεπερνά το ένα ή το άλλο διακόπτεται, καταλήγει σε έναν κόμβο Catch με την αιτία και δεν παρασύρει τίποτα άλλο. Όλα είναι στο [Plugins χωρίς npm](/el/flow/plugins/), μαζί με το πώς εμπιστεύεστε το κλειδί ενός εκδότη και τι λένε οι αρνήσεις. Τι σημαίνει για εσάς: αυτό για το οποίο το Node-RED χρειάζεται npm και μια ολόκληρη εγκατάσταση Node.js, το Flow το τρέχει ως απομονωμένο αρχείο που μπορείτε να επαληθεύσετε πριν φορτωθεί.

Ένα plugin μπορεί να γραφτεί σε Rust, TinyGo, Zig ή AssemblyScript αντί για JavaScript, ώστε η επεξεργασία σήματος που πραγματικά θέλει μια ροή OT να τρέχει μεταγλωττισμένη, με ανώτατο όριο μνήμης που δεν μπορεί να το αμφισβητήσει.

Το ABI του φιλοξενούμενου είναι τρεις εξαγωγές, δύο από αυτές άγκιστρα του εκχωρητή, και είναι τόσο μικρό επίτηδες. Κάθε εξαγωγή είναι επιφάνεια επίθεσης και ένα ακόμη πράγμα που πρέπει να κάνει σωστά κάθε συγγραφέας φιλοξενούμενου.

| Εξαγωγή | Υπογραφή | Υποχρεωτική |
|---|---|---|
| `hotloop_flow_process` | `(ptr i32, len i32) -> i64` | ναι |
| `hotloop_flow_alloc` | `(size i32) -> i32` | ναι |
| `hotloop_flow_free` | `(ptr i32, size i32)` | όχι |

Το αποτέλεσμα `i64` πακετάρει μια μετατόπιση στα υψηλά 32 bit και ένα μήκος στα χαμηλά 32, δείχνοντας μια απάντηση JSON στη δική του μνήμη του φιλοξενούμενου. Όλα περνούν ως JSON, ώστε ένας φιλοξενούμενος σε οποιαδήποτε γλώσσα να μπορεί να την παράγει χωρίς κοινό μεταγλωττιστή σχημάτων.

Τα όρια είναι μικρά επίτηδες. Αυτό τρέχει σε υλικό άκρου δίπλα στις ροές που πραγματικά μετρούν, και ένας κόμβος που χρειάζεται περισσότερα θα πρέπει να το δηλώνει:

| Όριο | ο διερμηνέας JavaScript | WASM |
|---|---|---|
| Χρονικό όριο ανά κλήση | 5 s | 5 s |
| Ανώτατο όριο μνήμης | κανένα που να επιβάλλεται | 16 MiB ανά κόμβο εκτός αν το πει το plugin, το πολύ 64 MiB εκτός αν αυξήσετε το `plugins.maxMemoryMiB`, αυστηρό |
| Μέγιστη έξοδος | 16 MiB | 8 MiB |

Και τα δύο περιβάλλοντα εκτέλεσης είναι καθαρή Go χωρίς cgo.
