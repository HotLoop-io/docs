---

«Τι άλλαξε, ποιος το άλλαξε, βάλτε το πίσω» είναι το πρώτο που ρωτά όλος ο κόσμος αφού σταματήσει μια γραμμή. Τρία αρχεία `.bak` δεν απαντούν σε τίποτα από αυτά. Δεν ξέρουν ποιος, γράφονται ξανά μετά από τρεις αποθηκεύσεις, και αυτό που χρειάζεστε είναι πάντα το τέταρτο.

Έτσι κάθε ανάπτυξη γράφει μια αμετάβλητη εγγραφή στο `data/deployments/`: ποιος την έκανε (από το token του, ποτέ από όσα ισχυρίζεται ο πελάτης), από πού, πότε, τη σημείωση που άφησε, την αναθεώρηση που αντικατέστησε, το αρχείο ροής byte προς byte, και τα διαπιστευτήρια όπως ήταν μετά την ανάπτυξη, κρυπτογραφημένα ακριβώς όπως το αρχείο διαπιστευτηρίων. Οι εγγραφές μόνο προστίθενται. Το αρχείο καταγραφής κρατά τις τελευταίες 100 από προεπιλογή (`history.retain`, και το 0 τις κρατά όλες), και δεν κλαδεύει ποτέ την πιο πρόσφατη, γιατί η πιο πρόσφατη είναι αυτή που τρέχει.

```bash
curl -s -H "Authorization: Bearer $TOKEN" http://localhost:1880/deployments
curl -s -H "Authorization: Bearer $TOKEN" http://localhost:1880/deployments/42/flows > flows-42.json
```

Μια σημείωση μπαίνει με την ανάπτυξη, ως `"note"` στο τυλιγμένο έγγραφο (`{"rev": ..., "flows": [...], "note": "..."}`) ή ως κεφαλίδα `HotLoop-Flow-Deployment-Note`. Η μορφή εγγράφου υπάρχει επειδή ένας περιηγητής δεν βάζει τίποτα εκτός Latin-1 σε κεφαλίδα, και οι άνθρωποι γράφουν σημειώσεις στη δική τους γλώσσα.

Κάνει δύο πράγματα που θα τα χρειαζόσασταν μόνο αφού σας δαγκώσουν:

- **Μια χειροκίνητη επεξεργασία εντοπίζεται.** Αν το αρχείο ροής στον δίσκο δεν είναι αυτό που κατέγραψε τελευταίο το αρχείο καταγραφής, επειδή κάποιος το επεξεργάστηκε ενώ η διεργασία ήταν σταματημένη, η εκκίνηση το καταγράφει ως εγγραφή `baseline` που το λέει. Το ίδιο στην πρώτη εκκίνηση με ήδη υπάρχον αρχείο ροής. Αλλιώς μια χειροκίνητη επεξεργασία γίνεται αθόρυβα ένα παρελθόν που κανείς δεν κατέγραψε.
- **Ένα αρχείο καταγραφής που δεν γράφεται δεν σταματά τη γραμμή.** Το αρχείο ροής έχει ήδη αποθηκευτεί μέχρι τότε, οπότε η άρνηση της ανάπτυξης θα άφηνε τον δίσκο και τις ροές που τρέχουν σε διαφωνία μέχρι την επόμενη επανεκκίνηση. Η ανάπτυξη προχωρά, και η απάντηση και το αρχείο καταγραφής λένε, με λέξεις, ότι αυτή δεν έχει εγγραφή.

Το API δεν δίνει ποτέ τα διαπιστευτήρια μιας εγγραφής, κρυπτογραφημένα ή όχι. Κρατιούνται για μία δουλειά, να τα ξαναβάλουν στη θέση τους, και ένα endpoint ιστορικού δεν είναι τρόπος να φύγει κανείς μαζί τους.

## Η διαφορά διαβάζεται σαν αναθεώρηση

Μια διαφορά γραμμή προς γραμμή ενός αρχείου ροής είναι ειλικρινής και άχρηστη. Σύρετε έναν κόμβο είκοσι pixel και είναι αλλαγή. Αλλάξτε ένα κατώφλι και είναι αλλαγή. Ο αναθεωρητής δεν μπορεί να πει ποια από τις δύο πρόκειται να σταματήσει μια πρέσα. Γι' αυτό το Flow συγκρίνει κόμβο προς κόμβο:

```
1 changed, 2 moved

Tab "Line 3" (t1)
  ~ switch "Pressure check" (sw1)
      rules[1].v: "7.5" -> "8.0"
      wire added: port 1 -> change "set alarm" (alarm1)

Moved on the canvas only
  mqtt in "press 01" (in1)
  debug "ok" (ok1)
```

Προστέθηκαν, αφαιρέθηκαν και άλλαξαν, ιδιότητα προς ιδιότητα με την παλιά και τη νέα τιμή, ποιες συνδέσεις μετακινήθηκαν ανά θύρα εξόδου, και **η διάταξη χωριστά από τη λογική**: η μετακίνηση, η αλλαγή μεγέθους ή η απόκρυψη μιας ετικέτας είναι «μετακινήθηκε στον καμβά», ποτέ αλλαγή, ώστε ένα συμμάζεμα να διαβάζεται ως συμμάζεμα. Ένα διαπιστευτήριο διαβάζεται ως «ορίστηκε» ή «άλλαξε», ποτέ με την τιμή του. Οι επεξεργασίες μέσα σε μια υποροή εμφανίζονται στην υποροή, και το σύρσιμο μιας θύρας της είναι επίσης διάταξη.

Η ίδια απάντηση παντού, από ένα πακέτο της μηχανής:

- Το `GET /deployments/{from}/diff/{to}` συγκρίνει δύο αναπτύξεις.
- Το `POST /flows/diff` συγκρίνει ό,τι τρέχει με ένα έγγραφο που κανείς δεν έχει αναπτύξει ακόμη, που είναι αυτό που κοιτάτε πριν πατήσετε ανάπτυξη.
- `hotloop-flow diff old.json new.json` στη γραμμή εντολών. `-json` για πρόγραμμα. Τερματίζει με 1 όταν κάτι διαφέρει, όπως το `diff`.
- **Μέσα στο git.** Κάντε το πρόγραμμα οδήγησης διαφορών του git για αρχεία ροής, και τα `git diff`, `git log -p` και `git show` εκτυπώνουν τη σημασιολογική διαφορά αντί για ένα τμήμα JSON:

  ```bash
  git config diff.hotloop-flow.command 'hotloop-flow diff'
  echo 'flows.json diff=hotloop-flow' >> .gitattributes
  ```

  Ή ως difftool: `git config difftool.hotloop-flow.cmd 'hotloop-flow diff "$LOCAL" "$REMOTE"'`, μετά `git difftool -t hotloop-flow`.

Μια ροή που συγκρίνεται με τον εαυτό της δεν είναι καθόλου αλλαγή, για κάθε έγγραφο που δέχεται ο αναλυτής.

## Βάλτε το πίσω

```bash
curl -s -X POST -H "Authorization: Bearer $TOKEN" \
  -H "HotLoop-Flow-Deployment-Rev: $CURRENT_REV" \
  -d '{"note":"42 broke the label printer"}' \
  http://localhost:1880/deployments/41/rollback
```

Μια επαναφορά αναπτύσσει ξανά μια παλιά εγγραφή **ως νέα εγγραφή**. Το ιστορικό μένει μόνο προσθήκης: η ανάπτυξη 41 δεν αγγίζεται, και η επαναφορά είναι η δική της εγγραφή που λέει «επαναφορά στην ανάπτυξη 41», ποιος την έκανε και γιατί. Το αρχείο ροής επιστρέφει byte προς byte, άρα είναι η ίδια αναθεώρηση με τότε.

**Επιστρέφουν και τα διαπιστευτήρια.** Κάθε εγγραφή τα φέρει όπως ήταν, οπότε ένας κόμβος που διαγράψατε επιστρέφει με τον κωδικό του broker αντί να επιστρέψει και να αποτύχει να συνδεθεί. Αυτό δοκιμάζεται απέναντι σε πραγματικό Mosquitto που αρνείται ανώνυμους πελάτες: διαγράψτε τον συνδρομητή, αναπτύξτε, κάντε επαναφορά, και συνδέεται ξανά και τα μηνύματα ρέουν.

Αρνείται με τρεις τρόπους, πριν γραφτεί οτιδήποτε. Ένα ξεπερασμένο `HotLoop-Flow-Deployment-Rev` παίρνει το ίδιο 409 που θα έπαιρνε μια ανάπτυξη, γιατί μια επαναφορά που τρέχει παράλληλα με την ανάπτυξη κάποιου άλλου παραμένει ανταγωνισμός. Μια ανάπτυξη που η διατήρηση έχει ήδη αφαιρέσει είναι 404. Και μια εγγραφή της οποίας τα διαπιστευτήρια δεν αποκρυπτογραφούνται με το τρέχον μυστικό διαπιστευτηρίων είναι 422, γιατί ροές που δεν μπορούν να συνδεθούν πουθενά είναι μια επαναφορά που μόνο φαίνεται ότι δούλεψε.

## Στον επεξεργαστή

**Το Deploy δεν αναπτύσσει.** Ανοίγει μια αναθεώρηση: τη διαφορά της μηχανής απέναντι σε ό,τι τρέχει, ζωγραφισμένη στον καμβά και γραμμένη με λέξεις, με ένα πλαίσιο για τη σημείωση. Το πράσινο είναι προστέθηκε, το κεχριμπαρί άλλαξε, το μπλε μετακινήθηκε μόνο, και κόκκινα φαντάσματα στέκονται εκεί που ήταν οι αφαιρεθέντες κόμβοι και συνδέσεις. Μια καρτέλα με κάτι αλλαγμένο παίρνει μια τελεία. Το δεύτερο κουμπί Deploy είναι αυτό που αναπτύσσει, και η σημείωση πηγαίνει στο αρχείο καταγραφής. Επεξεργαστείτε οτιδήποτε ενώ η αναθεώρηση είναι ανοιχτή και κλείνει, γιατί μια αναθεώρηση κάτι που έχετε από τότε αλλάξει είναι ψέμα για ό,τι πρόκειται να στείλετε.

**Ο πίνακας ιστορικού** απαριθμεί κάθε ανάπτυξη με ποιος, πότε και τη σημείωση. Το *Changes* ανοίγει εκείνη την ανάπτυξη σε καμβά μόνο για ανάγνωση με ό,τι άλλαξε ζωγραφισμένο πάνω του, πάνω από το αντίγραφο εργασίας σας, που μένει ακριβώς όπως το αφήσατε. Το *Roll back* ρωτά γιατί, σας προειδοποιεί αν πρόκειται να πετάξετε μη αποθηκευμένες αλλαγές, και την αναπτύσσει.

**Μια σύγκρουση ανάπτυξης δείχνει τι έκανε ο άλλος.** Παλιά ήταν ένα `confirm()` του περιηγητή που σας ζητούσε να αντικαταστήσετε τη δουλειά του άλλου ή να χάσετε τη δική σας χωρίς να λέει ποια ήταν η δική του. Τώρα λέει ποιος ανέπτυξε, πότε, τη σημείωσή του και την αλλαγή του κόμβο προς κόμβο, και μετά σας αφήνει να φορτώσετε τη δική του, να αντικαταστήσετε με τη δική σας ή να συνεχίσετε την επεξεργασία.

**Η αντιγραφή, η αποκοπή και η επικόλληση λειτουργούν όπως περιμένετε, και μιλούν το αρχείο ροής.** Επιλέξτε κόμβους, Ctrl+C, και ό,τι υπάρχει στο πρόχειρο είναι το ίδιο JSON που διαβάζει κάθε άλλο εργαλείο ροών, οπότε μπορείτε να το επικολλήσετε σε μια συνομιλία, ένα αίτημα ή άλλο μηχάνημα. Η επικόλληση το βάζει εκεί που είναι ο δείκτης σας, με νέα id κάθε φορά, οπότε η διπλή επικόλληση δίνει δύο αντίγραφα και ποτέ σύγκρουση. Μια σύνδεση προς κάτι που δεν αντιγράψατε κόβεται αντί να δείχνει στο τίποτα, και ένας κόμβος ρύθμισης που χρησιμοποιούν οι κόμβοι έρχεται μαζί. Αν αυτός ο κόμβος ρύθμισης υπάρχει ήδη στη ροή όπου επικολλάτε, το αντίγραφο τον μοιράζεται αντί να ανοίξει δεύτερη σύνδεση προς κάτι που τις μετρά. Τα διαπιστευτήρια δεν πηγαίνουν ποτέ στο πρόχειρο. Ένας κωδικός σε ένα buffer επικόλλησης είναι ο τρόπος που καταλήγει σε μια αναφορά σφάλματος.

**Το Import και το Export** κάνουν το ίδιο για μια επιλογή, μία ροή ή τα πάντα, με ένα πλαίσιο για αντιγραφή, ένα κουμπί Download και έναν επιλογέα αρχείου στην είσοδο. Τα σκουπίδια παίρνουν έναν λόγο («το id a εμφανίζεται δύο φορές», «η καταχώριση 1 δεν έχει id») και το παράθυρο μένει ανοιχτό. Ένας τύπος κόμβου που αυτό το runtime δεν έχει μπαίνει γκρι και διακεκομμένος, και η εισαγωγή σας λέει ποιοι, γιατί ένας κόμβος που πετιέται αθόρυβα είναι χειρότερος από έναν θορυβώδη.

Μια οθόνη είναι μέρος αυτού του αρχείου. Ο πίνακας ελέγχου που ζωγραφίζει μια ροή (`ui_tab`, `ui_group` και τα widget) είναι κόμβοι της ροής, οπότε οι οθόνες ενός πελάτη ταξιδεύουν με τις ροές του μέσω Export και Import, και καμία δεν ζει μέσα στο ίδιο το HotLoop Flow.

**Οι υποροές επεξεργάζονται σε δικό τους καμβά.** Πατήστε *+ subflow* και ανοίγει με τις θύρες εισόδου και εξόδου της. Συνδέστε τες με τους κόμβους μέσα όπως οτιδήποτε άλλο. Το *Subflow properties* ορίζει το όνομα, το χρώμα, πόσες εξόδους έχει και τις ιδιότητες που μπορεί να ορίσει ένα στιγμιότυπο. Τα στιγμιότυπα στις ροές ακολουθούν όταν αλλάζει το σχήμα, και η παλέτα απαριθμεί κάθε υποροή ώστε να ρίξετε μία. Κάντε διπλό κλικ σε ένα στιγμιότυπο για να του δώσετε δικό του όνομα και δική του τιμή για κάθε ιδιότητα. Μια υποροή δεν μπορεί να μπει μέσα στον εαυτό της ούτε μέσα σε μια που την περιέχει, και μια που ακόμη χρησιμοποιείται δεν μπορεί να διαγραφεί. Ο επεξεργαστής το λέει αντί να αφήσει την επόμενη ανάπτυξη να το ανακαλύψει.

**Από επιλογή σε υποροή.** Επιλέξτε κόμβους και πατήστε *Selection to subflow*. Μετακινούνται σε δική τους υποροή και ένα στιγμιότυπο παίρνει τη θέση τους. Κάθε σύνδεση που διέσχιζε το όριο της επιλογής γίνεται θύρα: ο μόνος δρόμος προς τα μέσα είναι η είσοδος της υποροής, και κάθε έξοδος ενός επιλεγμένου κόμβου που πήγαινε αλλού είναι έξοδος της υποροής, ώστε η ροή να κάνει ό,τι έκανε. Μια υποροή έχει μία είσοδο, οπότε αν η επιλογή συνδέεται με δύο διαφορετικούς κόμβους, το λέει και δεν αλλάζει τίποτα, γιατί το να τροφοδοτούνται και οι δύο από και τους δύο θα ήταν άλλη ροή. Επιλέξτε μια ομάδα και έρχεται με ό,τι περιέχει. Ένας κόμβος ρύθμισης που ανήκει στη ροή και τον χρησιμοποιεί μόνο η επιλογή πηγαίνει στην υποροή μαζί της, μαζί με ό,τι δείχνει. Ένας που τον χρησιμοποιεί και κάτι που έμεινε πίσω γίνεται καθολικός, ώστε τα δύο άκρα να συνεχίσουν να μοιράζονται την ίδια σύνδεση, γιατί μια δεύτερη σύνδεση broker σε μηχάνημα που τις μετρά είναι το είδος της έκπληξης που δεν παραδίδουμε. Οι μεταβλητές περιβάλλοντος που διαβάζουν οι μετακινημένοι κόμβοι (τύπου env, ως `${NAME}` ή `$(NAME)` σε συμβολοσειρά, ή `env.get`) και που δηλώνει η ροή γίνονται ιδιότητες της υποροής που προωθούν στη ροή, ώστε η τιμή να έρχεται ακόμη από εκεί που ερχόταν και το στιγμιότυπο να μπορεί να την παρακάμψει. Το Ctrl+Z τα αναιρεί όλα.

**Ροές.** Κάντε διπλό κλικ σε μια καρτέλα, ή πατήστε *Flow properties*, για να την μετονομάσετε ή να τη διαγράψετε. Η διαγραφή ρωτά, παίρνει μαζί της κάθε κόμβο της ροής και κόβει τις συνδέσεις και τους συνδέσμους που είχαν άλλες ροές προς αυτήν ώστε το αρχείο να μη δείχνει στο τίποτα. Αφαιρεί επίσης τους διαγραμμένους κόμβους από κάθε εύρος Catch, Status ή Complete που τους ανέφερε. Ένα Catch ή Status του οποίου διαγράφηκε ολόκληρη η λίστα κρατά το τελευταίο id, γιατί μια κενή λίστα σημαίνει ολόκληρη τη ροή και δεν θα γυρίσουμε έναν κόμβο από την παρακολούθηση ενός πράγματος στην παρακολούθηση των πάντων πίσω από την πλάτη σας. Το Ctrl+Z την επαναφέρει μέχρι να αναπτύξετε. Η τελευταία ροή δεν μπορεί να διαγραφεί, γιατί ένα runtime χωρίς ροή δεν έχει πού να βάλει έναν κόμβο.

**Οι κόμβοι ρύθμισης** βρίσκονται στην παλέτα κάτω από το *configuration*. Δεν κάθονται σε κανέναν καμβά, οπότε κάντε διπλό κλικ στον τύπο, συμπληρώστε το παράθυρο και προστίθεται στη λίστα κάτω από το *configuration in use*, όπου ένα διπλό κλικ τον επεξεργάζεται και ο σταυρός τον διαγράφει. Ένας που ένας κόμβος ακόμη χρησιμοποιεί δεν διαγράφεται και λέει πόσοι τον χρησιμοποιούν. Εκεί σας στέλνει το «Add one from the palette first» στο παράθυρο ενός κόμβου.

**Διαγραφή μιας σύνδεσης.** Alt-κλικ. Ένα απλό κλικ δεν κάνει τίποτα, ώστε το άγγιγμα μιας σύνδεσης ενώ επιλέγετε να μη μπορεί να χαλάσει μια ροή. Το Ctrl+Z τη βάζει πίσω.

**Ανθεκτικές συνδέσεις.** Κάντε διπλό κλικ σε μια σύνδεση. Τσεκάρετε το *Durable* και ζωγραφίζεται πιο χοντρή και μπλε, και ο κόμβος από τον οποίο ξεκινά παίρνει `ew_durable` στο αρχείο. Το σημάδι είναι στο ζεύγος κόμβων, οπότε ισχύει για κάθε σύνδεση μεταξύ τους. Είναι συνδεσμολογία προς το runtime, οπότε η σήμανση μιας δεν κάνει ποτέ επανεκκίνηση του κόμβου.

**Ομάδες.** Το Ctrl+G τυλίγει την επιλογή, το Ctrl+Shift+G τη διαλύει. Κάντε διπλό κλικ στη γραμμή τίτλου για να της δώσετε όνομα και χρώμα. Σύρετε μια ομάδα και ό,τι περιέχει πάει μαζί της. Σύρετε έναν κόμβο σε μία και μπαίνει, σύρετέ τον έξω και φεύγει. Οι ομάδες φωλιάζουν. Η διαγραφή μιας ομάδας διαγράφει ό,τι έχει μέσα, και το Ctrl+Z τα βάζει όλα πίσω.

**Η αναζήτηση** (Ctrl+F, ή το κουμπί) κοιτά σε όλες τις ροές και υποροές ταυτόχρονα: ονόματα, τύπους, id και κάθε ρύθμιση, ακόμη και μια γραμμή στη μέση του σώματος μιας συνάρτησης. Ένα αποτέλεσμα σάς πάει στη σωστή καρτέλα με τον κόμβο επιλεγμένο και στο κέντρο της προβολής. Εμφανίζονται και οι κόμβοι ρύθμισης, και το αποτέλεσμά τους ανοίγει το παράθυρό τους, αφού δεν έχουν θέση σε καμβά.

**Φιλτράρισμα αποσφαλμάτωσης.** Περιορίστε την πλαϊνή στήλη σε μια ροή, στους κόμβους που έχετε επιλέξει, σε μια λέξη ή μόνο στα σφάλματα. Ισχύει για ό,τι ήδη υπάρχει στο αρχείο καταγραφής, όχι μόνο για ό,τι φτάνει στη συνέχεια, οπότε ο περιορισμός δεν κάνει ποτέ τη γραμμή που κοιτούσατε να εξαφανιστεί.

Όλα αυτά πατιούνται με κλικ σε πραγματικό περιηγητή σε κάθε pull request, απέναντι στο πραγματικό δυαδικό με τον ενσωματωμένο επεξεργαστή. Αυτό περιλαμβάνει κάθε παράθυρο κόμβου που προσφέρει το runtime: η λίστα προέρχεται από το `GET /nodes`, οπότε ένας κόμβος που προστίθεται τον επόμενο μήνα είναι στο τεστ τον επόμενο μήνα χωρίς να χρειάζεται κανείς να θυμηθεί να τον προσθέσει. Γράφοντας αυτά τα τεστ βρήκαμε δύο πράγματα που δεν είχαν δουλέψει ποτέ στο Chromium: το διπλό κλικ σε έναν κόμβο για να ανοίξει το παράθυρό του και το σύρσιμο μιας σύνδεσης πάνω σε έναν κόμβο. Ο καμβάς κρατά τον δείκτη σε όλη τη διάρκεια του συρσίματος, οπότε ο στόχος του συμβάντος ήταν πάντα ο καμβάς και μια σύνδεση που αφήνονταν πάνω από έναν κόμβο δεν έβρισκε ποτέ τον κόμβο. Και τα δύο τόσο ντροπιαστικά όσο μπορούν να είναι τα σφάλματα σε έναν οπτικό επεξεργαστή. Και τα δύο διορθώθηκαν.

## Ροές ως κώδικας

Το αποθετήριο είναι το μέρος όπου οι ροές αναθεωρούνται, άρα το αποθετήριο πρέπει να μπορεί να τις αναπτύσσει. Κρατήστε το αρχείο ροής στο git, ρυθμίστε το πρόγραμμα οδήγησης διαφορών παραπάνω ώστε το pull request να διαβάζεται σαν αναθεώρηση, και αφήστε τη συγχώνευση να το αναπτύξει:

```bash
hotloop-flow export -o flows.json          # the live file, byte for byte, to commit
hotloop-flow deploy -file flows.json -note "PR #12: line 3 pressure check"
```

Το `deploy` εκτυπώνει τη διαφορά απέναντι σε ό,τι τρέχει, το ίδιο κείμενο όπως παντού, και μετά αναπτύσσει απέναντι στην αναθεώρηση από την οποία έγινε αυτή η διαφορά. Αν κάποιος αναπτύξει στο μεταξύ, είναι ένα 409 και ένα κόκκινο pipeline, όχι μια αθόρυβη αντικατάσταση. Το `-expect-rev` το καρφώνει στην αναθεώρηση απέναντι στην οποία έγινε ένα αναθεωρημένο σχέδιο, και το `-dry-run` εκτυπώνει τη διαφορά και δεν αναπτύσσει τίποτα. Ένα αρχείο χωρίς τίποτα να αλλάξει δεν αναπτύσσει τίποτα και δεν προσθέτει τίποτα στο ιστορικό, οπότε μια συγχώνευση που δεν άγγιξε τις ροές δεν γεμίζει το αρχείο καταγραφής. Ένας κόμβος που αποτυγχάνει να ξεκινήσει αναπτύσσεται και παρ' όλα αυτά αποτυγχάνει την εργασία, γιατί η υπόλοιπη ροή τρέχει και κάποιος πρέπει να κοιτάξει. Το `export -deployment 41` βγάζει οποιαδήποτε ανάπτυξη από το ιστορικό.

**Ένα pipeline δεν κρατά ποτέ κωδικό διαχειριστή.** Παίρνει ένα API token:

```bash
hotloop-flow token -name ci
```

εκτυπώνει ένα token, μία φορά, για το κρυφό αποθετήριο του pipeline, και το hash που δίνεται στο runtime: `HOTLOOP_FLOW_DEPLOY_TOKEN_HASH` για token ανάπτυξης, ή `auth.tokens` στο αρχείο ρυθμίσεων για οτιδήποτε άλλο. Το runtime κρατά πάντα μόνο το hash, όπως με έναν κωδικό. Ένα token ανάπτυξης μπορεί να διαβάσει τις ροές και να αναπτύξει, που περιλαμβάνει την επαναφορά, και τίποτα άλλο: ούτε ρυθμίσεις, ούτε inject, ούτε επεξεργαστή. Και οι δύο εντολές διαβάζουν το token από το `HOTLOOP_FLOW_TOKEN` (ή `-token-file`) και τη στιγμή από το `HOTLOOP_FLOW_URL` (ή `-url`), ποτέ token στη γραμμή εντολών, όπου θα κατέληγε στη λίστα διεργασιών και σε κάθε αρχείο καταγραφής pipeline που επαναλαμβάνει την εντολή. Το ιστορικό δείχνει το token ως αυτόν που ανέπτυξε, `token:ci`, με τη σημείωση που πέρασε το pipeline.

Τα διαπιστευτήρια δεν ταξιδεύουν ποτέ έτσι. Δεν είναι στο αρχείο ροής, οπότε μια ανάπτυξη από το git αφήνει κάθε κωδικό broker ακριβώς εκεί που ήταν.

## Ένας καθρέφτης git, αν θέλετε

Το αρχείο καταγραφής αναπτύξεων ζει στο μηχάνημα. Ένα αποθετήριο είναι το μέρος όπου κοιτάζουν ήδη όλοι οι άλλοι: έχει προβολή ιστού, blame, αντίγραφα ασφαλείας και ανθρώπους που ξέρουν να το διαβάζουν. Δείξτε το Flow σε ένα και κάθε ανάπτυξη γίνεται commit του αρχείου ροής σε έναν κλάδο όπου γράφει μόνο το Flow, **με συγγραφέα όποιον την ανέπτυξε**, την ώρα που την ανέπτυξε, με τη σημείωσή του ως μήνυμα:

```yaml
history:
  git:
    url: https://git.plant.example/line3/flows.git
    branch: main              # one nobody else pushes to
    path: flows.json
    emailDomain: plant.example  # dana deploys, the commit is from dana@plant.example
```

Ο κωδικός είναι ένα token πρόσβασης από τον διακομιστή git, και μπαίνει στο `HOTLOOP_FLOW_GIT_PASSWORD` από ένα Secret, ποτέ στο αρχείο (δουλεύουν και τα `HOTLOOP_FLOW_GIT_URL` και `HOTLOOP_FLOW_GIT_USERNAME`). Ένα URL με κωδικό μέσα απορρίπτεται κατά την εκκίνηση, ώστε το URL να μπορεί πάντα να καταγράφεται. Μόνο `http://` και `https://`: η εικόνα δεν έχει δυαδικό git για `file://` ούτε κλειδιά για `ssh://`, και ένας καθρέφτης που αποτυγχάνει σε κάθε push είναι χειρότερος από έναν που αρνείται να ξεκινήσει. Οι επαναφορές και οι βάσεις εκκίνησης λένε τι είναι στο commit, και κάθε commit φέρει ένα trailer `Flow-Deployment: N`, που είναι ο τρόπος με τον οποίο μια διεργασία που ξεκίνησε ξανά, ή μια της οποίας το clone σβήστηκε, συνεχίζει ακριβώς από εκεί που λέει το αποθετήριο ότι έφτασε, χωρίς διπλότυπο.

**Δεν καθυστερεί ποτέ μια ανάπτυξη.** Το push γίνεται στη δική του goroutine. Ένας διακομιστής git που είναι εκτός λειτουργίας, αργός ή αρνείται το push δεν κοστίζει τίποτα σε μια ανάπτυξη: τα commit περιμένουν σε ένα τοπικό clone κάτω από το `data/git-mirror` και φεύγουν στο επόμενο push που δουλεύει, με επανάληψη κάθε λεπτό. Το `GET /deployments` λέει πόσο έφτασε ο καθρέφτης και το τελευταίο σφάλμα, και το `hotloop_flow_git_mirror_behind_deployments` είναι ο αριθμός για τον οποίο να στήσετε ειδοποίηση. Δοκιμασμένο απέναντι στον δικό του smart-HTTP διακομιστή του git πίσω από basic auth: τρεις αναπτύξεις κάνουν τρία commit από τρεις συγγραφείς, ένα push που ο διακομιστής αρνείται περιμένει και φτάνει όταν σταματήσει να αρνείται, και μια ανάπτυξη με διακομιστή git που χρειάζεται δέκα δευτερόλεπτα για να πει όχι επιστρέφει σε χιλιοστά του δευτερολέπτου.

Είναι καθαρό Go (go-git), οπότε το δυαδικό μένει στατικό. Κοστίζει περίπου 3.8 MB δυαδικού, γι' αυτό μετριέται και δεν θεωρείται δεδομένο. Το δυαδικό ήταν 48,083,106 byte πριν από τους καταλόγους.
