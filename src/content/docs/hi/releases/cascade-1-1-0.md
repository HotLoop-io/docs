## यह क्या है

1.1.0 Cascade को एक MCP सर्वर देता है, वे स्क्रीन जो एडिटर में नहीं थीं, और साइन-इन को एडिटर में ले जाता है। इंजन, वर्कफ़्लो फ़ाइल फ़ॉर्मैट और REST API वही हैं जो 1.0.2 में थे।

## MCP सर्वर

यह `/mcp` पर है, API वाले ही पते पर, डिफ़ॉल्ट रूप से चालू आता है और लिखता है। HotLoop परिवार का हर MCP पढ़ता और लिखता है, और Cascade आख़िरी था जिसमें कोई MCP नहीं था।

एक एजेंट API कुंजी से साइन इन करता है और वह सब पाता है जो उस कुंजी का धारक कर सकता है, कुंजी के स्कोप तक सीमित। 79 टूल हैं, और हर एक REST API का एक रूट है: कॉल रूट के अपने हैंडलर से गुज़रती है, इसलिए अनुमति जाँच, वैलिडेशन, लिखना और ऑडिट पंक्ति रूट की ही हैं। MCP सर्वर में कुछ कॉपी नहीं किया गया, इसलिए कुछ अलग नहीं हो सकता, और कुछ छोड़ा नहीं गया, इसलिए कुछ छूटता नहीं।

- जो टूल कुछ बदलता है वह एक `reason` माँगता है, और ऑडिट लॉग उसे बदलाव के बगल में रखता है, कुंजी और क्लाइंट ने ख़ुद को जो नाम दिया उसके साथ।
- क्रेडेंशियल का सीक्रेट कभी वापस नहीं आता, किसी को भी नहीं। MCP से बनाए गए क्रेडेंशियल के सीक्रेट आते ही सील हो जाते हैं।
- `HOTLOOP_CASCADE_MCP` और `HOTLOOP_CASCADE_MCP_WRITES` डिप्लॉयमेंट के स्विच हैं, दोनों डिफ़ॉल्ट रूप से चालू। कोई टूल या API रूट इन्हें नहीं बदल सकता, इसलिए इंस्टेंस की सेटिंग्स बदल सकने वाला एजेंट भी राइट्स को दोबारा चालू नहीं कर सकता।
- जो रूट कुंजी को ख़ुद ठुकरा देते हैं (API कुंजियाँ, SCIM टोकन, सीक्रेट प्रदाता और लॉग गंतव्य बनाना) वे टूल नहीं हैं, क्योंकि कुंजियाँ बना सकने वाली कुंजी एक लीक हुई कुंजी है जो ख़ुद को ज़िंदा रखती है। MCP पेज उन्हें हर टूल और उसकी माँगी अनुमति के साथ सूचीबद्ध करता है।

## स्क्रीन

क्रेडेंशियल, प्रोजेक्ट, आपका खाता, और स्वामियों और एडमिन के लिए सेटिंग्स, उपयोगकर्ता और ऑडिट लॉग। हर एक API जैसी ही अनुमतियाँ मानती है: हर व्यक्ति को केवल वही दिखता है जो उसकी भूमिका अनुमति देती है, और बाकी सर्वर अब भी मना करता है।

- **क्रेडेंशियल** बनाए, खोले, बदले, दूसरे प्रोजेक्ट के साथ साझा किए और हटाए जाते हैं। सीक्रेट एक बार डाला जाता है और स्क्रीन सिर्फ़ बताती है कि वह सेट है।
- **प्रोजेक्ट** में सदस्य और उनकी भूमिकाएँ हैं, और सर्विस अकाउंट कुंजियाँ जिनसे कोई स्थायी इंटीग्रेशन साइन इन करता है, जो एक बार दिखाई जाती हैं।
- **खाता** आपकी API कुंजियाँ बनाता और रद्द करता है, जिनसे API और MCP साइन इन करते हैं, और आपका पासवर्ड बदलता है।
- **उपयोगकर्ता** लोगों को बनाता है और उन्हें बंद या चालू करता है। **ऑडिट लॉग** पढ़ा जाता है, फ़िल्टर किया जाता है और छेड़छाड़ के लिए जाँचा जाता है। **सेटिंग्स** में दूसरे फ़ैक्टर की अनिवार्यता और एरर वर्कफ़्लो है।

साइन-इन अब एडिटर का अपना पेज है, `/login` पर, एडिटर के रंगों में, लाइट और डार्क, फ़ोन पर भी और डेस्क पर भी। यह वह सब करता है जो पुराना पेज करता था: पहली बार का सेटअप, पासवर्ड, डायरेक्टरी खाते, सिंगल साइन-ऑन, पासकी, दूसरा फ़ैक्टर और रिकवरी कोड।

## सिर्फ़ amd64, और क्यों

यह रिलीज़ सिर्फ़ amd64 बनाता है। मल्टी-आर्च अपने अलग रन में आता है, इसलिए इसके बाद वाला रिलीज़ एक छोटा वर्ज़न बम्प है जो दोनों बनाता है। तब तक `stable`, `latest` और छोटे टैग इस amd64 इमेज को उस arm64 इमेज के साथ सूचीबद्ध करते हैं जिस पर वे पहले से इंगित थे, इसलिए arm मशीन अब भी खींच सकती है। वर्ज़न टैग, `1.1.0`, सिर्फ़ amd64 है।

## अपग्रेड, और वापस जाना

कोई माइग्रेशन नहीं। 1.1.0 पर `helm upgrade` करें, या `:stable` को Quadlet यूनिट आगे बढ़ाने दें। 1.0.2 वापस रखना सुरक्षित है, क्योंकि डेटाबेस में कुछ नहीं बदला। रोलबैक जो नहीं उलट सकता वह है जो कोई एजेंट पहले ही कर चुका है: उसके बदलाव हो चुके रहते हैं, और उसकी लिखी ऑडिट पंक्तियाँ एक्टर प्रकार `mcp` के साथ लॉग में रहती हैं। किसी भी अपडेट से पहले बैकअप लेना अब भी अच्छी आदत है।
