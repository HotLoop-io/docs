Cascade प्लांट को बाकी सब कुछ से बात करवाता है। कोई अलार्म, वेबहुक, शेड्यूल, नई पंक्ति या MQTT की बौछार आइटमों का एक बैच बन जाती है, और ये आइटम ऐसे स्टेप से गुज़रते हैं जो असली क्रेडेंशियल के साथ असली सिस्टम को कॉल करते हैं। अगर कोई API बंद हो या बीच में बॉक्स रीबूट हो जाए, तब भी काम पूरा होता है, क्योंकि हर स्टेप का चेकपॉइंट बनता है और रीट्राई डेटाबेस की एक पंक्ति है।

यह एक स्टैटिक Go बाइनरी है। Raspberry Pi पर SQLite, या k3s पर जितने चाहें उतने वर्कर के साथ Postgres। कतार भी Postgres ही है, इसलिए प्लांट क्लस्टर पर संभालने के लिए कोई Redis नहीं है।

## यह क्या नहीं करता

**यह आपके उपकरणों पर नहीं लिखता।** Cascade पढ़ता है और सब्सक्राइब करता है। वाल्व हिलाने या सेटपॉइंट बदलने वाली हर चीज़ HotLoop के राइट गेट से गुज़रती है, इसलिए गेट का ऑडिट हर लिखाई को देखता है, चाहे उसे किसी भी वर्कफ़्लो ने शुरू किया हो। PLC तक पिछला दरवाज़ा रखने वाला वर्कफ़्लो इंजन वही तरीका है जिससे ऑडिट ट्रेल ईमानदार नहीं रह जाता।

**यह आपके फ़ील्ड में JavaScript नहीं चलाता।** फ़ील्ड एक्सप्रेशन expr इस्तेमाल करते हैं, वही छोटी भाषा जो HotLoop के ऑटोमेशन इस्तेमाल करते हैं। वह OS, नेटवर्क या फ़ाइलसिस्टम को छू नहीं सकती और हमेशा खत्म होती है। JavaScript सिर्फ़ एक जगह रहता है, Code स्टेप, और वह एक अलग बंद प्रोसेस में चलता है जिसमें कोई सीक्रेट, नेटवर्क या फ़ाइलसिस्टम नहीं होता। इसे हर दूसरे फ़ील्ड से बाहर रखने से रिमोट कोड एक्ज़ीक्यूशन भी उनसे बाहर रहता है।

**यह किसी चीज़ पर ताला नहीं लगाता।** SSO, ज़बरदस्ती MFA, RBAC, ऑडिट, वर्शन इतिहास, सीमित दायरे वाली API कुंजियां और HA वर्कर, सब एक ही बाइनरी में हैं। कोड में कहीं भी लाइसेंस जांच नहीं है।

**यह कहीं रिपोर्ट नहीं भेजता।** कोई लाइसेंस सर्वर नहीं, क्लाउड पर कोई निर्भरता नहीं। टेलीमेट्री अपनी मर्ज़ी से चालू करनी होती है, डिफ़ॉल्ट रूप से बंद रहती है, और आने पर हर फ़ील्ड तक दस्तावेज़ में दी जाएगी।
