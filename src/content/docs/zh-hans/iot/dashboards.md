仪表板是某个人搭建的一页卡片。可以放仪表盘、趋势、实体列表、启动水泵的按钮，还有把各区温度摆在对应位置的平面图。工厂需要多少就建多少，把每一个交给需要它的角色，或交给它所在的那块屏幕，原来的 Board 只是其中之一。

HotLoop IoT、Edge 和 Gateway 中都有。Edge Relay 没有界面，也就没有仪表板。Edge HMI 完全由这一页搭成，其余部分之所以是现在这个样子，原因就在这里。

## 为什么这样设计

**卡片不下任何命令。** 设计任何一页按钮时，第一个问题是这一页会不会成为运行工厂的第二条通道。不会。卡片只指向一个变量、实体、脚本或配方，浏览器对它们的处理与其他所有屏幕完全一样。写入按钮发送 `POST /api/write`。实体的控件调用 `POST /api/services`。脚本按钮打开脚本屏幕的运行确认框，配方卡片打开配方屏幕的应用抽屉。每一个都有各自的权限，也要经过写入闸门，所以仪表板也不可能成为绕过的办法。`dashboards.write` 管的是由谁来决定按钮是什么，这是工程师的决定，与编写脚本同理，只有管理员可以做。

结果是：管理员保存的仪表板在操作员按下东西之前什么都不会做，而按下之后发生的事，与在其他任何屏幕上按下完全一样，连审计记录的那一行也一样。

**布局是流，不是坐标。** 卡片按阅读顺序排列。每张卡片只说明在十二列中占多宽、占多少行高，并不知道自己会落在哪里。面板电脑上是十二列，旁边开着另一个窗口的笔记本上是六列，平板上是两列，手机上是一列。按像素位置排的布局，只在画它的那块屏幕上才是对的，而 Edge HMI 必须在机器配的任何屏幕上都是对的。

结果是：没有人需要搭建手机版。根本没有手机版。

**保存要注明版本。** 交接班时两个人同时编辑一个仪表板，是会发生的事。保存时带着打开时的 `version`，过期的保存会被 `409` 拒绝，并说明是谁先保存的。否则第二个按下保存的人，就会在双方都没看见的情况下，删掉第一个人一下午的工作。

## 模型

```json
{
  "id": "line-2",
  "name": "Line 2",
  "description": "The extruder, for the floor.",
  "kind": "cards",
  "roles": ["operator", "admin"],
  "homeFor": ["operator"],
  "screens": ["line-2-panel"],
  "position": 1,
  "version": 3,
  "cards": [
    {"id": "temp", "type": "gauge", "title": "Zone 1", "w": 3, "h": 3,
     "config": {"tag": "press-01/Zone1_Temp"}},
    {"id": "go", "type": "button", "w": 3, "h": 1,
     "config": {"tag": "line-02/Speed", "value": 250, "label": "Run at 250", "confirm": true}}
  ]
}
```

- **`id`** 由小写字母、数字、连字符和下划线组成，以字母开头。它在地址里，永不改变。`wall` 是墙面看板的 id。
- **`kind`** 是 `cards`，墙面看板则是 `wall`。
- **`roles`** 是可以使用该仪表板的角色。为空表示所有角色。持有 `dashboards.write` 的人无论如何设置都能看到所有仪表板，因为他们必须能修好别人打不开的那个。未获提供的角色按名称请求时会得到 `404`，所以查看者无法通过询问得知有哪些仪表板。
- **`homeFor`** 是角色在不指定地址进入时打开的仪表板。一个角色最多一个，该仪表板必须提供给把它当作主页的角色。
- **`screens`** 是它所属的物理屏幕。一个屏幕名只属于一个仪表板。
- **`position`** 决定切换栏的顺序。新建的排在最后。
- **`cards`** 按阅读顺序，每个仪表板最多 60 张，全部合计 2 MB。
- **`version`** 每保存一次加一。

一张卡片包含 `id`（在仪表板内唯一，由页面生成）、`type`、可选的 `title`、`w`（1 到 12）、`h`（1 到 8），以及随类型而变的 `config`。省略 `w` 和 `h` 时使用该类型的默认值。config 会被严格检查：类型中没有的键是错误，存储的内容会补全所有默认值。卡片所指的变量、实体、脚本或配方不存在时，保存仪表板会被拒绝。按钮所指的变量没有标记为可写，或者按钮的数值超出变量的范围，同样被拒绝：闸门会拒绝每一次按下，这件事应该让搭建的人听到，而不是让按按钮的人听到。

## 卡片

| 类型 | 说明 | 配置 | 默认大小 |
|---|---|---|---|
| `status` | 在线设备、上报的变量、报警、历史数据库、运行时间：Board 的状态条 | 无 | 12 x 1 |
| `gauge` | 把一个变量显示成 Board 的表盘，标出量程和报警限值 | `tag` | 3 x 3 |
| `value` | 把一个变量显示成大数字，按报警状态着色 | `tag`, `decimals` | 3 x 2 |
| `trend` | 最多六个变量，范围从 15 分钟到一周 | `tags`, `minutes`, `labels` | 6 x 3 |
| `entities` | 您选的实体，以各自带控件的磁贴显示 | `entities` (最多 30 个) | 6 x 3 |
| `alarms` | 报警列表，有权限的人可以确认 | `outstanding`, `limit`, `devices`, `equipment` | 6 x 3 |
| `button` | 经确认后，向一个变量写入一个值 | `tag`, `value`, `label`, `confirm` | 3 x 1 |
| `script` | 通过脚本屏幕的确认框运行一个脚本 | `script`, `label` | 3 x 1 |
| `recipe` | 在最多八个配方中选一个，并打开它的应用抽屉 | `recipes` | 4 x 2 |
| `markdown` | 文本：标题、列表、粗体、斜体、代码、http(s) 链接 | `text` | 4 x 2 |
| `camera` | 定时刷新的快照，或动态 JPEG 流 | `url`, `stream`, `refreshSec` | 6 x 4 |
| `map` | 放有实时变量的平面图 | `image`, `markers` | 6 x 5 |
| `setpoint` | 为一个变量输入的数值，带限值、单位和确认，并显示设备回报的值 | `tag`, `label`, `min`, `max`, `step`, `unit`, `decimals`, `confirm` | 3 x 3 |
| `symbols` | 一台机器的图：符号按像素放在背景上，根据各自的变量绘制 | `image`, `width`, `height`, `symbols` | 8 x 5 |

几个不太直观的卡片，有些事值得了解：

- **`button`** 按保存时的类型发送 `value`。数字就是数字，`true` 是布尔值，字符串是文本。在 PLC 上 `1` 和 `1.0` 是不同的写入，闸门按 JSON 类型判断，所以卡片不会把其中一个变成另一个。`confirm` 默认开启，除非关掉。开启时会询问“这会命令真实设备”，并显示当前值和一条进入审计记录的原因（留空则记为 `dashboard <id> / <card>`）。关掉它适用于按住按钮本身就是目的的面板，这是工程师的决定，设置屏幕里的“写入前确认”会把它重新覆盖为开启。
- **`alarms`** 默认列出整个工厂的报警，除非您指定了范围。`devices` 是设备 id 的列表。`equipment` 是来自 `GET /api/equipment` 的设备节点 id 列表，任何层级都可以（厂区、区域、产线、单元），一个节点代表放在它位置及其下面的所有设备，所以某个区域的页面可以只显示该区域的报警。两者都填时，只要报警属于其中任何一个就会列出。省略或留空，这张卡片就是整个工厂，这些字段出现之前保存的所有卡片都是这样。数量上限计算的是过滤之后剩下的。`outstanding` 仍然会去掉已恢复正常并已确认的报警。限定在一个没有报警的地方的卡片会写“此处无”，这样没人会把它读成工厂很安静；设备被删除之后的卡片会说明这一点，而不是显示一个空列表。设备以节点的 id 存储，所以重命名或移动节点不会破坏卡片。设备或节点不存在时，保存仪表板会被拒绝。在构建器里您输入路径（`Plant 2 / Scrubbers / Kettle 3`），它保存 id。这张卡片读取设备树，所以角色需要 `equipment.read`（操作员和查看者有）。

  ```json
  {
    "id": "kettle-alarms", "type": "alarms", "title": "Scrubber alarms", "w": 6, "h": 3,
    "config": { "outstanding": true, "limit": 10, "equipment": [14], "devices": ["oven-1"] }
  }
  ```
- **`trend`** 画出您请求的时间窗口，终点是现在，而不只是读数碰巧覆盖的那一段。`minutes: 480` 是最近八小时的坐标轴，每个整点有一个刻度，按查看者所在的时区显示。没有变化的变量是停在最后一个有效读数上的一条水平线，因为停转的磨机或关闭的阀门看起来就是这样；而历史数据库只在数值越过死区时才记录一个读数，所以窗口内可能只有一个读数，也可能一个都没有。线上没有任何编造的东西。窗口开始时变量保持的值，是它之前最后一个有效读数（`GET /api/history` 用 `carry=true` 说明这一点），线从窗口开始到窗口内的第一个读数，都是这个值。最后一个读数之后，线延续到最后一次收到该变量消息的时间，绝不超过现在。第一个有人拿到的读数之前没有线，而窗口之前最后一个读数是无效的变量完全没有延续的值，因为它当时保持什么值是不知道的。一段无效读数就是一个缺口，和以前一样。只有一个读数时，是一条延伸到现在的线，没有地方可画时则是一个点。

  图例用变量自己的名称标注每条线，与数字卡片显示的名称相同，前面不带设备。来自不同设备的两条同名线会保留完整 id，以便区分。`labels` 是一个可选对象，从 `tags` 中的变量映射到您想显示的文本，1 到 80 个字符，对没有绘制的变量设置标签会被拒绝。悬停提示里始终在标签旁边显示完整的 id。

  ```json
  {
    "id": "mills", "type": "trend", "title": "Mill temperatures", "w": 6, "h": 3,
    "config": {
      "tags": ["plant-5-temperatures/Large Sand Mill Temperature", "plant-5-temperatures/Small Sand Mill Temperature"],
      "minutes": 480,
      "labels": { "plant-5-temperatures/Large Sand Mill Temperature": "Large mill" }
    }
  }
  ```
- **`camera`** 在浏览器里而不是在服务器上加载该地址。卡片的 config 对每个打开仪表板的角色都是可读的，所以带有登录信息或令牌的地址在保存仪表板时会被拒绝。请使用工厂网络中不需要登录的地址，或者使用代为添加登录的代理。静态画面每隔 `refreshSec` 秒用一个 `_hl` 查询参数重新获取，这样浏览器就不会一直显示第一张。
- **`map`** 是一张图片加上标记。图片是 http(s) 地址，或上传到卡片里的文件（png、jpeg、webp 或 gif，最大 500 KB，存在卡片里）。标记是变量，按图片宽度和高度的百分比放置，所以在任何大小下都停在放置的位置。这是平面图，不是街道地图：瓦片地图需要互联网上的瓦片服务器，而工厂的面板电脑通常连不上。
- **`setpoint`** 用于有人输入的数值：温度、速度、液位。输入框知道变量的单位（或卡片的 `unit`）及其限值：`min` 和 `max` 一起给出，卡片没有给出时用变量自己的量程。卡片只能收窄变量的量程，不能放宽，因为无论卡片怎么说，写入闸门都会拒绝超出变量量程的值；提供更宽范围的卡片在保存仪表板时被拒绝，针对保存文本或开关的变量的卡片也一样（这些请用 `button`）。超出限值、不符合 `step` 或不是数字时，输入框下方会这样提示，**Set** 保持关闭。**Set** 会先询问，显示当前值和一条进入审计记录的原因（除非该卡片在构建时关掉了 `confirm` 且设置没有覆盖它），然后通过 `POST /api/write`：总写入开关、变量的可写标志、角色的权限和审计行，都与其他所有写入相同。接着卡片会等设备的读数显示出这个值，再多观察两秒，并说明设备现在保持的值：“从设备读回 70 C：就是发送的值”；或者，如果 PLC 接受了写入又把它拉回到自己的限值，“设备接受了 70 C，随后改成了 60 C”；或者，如果读数始终没有显示它，“设备报告的是 60 C，不是 70 C”。“设备中现在的值”这一行始终是实时读数，所以 PLC 程序之后覆盖这个值也能看到。当设备没有有效读数时（PLC 关机或无法连接），输入框和 Set 都关闭，卡片会说设备没有应答，因为写入只会被拒绝。
- **`symbols`** 是一台机器的图。`width` 和 `height` 是页面自身的像素尺寸（省略则为 800 x 450），`image` 是可选的背景（http(s) 地址，或上传到卡片里的图片，与 `map` 相同），`symbols` 是从左上角起按像素放置的项目列表：`{"id": "p1", "type": "pump", "x": 120, "y": 300, "tag": "plc/bPumpRun"}`。页面作为一幅缩放的图绘制，所以无论卡片多大、在手机上，每个符号都保持在原位。类型有 `pump`、`motor` 和 `fan`（变量为开时转动）、`valve`（开或关）、`tank`（在 `min` 和 `max` 之间填充，或按变量的量程，或 0 到 100）、`heater` 和 `lamp`（开时点亮）、`pipe`（其可选变量为开时，管内流动）、`readout`（数字，带 `unit` 和 `decimals`）以及 `label`（固定文本）。`invert` 把变量反过来读，指示灯的 `tone`（`ok`、`warn`、`bad` 或 `info`）是点亮时的颜色：运行灯是绿色，故障灯是红色，变量只决定它是否点亮。符号除了颜色，还用文字说明状态（说明文字和标题）；变量处于报警或刚从报警恢复时画成红色或暖色，变量没有有效读数时变淡并显示“无读数”。当人们要求系统减少动态效果时，动画会停止。这些符号是 HotLoop 为 HotLoop 画的，没有借用任何别人的。带变量的符号被点击时会打开该变量，就像平面图上的图钉。它不下任何命令：要下命令，请在旁边放一张 `setpoint` 或 `button` 卡片。在构建器里，可以用指针拿起并移动符号，或用方向键（Shift 一次移动十个像素），也可以直接输入像素数值。
- **`markdown`** 构建为 DOM 节点，从不构建为 HTML，所以输入的任何内容都不可能变成标记或脚本。
- **`gauge`、`value`、`map`、`setpoint`** 在仪表板保存之后其变量被删除时，会显示“此网关上已不存在”，而不是一个永远不动的表盘。

## 墙面看板

墙面看板是仪表板 `wall`，kind 为 `wall`。它始终存在，不能删除，也没有卡片：它的仪表盘是固定在 Board 屏幕上的变量，保存在看板自己一直以来的设置里。`GET` 和 `PUT /api/board`、`#board` 地址、固定变量的选择器和拖动排列都保持不变。

成为仪表板带来的好处，是切换栏（它是每个仪表板上的第一个标签，Board 上也有这个栏）和分配：它可以提供给部分角色，可以成为某个角色的主页，也可以属于某块物理屏幕。墙上的电视打开 `/?screen=wall-tv`，得到的是没有页眉和标签页的 Board。

## 角色和屏幕

**按角色。** `roles` 决定向谁提供仪表板。`homeFor` 决定角色落在哪里。主页为 `line-2` 的操作员打开 HotLoop 时看到的是 2 号线。地址中带有 URL 片段（`#alarms`）时，页面会打开到地址指定的位置。

**按屏幕。** 屏幕是一台物理显示器。用 `/?screen=<name>` 打开 HotLoop，就会显示 `screens` 中带有该名称的仪表板，没有页眉，没有标签页，触控目标更大，因为走过面板电脑的人用不着一个退出页面的入口。没有任何仪表板使用的名称，会明确说明这一点，而不是显示别的东西。

**面板让人登录，而不是让面板自己登录。** 没有人登录时，它只显示一个“PIN 或工牌”输入框。操作员输入 PIN，或刷工牌（键盘仿真读卡器会把号码输入到框里），面板就会打开仪表板。他们的姓名和 **退出登录** 按钮在角落里，因为本来显示它们的页眉已经没有了。该仪表板上按钮的每一次写入，都以这个人的身份经过写入闸门，审计记录和日志簿里记的是他们的名字：“olga 向 line-02/Speed 写入 250”，而不是“panel-3”。无人触碰屏幕十五分钟后（可设置），面板会让他们退出登录并回到输入框，之后发出的写入会被拒绝。管理员在 **设置，用户** 中给每个人一个代码。完整内容，包括工牌是什么、代码如何存储以及它不做什么，见[认证与用户](/zh-hans/iot/authentication/#自助终端面板pin-或工牌以及空闲退出)。

在您自己的电脑上，这些都不适用：您用密码登录，按钮的写入直接通过闸门并记在您名下，也没有空闲退出。以前在有 PIN 之前不得不采用的做法，即用一个固定的操作员账号登录的面板，仍然可用，并且仍以该账号写入。不要给共享面板这样的登录。

Edge HMI 就是这样：一个设置了 `screens` 的仪表板，放在打开那个地址的机器上，面前的人用 PIN 或工牌登录。

## 搭建

持有 `dashboards.write` 的人（管理员）会在仪表板上看到 **编辑**，在栏里看到 **新建仪表板**。编辑时：

- 卡片是惰性的，所以抓住按钮去移动它不会按下它；
- 把一张卡片拖到另一张上就放到那里，或使用卡片工具栏上的箭头，手机用的就是这个，因为触摸屏不会启动拖动；
- 拖动角落来调整大小：宽度吸附到十二列中的一列，高度吸附到一行；
- 齿轮编辑卡片，复制按钮复制它，叉号删除它；
- **设置** 是名称、提供给谁、对谁首先打开、它的物理屏幕以及在切换栏里的位置。

点击 **保存** 之前什么都不会保存。**放弃** 会丢弃更改。保存时出现 `409` 表示有人先保存了：页面会提议载入他们的版本。

**导出**（在编辑旁边）把屏幕上的仪表板保存为文件，**导入**（在栏里新建仪表板旁边，供持有 `dashboards.write` 的人使用）把文件载入这个安装，所以一块屏幕就是客户的数据，可以在不同安装之间移动，无需任何人重新搭建。见[屏幕文件](/zh-hans/iot/screen-file/)。

## 布局

| 宽度 | 列数 | `w` 的卡片占用 |
|---|---|---|
| 超过 1100 px | 12 | `w` |
| 700 到 1100 px | 6 | `w` 的一半，向上取整 |
| 480 到 700 px | 2 | 一列，`w` 超过 4 时占两列 |
| 低于 480 px | 1 | 全部 |

宽布局上行高 76 px，间距 16 px。在手机上，卡片的高度由内容决定，并有一个来自行数的下限，所以不会有东西被截掉。切换栏在自身内部横向滚动，页面永远不会横向滚动。

## 在手机上

网页界面可以安装到手机上，没有连接时也能打开。它是同一个页面，加上清单文件、图标和 service worker，由 HotLoop 自己提供，所以服务器上不用构建任何东西，也不用安装任何东西。

**安装。** 在 Android 上，Chrome 菜单里有 **安装应用**。在 iPhone 上，Safari 的分享菜单里有 **添加到主屏幕**。它以全屏打开，显示工厂的名称，在 Android 上长按图标可以直接进入报警和仪表板。浏览器只会在 **https** 或 `localhost` 上安装页面并运行 service worker。在工厂普通的 `http://` 地址上，HotLoop 仍然像以前一样在标签页里打开，但不能安装，也不能离线工作。请在手机前面放一个证书（用您已有的入口或反向代理）。浏览器无法安装时会告诉您原因：Chrome 开发者工具，Application，Manifest。

**它保存什么。** 页面本身，以及人们查看的各类读取的最后一次回应：报警列表、仪表板、读数和实体状态、设备和变量、状态、设备树和看板。页面打开并连接期间，它每分钟请求一次这些内容，这样打开时就有东西可看，手机放在口袋里时则不请求。没有连接时打开，页面会加载，报警列表和仪表板显示手机上次看到的内容，底部有一条横栏说明这一点，并附上时间：

```
Offline. This is what this phone last saw as of 10/22/2026, 05:42:23. Nothing you
do here is sent until the connection is back.
```

连接恢复后几秒内，这条横栏消失，屏幕用实时回应刷新，实时推送重新连接。

**离线且从未登录。** 装了应用但没有登录的手机（从没登录过，或已退出登录，这会清空它保存的内容），在没有连接时没有东西可显示，所以它显示登录屏幕并说明原因：从这里 HotLoop 没有应答，而它会不断重试。HotLoop 一应答，页面就自动重新加载进入真正的登录。它绝不会显示一个什么内容都没有的应用。

**它绝不做的事。** 任何会改变东西的操作，都不会从离线页面发出。写入，无论是向变量写值、脚本、配方还是确认，都会在离开页面之前被拒绝，并附上原因：

```
You are offline, so nothing was sent. Everything here is as of 10/22/2026, 05:42:23.
Try again when the connection is back.
```

service worker 不会应答、保存或排队任何写入，其中也没有后台同步。给设备的命令，只会由看着实时回应的人发出，没有连接时按下的按钮不会在某处等着以后发出去。从通知里确认是另一回事，同样需要网络：ntfy 应用按的是它自己的按钮。

**它不保存什么。** 实时推送、趋势和历史、日志簿、设置、用户、升级策略，以及与通知有关的一切。有些太大，而且每次都不同，不值得保存，有些包含不该放在手机缓存里的东西（人们的 ntfy 主题、账号），所以这些屏幕需要 HotLoop 应答。

**在手机上。** 保存的内容放在那部手机的浏览器缓存存储里，最多 200 条回应，最旧的先丢弃。**退出登录会清空它**，会话过期或被撤销也会（第一个 `401` 就清空）。只有已登录的会话才会被保存，所以离线的手机绝不会打开别人的数据。新的 HotLoop 版本有自己的页面缓存，旧的会被删除；有连接时页面总是实时获取，所以新版本或改名后的工厂在下次打开时就会显示。

同一项测试会把服务器拿掉，页面和 worker 都一样，然后重新加载：页面能打开，报警列表和仪表板显示保存的内容，对变量的写入和确认都被拒绝，连接恢复后报警仍是未确认状态、写入审计为空，退出登录会清空保存的内容。在裸机上运行（2026-11-17），包括安装到真实的手机、iPhone 上的 Safari，以及真实工厂 Wi-Fi 掉线的情况。

## 权限

| 权限 | 查看者 | 操作员 | 管理员 |
|---|---|---|---|
| `dashboards.read` | 是 | 是 | 是 |
| `dashboards.write` | 否 | 否 | 是 |

读取是每个角色都有的，按 `roles` 过滤。写入归管理员。按下卡片时能做什么，取决于按下者自己的权限：查看者看到的写入按钮是禁用的，即使绕过了这一点，服务器也会拒绝。

## API

| 方法 | 路由 | 权限 |
|---|---|---|
| `GET` | `/api/dashboards` | `dashboards.read` |
| `POST` | `/api/dashboards` | `dashboards.write` |
| `GET` | `/api/dashboards/{id}` | `dashboards.read` |
| `PUT` | `/api/dashboards/{id}` | `dashboards.write` |
| `DELETE` | `/api/dashboards/{id}` | `dashboards.write` |
| `GET` | `/api/dashboards/{id}/export` | `dashboards.read` |
| `POST` | `/api/dashboards/import` | `dashboards.write` |

带请求体和错误的参考在 [HTTP API](/zh-hans/iot/api/#仪表板) 中。每一次创建、保存和删除，都会作为对主体 `dashboard:<id>` 的 `config` 事件记录在案，所以日志簿能说明是谁改了面板上显示的内容。

这张表是 `dashboards`，在 PostgreSQL、TimescaleDB 和 SQLite 的迁移 0023 中添加。它只增不减（[迁移只增不减](/zh-hans/iot/migrations/)）。墙面看板的行不是由迁移创建的，而是应用程序在第一次被请求时创建的，所以从仪表板出现之前的备份恢复的数据库，也会重新得到它。

## 这里没有的

- **精确到像素的布局。** 是有意的，见上文。如果某台机器的 HMI 确实需要一个控件固定在某个位置，那就是专门为那台机器做的屏幕，不是这里要做的。
- **按卡片设置可见性。** 仪表板提供给角色，卡片不是。两类读者要看不同的卡片，就是两个仪表板。
- **瓦片地图。** 见 `map` 卡片。
- **按住按钮。** 按钮按下时写入一次。按下时写入、松开时再写入的瞬时控件是另一种卡片，目前没有。
- **Edge Relay 中的仪表板。** 它没有界面。
