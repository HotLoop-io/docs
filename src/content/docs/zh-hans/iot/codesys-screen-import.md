您的操作员已经有一个 CODESYS 画面。从 IDE 导出，导入 HotLoop，它就会作为 HotLoop 画面打开，使用同一台 PLC 的变量。这是告别 WebVisu 的途径：PLC 继续运行自己的程序，HotLoop 通过 OPC UA 连接器读取它，画面则属于 HotLoop。HotLoop for CODESYS 运行 Edge，所以这也是它的导入。

## 使用方法

在 CODESYS IDE 中，在项目树里选中该可视化，使用**项目、导出**（CODESYS 原生导出，生成 `.export` 文件）。不要用**导出 PLCopenXML**：那个文件里没有可视化，如果您选了它，HotLoop 会这样告诉您。

在仪表板界面选择**导入**，选择 `.export` 文件，再点**读取文件**。它会告诉您：

* 找到的可视化（如果文件里有多个，会问您选哪一个），
* 画面读取而本安装中没有的每个变量。这些变量以 `plc/<GVL>.<variable>` 的形式到来：把设备 `plc` 映射到 PLC 所在的 HotLoop 设备，所有变量一次就迁移过去，也可以逐个映射变量，
* **值得一看**：它无法放到画面上的每个元素及原因，在保存任何内容之前列出。

只要还有阻碍，就不会保存任何东西。导入需要 `dashboards.write`，对未标记为可写的变量设置按钮或设定值会在这里被拒绝，与搭建时一样，所以画面上永远不会有关口会拒绝的控件。

通过 API 是 `POST /api/dashboards/import`，用 `codesys`（文件的文本）代替 `file`，并用 `visualization` 在多个中指定一个：

```json
{"codesys": "<ExportFile>...", "visualization": "Overview", "dryRun": true,
 "remap": {"devices": {"plc": "line-3"}}}
```

报告里有常见的 `problems`、`warnings` 和 `remapped`，以及一个 `conversion`，其中 `mapped` 列出每个元素及其变成了什么，`unmapped` 列出每个元素及未能转换的原因。

## 能转换的内容

| CODESYS 元素 | 在 HotLoop 中 |
|---|---|
| 矩形、圆角矩形、带文字和变量的椭圆（`Temperature: %2.1f C`） | 一个读数：变量的变量名，其前的文字作为标题，其后的文字作为单位，小数位数来自格式 |
| 同样的图形，有文字但没有变量 | 一个标签 |
| 指示灯 | 一个指示灯，由变量点亮，并按指示灯自己的颜色着色（红色是故障，黄色是警告，蓝色是信息，其他是运行灯）。`NOT x` 把变量反着读 |
| 仪表、电位器 | 变量的读数。用来设定数值的旋钮还会得到一张设定值卡片，以表盘的刻度作为限值 |
| 跷板开关、拨动开关、按钮 | 一个显示状态的指示灯和一张按钮卡片：拨动开关是开和关，点按是那一个值 |
| 多边形、折线，以及没有文字也没有变量的形状（管道、容器、边框） | 符号后面的图形，根据它们的点和颜色绘制 |
| 组 | 它的成员，从组的角点开始放置 |
| 元素的 **Invisible** 变量（`bInvisible`），或其所在组的变量 | 符号上的 `show` 规则：只有在变量表明该元素应当可见时才绘制（`NOT x` 会将其反转） |
| 元素的 **Toggle color** 变量 | 符号上的 `colors` 规则：变量开启期间，符号以最接近元素自身报警颜色的色调着色（红色是 `bad`，黄色和橙色是 `warn`，蓝色是 `info`，绿色是 `ok`；没有自身报警颜色的元素是 `bad`，因为 CODESYS 默认的报警边框是红色） |

每个元素都保留它的像素位置：页面就是符号卡片，绘制为一张缩放图，因此画面在任何尺寸下以及在手机上都保持形状。

## 无法转换的内容

导入时会说明，每项一行，绝不会悄悄丢弃：

* 没有 HotLoop 符号的元素类型（趋势图、表格、滑块、图像元素，以及工具箱里的其余部分），
* 作为表达式的变量（`Temp * 2`、`a AND b`、数组元素）：HotLoop 显示的是变量，所以请为表达式添加一个变量，并让读数指向它，
* 绘制在背景图片中的形状（管道、容器、边框）上的不可见或切换颜色变量：图片是一张图像，因此形状始终存在并保持其颜色。会在导入结果中连同变量一起说明，
* 任何其他由 PLC 值驱动的设置（用于填充、边框或文字的颜色变量、移动、闪烁、文本列表）：符号保持绘制时的样子，当其变量是普通变量时，会报告该规则，
* 贝塞尔曲线绘制为各点之间的直线，旋转过的元素不会被旋转，
* 页面大小，因为导出文件中没有：页面大小等于最外层元素的大小再加上边距，
* 超过 40 个字符的文字会被截断，表盘是数字，而不是表盘。

CODESYS 样式的文字样式、字体和颜色是 HotLoop 的：画面跟随 HotLoop 的主题。

## 它如何读取文件

CODESYS 说明了原生导出存在并且是 XML，但没有说明其中有什么。这里的读取器遵循 IDE 自己写出的内容（CODESYS 3.5 SP22，Visualization 4.10）：每个元素把其设置存为带编号的成员列表，编号是该成员在元素描述中的路径的 CRC-32，例如 `m_StaticPosition.iX`，由 IDE 安装在自己旁边。IDE 自己的元素树列出了每条路径及其 id（`ITypeNode.CompletePath` 和 `CRCIdNumber`）；不可见变量（`m_pStateVariables..State.bInvisible`，2880254039）和切换颜色变量（`m_pColorVariables..ToggleColor`，1999528970）的 id 就来自那里，前者正是 CODESYS Refrigerator 示例用来存储其组的 `NOT Glob_Var.DoorOpen` 的 id。测试中包含从 IDE 自己的导出读取的值。带有变量但未被读取的设置会如上所述被报告，所以界面绝不会在不完整时被当作完整导入。

## 下一步

打开画面，对照工厂检查读数，把设定值卡片和按钮卡片放到操作员期望的位置。从这里开始，手工搭建的画面和导入的画面就是同一回事：它可以导出为[画面文件](/zh-hans/iot/screen-file/)，每次保存都会生成新版本，也能用同样的方式转到另一个安装。

## TwinCAT 可视化（.TcVIS）

TwinCAT 的 `.TcVIS` 文件是 IDE 对象归档 XML 中的同一种可视化，元素类型和成员 id 都相同，所以它经过同一个转换器。已用真实的 TwinCAT PackML 示例检查过。

- 按钮：按钮输入动作中的每个普通赋值（`X := 5`、`X := TRUE`、`X := E_PMLCommand.ePMLCommand_Start`）都会变成一张按钮卡片，把该值写入 X，标题作为标签带过来。配置了的 Toggle 输入会变成一对按钮，开和关。比赋值更复杂的代码（条件、调用、运算）会连同其文本一起被报告。
- 枚举：OMAC PackML 成员（`E_PMLCommand`、`E_PMLUnitMode`）是已知的，编号取自 Beckhoff 的 PackML_HMI_Example 配置和 SPT-Libraries 的 `E_PMLUnitMode` 声明。任何其他枚举放进导入的 `enums`（`{"E_Own.eOwn_Go": 7}`）。没有已知编号的成员按其名称写入，报告会说明这一点。
- 表达式：指示灯的变量和不可见变量可以是一个变量与数字、TRUE、FALSE 或枚举成员的比较（`=`、`<>`、`<`、`<=`、`>`、`>=`），以及 NOT、AND 和 OR，可带括号。它们会变成符号规则（参见 DASHBOARDS.md：指示灯的 `lit` 规则、符号的 `show` 和 `colors` 规则，规则可用 `all` 和 `any` 组合）。两个变量的比较、运算和调用无法表达，会连同无法处理的部分一起被报告。
- 框架：框架显示另一个可视化。请把项目的其他文件与第一个文件一起发送（API 中用 `codesysRelated`；在对话框中选择多个文件，第一个是界面）。框架的可视化会放入框架中，它接收的每个输入都绑定到赋给框架的变量（V_Module 的 `HMI` 变为 `MAIN.VFFSDemo.Sealer.PackMLBaseModule_HMI`）。可视化不在这些文件中的框架会连同其名称一起被报告。

PackML 集合（V_Main 连同 V_Module 和 V_MachineModule）：60 个元素已映射，没有未映射的。
