您的操作员已经有一个 CODESYS 画面。从 IDE 导出，导入 HotLoop，它就会作为 HotLoop 画面打开，使用同一台 PLC 的变量。这是告别 WebVisu 的途径：PLC 继续运行自己的程序，HotLoop 通过 OPC UA 连接器读取它，画面则属于 HotLoop。HotLoop for CODESYS 运行 Edge，所以这也是它的导入。

## 使用方法

在 CODESYS IDE 中，在项目树里选中该可视化，使用**项目、导出**（CODESYS 原生导出，生成 `.export` 文件）。不要用**导出 PLCopenXML**：那个文件里没有可视化，如果您选了它，HotLoop 会这样告诉您。

在仪表板界面选择**导入**，选择 `.export` 文件，再点**读取文件**。它会告诉您：

* 找到的可视化（如果文件里有多个，会问您选哪一个），
* 画面读取而本安装中没有的每个变量。这些变量以 `plc/<GVL>.<variable>` 的形式到来：把设备 `plc` 映射到 PLC 所在的 HotLoop 设备，所有变量一次就迁移过去，也可以逐个映射变量，
* **值得一看**：它无法放到画面上的每个元素及原因，在保存任何内容之前列出。

只要还有阻碍，就不会保存任何东西。导入需要 `dashboards.write`，对未标记为可写的变量设置按钮或设定值会在这里被拒绝，与搭建时一样，所以画面上永远不会有关口会拒绝的控件。

通过 API 是 `POST /api/dashboards/import`，用 `codesys`（文件的文本）代替 `file`，并用 `visualization` 在多个中指定一个：

```json
{"codesys": "<ExportFile>...", "visualization": "Overview", "dryRun": true,
 "remap": {"devices": {"plc": "line-3"}}}
```

报告里有常见的 `problems`、`warnings` 和 `remapped`，以及一个 `conversion`，其中 `mapped` 列出每个元素及其变成了什么，`unmapped` 列出每个元素及未能转换的原因。

## 能转换的内容

| CODESYS 元素 | 在 HotLoop 中 |
|---|---|
| 矩形、圆角矩形、带文字和变量的椭圆（`Temperature: %2.1f C`） | 一个读数：变量的变量名，其前的文字作为标题，其后的文字作为单位，小数位数来自格式 |
| 同样的图形，有文字但没有变量 | 一个标签 |
| 指示灯 | 一个指示灯，由变量点亮，并按指示灯自己的颜色着色（红色是故障，黄色是警告，蓝色是信息，其他是运行灯）。`NOT x` 把变量反着读 |
| 仪表、电位器 | 变量的读数。用来设定数值的旋钮还会得到一张设定值卡片，以表盘的刻度作为限值 |
| 跷板开关、拨动开关、按钮 | 一个显示状态的指示灯和一张按钮卡片：拨动开关是开和关，点按是那一个值 |
| 多边形、折线，以及没有文字也没有变量的形状（管道、容器、边框） | 符号后面的图形，根据它们的点和颜色绘制 |
| 组 | 它的成员，从组的角点开始放置 |

每个元素都保留它的像素位置：页面就是符号卡片，绘制为一张缩放图，因此画面在任何尺寸下以及在手机上都保持形状。

## 无法转换的内容

导入时会说明，每项一行，绝不会悄悄丢弃：

* 没有 HotLoop 符号的元素类型（趋势图、表格、滑块、图像元素，以及工具箱里的其余部分），
* 作为表达式的变量（`Temp * 2`、`a AND b`、数组元素）：HotLoop 显示的是变量，所以请为表达式添加一个变量，并让读数指向它，
* 由 PLC 数值驱动的可见性、颜色或移动规则：符号始终显示，不会变色，
* 贝塞尔曲线绘制为各点之间的直线，旋转过的元素不会被旋转，
* 页面大小，因为导出文件中没有：页面大小等于最外层元素的大小再加上边距，
* 超过 40 个字符的文字会被截断，表盘是数字，而不是表盘。

CODESYS 样式的文字样式、字体和颜色是 HotLoop 的：画面跟随 HotLoop 的主题。

## 它如何读取文件

CODESYS 公布了原生导出存在且为 XML，但没有公布其中有什么。这里的读取器遵循 IDE 自己写出的内容（CODESYS 3.5 SP22，Visualization 4.10）：每个元素把设置存为一组带编号的成员，编号是成员在元素描述中的路径的 CRC-32，例如 `m_StaticPosition.iX`，IDE 把这份描述安装在自己旁边。测试中包含从 IDE 自身导出读取的数值。带有变量但未被读取的设置会按上述方式报告，所以画面不完整时，绝不会被当作完整的导入。

## 下一步

打开画面，对照工厂检查读数，把设定值卡片和按钮卡片放到操作员期望的位置。从这里开始，手工搭建的画面和导入的画面就是同一回事：它可以导出为[画面文件](/zh-hans/iot/screen-file/)，每次保存都会生成新版本，也能用同样的方式转到另一个安装。
