只给绝对数字。并排对比的表格每次换设备就会变，最后描述的往往是别的东西而不是这个产品。

Flow 在台式机上每秒响应约 15,000 个请求，在 Raspberry Pi 5 上每秒约 13,000 个，台式机上内存不到 30 MiB，Pi 上是 42 MiB。这正是流程引擎要小到能放进车间里那个盒子的全部意义。

## 流程

五个节点：一个 HTTP 端点，三次属性修改，一个回复。其中没有任何东西是刻意做快的。它是一个小而真实的流程的样子，这正是流程引擎基准测试应该测的对象。负载生成器是闭环的：每个客户端在上一个请求返回后才发送下一个，所以它测的是对端能承受多少，不会产生开环生成器在目标落后时报告的那种误导性延迟。

## 自己运行

`hotloop-flow bench` 内置在二进制文件里。`-launch` 会启动二进制文件，计时流程多久开始响应（冷启动），两秒后读取进程的常驻内存（空闲），然后在负载期间对其采样并保留峰值。不带 `-launch` 的 `-target` 通过 HTTP 驱动一个已在运行的实例，即容器或 Pod，用于测量吞吐量和延迟。

```bash
hotloop-flow bench -mode http -launch ./hotloop-flow -target http://127.0.0.1:18897 -path /bench -duration 30s -warmup 5s -connections 8
hotloop-flow bench -mode engine -chain 5 -messages 200000
```

## 结果

在一台 x86 台式机（24 个 CPU）上，使用原生静态二进制文件测得，每项三次运行。

| <span class="sr-only">详情</span> | 运行 1 | 运行 2 | 运行 3 |
|---|---|---|---|
| 冷启动 | 0.05 s | 0.05 s | 0.05 s |
| RSS，空闲 | 16.7 MiB | 16.7 MiB | 16.4 MiB |
| RSS，负载下峰值 | 26.4 MiB | 26.4 MiB | 28.5 MiB |
| HTTP 吞吐量 | 15.0k req/s | 15.3k req/s | 13.0k req/s |
| HTTP 延迟 p50 / p95 / p99 | 0.39 / 1.22 / 1.82 ms | 0.39 / 1.20 / 1.78 ms | 0.41 / 1.49 / 4.03 ms |
| 引擎，每条消息 | 2.61 µs | 3.11 µs | 2.20 µs |
| 引擎，每条消息分配 | 3,868 bytes | 3,869 bytes | 3,868 bytes |

## Raspberry Pi 5 上的结果

在一块 8 GB 的 Raspberry Pi 5 上测得，时钟限制在 2.0 GHz，作为 k3s 上的 Pod 运行，节点上没有其他任何东西。同一个流程，三次运行，每次都在全新的 Pod 中。

| <span class="sr-only">详情</span> | 运行 1 | 运行 2 | 运行 3 |
|---|---|---|---|
| 冷启动 | 0.46 s | 0.15 s | 0.10 s |
| RSS，负载下峰值 | 40.3 MiB | 40.5 MiB | 40.3 MiB |
| HTTP 吞吐量 | 13.2k req/s | 13.4k req/s | 13.3k req/s |
| HTTP 延迟 p50 / p95 / p99 | 0.48 / 1.45 / 2.78 ms | 0.48 / 1.42 / 2.72 ms | 0.48 / 1.44 / 2.74 ms |
| 引擎，每条消息 | 8.15 µs | 7.74 µs | 7.89 µs |

在同一块板子上用同一条命令持续 600 秒，稳定在 11.4k req/s，p50 为 0.58 ms，p99 为 3.00 ms。这块板子只用裸散热片、没有主动风扇，负载这么高时会降频，所以对一个持续满载的盒子来说，这才是诚实的数字。

### 这些数字不代表什么

**HTTP 吞吐量包含 HTTP 协议栈。** 这是有意的：它是你的流程的客户端所体验到的。它不是对调度器的测量。引擎那几行才是，路径中完全没有 I/O。

**一种流程形态，一种负载大小，一种并发度。** 做真实 I/O 的流程，比如 MQTT 发布或数据库写入，由 I/O 主导。这些数字是运行时自身的开销，不是对每种工作负载的承诺。

**尾部比中位数波动更大。** 饱和时一切都在排队，p99 由排队决定。中位数才是处理一个请求的成本显现的地方。

**这是基准测试流程，不是持久连线。** 这里没有任何东西测量持久连线背后的存储或 SD 卡写入。

## 内存

RSS 是进程自身的常驻内存，从 `/proc` 读取。它不是 `podman stats` 报告的数值，后者显示的是内核记在容器名下的部分，可能比进程实际占用的低很多。
