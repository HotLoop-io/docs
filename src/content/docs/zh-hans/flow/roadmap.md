HotLoop Flow 接下来会成为什么样子，按构建的先后顺序排列。不在这份清单上的就不会去做，所以请把它加进清单。

Flow 与 HotLoop 并行构建，并始终是独立的产品。FlowLab 及其图表，即第 9 阶段，是放在消息运行时旁边的一个独立套件。

## Flow 是做什么的

一个面向工厂现场的可视化流程引擎。每一次部署都会做差异对比、经过测试，并且一键即可回滚。凌晨 3 点出了问题时，您能准确看到消息走了哪条路径，以及它在每一跳上是什么样子。它以一个静态二进制文件运行，小到可以放进 Pi，传感器数据猛增时也不会趴下。

它还能原样读取您现有的 `flows.json`。这是一项特性，不是重点。

下面每一项都遵守这些规则：

- 没有桩代码。没有构建完成、没有对真实对象测试过、没有正常工作，就不打勾。
- 任何能向设备下达指令的东西，都要经过一道可以说不的关口，并说明原因。
- 没有任何东西被悄悄丢弃。每一次丢弃、拒绝和溢出都会被计数，并显示在指标中。
- 流程文件始终逐字节原样加载和保存。新数据放在其他工具会忽略的键中，往返测试也覆盖带有这些数据的文件。

### 第 1 阶段：历史、差异、回滚

每一次部署都是一条记录：谁、何时、一条备注、确切的字节，以及改了什么。生产线停下之后，人们首先问的就是“改了什么、谁改的、给我还原”，而今天的答案是三个 `.bak` 文件。

- [x] 部署日志：每次部署都是一条不可变的记录，包含用户、时间、可选的备注、流程的字节，以及当时加密的凭据。保留期限是一项设置。`GET /deployments`
- [x] 语义差异：逐节点、逐属性。新增、删除、修改、重新连线。拖动节点只会显示为布局变化，绝不会显示为逻辑变化。通过 API 使用，也可用 `hotloop-flow diff a.json b.json`
- [x] 这个差异可以当作 git difftool 使用，所以针对某个流程的拉取请求读起来是“规则 2 的阈值 7.5 改为 8.0”，而不是一大块 JSON
- [x] 回滚：把旧记录作为新记录重新部署，凭据也包含在内，所以您删掉的节点会连同它的 broker 密码一起回来。历史始终只增不减
- [x] 编辑器：历史面板、画在画布上的差异、带备注的“审阅并部署”、回滚按钮。部署冲突时，显示对方改了什么，而不是一个是/否的对话框
- [x] 流程即代码：用于 CI/CD 的 `hotloop-flow deploy` 和 `hotloop-flow export`，配有仅限部署的令牌，所以流水线永远不会持有管理员密码
- [x] 可选的 git 镜像：每次部署都以部署者本人为作者，作为一次提交推送。纯 Go，二进制大小检查仍然通过
- [x] 审计日志：登录、登录失败、部署、回滚和注入，每一项都带有谁以及来自哪里。部署日志是它的第一张表
- [x] MFA（TOTP），免费，任何想用的人都可以开启。任何与安全登录有关的功能，永远不会被放在付费墙后面
- [x] 登录限速与锁定、重启后仍然保留的会话，以及改用子协议而不是 URL 来发送的 websocket 令牌。URL 中的令牌对现有脚本仍然有效，并会记录一条警告，因为升级时让它们失效比泄露更糟；移除它要等到一个主版本发布

### 第 2 阶段：流程测试

“我的改动有没有搞坏生产线？”这个问题在部署之前回答，而不是之后。测试是放在流程旁边的 YAML，所以它们的差异对比和审阅方式都与流程相同。

- [x] `hotloop-flow test`：真实的运行时和真实的节点，在进程内运行。注入一条消息，期望在期限内从某个端口出来什么，期望什么都不出来，期望一个错误到达 Catch。为 CI/CD 提供 JUnit 输出
- [x] 虚拟化 I/O：测试中的 MQTT out、数据库写入或 HTTP 请求只记录它本来会发送的内容，绝不会碰到网络
- [x] 虚拟时钟：一个五分钟的 Delay 在几毫秒内跑完，每一个计时节点都据此得到验证
- [x] 上下文和凭据的固定数据，以及之后对上下文的断言。一个测试不能依赖另一个测试留下的东西
- [x] 部署关口：开启后，测试不通过的部署会被拒绝，并附上失败的断言，而已经在运行的流程毫无察觉
- [x] 编辑器：两次点击就能把捕获的调试消息变成测试，在编辑器里运行整套测试，并在节点上显示通过和失败

### 第 3 阶段：追踪与回放

- [x] 点击一条调试消息，画布就会点亮它走过的路径，显示每一跳的耗时和载荷，穿过拆分、合并和子流程
- [x] 有界的追踪缓冲区。在一百万条消息的浸泡测试中内存保持平稳，并公布这个数字
- [x] 把捕获的消息回放到流程的草稿中，并比较输出
- [x] 捕获的追踪可以变成第 2 阶段的测试
- [x] OpenTelemetry 导出，已用真实的采集器验证

### 第 4 阶段：持久状态

历史数据库停机一小时，不该让您丢掉一小时的读数。

- [x] SQLite 中的持久上下文，纯 Go、不用 cgo，带有原子操作（比较并交换、递增、更新）。现在用于上下文，接下来用于持久队列，是一个存储而不是两个。如今流程上下文和全局上下文在每次重启时都会丢失，这是最可能最先让人栽跟头的缺口。每三十秒在一个事务中延后写入，而一个被设为与原来相同的值不会产生任何写入
- [x] 持久连线：把一条连线标记为持久，它的队列就会溢出到同一个存储中，而不是阻塞或丢弃。重启后仍在，保持顺序，遵守磁盘配额，深度是一项指标。在流程文件中用 `ew_durable` 标记，所以往返仍然逐字节一致。在编辑器中双击一条连线即可标记
- [x] 用最苛刻的方式验证了存储并转发：在稳定输入下把真实的 InfluxDB 停十分钟，再恢复，数行数。没有缺行，没有重复。然后在队列处理到一半时对运行时执行 kill -9，再数一遍。脚本、计数以及每小时的磁盘写入量见 [durable/](/zh-hans/flow/durable-state/)
- [x] 已在真实的 Pi 5 上验证：内存、启动时间和持续吞吐量见 [docs/bench](/zh-hans/flow/benchmarks/#raspberry-pi-5-上的结果)，连同它出现的降频情况
- [ ] 在 Pi 4 和 Zero 2 W 上验证，以及在一张卡上测每小时的 SD 卡写入量，因为一个会磨损 SD 卡的上下文存储就是一个缺陷。保持未完成是因为需要这些板子。Pi 5 已经测过；从任何其他机器上得到的数字都是编造的数字

### 第 5 阶段：工厂现场

`scan` 今天能发现 PLC，但节点面板里没有任何东西能与它通信。对一个为工厂而造的产品来说，这是最大的漏洞。

- [x] Modbus TCP 读取和写入
- [x] OPC UA 读取、订阅和写入
- [x] S7 读取和写入
- [x] Sparkplug B，既可作为边缘节点，也可作为主机
- [x] EtherNet/IP 读取和写入
- 全部是模拟器。没有任何 Siemens CPU 或 Logix 控制器接入过其中任何一项
- [x] HotLoop 节点：实体变化输入、实体状态、调用脚本、应用配方。每条指令都经过 HotLoop 的写入关口，并以 `flow:<node id>` 记入它的日志簿，被关口拒绝的写入会连同关口给出的原因到达 Catch 节点
- [x] 有 HotLoop 时，Flow 对设备的写入经过 HotLoop 的关口，而不是直接到 PLC。两者都在 2.3.0 中发布。经过真实关口的写入已对已发布的 HotLoop 镜像用 Modbus 验证；OPC UA、S7 和 EtherNet/IP 的写入节点通过同一段代码发送，并有一个测试检查每个节点都提供该关口。

### 第 6 阶段：无需 npm 的插件

- [x] 已有主机上的 `wasm` 节点：硬性内存上限、超时，超出其中任何一项的 guest 会陷入 trap，而不会拖垮其他任何东西
- [x] 插件格式：模块、让编辑器渲染其对话框的描述符，以及签名。未签名或被篡改的插件拒绝加载，并说明原因
- [x] 能力：插件没有任何主机访问权限，除非它的清单提出请求且操作员授予。请求未授予的东西会使部署失败

### 第 7 阶段：带类型的连线与 MCP

- [x] `json` 节点上的模式校验，第一部分
- [x] 端口上的可选模式。编辑器能看到的不匹配会在部署时被拒绝；看不到的则连同出错字段的路径送到 Catch 节点和一项指标
- [x] 在编辑器的连线上画出类型
- [x] 流程即 MCP 工具：一个 tool 节点声明名称、描述和输入模式，Flow 提供 `/mcp`。调用流程的代理拥有与人相同的权限和相同的审计日志
- [x] 一个 MCP 客户端节点，让流程可以调用其他服务器上的工具，包括 HotLoop 的
- [x] Flow 自己的 MCP 工具：列出、读取、部署和回滚流程，列出部署记录，并按下一个 inject 节点，通过管理 API 自己的处理程序，使用相同的权限、相同的部署检查和相同的审计轨迹，因为一个只能调用流程作者接好的东西的 MCP，既无法读取也无法写入 Flow 本身
- [x] Flow 自己用于图表和仪器的 MCP 工具：列出和读取图表，运行和停止一个图表，驱动它的调试器，设置它面板上的控件，设置断点和探针，创建子图表，以及读取和切换仪器的写入；每一个都是一条管理路由，通过它自己的处理程序、以该路由所要求的权限（`status.read`、`diagram.run`、`instrument.write`）运行。此前图表路由没有工具，所以代理能部署一个图表却无法运行它。现在每条管理路由要么是一个工具，要么在测试中被点名为必须由人来做的，新增路由而没有工具时测试会失败。算上站点、故障切换和追踪的工具，现在共有 44 个工具

### 第 8 阶段：编辑器，用 Astro 重写

已完成，并且被提前了。它本该排在最后，我们把它提到了 Flow 的第一批截图之前，因为谁都不该在一个看起来像出自另一家公司的编辑器里看到第一批截图。

每个 HotLoop 项目都将拥有一套现代的统一界面，而这个编辑器是唯一不匹配的。它曾是原生 SVG 之上手写的原生 TypeScript，在目标是一个没有什么需要审计的小型静态二进制文件时，这是正确的选择。现在它是带 Svelte 岛的 Astro，与 Cascade 的编辑器是同一套技术栈，用同样的 HotLoop 令牌，浅色和深色都支持。

- [x] 先做一轮设计，在写下第一行 Astro 之前。编辑器放在 HotLoop 其余部分旁边应该是什么样子、什么手感，在纸面上和共享令牌里先定下来，这样重写就是在构建一件已经有人决定好的东西，而不是边做边决定
- [x] 用 Astro 重建的编辑器，画布、对话框、历史、审阅、测试、追踪、搜索和分组全部沿用，且一项都不许变差。`web/e2e` 里的浏览器测试就是标准：它们不加修改就能在新编辑器上通过
- [x] 仍然内嵌在一个静态二进制文件中，边缘设备上仍然不需要网络，仍然在二进制大小预算之内，许可证关口仍然覆盖打包进去的所有内容

画布以及它下面的图并没有被重写。它们保持原来的 TypeScript，移入 `web/src/lib`，换了一层新外观，所以连线、拖动、撤销和逐字节的流程文件往返用的就是已经测试过的代码。围绕它们的一切都是 Svelte。

在这一切过程中，Flow 仍是独立的产品。它与 HotLoop 共享外观，不共享代码，也永远不会内嵌在 HotLoop 中。

### 第 9 阶段：FlowLab，图表

运行一个标签页的第二种方式，与消息并列，绝不取而代之。在图表中，每个节点在其所有已连线的输入都有值时运行一次，彼此之间没有连线的分支同时运行。这正是测试台或数据记录器所需要的：把一个值从一轮带到下一轮的循环、沿着自己专属连线传递的错误、操作员可以在手机上打开的面板，以及可以暂停一次运行并显示每条连线上内容的调试器。现有流程不受影响，流程文件仍然逐字节加载和保存：图表是带有 `ew_diagram` 键的标签页，而连线落在哪个输入上，保存在连线所离开的节点的 `ew_in` 中。其余内容见 [FlowLab](/zh-hans/flow/flowlab/)。

- [x] 调度器：所有已连线的输入就绪即运行，独立分支并行，并为没有数据流动的地方提供 `after` 连线来排定顺序
- [x] 带有携带值的 while 和 for 循环，以及一条错误连线：它跳过故障之后的节点、停止循环，并携带其来源和代码
- [x] 串口，可读取到终止符或指定字节数，超时走错误连线，线缆被拔掉后会重新打开该端口并计数
- [x] 读数解析器、稳定值检测，以及带时间列的文本日志
- [x] 由 Flow 提供的面板：控件、指示器以及图表或曲线图，运行进行时可在手机上打开，桌面上还可有第二个观看者，各自在一秒内跟上运行
- [x] 运行、停止、高亮执行过程、任意连线上的探针、节点、连线和轮次上的断点，以及单步进入、单步跳过和单步跳出
- [x] 编辑器绘制具名端口，并把连线接到您放下的那个端口上，同一个页面既运行也调试
- [x] Case 结构、记录与共享类型、波形
- [x] TDMS 和二进制日志，以及数据库和 MQTT 输出
- [x] 仪器会话，通过原始套接字和串口，已用模拟器和 pty 验证
- [ ] 用 NI 自己的服务器验证过的数据采集客户端。它已经构建并发布，只用一个替身服务器测试过，所以在用 NI 的服务器和一台设备运行过之前，它保持未完成
- [x] 分析：统计和滤波器
- [x] 子图表、CI/CD 中的错误列表，以及编辑器的缩放和布局方面的工作
- [x] 回放一次已结束的运行：记录每个节点的开始和结束以及每条连线上的值，图表栏在画布上回放最近一次运行。`GET /diagrams/{id}/trace`，`get_diagram_trace` 工具
- [x] 一个保留数据库漏掉内容的数据库接收端：`postgres out`，持久，按顺序写入，并在数据库恢复后分批写入，已在真实的 TimescaleDB 上验证
- [x] 把一个流程文件，也就是一组图表，推送到租户在 EmberNet 中运行的每一个 Flow 安装，每台之后都做检查，失败的会被还原（[推送到租户的站点](/zh-hans/flow/stations/)），已在三个真实的 Flow 进程上验证
- [ ] 在一台 Pi 上验证一整天，这需要板子和一次长时间运行

## 日常的缺口

这些与各个阶段并行进行。没有人会因为一个流程引擎有这些而选它，但有很多人会因为它没有这些而放弃它。

- [x] 部分部署：只有改动过的节点及其连线会重启。如今每次保存都会掐断所有 MQTT 会话和所有在途消息，这让操作员学会了不在班次中部署
- [x] JSONata，已用公布的示例验证，因为它是导入的流程最常栽跟头的地方
- [x] cron 风格的 inject
- [x] Link Call 和 Link Out 的返回模式
- [x] 按超时 join 和 reduce、按时间 batch、流式 split
- [x] MQTT v5 和遗嘱消息
- [x] TCP 上的 TLS，HTTP 上的 cookie 和 multipart
- [x] 编辑器：复制和粘贴、导入和导出所选内容、子流程和分组编辑、跨流程搜索、调试过滤
- [x] 第一轮留下的编辑器缺口：从节点面板添加配置节点（对话框让您这么做，而您却做不到）、把所选内容变成子流程、重命名和删除流程，以及通过双击连线把它标记为持久
- [x] 为持久连线的目标永远拒收的消息提供一条出路：每条连线可选的尝试次数上限。被拒绝这么多次之后，消息连同附带的消息体作为错误交给流程的 Catch，连线继续前进。默认关闭，所以连线仍然像以前一样保留并重试
- `store.*` 在持久化工作中就已存在，现在同样要经过这项检查
- [x] 指向文件中不存在的配置节点的节点（某个流程连同它自己的 broker 一起被删除，而子流程、手工编辑或导入仍然引用着它）会由 `hotloop-flow import`、加载和部署时的编辑器以及部署响应报告，该节点会成为启动失败，而不是一个悄悄永远不工作的节点

## 已决定

这份清单曾经带着的每一个问题都有了答案。它们连同答案一起留在这里，因为理由才是阻止别人重新翻案的东西。

2026-10-03 决定：

- **工业节点在 Flow 中构建，**基于 HotLoop 驱动所用的同一批开源库。HotLoop 的驱动仍属于 HotLoop。Flow 保留自己的许可证，做出这个决定时它是另一个，现在是 HotLoop Source License Agreement 1.0，它取代了 EmberNet Source License 1.0，在那之前则取代了它从 2.2.0 起沿用的 Business Source License 1.1。
- **Flow 仍是独立的产品，永远不会内嵌在 HotLoop 中。**它与 HotLoop 并排运行，从外部与 HotLoop 的 API 对话，这正是第 5 阶段的 HotLoop 节点所做的，两者的关系仅此而已。
- **README 以 Flow 能做什么开头。**“连接工厂。像审阅代码一样审阅它。”导入现有流程放在更靠后的“带上您的流程”中，开头也不拿 Flow 与任何东西比较。Flow 靠自己立足。
- **持久上下文从一开始就用 SQLite，**纯 Go、不用 cgo。现在用于上下文、之后用于持久队列的是同一个存储，而不是先做一个文件存储、再做第二个存储。
- **工作流自动化产品是它自己的东西，**不共享 Flow 的引擎。历史、差异等在这里仍然是引擎包，因为 API、CLI、编辑器和 git 都必须得到同一个答案。

- **MFA 和审计日志在第 1 阶段发布，**排在那些好玩的东西之前。两者都做到了。
