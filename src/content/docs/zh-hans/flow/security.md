---
title: "Flow 的安全立场"
description: "没有登录就无法启动，exec 默认关闭，文件节点受限，凭据加密存储。Flow 拒绝什么，以及如何有意识地选择放开。"
---

这一切背后的规则是：任何能部署流程的人，都能让这台机器做事，因为流程本来就是干这个的。所以“谁能部署流程”由运维人员有意识地回答，而绝不由默认值回答。

**没有认证就不会启动。** 不是日志里没人看的一条警告，也不是指望您去修改的默认值：而是一个启动错误，修复方法就印在旁边。关闭它需要在环境变量中设置 `HOTLOOP_FLOW_INSECURE=true`，这是有意为之，因为配置文件无法单独做到：文件是复制粘贴的内容最终落脚的地方。这样做之后，每次启动日志都会发出警告，编辑器会显示 **no login** 徽章，让下一个人知道门是开着的。

**双因素登录免费且内置。** 任何用户都可以在编辑器的 Two-factor 按钮中开启：用任何验证器应用扫描二维码（或输入密钥），再输入一个验证码，此后登录需要密码和六位数字。在第一个验证码证明手机里有它之前，什么都不会改变，所以中途放弃的设置不会把任何人锁在门外。验证码只能使用一次：它所属的时间步会被记住，所以从别人肩膀上偷看到的验证码，在他们使用的那一刻就失效了，比它更早的验证码也一样。允许两个方向各三十秒的时钟偏差。关闭它同样需要验证码，所以在共用屏幕上遗留的打开的会话，不足以把它从账户上摘掉。丢失手机的情况是：拥有 `auth.admin` 的账户调用 `POST /auth/mfa/reset`，这会连同谁对谁做的一起记入审计记录。登记信息用凭据密钥加密，与节点凭据的方式相同。安全登录的任何部分在这里都不是付费层级，将来也不会是。

**猜密码行不通。** 同一地址对同一账户连续五次输错密码（或密码正确但验证码错误），该地址上的该账户会被锁定十五分钟；同一地址对任意账户失败二十次，该地址会被锁定。账户锁定按地址进行是有意为之：如果在所有地方锁定账户，任何能连上该端口的人都可以从工厂另一头把真正的操作员锁在外面。被锁定的尝试在密码被检查之前就收到带 `Retry-After` 的 429，锁定及其拒绝的每次尝试都记入审计记录。在反向代理之后，每个请求都带着代理的地址，所以按地址的限制就对所有人一起生效；这是出错时偏安全的一边，具体数值在 `auth.lockout` 中。没有任何设置可以关闭它。

**会话能挺过重启。** 它们过去保存在内存中，所以每次 pod 重新调度和每次升级都会让所有人退出登录，而恰好需要修改流程的人就得去找密码。现在它们保存在 `data/sessions.json` 中，只以 SHA-256 哈希的形式，所以文件在出示令牌时能够验证它，对复制它的人却毫无用处。会话记住的是谁，而不是他们能做什么：从配置中删掉一项权限或一个用户，下一个请求就知道了。

**把令牌放在请求头里，而不是 URL 里。** 浏览器无法在 WebSocket 握手上加 `Authorization` 请求头，所以编辑器的事件流过去把令牌放在查询字符串里，而那恰恰是访问日志、代理和浏览器历史保存内容的地方。现在它在 `hotloop-flow` 之外提供令牌，作为第二个 WebSocket 子协议 `hotloop-flow.bearer.<token>`，这是一个按习惯没有任何东西会记录的请求头，服务器以 `hotloop-flow` 作答。仍发送 `?access_token=` 的脚本照常工作，因为在升级中让它失效会更糟，并且服务器对每个这样的连接都会记录一条警告，说明应该改发什么。Flow 绝不会把 URL，或其中的令牌，写入自己的日志或审计记录。

**一切重要的事情都会留下痕迹。** 登录、失败的登录（包括名称是否存在，客户端永远不会被告知，但运维人员应当知道）、登出、部署、被拒绝的部署、回滚、inject、MCP 工具调用和流程测试的保存都会写入 `data/audit.log`，每条一行 JSON，在响应请求之前同步到磁盘。每一条都说明谁、从哪个地址、做了什么：部署指向其部署记录，inject 指明节点。`X-Forwarded-For` 与套接字地址并列保存，绝不取而代之，因为任何人都可以发送这个请求头。`GET /audit` 按最新优先读取，可用 `?event=`（所有类型的登录用 `login.`）、`?user=`、`?since=` 和 `?limit=` 过滤，并且它需要单独的 `audit.read` 权限，因为被允许部署并不意味着被允许读取还有谁登录过。它按大小轮转（`audit.maxBytes`、`audit.keep`），所以繁忙的实例无法写满自己的卷，而写不进去的记录绝不会阻止它所记录的操作：它会被记入日志，并在 `hotloop_flow_audit_write_failures_total` 中计数，这个值应当永远为零。

**`exec` 节点默认关闭。** 由运维人员指明流程可以运行的命令，启用了却没有允许列表的节点是启动错误，而不是运行任何东西的许可。允许列表匹配的是**解析后的绝对路径**，而不是流程输入的字符串。按字符串匹配的话，流程请求 `curl`，得到的是 `PATH` 中排在最前面的那个 `curl`，而它是 Function 节点能读、sidecar 能影响的。而且没有 shell。命令行只按引号规则拆分，不带引号的 shell 元字符（`|`、`&`、`;`、`$` 之类）会被拒绝，而不是当作字面量传过去并寄希望于运气。所以 `ping -c1 10.0.0.1; rm -rf /data` 是一个错误，而不是两条命令。

**文件节点被限定在数据目录内。** 符号链接按路径中最长的已存在前缀来解析，这堵住了显而易见的漏洞：在卷下放一个指向 `/` 的符号链接，然后直接穿过它去读。单纯的前缀检查会眼都不眨地放行，这样流程就能读取进程能读取的任何东西。

**密钥有自己的范围，而它不是文件节点的范围。** tls-config 通过 `secrets.allowedPaths` 读取其证书、密钥和 CA：数据目录加上您列出的内容。把 cert-manager 生成的 Secret 挂载到那里，TLS 配置就能使用密钥，而没有任何流程能读取它，因为通过该范围读取的一切都会进入握手，绝不会进入消息。如果把同一个密钥放到 `files.allowedPaths` 下，任何带有 File In 节点的流程都可以把它取走，并邮寄给它喜欢的任何人。

**密码可以放在 Secret 里，而不是流程里。** 任何节点的凭据都可以指明一个文件，而不是保存值本身：

```json
{"id": "b1", "type": "mqtt-broker", "broker": "plc-broker", "user": "line3",
 "ew_credentialFiles": {"password": "/etc/hotloop-flow/secrets/plc-broker/password"}}
```

节点启动时，该文件通过同样的密钥范围读取。末尾的一个换行符会被去掉，因为那是 `echo` 留下的，而末尾带换行符的密码会让登录失败，日志里却没有任何说明原因的内容。流程文件、部署日志、diff 和 git 镜像都只带路径而绝不带密码，所以流程可以放进 git，密码则留在运行集群的人本来就存放密码的地方。文件缺失或在范围之外，会让该节点的部署失败，而不是让它在没有密码的情况下连接。chart 在 `secrets.mounts` 下为您挂载 Secret。轮换后的 Secret 在下一次部署或重启时生效。

**凭据采用 AES-256-GCM，密钥由 Argon2id 派生。** GCM 会直接拒绝被篡改的文件，而不是把它解密成攻击者选定的内容，Argon2id 使每次对弱密钥的猜测都要消耗 64 MiB 内存。流程文件的写入顺序是：临时文件、fsync、重命名、目录 fsync，并保留三份备份，所以保存过程中断电，留给您的是旧文件或新文件，绝不会是各一半。如果它读到损坏的文件，就会退回到备份，并明确说出来。

**发现节点默认关闭，** 并受运维人员配置的 CIDR 允许列表限制。一个主机名如果解析出一个范围内的地址和一个范围外的地址，会被直接拒绝，否则 DNS 就成了绕过允许列表的途径。

**Function 节点没有可触及的东西。** 它运行在纯 Go 的 JavaScript 解释器上，除非有人添加，否则没有任何宿主绑定，而没有人添加过。没有 `require`，没有 `process`，没有 `Buffer`，没有文件系统，没有网络，并且有一个测试运行了经典的构造函数链逃逸来证明它什么也触及不到。
