**它能运行。** 它能启动，提供 API 和编辑器，从卷中加载流程，传递消息，并在重启后带着流程、凭据和上下文回来。Chart 在全部三种网络模式下部署它，整条发布链都能解析。它在真实的工厂现场运行。

**已针对真实基础设施验证**：Mosquitto、InfluxDB 和 PostgreSQL。InfluxDB 的标签值从真实数据库里原样取回，是 `press 01,west`，空格和逗号都完好。这正是那个转义缺陷，否则它会悄悄把一个序列拆碎，让人花一天才能找到。

**Cookie 和 multipart 的响应方式与 Node-RED 自己的库一致**，因为已经与它们对照检查过，超过一百个用例，答案被记入一个 golden 文件，测试通过真实套接字回放。其中包括难看的情况：UTF-8 文件名乱码的方式与 Node-RED 栈完全一样，名为 `value` 的 cookie 在 `msg.responseCookies` 中丢失了它的值，那边也是如此。连缺陷也要对上，这正是目的。依赖其中某个缺陷的流程，会在它消失的那天出问题。

**已在真实硬件上运行（2026-11-17）：** S7 和 EtherNet/IP 节点、持久连线（存储并转发以及磁盘写入）和插件，连同它们的陷阱和拒绝行为，以及在真实集群中的一个已签名插件。磁盘写入和单次调用的数字仍然标明了测量地点。

接下来构建什么、按什么顺序，见[路线图](/zh-hans/flow/roadmap/)。

## 在成为 HotLoop Flow 之前

它原来叫 Emberwire，`v0.1.0` 仍在原处，位于 `ghcr.io/embernet-ai/emberwire:0.1.0`。`2.0.0` 是这个名字下的第一个版本，2.x 不读取旧名字写出的任何内容：`EMBERWIRE_*` 变量、两个 `emberwire-` 数据库节点类型、针对旧导出构建的 WASM 模块以及 0.1.0 的凭据文件，都需要重做。这是有意为之的干净断裂。没有人在 0.1.0 上构建过东西，为零个用户做兼容层只会多出更多可能出错的代码。从 2.0.1 起，旧的凭据文件会收到一条清晰的消息，指出文件名，说明它是 Emberwire 写的，并请您把它放到一边，重新输入凭据。
