FlowLab 是 Flow 中面向测试台和数据记录仪的部分，它的单位是图：Flow 运行标签页的另一种方式。在流程中，消息经过一个节点，任何一个输入都会唤醒它。在图中，每个节点每次运行只运行一次，条件是每个有连线的输入都已有值。两个之间没有连线的节点会同时运行。测试台或数据记录仪就是这样搭起来的：读取设备，解析读数，判断是否稳定，显示出来，记录下来。

这一切都不会影响流程。带有 `ew_diagram` 的标签页不在消息运行时之内，其他所有标签页的运行方式和以前完全一样。

对您来说，这意味着：逻辑只需画一次，点运行，就能看到数值在连线上流动。任何知道面板地址的人，都能在手机上看到同一次运行。

## 文件

图是带有 `ew_diagram` 对象的标签页。它的节点就是流程文件里的普通条目。`wires` 照常给出连线通向的节点，源节点上的 `ew_in` 则用同样的形式说明每条连线落在目标的哪个输入上：

```json
{ "id": "a", "type": "dia-const", "z": "d", "value": "1", "x": 100, "y": 80,
  "ew_in": [["a"], []], "wires": [["sum"], []] }
```

文件带着这些键，按字节原样加载和保存。标签页的设置：

| 键 | 作用 |
|---|---|
| `autostart` | `true` 表示 Flow 启动时以及每次部署之后自动开始运行，不需要打开浏览器。 |
| `role` | `"body"` 用于由循环运行的图。主体不会自己运行。 |

每个节点还有一个可选的输入 `after` 和一个输出 `done`。把一个节点的 `done` 接到另一个节点的 `after`，第二个节点就会等第一个，中间不需要任何别的东西。顺序成了一条看得见、也能用 diff 比较的连线。

## 运行

图从已部署的内容运行。在编辑器中打开一个图标签页，点运行。画布上方的工具栏有：

- **高亮执行过程**：每个节点运行前稍作等待，方便您跟着看，数值走过的连线会亮起来。十分钟后自动关闭。
- **暂停、继续、步入、步过、步出**：单步逐个节点前进。步过会运行循环的整个主体。步入会停在其中的第一个节点。
- **在所选内容处中断**：在所选节点上设一个断点。双击一条连线可探测它，会保留它最近的 100 个值，也可以在有值放到连线上时中断。探针绝不会改变一次运行。
- **打开面板**：操作员用的页面。

运行之后把鼠标移到任意连线上，就能看到它最后传送的值。问题按钮会列出图无法运行的每一个原因，并写明节点和输入。

| 调用 | 作用 |
|---|---|
| `GET /diagrams`, `GET /diagrams/{id}` | 已部署的内容、面板，以及每条连线上的最后一个值。 |
| `GET /diagrams/{id}/trace` | 最近一次运行做了什么，按顺序列出：每个开始或结束的节点，以及每个经过连线的值，并附上从运行开始起的毫秒数。部署后还没有运行过的图会返回 404。 |
| `POST /diagrams/{id}/run`, `/stop`, `/debug` | 需要 `diagram.run`。每一次调用都会连同执行人记入审计日志。 |
| `POST /diagrams/{id}/sub` | 发送 `{flows, nodes, name}`，返回把这些节点变成子图后的流程文件。只读取和计算，不保存也不部署任何内容。 |
| `PUT /diagrams/{id}/controls/{node}` | 设置一个控件。会按它的类型、范围和选项进行检查。 |
| `PUT /diagrams/{id}/breakpoints`, `/probes` | 键是节点 id、`wire:<wire key>` 或 `diagram:<tab>`。 |

一次运行的事件通过与编辑器相同的套接字发出，名称为 `diagram/<id>/node`、`token`、`run`、`paused` 和 `values`。

## 节点

| 节点 | 作用 |
|---|---|
| `dia-const`, `dia-math`, `dia-compare`, `dia-logic` | 数值和算术。数学运算对数组逐元素进行。 |
| `dia-wait` | 等待，然后把输入传下去。 |
| `dia-bundle`, `dia-field`, `dia-array` | 记录和数组。 |
| `dia-while`, `dia-for` | 循环。主体是一个独立的图，由它的标签页指定。携带的值从连线或 Start values 开始，并以上一轮的值输出。for 循环接受一个次数或一个数组。while 循环至少运行一次。 |
| `dia-case` | 分支结构。`selector` 上的值选出一个要运行的主体，只运行那个主体。布尔值选择 `true` 或 `false`，数字选择该值对应的分支，无论怎么写，字符串或枚举选择同名的分支。分支是从分支名到图的 JSON 对象，没有任何分支命名的值会运行默认分支。没有默认分支时，节点会在它的错误连线上放一个错误，部署时也会警告没有默认分支（同时有两个分支的布尔值除外）。每个主体必须用相同的名称输出每个结果，不这样做的主体在部署时就是一个问题。`case` 输出说明运行了哪个分支。 |
| `dia-body-in`, `dia-body-out` | 主体的两端。`iter` 是第几轮。`stop` 结束 while 循环。携带值的名称会把它送入下一轮。 |
| `dia-serial-open`, `dia-serial-read`, `dia-serial-write` | 一个串口。读取在遇到结束符或达到字节数时结束。 |
| `dia-instr-open`, `dia-instr-query`, `dia-scpi-parse` | 按地址访问的测试仪器。见下面的仪器一节。 |
| `dia-parse-reading`, `dia-stable` | 从一行中取出数字和单位，并说明最近几个读数是否一致。 |
| `dia-log-text` | 把一条记录作为一行追加到文本文件，并带一个时间列。 |
| `dia-daq-read` | 通过 NI 的 gRPC Device Server，从 NI 硬件上的数据采集任务读取采样。见下面的数据采集一节。 |
| `dia-mqtt-out` | 通过流程文件配置的 MQTT 服务器发布它的值，使用与 MQTT 节点相同的连接。把它标为 durable 后，代理漏收的消息会写到磁盘，并在代理恢复时按顺序发出，重启之后也不例外。 |
| `dia-postgres-out` | 通过流程文件配置的服务器，把一条记录作为一行写入 PostgreSQL 或 TimescaleDB 的表，使用与 postgres 节点相同的连接。把它标为 durable 后，数据库漏收的行会保存在磁盘上，并在数据库恢复时按顺序写入。见下面的数据库中断一节。 |
| `dia-log-tdms` | 把一条记录追加到 TDMS 文件，每个字段一个通道。见下文。 |
| `dia-control`, `dia-indicator`, `dia-chart` | 面板。 |
| `dia-stats` | 数组的平均值、RMS、最小值、最大值和标准差。标准差除以 n 减一，所以需要两个读数。 |
| `dia-integral` | 用梯形法则求数组下的面积，结果是一个数字，或每个采样点处的累计面积。 |
| `dia-derivative` | 数组每个采样点处的斜率。 |
| `dia-filter` | 1 到 10 阶的 Butterworth 低通、高通、带通或带阻滤波器，截止频率以赫兹为单位。 |

### 滤波器

滤波节点是一个 Butterworth 滤波器：通带内平坦、无纹波，在截止频率处下降 3 dB。它由模拟滤波器经双线性变换设计而成，并对截止频率做了预畸变，所以 3 dB 点正好落在您输入的频率上，它以二阶节级联的方式运行，因此高阶时也保持精确。n 阶的带通或带阻滤波器有 2n 个极点。截止频率必须大于零且小于采样率的一半，无法构建的设计会在运行前列在问题中。采样率是一个属性，也可以是优先于它的输入。滤波器在一次运行中会在多次调用之间保留它的状态，所以被循环切成小段的数组，输出就像整体滤波的一样，每次新的运行都从静止状态开始。

它做不到的事：它不是线性相位滤波器，所以对不同频率的延迟不同，也没有向前再向后滤波的零相位模式。在两个信号之间的时序必须对齐、或者波形的形状必须保留的地方，这个滤波器就不合适。积分和微分从以秒为单位的 `dt` 输入、以赫兹为单位的 `rate` 输入，或 Samples per second 属性取得采样之间的时间。

### 记录到 TDMS

`dia-log-tdms` 把测试台采集的测量值写入 TDMS 文件，这种格式可以被数据采集和分析工具打开。把一条记录接到 `row`。记录的每个字段是同一个组里的一个通道，所以包含 `pressure`、`ok` 和 `operator` 的记录会生成三个通道。数字存为 64 位 float，真或假存为 bool，其他一律存为文本。包含数字列表的字段会追加整个列表，一块采样就是这样写进去的。设置：

| 设置 | 含义 |
|---|---|
| `path` | 文件。已存在的文件会被追加，所以一次接一次的运行会累积成一个文件。 |
| `group` | 通道所在的组。 |
| `columns` | 要记录的字段，按顺序。为空则按名称记录每个字段。 |
| `properties` | 文件属性的 JSON 对象，例如 `{"title": "bench 4", "station": 4}`，在运行开始时写入。 |
| `sync` | 默认开启：每一行在节点结束之前都会写到磁盘。 |

每一行是一个分段，一次写完。如果写到一半断电，文件会显示它在哪里被截断，读取器会返回它之前的每一行，下一次运行会修复文件末尾并继续。字段的类型由一次运行的第一行决定。之后不匹配的行，比如数字列里出现文本，会作为错误输入进入错误连线，文件保持不变。缺失的数字写作 not-a-number。

要打开这个文件，用任何 TDMS 读取器都可以。`unit_string` 这样的通道属性，以及波形属性 `wf_start_time`、`wf_increment` 和 `wf_samples`，库是支持的；节点目前还不会设置它们。

读取器接受的内容：little endian 和 big endian 分段、交错和连续的数据、分段中未变化时省略的元数据、新的对象列表、8、16、32 和 64 位整数、32 和 64 位 float、bool、文本和时间戳。它拒绝的内容，会指名道姓，并且不会读一半文件：数据采集驱动写入的原始数据、经过缩放或压缩的数据、扩展精度的 float、定点数和复数。写入器写出的内容：little endian、连续数据，以及同样这些类型。它不写 big endian。

### 错误连线

与外部世界打交道的节点有输入 `err` 和输出 `err`。错误是一条记录：一个标志、一个数字代码、来源文本，以及它来自哪个节点。输入带有错误的节点不做任何工作，只把错误传下去，所以链条开头的一个故障会跳过后面的一切，并只在最后出现一次。把一个错误接到循环的 `err` 主体输出，循环就会在它上面停止，错误出现在循环的错误输出上。面板上的错误指示灯在故障时变红，在下一个没有错误的值到达时熄灭。

### 会中断的目标

durable 的 `dia-mqtt-out` 在代理应答时直接发给代理。不应答时，消息会在节点结束之前提交到 Flow 的 durable 存储，链路恢复后，由一个泵按最旧的先发的顺序投递队列。别人在排队时放进来的内容排在它们后面，所以没有谁能插队。从队列投递是至少一次：一条因为客户端没发现链路已断而发送超时的消息，在客户端重新连接时仍可能被投递，所以它可能到达两次，每次超时的发送各一次。队列和 durable 连线放在同一个存储中、同一个磁盘配额下，重启后无需任何运行、无需浏览器就会被清空。没有 durable 时，代理漏收的消息是错误连线上的一个错误。

### 会中断的数据库

`dia-postgres-out` 通过 `hotloop-flow-postgres` 服务器，把收到的每条记录作为一行写入您指定的表。记录的字段进入同名的列，所以带有 `n` 和 `sensor` 的记录会填充 `n` 和 `sensor` 列。用逗号分隔列出列名，可以只写部分列或固定它们的顺序；让列表为空，节点就使用记录的字段。节点在循环的每一轮运行一次，所以循环每一轮写一行。不是普通名称的表或列，是部署时的问题，绝不会成为运行中途的一条语句。整数同样可以放进 integer、float 或 numeric 列，记录或数组则原样放入，json 或 jsonb 列就接受这种形式。

为一个**时间列**命名，每一行都会带上它到达节点的时间。这是读数产生的时间，而不是写入的时间：在磁盘上等了五分钟的行，仍然带着它产生的那一分钟。

没有**保留数据库漏收的数据**时，数据库不接受的行会作为错误出现在节点的错误连线上，然后丢失。有了它，数据库应答时行会直接写入。数据库不应答时，行会在节点结束之前提交到 Flow 的 durable 存储，节点的 `sent` 输出显示 `false`。这些行在磁盘上等待，经得起重启，并在数据库恢复后按顺序写入，之后进来的任何内容都不会超过它们。积压的内容每条语句写入多行，最多 256 行，所以数据库不在时积累起来的内容几秒就能追上，而不是按每行一次往返的速度。测试让 30,000 行在磁盘上等待，相当于每秒 100 行持续五分钟，数据库恢复后几秒内全部按顺序写入。

从磁盘投递是至少一次。链路断开时已发出 insert 的行，可能已经提交但应答丢失，它会再次发送，所以可能被写入两次，最多一批。如果这很重要，给表一个唯一键，并在发生冲突时选择**跳过该行**：这样第二行就会被数据库丢弃。

数据库因内容而拒绝的行，比如值对它的列来说太大，或键已存在而发生冲突时设为抛出错误，每次都会被拒绝。它会连同一个携带该行的审计事件 `diagram.row_rejected` 被放弃，后面的行继续写入。否则一个坏行就会让日志停下。数据库宕机、表还不存在和密码错误都不属于这种情况：这些行会等待。

### 仪器

`dia-instr-open` 接受一个地址：用于原始套接字上局域网仪器的 `10.0.0.5:5025`，用于串口仪器的 `serial:///dev/ttyUSB0?baud=19200&data=8&parity=E&stop=1`，或者用于 9600 8N1 的简单 `/dev/ttyUSB0` 或 `COM3`。运行结束时会关闭会话。如果链路断开，下一次查询会重新打开它，这次断开会记在会话上。

`dia-instr-query` 写入一条命令和结束符，然后读取应答。选择文本（一行，从 `reply` 输出）、none（单纯写入）或 block，block 读取 `#41024...` 二进制块，并把采样作为数组从 `samples` 输出，类型可以是 int8、uint8、int16、uint16、int32、float32 或 float64，big 或 little endian。不定长的 `#0` 块在第一个行尾结束。没有及时到达的应答，是错误连线上带着地址的超时。

`dia-scpi-parse` 把文本应答读成数字列表、单个数字、标识（把 `*IDN?` 读成制造商、型号、序列号和固件），或状态字节（把 `*STB?` 或 `*ESR?` 读成已置位各位的名称）。

### 串口

端口消失，比如拔掉电缆或适配器，是读取的错误连线上的一个故障。下一次读取会每秒一次尝试重新打开它，并统计丢失和恢复。端口有流控，可以是无、硬件（RTS 和 CTS）或软件（XON 和 XOFF），在 Linux 上设置在终端本身；伪终端能显示设置已经到达，而线路在真实适配器上的行为还没有证明。

### 数据采集

`dia-daq-read` 通过 NI 自己的开放 gRPC Device Server，读取 NI 硬件（如 CompactDAQ 机箱）上的任务。Flow 通过网络与该服务器通信，所以硬件可以在与 Flow 不同的机器上，Flow 不需要 NI 驱动，也不需要自带的厂商库。它仍然是一个静态二进制文件。

**在连接硬件的机器上**，安装 NI 的 DAQmx 驱动和 NI 的 gRPC Device Server（https://github.com/ni/grpc-device，MIT 许可证）。在配置文件另有规定之前，服务器只在那台机器上监听（`localhost`，端口 31763）。要从另一台机器上的 Flow 访问它，把它的 `server_config.json` 里的 `address` 设为 `[::]` 或您想要的接口，并设置 `server_cert`、`server_key`，双向 TLS 还要设置 `root_cert`，文件放在配置旁边的 `certs` 文件夹里，以此开启 TLS。您所运行版本的详细说明在 NI 的 README 中。不要让服务器默认的、不受保护的端口在工厂网络上开放：任何能连上它的人都能操作硬件。

**在节点中**，设置：

* `address` 为服务器的 `host:port`。
* `tls` 为 `off`（仅用于同一台机器上的服务器）、`on`（Flow 用 `caFile` 检查服务器证书，为空则用系统的证书颁发机构）或 `mutual`（Flow 还会出示 `certFile` 和 `keyFile`，由服务器用它的 `root_cert` 检查）。`serverName` 是服务器证书不是 `address` 中的主机时要查找的名称。
* `device` 和 `channels` 指明硬件，如 `cDAQ1Mod1` 和 `ai0:3`，或类似 `ai0, ai2` 的列表。`kind` 是 `voltage`、`current` 或 `thermocouple`，用 `min` 和 `max` 给出预期范围，用 `terminal` 给出接线方式。热电偶需要 `tcType` 和 `unit`，并使用模块自己的冷端补偿。
* `mode`、`rate` 和 `samples`。有限模式每次调用按 `rate` 为每个通道采集一次 `samples`，每次都重新开始。连续模式在第一次调用时启动任务，之后每次调用读取接下来的 `samples`，所以循环主体中的节点能一块一块地读取数据流。`trigger` 在 `/cDAQ1/PFI0` 这样的端子上由数字边沿启动任务。

`y` 是一个通道的采样数组，或数组的数组，每个通道一个，顺序与您指定通道时的顺序一致。`dt` 是采样之间的秒数，即速率的倒数，所以一块数据以秒计的长度是它的采样数乘以 `dt`：每秒 1,000 个采样，1,000 个采样覆盖 1.000 s。采样的时间照旧由设备自己的时钟确定。Flow 只负责搬运数据。服务器或驱动的拒绝会带着驱动自己的代码和文字出现在 `err` 上，在 `callTimeoutSec` 内不应答的服务器就是超时。任务在运行期间存在，运行结束时在服务器上清除，所以硬件会重新空闲。

已完成的：模拟电压输入、模拟电流输入和热电偶温度输入，有限或连续，带采样时钟和可选的数字启动触发。未完成的：数字输入输出和计数器使用不同的读取调用，尚未构建，写入、其他触发类型，以及模块本身所做之外的缩放也没有。

该节点已针对一个说同样调用、以正弦波应答的替身服务器运行过，也在裸机上运行过（2026-11-17）。

## 面板

运行时上的 `/panel/<diagram id>` 会打开一个页面，显示图的控件、指示器和图表，登录方式与编辑器相同。它是为用拇指操作而做的：上面没有任何东西比手指更小。图表默认保留最近的 1,024 个点，除非您修改，并会说明它丢弃了多少。曲线图每收到一个数组就替换它的数据。XY 图表把 x 对 y 绘制出来，同样保留历史。强度图接受一个网格，即各行长度相同的数字数组（最大 512 乘 512），并把每个值绘制成从其中最小值到最大值的颜色，每个网格都会替换整幅图；一维数组或参差不齐的网格，是节点错误连线上的一个错误。

几个人可以同时观看一次运行。从浏览器设置控件需要 `diagram.run`，在服务器上检查，并写入审计日志。

## 控件

`dia-control` 有一个**类型**（它保存什么）和一个**外观**（面板如何绘制它）。服务器按类型检查每个值，不管外观是什么，所以调用 `PUT /diagrams/{id}/controls/{node}` 的脚本和手指受同样的规则约束。操作员设置的值在图一部署后、第一次运行之前就会显示在面板上，控件节点每次运行时都会把这个值交给图。

| 类型 | 外观 | 图读取什么 |
|---|---|---|
| `number` | `entry`（键入）、`spin`（键入，带减号和加号按钮，按 `step` 递进并在范围处停止）、`slider`、`knob` | 一个数字，设置了 `min` 和 `max` 时限制在其范围内 |
| `bool` | `switch`、`button`（按一下设为 true，图读取它时由 `latch` 复位）、`led`（可以按的 LED） | 真或假 |
| `string` | 一个文本框 | 文本 |
| `enum` | `options` 的下拉列表 | 其中一个选项 |
| `array` | 操作员可以添加和移除条目的列表 | 按 `elem` 为数字、开关或文本的列表；`min` 和 `max` 限制每个数字条目，`maxlen` 限制长度 |
| `record` | 每个字段一个输入 | 恰好带有这些 `fields`（`rate:number, on:bool, note:string`）的对象，每个字段始终存在 |

slider 和 knob 需要最小值和最大值。缺少这两个值的 knob 在部署时是一个警告，在补齐之前会画成键入框（slider 本来就是这样）。knob 是一个转动 270 度的旋钮：用鼠标或手指绕着它拖动，按一下就把它放到那里，或使用方向键（一个 `step`）、Page Up 和 Page Down（十步）、Home 和 End。松手时它会写入。数组的初始值是 JSON（`[1, 2, 3]`）或简单的逗号列表（`1, 2, 3`），记录的初始值是 JSON 对象（`{"rate": 3}`）；省略的字段从空开始。没有字段的记录、未知的字段名或不匹配的初始值，在部署时是一个问题。

面板上的每个按钮、输入框、开关和旋钮，在两个方向上都至少有 44 像素，页面在 390 像素宽的手机上不会横向滚动。

控件在被修改时写入，图在控件节点运行时读取它；没有哪个控件会在被修改时自己启动一次运行或触发一个节点。那是事件结构，目前还没有构建。

## 这不是什么

图运行在通用操作系统上的 Go 进程中。垃圾回收和调度器可能让节点延迟几毫秒，所以节点无法承诺一个截止时间。必须满足截止时间的工作属于 PLC 或为此构建的运行时。数据采集设备的采样时序不受这一切影响：由设备自己的时钟负责，Flow 只负责搬运数据。

## 图的测试

流程测试文件可以在消息测试之外包含一个图的测试。它设置图的控件，用真正的图引擎运行一次，并说明它的指示器保存了什么：

```yaml
tests:
  - name: weighs and flags a heavy load
    diagram:
      name: Scale logger          # the diagram's name or id
      controls: {Limit: 10}       # by label or id, checked like an operator's entry
      expect:
        Weight: 12.5              # a number matches to within a millionth
        Heavy: true
        Reading: {min: 12, max: 13}
```

图里没有的控件、它拒绝的值、不是指示器的指示器、两个东西共用的名称，以及无法运行的图，都是带原因的错误。含有会伸到测试之外的节点（串口、仪器、数据采集设备、MQTT 输出、对 HotLoop 的写入、日志文件）的图会被拒绝，因为图的测试里没有它们的替身。用脚本模拟的串口设备，用来测试拔掉电缆或一连串垃圾帧，还没有构建。

## CI/CD 中的错误列表

`hotloop-flow test` 和部署关卡会对流程文件中的每个图运行编辑器的检查。无法运行的图会列为 `--- DIAGRAM: <diagram>: <node> input <port>: <reason>`，即使所有测试都通过，也会让文件失败；JUnit 报告把每一个作为类型为 `diagram` 的错误。警告，比如没有默认分支的分支结构，会被列出，但不会导致失败。

## 波形

波形是一块等间隔采样，它知道自己何时开始、采样间隔多大，在连线上是一条记录：`{"type": "waveform", "t0": "2026-11-14T12:00:00Z", "dt": 0.001, "y": [...], "attrs": {"unit_string": "V"}}`。`dia-wave` 用数组构建一个波形（步长取自 `dt`，没有则取 `rate`，再没有则取它的设置；起点取自 `t0`，没有则取它运行的那一刻），`dia-wave-parts` 把波形拆开，包括它跨越多长时间。波形最多保存 `maxSamples` 个采样（默认 1,048,576），其余会被截掉并计入 `dropped`。分析节点在接受数组的地方也接受波形，并使用它的步长。`dia-log-tdms` 把波形列写成带有 `wf_start_time`、`wf_increment`、`wf_samples` 的通道，并把属性写成通道属性。

## 子图

`dia-sub` 是当作节点使用的图：它的输入和输出就是连接器，每个输入是其主体中同名的 `dia-body-in`，每个输出是 `dia-body-out`。输入是必需的，除非名称以 `?`（可选）或 `~`（推荐：没有它也能运行，未连接时部署会警告）结尾。选中节点并用它们创建子图（`POST /diagrams/{id}/sub`），这些节点会移到新的主体标签页，由一个 `dia-sub` 取代它们的位置，连接器由穿过选区边缘的连线推算出来：为每个给选区供数的源输出建一个输入，为每个给外部节点供数的所选输出建一个输出。外部的连线会重新接上，所以运行得出的结果和以前一样。

## 共享记录类型

记录类型只在图标签页的设置里、`types` 之下命名一次，每个把 `shape` 设为这个名称的 `dia-bundle` 或 `dia-field` 都会按这一个定义检查：

```json
{"types": {"Reading": {"fields": {"pressure": "number", "ok": "boolean", "state": {"enum": ["idle", "run"]}}}}}
```

字段是 `number`、`integer`、`boolean`、`string`、`timestamp`、`array`、`waveform`、`record:Name`（另一个共享类型）或枚举。在定义中重命名一个字段，仍使用旧名称的每个 bundle 在下一次部署时都是一个问题，和未接线的输入出现在同一个错误列表里，并写明节点和字段。bundle 在运行时让每个值符合其字段的类型，不匹配的值由错误连线携带。`Set.Schema` 以 JSON Schema 的形式给出同一个类型，这正是带类型的连线所检查的。

## 轮转与保留

`dia-log-text` 和 `dia-log-tdms` 可以在当前文件达到 `rotateMB` 兆字节或 `rotateHours` 小时时开始一个新文件，并只保留最新的 `keep` 个已完成文件。已完成的文件取日志的名称，在扩展名之前加上关闭的时间（`bench.csv` 变成 `bench-20261114T120000Z.csv`），日志在 `bench.csv` 中继续，带新的表头，TDMS 则重新写入文件属性。保留机制只删除匹配该模式的文件，绝不删除当前的日志，也绝不删除只是放在旁边的文件。时间从一次运行首次写入该文件时算起。文本日志可以在电子表格中打开，TDMS 日志是用于大数据的二进制格式。

## 编辑分支结构与选择图

分支结构的分支是由分支名和图选择器组成的行，默认分支另有第二个选择器，指明循环或子图所运行的图的属性也是一个选择器。选择器列出流程文件中的 FlowLab 图，并保存标签页的 id；旧流程文件中手写的名称会显示为该标签页，并保存为它的 id，运行时以同样的方式读取。保存的值是和以前一样的 JSON（`cases` 是从分支名到图的对象），所以在对话框里编辑的流程文件和手工编辑的是同一个文件。

## 就地打开子图

子图节点右上角有一个小方框。点它，或者选中节点后在图工具栏里点**就地打开**，节点就会在原来的位置以展开的样子画出来：一个带有子图名称的框，两条边上标着连接器名称（输入在左，输出在右，和任何节点一样有 `after` 和 `done` 端口与错误连线），里面是它主体的节点和连线。不会在第二个窗口中打开任何东西，您所在的标签页也不会改变。原来通向节点的连线现在通向框的连接器，每个连接器名称到同名的 body in 或 body out 节点之间有一条淡淡的虚线。框标题栏里的方框（或**就地关闭**）可以再次关闭它。

框里画出来的是主体自己的节点，不是副本。选中一个，拖动它，双击查看属性，修改它的值或删除它，就等于编辑了主体，这是一个可以撤销的步骤，部署会保存它。拖动框的标题栏会移动子图节点，主体随它一起移动。连线只连接同一个图中的两个节点，所以从外部节点到内部节点的连线会被拒绝并给出说明；请接到框上的连接器。缩放、平移、适应窗口和框选与其他地方一样工作。

哪些子图是打开的，只是您查看图的方式。它不在流程文件里，不是一个撤销步骤，重新加载会全部关闭，所以打开一个子图从不会改变部署所发送的内容。打开的子图里的子图有自己的方框，也可以打开，最深三层。已经在别处打开的主体不会再打开第二次，主体通向已打开的图的子图会以关闭状态绘制，这样一个包含自己的图不会让编辑器陷入循环。没有被任何东西命名、或者被两个图共用的名称所命名的主体没有方框，因为运行时也找不到它。循环和分支结构也拥有主体，目前还不能就地打开。

## 在编辑器中创建子图

在图上选中节点后，工具栏的**所选内容转为子图**会询问名称，用编辑器持有的流程文件调用 `POST /diagrams/{id}/sub`，并把返回结果作为一次可撤销的编辑载入：这些节点移到自己的标签页，由一个子图节点取代它们的位置，它的输入和输出由穿过选区的连线推算出来。部署之前不会保存任何内容。

## 回放一次运行

高亮执行过程会让运行在进行时变慢。画布底部的**回放上次运行**会根据已记录的内容，播放一次已经结束的运行，让您事后也能跟着看。它像实时运行一样点亮连线、标记节点，一次一个事件，速度由您选（慢、正常、快或很快），结束时画布显示这次运行留下的结果。**停止回放**会提前结束它。它不会改变运行时里的任何东西，也不会启动任何东西：运行进行时按钮是关闭的，您转到另一个标签页时回放就会结束。

每次运行都会记录各节点的开始和结束，以及每个经过连线的值，最多 20,000 个事件。更长的运行保留最开始的 20,000 个，在回放时会说明，回放显示的就是这段开头，因为从中间开始的回放没有可以出发的起点。数值按连线显示的简短预览保存，所以几千个采样的数组就是它的长度和最前面的几个值。记录是上一次运行的，新的运行会替换它；重启后不会保留。`GET /diagrams/{id}/trace` 是同一份记录，供脚本使用。

## 整理布局

标签页栏里的**整理布局**会排列视野内的节点，让数据从左向右读，并且没有连线穿过节点。节点所在的列，是通向它的最长连线链。跨列的连线会得到一条穿过各列的通道，列内的节点按顺序排列以理顺交叉，然后每条长连线沿它实际绘制的曲线，与它所穿过各列中的节点逐一核对，挡路的节点会被移开。这一块保持左上角不变，整个操作是一次可撤销的编辑。接线中的环，其闭合那条连线会被排除在排序之外，所以它是反向运行的，而不会让布局陷入循环。

## 连线名称

图中的连线在中点处以它所来自的输出命名（`sum`、`result`、`iterations`），当任一端声明了类型时，类型显示在名称旁边，鼠标悬停时仍然显示它最后传送的值。

## 缩放

画布以指针为中心在 5% 到 400% 之间缩放，并把缩放值读作画布上的 `data-zoom`。

## 按名称设置面板对象

`dia-panel-set` 在图运行时按对象的标签（或它的 id）修改控件或指示器的一个属性：`visible` 和 `enabled` 取 true 或 false，`color` 取 red、amber、green、blue、gray 或 default，`label` 取文本，`min` 和 `max` 为数字控件取一个数字。被禁用的控件会拒绝操作员的设置，隐藏的对象不会绘制，操作员已经打开的面板会跟着变化。匹配不到任何对象或匹配到多个对象的名称，在节点上键入时是部署时的问题，通过连线传入时是连线上的错误，而运行从设计时的面板状态开始。

## 符号

每种 FlowLab 节点类型都在主体中间画有我们自己的符号（数学用加号，统计用西格玛，波形用正弦曲线，串口用插头），位于文字标签旁边。它们是画在 `web/src/lib/symbols.ts` 里的简单线条，不是图标字体，也不是别人的作品，当图的节点类型指向一个没有绘制的图标时，测试会失败。

## 写入设备：写入关口

图只有一种方式向设备发出命令：`dia-hotloop-write`。它通过 HotLoop 的写入关口，把它的值发送到 HotLoop 中的一个标签（`device/tag`，在节点上设置或通过连线传入），关口按自己的顺序判定写入已开启、标签已布防、值在范围内。Flow 自己从不向机器写入。HotLoop 记录每一次尝试，无论是否被拒绝，原因记为 `flow:<diagram>/<node id>`，所以它的审计记录会写明图和节点。拒绝是节点错误连线上的一个错误，带着关口自己给出的原因（代码 5006），无法访问的 HotLoop 也是这样；两种情况下写入都不会发生，未选择 HotLoop 的节点拒绝部署。原始的串口和仪器节点与台式仪器（万用表、电源、负载）通信，这些仪器在 HotLoop 中没有标签，所以它们有自己的开关（见下）。

## 仪器写入开关

读取仪器不会改变任何东西，始终是开放的。写入仪器则可能：电源的输出、耐压测试仪的高压、负载的电流。所以每台仪器都以写入**关闭**开始，来自图的写入会被拒绝，直到具有 `instrument.write` 权限的人打开该仪器的写入，一次一台仪器。

- **什么算写入。** `dia-serial-write` 始终是写入。`dia-instr-query` 的命令是查询时（其中每条 SCPI 语句都以 `?` 结尾，如 `*IDN?` 或 `MEAS:VOLT?;MEAS:CURR?`）是读取，否则（`OUTP ON`、`VOLT 5`、`*RST` 或 `VOLT 5;MEAS:VOLT?`）是写入。通过连线传入的命令按可能写入来计。
- **哪台仪器。** 仪器就是它的地址：`tcp://host:port` 或 `serial:///dev/ttyUSB0`，不含串口设置，所以以两种方式打开的同一台仪器只有一个开关。
- **拒绝**是节点错误连线上的一个错误（代码 5007），说明对该仪器的写入已关闭，仪器永远听不到这条命令。
- **打开它。** 用 `{"instrument": "tcp://10.0.0.5:5025", "allowed": true, "note": "bench 2"}` 调用 `PUT /instruments/writes`，需要 `instrument.write`（管理员拥有），并保存在数据目录的 `instrument-writes.json` 中，所以重启不会改变任何东西。`GET /instruments` 列出每台带有开关、或有已部署的图会向它写入的仪器，包括设置人，以及相关的图和节点。
- **审计。** 每次开关变更是 `instrument.switch`，图的每次写入是 `instrument.write`，被拒绝时是 `instrument.refused`，并带有图、节点、仪器和命令。
- **部署会提示。** 会向仪器写入的节点是图上的一条说明（工具栏的**说明**，以及 `hotloop-flow test` 打印的列表），指明仪器并说明在有人打开之前它的写入是关闭的。只读取的流程文件不受影响。

## 导入 LabVIEW VI

在编辑器的导入对话框里导入 `.vi`（或通过 MCP 的 `import_vi`，或 `POST /flows/import-vi`），FlowLab 会读取它能读的内容，并在添加任何东西之前列出它没能读取的内容。请阅读 docs/labview-import.md：里面准确说明了哪些内容会导入、哪些不会。简单说：VI 的名称、描述、版本、前面板名称，以及它调用的 VI 会导入，作为一个独立流程上的说明。框图的连线和基本函数不会导入，所以图需要您自己画，旁边留着这些名称。
