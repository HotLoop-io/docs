代码里任何地方都没有许可证检查。每个阶段结束的标准，是它的“真实”清单已经在真实系统上做完，而不是代码能编译。

## 0.1.0，MVP

已完成。引擎、持久化执行、Postgres 队列和 worker、表达式、关在隔离环境里的 Code 步骤、凭据保险库和 OAuth2、Webhook、计划任务和 MQTT、强制 MFA 的用户、OIDC、项目和 RBAC、审计、版本历史、API、编辑器、已批准清单中的连接器、工作流导入、指标和追踪、Helm chart 和 Quadlet 单元。按 `RELEASE_CHECKLIST.md` 发布，此前不发。

## 0.2.0，身份与治理

已完成，随新编辑器一起包含在 1.0.0 中发布。SAML、LDAP 和 AD、SCIM、自定义角色、外部密钥、日志流、变量、文件夹、分析、执行注释、S3 和 Azure 的 blob 后端，以及执行内容脱敏策略。每一项都对着它所连接的真实服务器试过，每一项在编辑器里都有自己的界面。

## 1.0.x 带来了什么

1.0.0 是 0.1.0 加上 0.2.0 再加上新的编辑器，全在一个版本里。编辑器是我们在把名字署在这个版本号下之前想要的最后一块。

1.0.1 修复了登录中的一个错误：数据库读不出来时，系统会回答“未登录”并清除 Cookie，于是一次短暂故障会让所有人退出登录，还可能把正确的第二重验证变成错误的验证码。现在它回答“请重试”并保留会话。1.0.2 让 Code 步骤能用保存为凭据的 HMAC 密钥签名和验证，并让 Webhook 指定哪些网页来源可以从浏览器调用它。1.0.0 到 1.0.2 之间没有需要迁移的内容。

已保存的工作流如今遵守的规则：文件会说明自己属于其格式的哪个版本（`cascade: 1`），每个步骤都带有自己的版本，而引用了一个已不存在的步骤的工作流不会被悄悄修改，而是校验失败、不会启动。1.0.0 中移除 EmberOps 步骤就是这样做的。每个版本在发布前都会在上一个版本的数据上启动一遍：工作流仍然在，凭据仍然能打开。

## 1.3.0，14 种语言的编辑器

已完成。英语、西班牙语、法语、意大利语、德语、书面挪威语、保加利亚语、希腊语、韩语、日语、越南语、印地语、简体中文和阿拉伯语。顶部栏和登录页有语言选择器；每个界面、步骤标题和帮助、以及服务器的拒绝信息都已翻译；日期、数字和时长跟随语言；阿拉伯语从右向左书写，画布和代码仍从左向右。每种语言都在真实浏览器里，以桌面和手机两种宽度在每个界面上试过，缺一行的语言会被构建拒绝。用词来自 HotLoop 共用术语表。

## 1.5.0，删除一个人

已构建。实例所有者可以在用户页、REST API（`DELETE /api/v1/users/{user}`）或 MCP 服务器（`delete_user`）中删除一个人。其账户、会话、通行密钥、登录身份和 API 密钥都会消失，审计日志会记录是谁做的以及什么被删除了。其工作流、凭据和运行记录会保留：个人项目会变成以其名字命名并带有“(removed)”的共享项目，由所有者或管理员转移工作或交接给他人。任何人都不能删除自己的账户，最后一位所有者也不能被删除。停用某人的功能仍然保留，用于您想保留账户的情况。

## 1.4.2，登录页面

已构建。登录页面是安静页面上居中的一张卡片，上方是产品标志和名称，主按钮采用 HotLoop 橙色，其他登录方式（通行密钥、单点登录）是旁边的简洁按钮，浅色、深色以及手机上都是如此。当提供方是 Vord 时，单点登录按钮会带上其提供方的图标。每个字段、id 和登录路径都和以前一样。

## 1.4.1，设置页面

已完成。当保存的响应在用户修改字段之后才到达时，设置页面不再把该字段改回去：仍然保持已发送内容的字段会采用服务器的值，之后被编辑过的字段则保留编辑。另外，语言文件夹里的审阅清单已经没有了。

## 1.4.0，等待、保留、限制和备份

已完成。比数据库先启动的 pod（chart 在拆分形态下就是这样）现在会等待数据库并说明情况，而不是重启两三次（在 chart 测试中，安装没有出现重启）。还有保留：一个设置，决定已完成的执行保留多少天，默认关闭；以及每小时一次的清理，把较旧的执行连同其步骤数据一起删除。同一次清理还会删除 blob 存储中不再有任何执行指向的文件：数据库放不下的过大输出和附件，共用的文件只有在最后一个使用它的执行消失时才删除。还有针对每个 API 密钥的速率限制，通过 API 和 MCP 都生效，默认关闭，超限时返回 429 并告知需要等待多久。（Webhook 有自己的限制，账户在多次输错密码后会锁定，和以前一样。）还有 `hotloop-cascade backup` 和 `restore`：SQLite 数据库、密钥和 blob 文件，附带哈希清单；对 PostgreSQL 则是密钥和 blob，再加上用于数据库那一半的 `pg_dump` 命令。

## 1.2.0，MCP 服务器的最后四个工具

已完成。MCP 服务器之前缺四条密钥可以调用的路由：列出和撤销自己的密钥、打开某个工作流的测试 Webhook、发起 OAuth2 登录。现在它们都是工具了，一共 83 个，各自通过自己的路由，所以适用与编辑器相同的权限检查。需要有人登录的十条路由（创建密钥、SCIM 令牌、密钥提供方和日志目的地，以及您自己的密码）仍然排除在外，因为能创建它们的密钥可以让自己一直有效；MCP 页面说明了是哪些以及原因。

## 1.1.0，MCP 和缺少的界面

已完成，这就是该版本。位于 `/mcp` 的 MCP 服务器：79 个工具，每个都是 REST API 的一条路由，所以由路由自己的处理程序检查权限、校验请求体、执行修改并写入审计记录。它默认开启并支持读写，和 HotLoop 系列中的每个 MCP 一样，它的两个开关属于部署本身（`HOTLOOP_CASCADE_MCP`、`HOTLOOP_CASCADE_MCP_WRITES`），任何工具和路由都改不了。MCP 页面列出了每个工具及其要求。

还有编辑器缺少的界面：凭据、项目（成员和服务账户）、用户、审计日志、设置，以及带有 API 密钥的账户页面，每个界面的权限都与 API 相同，并以每一种角色在真实浏览器里试过。登录页现在属于编辑器，使用它的配色和字体，不再是旧的 Go 页面。

## 1.6.0，审批、AI、Git 与连接器

已完成。此前在本页列为未构建的四件事在同一个版本里到来：带有人工审批步骤的表单、AI 步骤、带环境和受保护实例的 Git 源代码管理，以及声明式连接器规范及其配套工具。每一项在下面都有各自的章节。

## 带有人工审批步骤的表单

已完成。请求审批步骤会暂停一次运行并询问一个人。对方在手机上打开这次运行的审批链接，阅读您写的内容，如有表单就填写，然后点击批准或拒绝；运行从“已批准”或“已拒绝”继续，并带上谁回答、何时回答以及说了什么，Cascade 会把答复保存为一条记录，可在编辑器、API（`GET /api/v1/approvals`）和 MCP 服务器（`list_approvals`）中查看，每条都有一行审计。该页面是不含脚本的纯 HTML，提供编辑器的十四种语言。它以审批人输入的姓名或其已登录的账号来标识审批人。

## Git 源代码管理、环境与受保护实例

已完成。项目的工作流保存在 Git 仓库中，每个一个文件，以工作流命名并带有其 id。push 写入它们并以执行 push 的人的身份提交；pull 让项目与仓库保持一致，保留 id，新工作流保持关闭，已更改的变成新版本，而两边都改过的内容除非您说明谁优先，否则不去动它。这是项目上的一个界面、六个 API 路由和六个 MCP 工具。可以给实例起个名字，显示在每个界面顶部，而受保护的实例不允许在编辑器、API 或 MCP 中手动创建、编辑、恢复或删除其工作流：它们通过从 Git pull 而来，凭据、变量、运行以及开启或关闭工作流则保持开放。

## 规模

这个阶段已经做的：Webhook 角色（chart 拆分形态中它自己的 Deployment）、每个工作流的并发限制，以及多个 main 对一个数据库。我们还没做的，是为这个阶段设定的测试：在分钟级计划任务期间杀掉一个 main，并在一小时内没有发现任何重复或遗漏的执行。

## 连接器

已批准清单中已经做好的连接器都在了：HTTP、ntfy、Discord、Gotify、电子邮件、HotLoop、MQTT、数据库、文件，以及 S3 和 Azure 的 blob 存储。EmberOps 连接器在 0.1.x 中存在，1.0.0 中已移除。

现在连接器可以是一个文件：声明式连接器规范已经发布（一种带版本的格式，附 JSON Schema），文件所描述的任何 API 都会变成无需代码的步骤。用于编写、试用、发布和安装连接器的工具都在二进制文件里（`connector init`、`validate`、`call`、`index` 和 `install`），而索引是任何人都能托管的静态文件，每个文件都有哈希。

## AI 步骤

已完成。询问模型和运行智能体。模型是您自己的，可以是 Ollama 这样的本地服务器，也可以是使用您自己密钥的托管服务，由凭据指定，OpenAI 和 Anthropic 两种协议都支持。智能体把其他工作流当作工具使用，并在回合之间在数据库中等待。

未构建，未排期：用您的模型来编写工作流的助手。没有托管服务，以后也不会有。（MCP 服务器可以让智能体从外部操作 Cascade，已经构建完成：见 1.1.0。）

## 新编辑器界面

已完成，包含在 1.0.0 中。编辑器用 Astro 搭配 Svelte 孤岛重写，构建为静态资源，并像旧版一样内嵌在 Go 二进制文件里，所以仍是同一个“一个二进制文件”的方案，没有任何需要新运行的东西。它的配色、字体和标志取自 HotLoop 品牌文件，并跟随系统的浅色或深色模式。旧编辑器的每个界面都在其中，功能也和原来一样（画布代码原样迁移），0.2.0 的功能都有界面，还有一个浏览器测试在真实的 Chrome 里对着真实服务器逐一操作它们。这些都没有改动 API、文件格式或 Go 这一侧。
