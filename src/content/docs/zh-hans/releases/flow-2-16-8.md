HotLoop Flow 2.16.8 让你从 Node-RED 带过来的流程像在那里一样运行，并确保一个古怪的值永远不会让你工厂的 Flow 宕机。你的流程、设置和图表都没有任何变化。

## 变更内容

- **包含自身的值不再让 Flow 停止。** Node-RED 允许 change 节点把一个列表写进它自己，例如把 `msg.payload[0]` 设为 `msg.payload`，并继续运行。Flow 过去会沿着这个循环一直走，直到栈耗尽，整个进程退出。现在循环会在它回到自身的地方被切断，那个节点像任何其他节点错误一样报告“值引用了它自己”，其他所有流程继续运行。同样的保护也覆盖返回、发送或设置这种值的 function 节点。我们用一家真实工厂的流程复现了它，13,737 个节点应答一个 Modbus 模拟器：旧版本在一分钟内就挂了，这个版本继续运行。
- **function 节点支持现代 JavaScript。** `await`、函数体返回的 promise、会扣住第一条消息直到其完成的 Setup promise，以及 `node.linkcall` 都能工作，所以为 Node-RED 4 编写的函数可以按原样运行。没有任何 Catch 节点接手的错误会被标记为未处理，和 Node-RED 的标记方式一样。
- **Node-RED 自带的示例流程给出 Node-RED 的输出。** 全部 62 个已录制的示例现在都与真实 Node-RED 的结果一致。这个版本修复了 switch 写入的部分计数、csv 节点盖在其行上的类型、csv 的 `msg.columns` 和 `msg.reset`，以及 delay 所扣住的消息的重置和清空。
- **FlowLab 可以读取 LabVIEW VI 的框图。** 节点、连线、常量、控件、指示器和结构体都会被带过来，FlowLab 没有对应物的东西会作为一个有名字的节点保持可见，让你看到框图在哪里止步。
- **更大但仍自包含的二进制。** Flow 仍然是内含编辑器的单个静态二进制。现在它被允许增长到 58 MiB，以容纳以上所有内容。

## 新设置

无。

## 升级

对 2.16.8 的镜像和图表做一次普通的 `helm upgrade`，或在你的 Quadlet 单元里换上新标签。首次启动不会发生任何事，也无需迁移。流程文件和以前一样按字节加载和保存。这个版本构建 amd64 镜像。`2.16` 和 `2` 标签保留它们已从 2.16.1 获得的 arm64 镜像，一个别无他物的小型后续版本会把 arm64 带回来。如果你在 arm64 上，在那之前请留在 2.16.1。

镜像：`ghcr.io/hotloop-io/hotloop-flow:2.16.8`，linux/amd64。Chart：`https://hotloop.io/hotloop-flow/`。这个标签的 README 有其余内容，还配有图片：https://github.com/HotLoop-io/hotloop-flow/blob/v2.16.8/README.md
