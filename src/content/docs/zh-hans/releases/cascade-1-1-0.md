## 这是什么

1.1.0 为 Cascade 带来了 MCP 服务器和编辑器缺少的界面,并把登录移到了编辑器里。引擎、工作流文件格式和 REST API 与 1.0.2 一致。

## MCP 服务器

它位于 `/mcp`,与 API 同一个地址,默认开启并且可写。HotLoop 系列的每个 MCP 都能读写,Cascade 是最后一个完全没有 MCP 的产品。

智能体用 API 密钥登录,得到该密钥持有者能做的事,再按密钥的作用域收窄。一共有 79 个工具,每个都是 REST API 的一条路由:一次调用经过该路由自己的处理程序,所以权限检查、验证、写入和审计行都是路由的。没有任何东西被复制到 MCP 服务器,所以不会产生偏差,也没有遗漏任何东西,所以不会跳过任何环节。

- 会更改内容的工具需要一个 `reason`,审计日志把它与更改保存在一起,连同密钥和客户端给自己起的名字。
- 凭据的密钥永远不会返回给任何人。通过 MCP 创建的凭据,其密钥在到达时就被加密封存。
- `HOTLOOP_CASCADE_MCP` 和 `HOTLOOP_CASCADE_MCP_WRITES` 是部署的开关,默认都开启。没有任何工具或 API 路由能更改它们,所以能编辑实例设置的智能体也无法重新开启写入。
- 自己会拒绝密钥的路由(创建 API 密钥、SCIM 令牌、密钥提供商和日志目标)不是工具,因为能创建密钥的密钥,就是会让自己一直存活的泄露密钥。MCP 页面列出了所有工具及每个工具所需的权限。

## 界面

凭据、项目、你的账户,以及面向所有者和管理员的设置、用户和审计日志。每个界面都遵循与 API 相同的权限:每个人只会看到其角色允许的内容,其余的服务器仍然会拒绝。

- **凭据** 可以创建、打开、更改、与其他项目共享和删除。密钥只输入一次,界面只会显示已设置。
- **项目** 包含成员及其角色,以及常驻集成用来登录的服务账户密钥,只显示一次。
- **账户** 创建和撤销你的 API 密钥(API 和 MCP 用它登录),并修改你的密码。
- **用户** 创建人员并停用或启用他们。**审计日志** 可以阅读、筛选,并检查是否被篡改。**设置** 包含第二重验证要求和错误工作流。

登录现在是编辑器自己的页面,位于 `/login`,使用编辑器的配色,支持浅色和深色,手机和桌面上都一样。旧页面能做的它都能做:首次运行设置、密码、目录账户、单点登录、通行密钥、第二重验证和恢复代码。

## 为什么只有 amd64

这个版本只构建 amd64。多架构在单独的一次运行中发布,所以这个版本之后的那个版本是一次小的版本号提升,同时构建两种架构。在此之前,`stable`、`latest` 和短标签会把这个 amd64 镜像和它们原来指向的 arm64 镜像一起列出,所以 arm 机器仍然能拉取。版本标签 `1.1.0` 只有 amd64。

## 升级与回退

没有迁移。把 1.1.0 `helm upgrade` 上去,或者让 `:stable` 推进 Quadlet 单元。放回 1.0.2 是安全的,因为数据库里没有任何变化。回滚无法撤销的是智能体已经做过的事:它的更改依然有效,它写入的审计行会以参与者类型 `mcp` 留在日志里。任何更新之前先备份,仍然是个好习惯。
