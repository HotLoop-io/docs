## 这是什么

1.2.0 补全了 MCP 服务器的工具列表。引擎、工作流文件格式、界面和 REST API 与 1.1.1 一致。

## 四个工具

HotLoop 系列的每个 MCP 都能读写,而 Cascade 的 MCP 漏掉了四条密钥可以调用的路由。它们现在是工具了,一共 83 个:

- `list_keys` 和 `revoke_key`:密钥所属者的密钥,以及撤销其中一个。密钥可以撤销它自己,这是泄露密钥的持有者首先应该能做的事。调用者可以撤销谁的密钥,由路由自己的检查决定,与编辑器相同。
- `listen_workflow`:为一次调用打开工作流的测试 Webhook URL,时长 1 到 600 秒。
- `start_oauth`:返回一个地址,人打开它即可为 OAuth2 凭据登录。仍然需要这个人点头同意。

每个工具都经过自己的路由,所以权限检查、验证和审计行都是路由的,写入类工具和其他写入工具一样需要一个理由。

## 不包含的内容

有十条路由会自己拒绝密钥,因为它们要求有人登录:创建 API 密钥或服务账户密钥、创建 SCIM 令牌、添加、更改或删除密钥提供商或日志目标,以及你自己的密码。能创建密钥,或能更改审计日志去向的密钥,就是会让自己一直存活的泄露密钥。MCP 页面里有列表和原因。

## 为什么只有 amd64

这个版本只构建 amd64。多架构在单独的一次运行中发布,所以这个版本之后的那个版本是一次小的版本号提升,同时构建两种架构。

## 升级与回退

没有迁移。把 1.2.0 `helm upgrade` 上去,或者让 `:stable` 推进 Quadlet 单元。放回 1.1.1 是安全的,因为数据库里没有任何变化。回滚无法撤销的是智能体已经用新工具做过的事。
