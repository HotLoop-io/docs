HotLoop Flow 2.10.0 让 FlowLab 向真正的工作台前进了一大步:可以与之对话的仪器、分支结构、波形、共享记录类型、子图表、日志轮转以及 持续集成中的图表错误列表。智能体现在可以通过 MCP 列出、读取、部署和回滚流程。它还修复了持久 MQTT 输出可能把一条消息发送两次的一种情形。

## 新功能

- **Flow 自己的 MCP 工具。** 在同一个 `/mcp` 上有七个内置工具,与各流程自己的工具并列:`list_flows`、`get_flows`、`get_flow`、`deploy_flows`、`list_deployments`、`rollback_deployment` 和 `inject_node`。每个工具都以端点所认证的调用方身份运行管理 API 自己的处理程序,所以来自智能体的部署会遇到编辑器部署会遇到的一切:修订检查、带类型的连线、插件拒绝和失败的流程测试。调用方需要 `mcp.call` 和该工具自己的权限(`flows.read`、`flows.write` 或 `inject.write`),它无权调用的工具不会出现在它的列表里。它们在部署之后依然保留,流程不能提供与它们同名的服务。README 中有表格。
- **仪器。** 通过原始套接字或串口的仪器会话、一个查询节点和 SCPI 解析器,使图表可以向仪表请求读数并解析回答。
- **分支结构。** `dia-case` 只运行其选择器选中的主体:布尔值、数字、字符串或枚举,并带有默认分支。没有任何分支命名的值,在没有默认分支时是节点错误连线上的错误,没有默认分支时部署会给出警告。
- **波形。** 波形是一块知道自己何时开始、采样间隔多大的采样数据。`dia-wave` 构建一个,`dia-wave-parts` 拆开一个。大小上限默认在 1,048,576 个采样处截断波形,并统计被丢弃的部分。分析节点在接受数组的地方接受波形并使用它的步长,TDMS 日志会写入 `wf_start_time`、`wf_increment`、`wf_samples` 及其属性。
- **共享记录类型。** 在图表标签页上为记录类型命名一次,然后在 `dia-bundle` 或 `dia-field` 上设置 `shape` 来使用它。在类型中重命名字段后,每个仍使用旧名称的地方都会在下一次部署时成为问题。bundle 在运行时让每个值符合其字段的类型。类型也可以作为 JSON Schema 获得。
- **子图表。** `dia-sub` 是用作节点的图表,带有命名的输入和输出。以 `?` 结尾的名称是可选的,以 `~` 结尾的名称是推荐的,没有连线时部署会给出警告。`POST /diagrams/{id}/sub` 接收一个流程文件和一个选择,返回把这些节点剪切成子图表的流程文件,连接器由穿过边缘的连线推算得出。
- **日志轮转和保留。** 文本日志和 TDMS 日志节点可以在 `rotateMB` 兆字节或 `rotateHours` 小时时开始新文件,并保留最新的 `keep` 个已完成文件。已完成的文件使用日志的名称,并在扩展名之前加上它关闭的时间。
- **持续集成中的图表错误列表。** `hotloop-flow test` 和部署闸门会对流程文件中的每个图表运行编辑器的检查,并列出每个无法运行的图表,附带其图表、节点和输入。

## 变更内容

- **`hotloop-flow test` 现在可以让一个所有测试都通过的文件失败。** 如果流程文件中的某个图表无法运行(有一个没人连线的输入,或有一个永远不说停止的主体),该文件就会失败,体现在文本输出、JSON、JUnit 报告和部署闸门中。没有图表的流程文件行为和以前一样。警告会被列出,但不会导致失败。
- **Flow 把堆保持在容器的内存上限之内。** 启动时 Flow 读取其 cgroup 内存上限,并把 Go 堆限制在其 85%,所以大的流程文件会在达到上限之前被回收,而不是被 OOM 终止。环境中的 `GOMEMLIMIT` 仍然优先,启动日志会说明适用哪个上限。在一家有 74 个标签页、13,727 个节点的工厂中观察到过,它在 2Gi 上限下、活动堆接近 800 MiB 时不断重启。
- **持久 MQTT 输出在重连后不再把消息发送两次。** 重连后,客户端在重放其存储之前就把链路标记为已连接,在这个间隙中交付的一次发布会发出两次,而第二次背后没有未确认的发送。现在输出会等到重放取好快照之后。已检查过 MQTT 5 连接,它们没有这个间隙。

## 新设置

在日志节点上：`rotateMB`、`rotateHours` 和 `keep`，默认全部关闭。在 `dia-wave` 上：`maxSamples`，默认 1,048,576。在 `dia-bundle` 和 `dia-field` 上：`shape`。在 `dia-sub` 上：`body`、`ins` 和 `outs`。

## 升级

对 2.10.0 的镜像和图表做一次普通的 `helm upgrade`，或在你的 Quadlet 单元里换上新标签。首次启动不会发生任何事，也无需迁移。2.9.1 的流程文件按字节加载和保存。请检查任何对含图的流程文件运行 `hotloop-flow test` 的 持续集成作业：无法运行的图现在会让文件失败。

镜像：`ghcr.io/hotloop-io/hotloop-flow:2.10.0`，先发布 linux/amd64，arm64 在 2.10.1 中跟进。Chart：`https://hotloop.io/hotloop-flow/`。这个标签的 README 有其余内容，还配有图片：https://github.com/HotLoop-io/hotloop-flow/blob/v2.10.0/README.md
