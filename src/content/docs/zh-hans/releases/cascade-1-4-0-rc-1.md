这是 1.4.0 的候选发布版本。它不会移动 `stable`、`latest`、`1.4` 或 `1` 标签,也不在 App Store 索引中,所以默认没有任何东西会拉取它。它就是 1.4.0 将发布的代码,在真正的标签之前已在真实的 Podman 主机上拉取并运行过,而 1.4.0 将是这份代码,只更改了版本字符串。请阅读 1.4.0 的说明了解其中包含什么。

## 这是什么

1.4.0 让 Cascade 安装更容易长期运行:服务器会等待数据库而不是崩溃,已完成的运行可以保留若干天并连同文件一起清理,所有者可以限制一个 API 密钥的调用频率,整个实例可以备份和恢复。它还完成了路线图上唯一没做完的规模测试。引擎、工作流文件格式、REST API、MCP 服务器(83 个工具)和 14 种语言与 1.3.0 一致。

## 等待数据库

在拆分安装中(PostgreSQL 上的 server、worker 和 webhook pod),pod 过去会在数据库名称解析之前启动,并在就绪前重启两三次。1.2.1 和 1.3.0 也是如此。现在,连不上数据库的 server、worker 或 webhook 会在日志里说明("waiting for the database",并带上已等待的时间),最多重试五分钟,数据库响应后再连接。错误的密码、格式错误的地址或不存在的数据库仍会让它立刻停止,因为等待解决不了这些问题。chart 的启动探针与程序等待同样久。在真实 k3s 上全新的拆分安装,在 chart 测试的三次运行中都没有出现重启。

## 保留已完成的运行

设置里新增了一个字段,已完成的运行保留天数(天),`PATCH /api/v1/settings` 接受 `retentionDays`。默认关闭(0),所有运行照常保留。设置一个数字后,每小时一次,主节点会删除结束时间早于该天数的成功、失败和已取消的运行,连同它们的步骤数据。仍在进行的运行不会被碰,父运行仍在进行的运行也不会。每一批都会在审计日志里写入 `execution.pruned`,更改设置会写入 `instance.retention`。

同样的每小时处理现在也会清理 Blob 存储,无论是否开启保留:数据库放不下的过大输出,以及不再被任何运行引用的附件。两个运行共用的文件会保留到最后一个运行消失,而且只会检查 24 小时前写入的文件,所以步骤刚存储的文件永远不会被删除。这对你手动删除的运行也是新的;以前,删除运行会让它的大输出永远留在磁盘上。读不到所需内容的处理不会删除任何东西,每次处理都会在审计日志里写入 `blobs.collected`。

## 每个 API 密钥的限制

设置里新增了一个字段,每个密钥每分钟的 API 请求数,`PATCH /api/v1/settings` 接受 `apiRateLimit`。默认关闭。设置一个数字后,每个 API 密钥,以及用密钥通过 MCP 登录的每个智能体,每分钟最多可以发出这么多请求。超出限制的调用会得到带 `Retry-After` 的 429。每个密钥有自己的计数,登录编辑器的人不受它限制。计数属于各自的进程,所以有三个主节点时,一个密钥最多可以做到该数字的三倍。更改它会在审计日志里写入 `instance.api_rate_limit`。

## 备份与恢复

`hotloop-cascade backup DIR` 会写入一个新目录,其中包含服务器运行时取得的一致的 SQLite 数据库副本、加密封存所有已存储凭据的密钥文件、Blob 文件,以及记录它们哈希的 `manifest.json`。`hotloop-cascade restore DIR` 会在对照清单检查每个文件之后把它们放回去,并且除非你指定 `--replace`,否则拒绝覆盖数据库或不同的密钥。对于 PostgreSQL,备份包含密钥、Blob 和清单,并打印数据库那一半所用的 `pg_dump` 命令;恢复会打印 `pg_restore` 的命令。保存在 S3 或 Azure 的 Blob 不会被复制。详情见 `docs/GOVERNANCE.md`。

## 支撑它的测试

- 路线图设定的规模测试已完成。一个 PostgreSQL 上的两个主节点运行了一个小时一个每分钟触发的工作流,期间其中一个在时间槽边界被 SIGKILL 终止,连续七次,每次停机约 25 秒:61 个分钟时间槽对应 61 次运行,没有漏掉,也没有重复。
- 测试栈的 OAuth 服务器(Hydra)现在运行在 Postgres 上。它以前在并行运行时失败,改后通过,把改动还原后又失败。Cascade 的代码不检查令牌。
- chart 测试现在会在安装时有 pod 重启就失败。
- 两条新的设置拒绝信息已在每种语言中翻译,设置帮助里说明大输出会随运行一起删除。

## 为什么只有 amd64

这个版本只构建 amd64。多架构在单独的一次运行中发布,所以这个版本之后的那个版本是一次小的版本号提升,同时构建两种架构。`stable`、`latest`、`1.4` 和 `1` 会把新的 amd64 镜像和它们原来指向的 arm64 镜像一起列出。

## 升级与回退

没有迁移:架构与 1.3.0 相同。把 1.4.0 `helm upgrade` 上去,或者让 `:stable` 推进 Quadlet 单元。放回 1.3.1 是安全的,因为数据库里没有任何变化。回滚无法撤销的是清理:被保留策略删除的运行已经没了,每小时清理移除的 Blob 也一样。保留在你开启之前是关闭的,所以请先备份;Blob 清理在没有保留的情况下也会运行。
