HotLoop Flow 2.12.0 完成了 FlowLab 的面板和画布:旋钮、微调输入、LED、数组和记录现在都是真正的控件,子图表在画布上原位打开,而不是要追着跑的第二个标签页,每台仪器的写入在有人打开之前都是关闭的。它还修复了无法在第一次运行之前设置的控件,并带来新的许可证。如果您的图表会驱动仪器,请在升级之前阅读“变更内容”。

## 新功能

- **完善的面板控件。** 旋钮是一个可转动 270 度的表盘:用手指或鼠标绕着它拖动,按在它上面把它放到那里,或使用方向键(一步)、Page Up 和 Page Down(十步)、Home 和 End,松手时写入。微调外观是一个输入的数字,带减号和加号按钮,按 `step` 递进并停在范围的两端。开关的 LED 外观是一个可以按的 LED。**数组**控件是操作员可以增删项的数字、开关或文本列表,由 `elem`、`min`、`max` 和 `maxlen` 决定。**记录**控件是 `fields`(`rate:number, on:bool, note:string`)中每个字段对应一个输入,图表读取包含所有字段的对象。无论用什么方式设置,服务器都会让每个控件符合其类型和范围,并指出哪一项或哪个字段有误。面板上每个控件的触控目标在各个方向上至少 44 像素,页面在 390 像素宽时不会横向滚动。
- **子图表原位打开。** 子图表节点的角上有一个小框,图表栏中有针对所选节点的**就地打开**。节点在原来的位置以打开的样子绘制:一个框架,左右边缘标出其连接器名称,里面是主体的节点和连线。它们是主体自己的节点,所以移动一个、双击查看其属性、连接两个、删除一个或在几个节点上框选,都是在编辑主体,按可撤销的步骤进行,部署时会保存。关闭后节点回到原位。已打开的子图表可以包含已打开的子图表,最深三层,通向已经打开的子图表的主体会以关闭的样子绘制,这样包含自身的图表就不会让编辑器陷入循环。哪些是打开的,取决于您如何查看图表:它不在流程文件里,所以部署发送的和以前一样。
- **仪器写入开关。** 读取仪器不会改变任何东西,始终开放。写入仪器则可能改变,所以每台仪器起初都关闭写入,来自图表的写入会被拒绝,直到拥有 `instrument.write` 权限的人打开该仪器的写入。`dia-serial-write` 始终是写入。`dia-instr-query` 在其中每条 SCPI 语句都以 `?` 结尾时是读取,否则是写入,而从外部接入的命令算作可能写入的命令。仪器就是它的地址(`tcp://host:port` 或 `serial:///dev/ttyUSB0`),所以以两种方式打开的同一台仪器是一个开关。拒绝是节点错误连线上的错误(代码 5007),仪器永远听不到这条命令。`PUT /instruments/writes` 配合 `{"instrument": "tcp://10.0.0.5:5025", "allowed": true, "note": "bench 2"}` 打开一个,`GET /instruments` 列出它们,开关保存在数据目录的 `instrument-writes.json` 中。每次开关变更都以 `instrument.switch` 审计,每次写入以 `instrument.write` 审计,每次拒绝以 `instrument.refused` 审计。部署会在图表栏的说明中列出图表将要写入的仪器。

## 变更内容

- **驱动仪器的图表会停下来,直到您打开该仪器。** 在 2.11.x 上,原始串口和仪器节点可以写入任何东西。在 2.12.0 上,第一次写入会被以代码 5007 拒绝,直到管理员(或任何拥有 `instrument.write` 的人)打开该仪器的写入。只读取的图表不受影响。这是有意为之,2.11.0 的说明已经说过它会来,它也是此版本中可能让运行中的图表停下来的变更。
- **旋钮和 LED 外观画出的就是它们的名字所说的样子。** 带旋钮外观和范围的数字控件以前画一个输入框,现在画表盘。带 LED 外观的开关以前画一个复选框,现在画 LED 按钮。没有最小值和最大值的旋钮仍然画输入框,部署现在会在图表的说明中说明这一点。滑块不变。
- **控件可以在第一次运行之前设置。** 面板过去只有在运行开始时才知道它的控件,所以先设置一个会被以“is not a control on this panel”拒绝。现在它从已部署的图表中得知控件,而对于部署改动过的控件,已不再适用的已存值会回到控件的起始值。
- **画布。** 在已适配视图的画布上画出的框选,在内容比画布高时,可能从指针移动到的位置以外的地方开始,现已修复。在窄于 820 像素的屏幕上,FlowLab 栏过去会折成很多行并压在所有节点上方。现在它在那里有了自己的空间。更宽的屏幕和以前一样绘制。
- **许可证。** `LICENSE`、`NOTICE` 和镜像的许可证标签从 Business Source License 1.1 改为 EmberNet Source License 1.0（`LicenseRef-EmberNet-Source-1.0`）。它们随镜像一起发布，位于 `/usr/share/doc/hotloop-flow`。在此之前发布的版本保持其发布时的条款。在依赖它之前，请阅读此版本中的 `LICENSE`。
- 其他方面与 2.11.1 的行为没有不同。

## 新设置

配置文件和环境变量中都没有。`dia-control` 接受 `array` 和 `record` 两种类型、`spin` 外观，以及 `elem`、`maxlen` 和 `fields` 属性。权限 `instrument.write` 和数据目录中的文件 `instrument-writes.json` 是仪器开关。就地打开子图没有设置。

## 升级

只需对 2.12.0 的镜像和 chart 执行一次 `helm upgrade`,或在您的 Quadlet 单元里换上新标签。首次启动时不会发生任何事,也不需要迁移:每台仪器起初都关闭写入,在有人打开一个之前不会有文件。此版本先发布 amd64,arm64 构建随 2.12.1 跟上,所以 arm64 机器在此之前留在 2.11.1。打开某台仪器的写入会连同操作人一起记入审计日志,所以请为它留一条备注。

镜像：`ghcr.io/hotloop-io/hotloop-flow:2.12.0`，先发布 linux/amd64，arm64 在 2.12.1 中跟进。Chart：`https://hotloop.io/hotloop-flow/`。这个标签的 README 有其余内容，还配有图片：https://github.com/HotLoop-io/hotloop-flow/blob/v2.12.0/README.md
