HotLoop Flow 2.14.0 让智能体通过 MCP 触达 Flow 的其余部分，并在中断之后分批而不是一条一条地排空积压。它新增 22 个 MCP 工具、一个列出全部 29 个的页面，以及让持久连线更快赶上一个离线过的 InfluxDB 的方法。它先发 amd64，arm64 随 2.14.1 跟进。

## 新功能

- **面向其余管理 API 的 MCP 工具。** Flow 自带的工具覆盖了流程，但没有覆盖它周边的东西：列出、读取、部署、回滚和按下一个 inject 节点。又增加了 22 个，所以智能体可以读取设置、节点面板和插件，读取审计日志，读取一次部署以及两次之间的变化，把草稿与正在运行的内容做差异比较并检查类型，导出流程，读取、替换和添加流程测试并运行它们，读取消息追踪并据此起草一个测试，回放追踪，读取运行时的数字，以及关闭某个用户的第二重验证（`reset_mfa`，需要 `auth.admin`）。每个工具都是由自己的处理器运行的一条管理路由，使用该路由所要求的权限，所以拒绝会带着路由自己的话返回，每次调用都以调用者的名字记入审计日志。登录、个人自己的第二重验证和实时编辑器套接字不是工具，MCP 页面说明了原因。该页面列出全部 29 个工具及其路由和权限。
- **持久连线分批排空。** 中断之后，`influxdb out` 每次请求写入最多 256 条积压消息，而不是一条。在一个写入要 8 ms 才响应的历史库、一家每秒发送 100 个读数的工厂、以及排着 2,000 个读数的情况下，同一个测试以前要 2 分 38 秒才排空，现在是 2.7 秒，每个读数一次且按顺序。

## 变更内容

- 通向接受批量的节点的持久连线，一次最多领取 256 条消息。如果某个批次没有被接收，第一个失败的消息之前的消息被标记为完成，那一条用连线一直具有的重试和放弃机制单独重试，其余的重新发送，所以不会丢失，也不会重新排序。其他所有目标仍然一次得到一条消息。投递仍然是至少一次，进程被杀死时正在传输的消息可能像以前一样再次到来。对批量目标来说，这是最多一个批次，最多 256 条消息，而不是一条，`_queuedAt` 时间戳让对 InfluxDB 的重复写入像以前一样是一次覆盖。
- `LICENSE` 文件的 Licensed Work 一行只提到 HotLoop Flow，因为其他产品改用各自的许可证。条款没有改变。
- 编辑器中没有任何改变。
- 其他方面与 2.13.1 的行为没有不同。

## 新设置

无。

## 升级

对 2.14.0 的镜像和图表做一次普通的 `helm upgrade`，或在你的 Quadlet 单元里换上新标签。首次启动不会发生任何事，也无需迁移。连接到 `/mcp` 的智能体会看到新工具，并且只看到其令牌权限允许的那些。这个版本仅限 amd64：arm64 机器留在 2.13.1，直到 2.14.1，后者是加上 arm64 镜像的同一份代码。

镜像：`ghcr.io/hotloop-io/hotloop-flow:2.14.0`，先发布 linux/amd64，arm64 在 2.14.1 中跟进。Chart：`https://hotloop.io/hotloop-flow/`。这个标签的 README 有其余内容，还配有图片：https://github.com/HotLoop-io/hotloop-flow/blob/v2.14.0/README.md
