HotLoop Flow 2.6.0 给持久连线增加了一种方式，让它告诉你自己已经停止投递。你的流程运行方式没有任何变化。如果你在工厂产线上使用持久连线，你得到的是一个可以设置告警的计数器，用来对付那种以前看起来像安静队列的故障。

## 新功能

**卡住的持久连线会被计数并描述。** 持久连线的泵现在会察觉：连线说有消息在等待，而队列里没有任何它能读取的内容，并且短暂重查后依然如此。它会给 `hotloop_flow_durable_wire_stranded_total{wire=...}` 加一，并在运行时日志中写一条警告，每种故障类型一次，附上连线的计数器和它的表中的内容：泵走到了哪里、深度、磁盘上的行数、正在传输的内容，以及追加、投递和丢弃了多少。在健康的连线上，计数器是零并保持为零，所以任何大于零的值都值得告警。

我们加上它，是因为一条丢弃最旧消息的连线在几千次测试运行中有一次没能排空，而我们没能抓到原因。这个版本是检测仪器，不是修复。如果它在你的产线上触发，日志那一行就是我们需要的。

## 变更内容

- 镜像中随附的许可证文本按规范副本的写法拼写 EmberNet。三行，只改拼写。
- README 的图片是普通图片，先浅色后深色，所以能在 docs.hotloop.io 上显示。

## 新设置

无。该指标已开启，没有开关。

## 升级

对 2.6.0 的镜像和图表做一次普通的 `helm upgrade`，或在你的 Quadlet 单元里换上新标签。首次启动不会发生任何事，没有需要迁移的内容，流程、部署记录和凭据都不会被触及。

镜像：`ghcr.io/hotloop-io/hotloop-flow:2.6.0`，linux/amd64 和 linux/arm64。Chart：`https://hotloop.io/hotloop-flow/`。这个标签的 README 有其余内容，还配有图片：https://github.com/HotLoop-io/hotloop-flow/blob/v2.6.0/README.md
