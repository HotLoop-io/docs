HotLoop Flow 2.8.0 给 FlowLab 新增了四样东西，FlowLab 是用于试验台和数据记录器的图表标签页：分析节点、用于 NI 硬件的数据采集节点、会保留代理漏掉消息的 MQTT 输出，以及 TDMS 日志。流程的运行与之前完全一样，您现在拥有的流程文件逐字节加载和保存，不是图表的标签页也看不到其中任何内容。

## 新功能

**分析。** 四个节点处理读数数组：统计（均值、RMS、最小值、最大值和标准差）、积分（按梯形法则计算数组下方的面积，输出一个数字或累计面积）、微分（每个采样点的斜率），以及 1 到 10 阶的 Butterworth 滤波器，可作低通、高通、带通或带阻，截止频率以赫兹为单位。

**数据采集节点。** `read DAQ task` 通过 NI 的 gRPC Device Server 从 NI 硬件读取采样，例如 CompactDAQ 机箱。客户端尽可能小：使用 Go 自带的 HTTP/2 和手写的消息，所以二进制没有引入 gRPC 库。

**不丢任何消息的 MQTT 输出。** `mqtt out` 通过流程文件所配置的代理发布，与 MQTT 节点使用的是同一个连接。把它标为持久，代理漏掉的消息会在节点结束之前写入磁盘，并在代理恢复后按先到先发的顺序发送，即使中间重启过也一样。没有任何消息会越过排在它前面的消息。它的已发送输出会告诉您这条消息是否直接发出。

**TDMS 日志。** `log to TDMS file` 向 TDMS 文件追加一条记录，每个字段一个通道，文件可在实验室现有的工具中打开。最后一次写入被断电截断的文件，仍能读取到最后一个完整的值。

## 变更内容

- 调色板的 FlowLab 部分现在有 28 种节点类型，原来是 21 种，README 也这样写。
- 2.7.1 的那次运行中有一个步骤失败过一次，却没有输出任何内容，原因是收集器测试在它所读取的日志还没包含整段时间之前就比较了这一段；现在它会等整段时间。另外两个测试也改成了等待它们所检查的内容。这些都不会随版本发布。
- README 的图片重新截取，让顶部栏显示 v2.8.0。
- README 中的二进制文件和镜像大小针对这次发布重新读取过。

## 新设置

无。

## 升级

在 amd64 上，只需对 2.8.0 的镜像和 chart 执行一次 `helm upgrade`，或在您的 Quadlet 单元里换上新标签。在 arm64 上，请先保持现状，等到 2.8.1，它就是加上 arm64 的这个版本，仅此而已。首次启动时不会发生任何事，也不需要迁移。

镜像：`ghcr.io/hotloop-io/hotloop-flow:2.8.0`，仅限 linux/amd64。我们先构建 amd64，让它在生产中被确认为稳定，然后一个别无他物的小版本 2.8.1 加上 arm64。在那之前，`2` 标签指向新的 amd64 镜像和 2.7.1 的 arm64 镜像，所以跟随 `2` 或 `2.7` 的 arm64 机器保持它现有的版本，固定在 `2.8.0` 的机器需要 amd64。图表：`https://hotloop.io/hotloop-flow/`。此标签的 README 有其余内容，附图片：https://github.com/HotLoop-io/hotloop-flow/blob/v2.8.0/README.md
