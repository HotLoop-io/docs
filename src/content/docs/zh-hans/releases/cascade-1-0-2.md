## 这是什么

1.0.2 让工作流可以签名和验证,而不必让密钥出现在条目数据里,并让另一个网站上的公开表单可以从浏览器调用 Webhook。其余内容与 1.0.1 相比没有变化。

## Code 步骤的新功能

- **加密辅助函数。** `sha256(text)`、`hmacSHA256(key, text)`、`randomHex(bytes)`、`base64Encode(text)`、`base64Decode(text)` 和 `safeEqual(a, b)`。它们在 Go 中计算,所以结果就是标准库的结果,脚本仍然没有 `require`、没有网络、没有文件。
- **步骤用的凭据。** Code 步骤有一个 `secret` 凭据槽。给它一个 `HMAC key` 凭据(一种新的内置凭据类型,只有一个密钥字段 `key`),脚本就以 `credential.key` 读取它。密钥和其他密钥一样存放在保管库中,即使脚本把它返回,保管库也会在运行保存的所有内容里将其隐藏。没有凭据的步骤看到的是一个空的 `credential` 对象。

原因:公开表单用 HMAC 检查工作量证明。在此之前,在工作流里做到这一点的唯一办法是把密钥放进条目或变量里,而这两者都会落到已存储的运行或明文中。现在密钥是凭据,已存储的运行里只有签名。

## Webhook 的新功能

- **`corsOrigins`。** Webhook 触发器接受一个网页来源列表(`https://example.com` 或 `*`),这些来源的页面可以从浏览器调用它。Cascade 自己回应浏览器的预检请求,不会启动运行,并在对列表中来源的响应里加上 `Access-Control-Allow-Origin`。没有列出任何来源的 Webhook 行为和之前完全一样:没有 CORS 头,所以浏览器页面读不到响应。每个条目必须是来源,不带路径。

## 升级与回退

没有迁移。把 1.0.2 `helm upgrade` 上去,或者让 `:stable` 推进 Quadlet 单元。从不使用新辅助函数的工作流行为和之前完全一样,所以对它们来说放回 1.0.1 是安全的;调用新辅助函数的工作流在 1.0.1 上会因辅助函数未定义而失败。任何更新之前先备份,仍然是个好习惯。
