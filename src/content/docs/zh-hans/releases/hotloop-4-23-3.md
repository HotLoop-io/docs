WebVisu 画面在导入时保留它的隐藏和报警颜色,而任何画面上的任何符号现在都可以由 tag 上的规则来显示和上色。备份列表的一个小修复随之而来。只为 amd64 构建;多架构构建作为下一个版本跟进。

## 变更内容

- **符号可以由规则来显示和上色。** `show` 只在 tag 上的规则成立时才绘制符号,所以为某个状态绘制的门、护罩或泵只在该状态下才存在。`colors` 最多四条规则,每条带一个色调(`ok`、`warn`、`bad` 或 `info`):第一条成立的规则把符号涂成该色调,如果没有一条成立,就按原样绘制。规则是一个 tag 加一个比较(`on`、`off`、`eq`、`ne`、`gt`、`ge`、`lt`、`le`)。tag 没有良好读数的规则什么都不成立,也不隐藏任何东西,所以丢失连接绝不会让符号消失。构建器的符号表单两者都有,画面文件会把规则的 tag 与其余内容一起列出并移动。参见[仪表板](/zh-hans/iot/dashboards/)。
- **CODESYS 画面导入会带上 Invisible 和 Toggle color。** 元素的 Invisible 变量(它所在组的也一样)变成 `show` 规则,用 `NOT x` 反转,它的 Toggle color 变量变成 `colors` 规则,色调最接近元素自己的报警颜色。它们在 CODESYS IDE 自己的元素树所给出的 id 处找到。它带不过来的内容会在导入里连同变量一起说明:画在背景图里的形状(管道、容器、边框)上的这两项,因为那幅图是一张单独的图像,以及其他所有由变量驱动的设置(填充、边框或文字颜色、移动、闪烁、文本列表)。参见 [Import a CODESYS screen](/zh-hans/iot/codesys-screen-import/)。
- **在备份被清理时,备份列表不再失败。** 定时备份在它自己的 goroutine 里清理旧备份,而恰好落在中间的列表会因缺失的文件而失败,API 把它回答为服务器错误。现在已消失的备份会从列表中略去。

## 迁移

无。

## API 变更

符号的配置接受 `show` 和 `colors`。没有路由改变。参见 [HTTP API](/zh-hans/iot/api/)。

## 从 4.23.2 升级

直接 `helm upgrade`。无需迁移，也没有新的 secret。没有这两种规则的符号照旧绘制。

## 尚未验证的内容

- CODESYS 导入是针对 IDE 自己导出的一个可视化,以及 CODESYS Refrigerator 示例的组变量验证的。来自其他项目的画面可能会列出更多它无法放置的内容。
- 新的符号规则是由套件的测试验证的,不是在工厂的画面上。
