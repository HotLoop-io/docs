HotLoop Flow 2.13.0 能通知人和 Kafka,把 FlowLab 做得更完整,并让部署不再重启未变化的运行。它新增五个发送消息所带内容的节点(ntfy、Gotify、Discord webhook、Discord 机器人、Kafka)、一个强度图、串口流控,以及可在 持续集成中运行的图表测试。除非您用到新增部分,否则您现有的一切都不会变,唯一的例外是部署不再重启您没有改动的图表。

## 新功能

- **通知节点。** `ntfy out`、`gotify out`、`discord out`(一个 webhook)和 `discord bot out`,配有配置节点,所用设置与 HotLoop core 发送报警时相同:一个 ntfy 服务器和一个令牌或登录账号(对允许任何人发布的服务器则两者都不需要)、一个 Gotify 应用令牌、一个 Discord webhook 地址、一个 Discord 机器人令牌和一个频道。它们发送 `msg.payload`,当节点留空时,从节点或消息中取标题、主题、优先级、频道或颜色,并传递消息。任何错误、状态或日志中都不会出现密钥:Discord webhook 地址本身就是全部凭据,公共服务器上的 ntfy 主题也是,连带有地址的网络错误也会被清理。被拒绝时保留服务器自己给出的原因。遇到速率限制时只等待一次,时长按服务器要求,最多一分钟,之后消息失败。Discord 内容在 2,000 个字符处截断,embed 的描述在 4,096 个字符处截断,按 Discord 的计数方式计算,消息里的任何内容都不能提及任何人。不支持 Slack 和 Teams。
- **Kafka out。** 带 `hotloop-flow-kafka` 配置节点的 `kafka out`：broker、SASL PLAIN 或 SCRAM-SHA-256 或 SCRAM-SHA-512、TLS。它把 `msg.payload` 带着可选的键写入主题，非文本时按 JSON 写入，并在集群从每个同步副本确认之后再把消息传下去。它使用 franz-go，也就是 HotLoop 核心的 Kafka 输出所用的客户端，所以任何会说 Kafka API 的东西都能回应它。
- **强度图。** 图表的模式可以是 `intensity`。它接收一个由数字行组成的数组,最大 512 x 512,把每个值画成从最小到最大的颜色,并在每个网格到来时替换图像。扁平或行长不一的数组是节点错误连线上的错误。
- **串口流控。** `dia-serial-open` 有 `flow` 设置(none、rtscts、xonxoff),`serial://` 仪器地址接受 `flow=`。它在端口打开之后设置在终端上,所以拔掉线缆后重新打开的端口会再次获得它,而 none 会清除其他程序留下的设置。仅限 Linux:在其他系统上,要求 none 以外设置的图表会被拒绝,而不是在没有它的情况下运行。
- **图表测试。** 流程测试文件可以包含 FlowLab 图表的测试:按标签或 id 设置控件,运行一次,然后检查指示器(精确到百万分之一的数字,或 `{min, max}`)。含有会触及测试之外的节点(串口、仪器、数据采集设备、MQTT out、HotLoop 写入、日志文件)的图表会被拒绝。

## 变更内容

- **部署会保留未变化的运行。** 以前部署会停止所有图表运行,再重新启动自动启动的那些,所以部署任何东西都会重启工厂的记录器。现在,当运行的图表、它运行的每个主体和每个配置节点都与之前完全一致时,运行会继续。节点画在哪里不算在内,所以在画布上移动节点永远不会重启任何东西。已变化的图表会停止,如果设为自动启动则重新启动,和以前一样。
- Flow 的 chart 带有 `artifacthub.io/license: LicenseRef-EmberNet-Source-1.0`。
- 其他方面与 2.12.1 的行为没有不同。在您不使用新节点、intensity 模式、流控或图表测试的地方,编辑器和面板都一样,对一个固定流程做编辑器前后清单对比即可看到。

## 新设置

配置文件和环境变量中都没有。新节点：`ntfy out`、`gotify out`、`discord out`、`discord bot out`、`kafka out`，以及配置节点 `hotloop-flow-ntfy`、`hotloop-flow-gotify`、`hotloop-flow-discord-bot` 和 `hotloop-flow-kafka`。新属性：`dia-serial-open` 上的 `flow`，以及图表 `mode` 的 `intensity` 值。

## 升级

只需对 2.13.0 的镜像和 chart 执行一次 `helm upgrade`,或在您的 Quadlet 单元里换上新标签。首次启动时不会发生任何事,也不需要迁移。新依赖已编译在内:镜像仍然没有 shell,运行方式和以前一样。此版本先发布 amd64,arm64 构建随 2.13.1 跟上,所以 arm64 机器在此之前留在 2.12.1。

镜像：`ghcr.io/hotloop-io/hotloop-flow:2.13.0`，先发布 linux/amd64，arm64 在 2.13.1 中跟进。Chart：`https://hotloop.io/hotloop-flow/`。这个标签的 README 有其余内容，还配有图片：https://github.com/HotLoop-io/hotloop-flow/blob/v2.13.0/README.md
