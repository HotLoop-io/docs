HotLoop Flow 2.16.0 让一个流程文件，以及随之的一组 FlowLab 图，可以推送到租户在 EmberNet 中运行的每个 Flow 安装，每个之后都有检查，失败的会被还原。它还让两个安装共享一项工作，用一个租约确保同一时间只有其中一个向设备写入。它先发 amd64，arm64 随 2.16.1 跟进。

## 新功能

- **推送到租户的站点（#201）。** `hotloop-flow stations list -tenant ID` 和 `hotloop-flow stations push -tenant ID -file flows.json` 会把一个流程文件放到 EmberNet 显示为该租户正在运行的每个 Flow 安装上，一次一个。站点来自 EmberNet 仪表板，从不手工输入，其他租户的行会被丢弃。每次部署之后，站点必须回答所有站点应有的修订，没有启动失败的节点，并且文件中每个自行启动的图都存在且正在运行或已完成。失败的站点会被还原到它之前所在的部署，推送随之停止；报告会说明哪些站点已完成、失败、跳过和从未开始。会重启正在运行的记录器的推送，在操作员在提示处回答是、传入 `-confirm-restart`，或给出包含当前时间的 `-window` 之前，不会改变任何东西。`docs/stations.md` 是相应的页面。
- **通过 API 和 MCP 进行相同的推送（#201）。** `GET /stations` 和 `POST /stations/push`，以及 MCP 工具 `list_stations` 和 `push_to_stations`，使工具数达到 43。它们只在设置了四项站点设置时存在。
- **带隔离租约的热备（#204）。** 两个 Flow 安装可以共享一项工作。一行 PostgreSQL 保存一个租约和一个每次持有者变化就递增的数字。持有者在每次向设备写入之前检查租约，涉及 Modbus、S7、OPC UA 和 EtherNet/IP 的写入节点、HotLoop 的脚本和配方节点，以及 FlowLab 图对 HotLoop、仪器和串口的写入。备用方，或已失去租约的持有者，其写入会在发送任何内容之前被拒绝，并记为一个计数的错误，备用方会在活动方的租约过期之后接管租约。`GET /failover` 和 MCP 工具 `get_failover`（使工具数达到 44）会说明这个安装是活动、备用还是已丢失，谁持有租约，以及有多少次写入被拦下。编辑器在备用方上显示一个横幅，提供 13 种语言，`docs/failover.md` 是相应的页面。
- **为此提供的图表值和 Quadlet 行（#204）。** 图表中的 `failover.urlSecret`、`failover.name`、`failover.ttl`、`failover.renewEvery` 和 `failover.writeMargin`，保存 PostgreSQL URL 的 Secret 作为文件挂载，Quadlet 单元所需的环境变量和 Podman secret 见 `docs/deploying.md`。
- **图表值和 Quadlet 行（#202）。** 图表中的 `stations.dashboardUrl`、`stations.tenant`、`stations.dashboardTokenSecret` 和 `stations.deployTokenSecret`，两个 Secret 作为文件挂载，Quadlet 单元所需的四个环境变量和两个挂载的 secret 见 `docs/deploying.md`。

## 变更内容

- 如果故障转移设置可能让活动方在两次续约之间缺少租约，比如写入余量与租约一样长，这样的启动会被拒绝。
- 只设置了四项站点设置中的一部分的启动会被拒绝，只设置了其中一部分的图表渲染也一样。要么四项都设置，要么都不设置。
- 向站点推送的令牌除了 `flows.read` 和 `flows.write` 之外还需要 `status.read`，因为每次部署之后的检查会读取该站点的图。`hotloop-flow token` 现在会输出这一点，README 和站点页面也是如此。普通的部署令牌用于 `deploy` 时仍和以前一样可用。
- 一组流程保存之后将拥有的修订，现在可以在保存之前就知道，来自保存同样使用的同一个函数。修订方面没有任何变化。
- 文档在原先写 `mcp-server` 的地方改为 `hotloop-flow-mcp-server`（#197、#199、#200）。
- 静态二进制为 51,859,618 字节（49 MiB），低于 `ci.yml` 中 50 MiB 的预算。

## 新设置

配置文件中的 `stations.dashboardUrl`、`stations.tenant`、`stations.dashboardTokenFile` 和 `stations.deployTokenFile`，或 `HOTLOOP_FLOW_STATIONS_DASHBOARD_URL`、`HOTLOOP_FLOW_STATIONS_TENANT`、`HOTLOOP_FLOW_STATIONS_DASHBOARD_TOKEN_FILE` 和 `HOTLOOP_FLOW_STATIONS_DEPLOY_TOKEN_FILE`。默认全部为空，此时该功能关闭。在图表中它们是上面的 `stations.*` 值。

配置文件中的 `failover.urlFile`、`failover.name`、`failover.holder`、`failover.ttl`、`failover.renewEvery` 和 `failover.writeMargin`，或 `HOTLOOP_FLOW_FAILOVER_URL_FILE`、`HOTLOOP_FLOW_FAILOVER_NAME`、`HOTLOOP_FLOW_FAILOVER_HOLDER`、`HOTLOOP_FLOW_FAILOVER_TTL`、`HOTLOOP_FLOW_FAILOVER_RENEW_EVERY` 和 `HOTLOOP_FLOW_FAILOVER_WRITE_MARGIN`。名称默认为 `flow`，持有者默认为主机名，ttl 为 15 秒，续约为其三分之一，写入余量为 5 秒。没有 URL 文件时该功能关闭，每次写入都和以前一样发出。在图表中它们是上面的 `failover.*` 值。

## 升级

对 2.16.0 的镜像和图表做一次普通的 `helm upgrade`，或在你的 Quadlet 单元里换上新标签。首次启动不会发生任何事，也无需迁移。流程文件和以前一样按字节加载和保存。这个版本仅限 amd64：arm64 机器留在 2.15.1，直到 2.16.1，后者是加上 arm64 镜像的同一份代码。

镜像：`ghcr.io/hotloop-io/hotloop-flow:2.16.0`，先发布 linux/amd64，arm64 在 2.16.1 中跟进。Chart：`https://hotloop.io/hotloop-flow/`。这个标签的 README 有其余内容，还配有图片：https://github.com/HotLoop-io/hotloop-flow/blob/v2.16.0/README.md
