## 这是什么

1.3.0 让编辑器支持 14 种语言:英语、西班牙语、法语、意大利语、德语、挪威语书面语、保加利亚语、希腊语、韩语、日语、越南语、印地语、简体中文和阿拉伯语。引擎、工作流文件格式、REST API 和 MCP 服务器与 1.2.1 一致。

## 语言

- 编辑器顶部栏和登录页面上有一个语言选择器。选择会保存在浏览器里,首次访问时跟随浏览器的语言。
- 每个界面都已翻译:工作流、运行、洞察、变量、凭据、项目、用户、角色、审计日志、设置、你的账户、密钥、日志流式输出和步骤编辑器。步骤标题及其帮助、凭据类型,以及保存、删除或登录被拒绝时服务器发送的拒绝信息也已翻译。
- 日期、数字、时长和列表采用浏览器自己针对所选语言的格式。阿拉伯语从右向左书写,画布、代码和表达式仍然从左向右。阿拉伯语使用数字 0 到 9 和公历。
- 产品名称、节点名称、协议名称和示例值在所有语言中保持英文。关于运行实例的人如何设置目录、SAML 或 OpenID 提供商、密钥存储或密钥文件的消息,会按服务器写的原样显示,因为运维人员会搜索这段文字。
- 词汇来自 HotLoop 共享术语表。母语读者应先确认的行,列在每种语言的 `_review.json` 中,位于 `web/src/i18n/locales` 下。还没有以这些语言为母语的人审阅过它们。
- 只有一种语言的每一行都齐全时才会提供它。构建会检查每种语言都有英文的每个键,占位符和标签都保留,复数形式正确。一个 Go 测试让英文步骤用词和服务器消息与服务器能说的内容保持一致,所以新的步骤或拒绝信息不可能在没有待翻译行的情况下发布。

## 此版本中的其他内容

- 检查构建出的文件从不指向其他主机的编辑器测试,现在允许四个示例地址(`https://ntfy.sh`、`https://example.com`、`https://hotloop.plant` 和 `http://hotloop:8080`)。它们出现在步骤的帮助文本里,这些文本现在为所有语言内置在编辑器中,它们只是句子里的文字,没有任何东西会去获取。如果编辑器向其他主机请求任何内容,浏览器测试仍然会失败。
- 测试浏览器装有韩语、日语、中文和印地语的 Noto 字体,所以这些界面绘制的是文字,而不是空方框。
- OpenBao 测试辅助程序在 OpenBao 提示新的键值挂载仍在升级时,会重试写入(26e1e13)。
- HotLoop LLC 被列为 Cascade 的许可方和维护者(0ea9cd5)。

## 为什么只有 amd64

这个版本只构建 amd64。多架构在单独的一次运行中发布,所以这个版本之后的那个版本是一次小的版本号提升,同时构建两种架构。`stable`、`latest`、`1.3` 和 `1` 会把新的 amd64 镜像和它们原来指向的 arm64 镜像一起列出。

## 已知问题

在拆分安装中(PostgreSQL 上的 server、worker 和 webhook pod),pod 会在数据库名称解析之前启动,并在就绪前重启两三次。它们最终会起来,安装也能通过,但很吵。1.2.1 也是这样,所以这不是新问题。修复方法是带重试地连接,直到数据库就绪,它会在下一个版本中发布。

## 升级与回退

没有迁移。把 1.3.0 `helm upgrade` 上去,或者让 `:stable` 推进 Quadlet 单元。放回 1.2.1 是安全的,因为数据库里没有任何变化。选择的语言保存在浏览器里,所以回退只会丢掉语言选择器。
