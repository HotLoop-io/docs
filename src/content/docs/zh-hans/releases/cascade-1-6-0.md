## 这是什么

1.6.0 是 Cascade 不再只是工作流运行的地方,而成为人、模型和其他服务器共同参与的地方的版本。一次运行可以暂停,在手机上询问某个人。一次运行可以询问属于你自己的模型。你的工作流可以放在 Git 里,生产实例可以拒绝被手工编辑。任何 Web API 都可以用一个文件变成步骤。引擎、文件格式和其余一切都与 1.5.1 相同。

## 在手机上询问某个人

新的请求批准步骤会暂停运行并等待。把 `execution.approvalUrl` 放进推送通知,收到的人点开它,阅读你写的内容,如果你做了小表单就填写,然后点批准或拒绝。页面简单、快速,除非你要求否则无需登录,并且在全部十四种语言中都使用浏览器的语言。运行从已批准或已拒绝端口继续,并附上是谁、什么时候、回答了什么。每个回答都是一条记录:在运行上的编辑器里,在 API 的 `GET /api/v1/approvals` 上,在 MCP 服务器里叫 `list_approvals`,也在审计日志里。让该步骤要求已登录账户,它就只接受你列出的账户的回答。链接只能使用一次。等待不花任何成本,所以回答可以一周后才到,并且能经受任何重启。

## 询问模型

两个新步骤,AI:询问模型和 AI:运行智能体。模型是你自己的:凭据指向你自己运行的服务器(Ollama、vLLM、llama.cpp),或你有密钥的托管服务,使用 OpenAI 协议或 Anthropic 协议。凭据没有指向的地方不会发出任何东西,没有托管服务,每次调用都和其他调用一样经过出站策略。询问模型把回答放到条目上,可以是文本,也可以是符合你给定模式的 JSON 对象。运行智能体给模型一个目标和一份工具清单,每个工具都是你的另一个工作流。模型请求一个,Cascade 运行它并返回结果,如此重复,直到模型作答或轮次用完。轮次之间,运行在数据库里等待,所以慢的工具不会占用任何 worker。

## Git 中的工作流

把项目连接到一个仓库、一个分支和一个文件夹,然后 push 或 pull。Push 为每个工作流写一个文件,以它命名并带上它的 id,并以执行 push 的人的身份、用他给出的消息提交。Pull 让项目与仓库一致:新文件变成工作流(在你开启之前保持关闭),改动的文件变成新版本,id 会保留,因此工作流在每个实例上都是同一个,两边都改过的内容会被报告并保持原样,除非你指定谁胜出。只有在你要求时才会删除。每个项目上有一张卡片、六条 API 路由和六个 MCP 工具。它通过出站策略,使用保管库里存放的用户名与令牌或密码,以 HTTPS 通信。

## 受保护的实例

给实例起个名字(开发、预发布、生产),它会显示在每个屏幕顶部的徽章里。保护它,在设置里或用 `HOTLOOP_CASCADE_PROTECTED`(图表的 `protected` 值,任何设置都无法撤销),它的工作流就不能在编辑器、API 或 MCP 中被手工创建、编辑、恢复或删除。工作流通过从 Git pull 到达。凭据、变量、运行以及工作流的开启和关闭保持开放,因为它们在各环境之间本来就不同。受保护的实例只 pull,不 push。

## 用文件定义连接器

连接器是一个文件,说明 API 在哪里、如何登录,以及每次调用接收什么、返回什么。把它放进 `HOTLOOP_CASCADE_CONNECTORS_DIR`(数据目录下的 `connectors` 文件夹),每个操作就是一个步骤,带有自己的表单、自己的凭据类型、分页和重试,整理方式与内置连接器一样。格式已发布,有版本,并有 JSON Schema(`hotloop-cascade connector schema`)。编写连接器的工具就在二进制文件里:`connector init`、`validate`、`call`(用真实 API 试一个操作),以及用于分享的 `index` 和 `install`,索引就是静态文件,每个文件带一个哈希。Cascade 绝不会下载你没有指定的索引。MCP 服务器现在有 91 个工具。

## 回退

此版本新增三张表(批准以及两张 Git 用表),迁移只向前,因此回到 1.5.1 需要你升级前做的备份,而不只是旧镜像。现有的任何东西都不会改变形态。
