## 这是什么

1.5.0 让所有者可以删除一个人。引擎、文件格式和其他所有界面与 1.4.2 一致,也没有迁移。

## 删除一个人

在此之前,移除账户的唯一办法是停用它,而它会永远留在列表里。现在用户页面在停用旁边有一个删除按钮,对所有者显示,针对除自己以外的所有人,并且在执行任何操作前会先询问。同样的调用也在 REST API 的 `DELETE /api/v1/users/{user}` 中,以及 MCP 服务器的 `delete_user` 中,规则相同:只有实例所有者可以,绝不能是你自己的账户,也绝不能是最后一位所有者。

账户、它的会话、通行密钥、登录身份和 API 密钥会立即消失,所以任何仍以这个人身份登录的东西,在下一次请求时就会停止工作。审计日志会记录谁删除了谁,包括电子邮件、角色以及消失的会话和密钥数量,其链条仍然可以验证。

他们的工作会保留。他们的个人项目会变成一个以他们名字命名、后面带 "(removed)" 的共享项目,保留它原有的每个工作流、凭据和运行,所有者和管理员可以把其中任何内容移到另一个项目或交给某个人。同一个电子邮件以后可以用来创建新账户,新账户从属于自己的项目开始。

停用保持不变,当你想保留账户时它是正确的选择。你的身份提供商通过 SCIM 移除的人,仍然是被停用并隐藏,而不是被删除。

## 回退

没有迁移,所以之前的镜像可以在同样的数据上运行。已删除的账户不会回来;如果需要,请恢复你在删除之前做的备份。

## 为什么只有 amd64

这个版本只构建 amd64。多架构在单独的一次运行中发布,所以这个版本之后的那个版本是一次小的版本号提升,同时构建两种架构。`stable`、`latest`、`1.5` 和 `1` 会把新的 amd64 镜像和它们原来指向的 arm64 镜像一起列出。
