## 개요

1.0.2는 비밀 값이 항목 데이터에 들어가지 않고도 워크플로가 서명하고 검증할 수 있게 하며, 다른 웹사이트의 공개 폼이 브라우저에서 웹훅을 호출할 수 있게 합니다. 그 밖에는 1.0.1에서 바뀐 것이 없습니다.

## Code 단계의 새 기능

- **암호화 도우미.** `sha256(text)`, `hmacSHA256(key, text)`, `randomHex(bytes)`, `base64Encode(text)`, `base64Decode(text)`, `safeEqual(a, b)`. Go에서 계산하므로 결과는 표준 라이브러리의 것이며, 스크립트에는 여전히 `require`도 네트워크도 파일도 없습니다.
- **단계용 자격 증명.** Code 단계에는 `secret` 자격 증명 슬롯이 있습니다. 여기에 `HMAC key` 자격 증명(비밀 필드 `key` 하나만 있는 새 내장 자격 증명 유형)을 지정하면 스크립트가 `credential.key`로 읽습니다. 키는 다른 시크릿처럼 보관함에 있고, 스크립트가 반환하더라도 보관함이 실행이 저장하는 모든 곳에서 가려 줍니다. 자격 증명이 없는 단계에서는 `credential` 객체가 비어 있습니다.

이유는 이렇습니다. 공개 폼은 HMAC으로 작업 증명을 확인합니다. 이전에는 워크플로에서 이를 하려면 키를 항목이나 변수에 넣는 방법뿐이었고, 둘 다 저장된 실행이나 평문에 남습니다. 이제 키는 자격 증명이고, 저장된 실행에는 서명만 남습니다.

## 웹훅의 새 기능

- **`corsOrigins`.** 웹훅 트리거는 해당 페이지가 브라우저에서 호출할 수 있는 웹 오리진 목록(`https://example.com` 또는 `*`)을 받습니다. Cascade는 실행을 시작하지 않고 브라우저의 사전 요청에 직접 응답하며, 목록에 있는 오리진에는 응답에 `Access-Control-Allow-Origin`을 추가합니다. 목록이 없는 웹훅은 이전과 똑같이 동작하고 CORS 헤더가 없으므로 브라우저 페이지가 응답을 읽을 수 없습니다. 항목은 경로 없는 오리진이어야 합니다.

## 업그레이드와 되돌리기

마이그레이션은 없습니다. 1.0.2로 `helm upgrade`하거나 `:stable`이 Quadlet 유닛을 옮기게 두세요. 새 도우미를 쓰지 않는 워크플로는 이전과 똑같이 동작하므로 1.0.1로 되돌려도 안전합니다. 새 도우미를 호출하는 워크플로는 1.0.1에서 도우미가 정의되지 않아 실패합니다. 업데이트 전에 백업하는 습관은 여전히 좋습니다.
