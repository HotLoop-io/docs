새 웹 UI가 이제 `/`의 화면이며, 에이전트는 MCP로 읽을 수 있는 모든 것을 바꿀 수 있습니다. 마이그레이션은 없고, 평범한 `helm upgrade`나 Quadlet 자동 업데이트로 적용됩니다. 이전 릴리스인 [4.19.11](/ko/releases/hotloop-4-19-11/)은 기본 화면이 이전 것이던 마지막 릴리스입니다.

이 빌드는 amd64 전용이며, 다음 릴리스는 두 차례로 나눠 진행하는 방식대로 arm 이미지를 빌드하는 작은 버전 올림입니다. 그동안 `stable`은 가지고 있는 arm 이미지를 그대로 유지합니다.

## 바뀐 내용

- **새 웹 UI가 기본이며 이전 UI는 없어졌습니다.** 모든 화면을 정적 페이지(Astro와 Svelte 일부)로 다시 만들어 하나의 바이너리에 내장했고, 박스에 Node도 CDN도 필요 없습니다. 4.19.x에서는 `/next`에 있었습니다. `/`에서는 viewer, operator, 관리자에게 같은 열아홉 개 화면이 같은 컨트롤, 필드, 컬럼, 폼, 문구로 나옵니다. 의도적으로 달라 보이는 점:
  - 색은 사이트, Flow, Cascade와 같은 HotLoop의 따뜻한 바탕과 주황색이며, 마크는 공식 마크입니다.
  - 화면은 데스크 위의 레일에서 Operate, Plant, Build, System으로 묶입니다. 휴대폰에는 다섯 개짜리 막대(Board, Alarms, Dashboards, Entities, More)가 있고, More가 모든 화면을 엽니다.
  - 테마 컨트롤은 달 모양 대신 Dark 또는 Light라고 표시합니다.
  - 설치된 앱의 아이콘, 테마 색, 스플래시 색이 새 모양을 따릅니다.
  - 서랍은 스크롤바 자리를 비워 두므로, 그 안의 카드가 이력을 불러올 때 움직이지 않습니다.
- **HotLoop에 닿지 않을 때의 로그인은 이유를 알려 주고 스스로 복구합니다.** 한 번도 로그인하지 않았거나 로그아웃한 휴대폰이 연결 없이 페이지를 열면, HotLoop이 여기서는 응답하지 않는다는 문장이 있는 로그인 화면이 나옵니다. 페이지는 3초마다 다시 묻고, 연결이 돌아오면 손대지 않아도 다시 불러옵니다. 이전 동작을 그대로 유지한 것입니다.
- **MCP가 읽을 수 있는 모든 것을 바꿀 수 있습니다.** 플랜트를 읽고 설비를 명령하는 도구가 스물일곱 개였는데 이제 128개입니다. 64개가 더 설정을 바꿉니다. 장치와 tag, 디스커버리와 브로커, UniFi 네트워크, 엔티티, helper, 설비와 레이블, 알람, 자동화와 blueprint(에이전트가 이제 blueprint로 규칙을 만들 수 있으며, 전에는 미리 보기만 가능했습니다), 스크립트, 레시피, 대시보드, 그리고 화면이 저장할 수 있는 나머지입니다. 37개는 관리자 자신의 기능에 닿습니다. 사용자와 PIN, 설정, 백업, 에스컬레이션, historian 대상, 브로커 로그인, edge relay 플릿, 리포트입니다. 어느 것도 두 번째 구현이 아닙니다. 각각은 REST API의 라우트 하나를 그 라우트 자신의 핸들러로 실행하는 것이므로, 검증, 권한 확인, 런타임 다시 불러오기, 감사 행은 그 라우트의 것이며 에이전트가 행위자로 기록됩니다.
- **변경 앞에 놓이는 것.** 스위치 `HOTLOOP_ALLOW_MCP_WRITES`(기본 켜짐)가 켜져 있어야 하고, `HOTLOOP_MCP_OIDC_WRITE_ROLE`이 설정된 호출자는 그 역할을 가져야 합니다. 호출은 해당 라우트가 요구하는 정확히 하나의 권한(`devices.write`, `alarms.write`, `users.manage`, `settings.write` 등)을 가지며, 없으면 라우트 자신의 표현으로 거부됩니다. 모든 변경에는 필수 `reason`이 있으며 시스템 로그에 라우트 자신의 줄 옆에 `config` 줄로 기록됩니다. 설비를 명령하는 일은 여전히 `write_tag`, `call_service`, `run_script`, `apply_recipe`, `trigger_automation`이며 `HOTLOOP_ALLOW_WRITES`, tag의 쓰기 가능 표시, 그 범위 뒤에 있습니다. tag, 규칙, 레시피를 쓰기 가능하게 만드는 것은 설정이며, 사용되기 전에는 아무것도 명령하지 않습니다. 그때 명령하는 것은 같은 게이트를 만납니다. 두 쓰기 스위치에는 라우트가 없으므로 Settings 화면처럼 `save_settings`가 에이전트에게는 이를 거부하며, 에이전트는 자신의 쓰기가 기다리는 스위치를 켤 수 없습니다. 사용자의 비밀번호는 API를 거칠 때처럼 호출을 거치며 감사 행에는 절대 담기지 않습니다. 도구는 `--mcp-stdio`에서도 있습니다. 모든 도구와 라우트, 권한은 [MCP](/ko/iot/mcp/#구성-변경)에 있습니다.

## API 변경 사항

- `GET /next`와 `GET /next/`는 루트로의 `301`이므로, 새 UI가 이전 UI 옆에 있을 때 만든 북마크도 여전히 도착합니다. `Location`은 상대 경로이므로 base path 아래에서도 올바릅니다.
- `GET /static/`이 사라졌고 `GET /next/manifest.webmanifest`도 함께 사라졌습니다. 페이지, 파일, 아이콘, `/manifest.webmanifest`, `/sw.js`는 이전처럼 루트에서 제공되며, 이전 스타일시트와 스크립트는 어디에서도 링크되지 않아 제공하지 않습니다.
- `HOTLOOP_UI`는 더 이상 읽지 않습니다. 설정해도 아무 일도 일어나지 않습니다.
- 다른 라우트는 바뀌지 않았습니다. MCP 도구는 REST 라우트가 아니라 새로운 표면입니다.

## 4.19.11에서 업그레이드

평범한 `helm upgrade` 또는 Quadlet 자동 업데이트입니다. 마이그레이션도 설정할 것도 없습니다. 첫 로드에서 새 페이지를 가져오고 service worker가 이전 캐시를 교체하므로, 앱을 설치해 둔 휴대폰은 다음에 열 때 새 화면을 보여 줍니다. 업그레이드로 되돌릴 수 없게 되는 것은 없으며, 데이터베이스에서 바뀐 것이 없으므로 4.19.11로의 롤백은 안전합니다.

## 알려진 것

- 새로운 것은 없습니다. [로드맵](/ko/roadmap/)의 Broken or missing 아래에 아직 열려 있는 것: OPC UA X.509 사용자 토큰, 우리 OPC UA 서버가 제공하는 폐기된 `Basic128Rsa15`와 `Basic256` 정책과 64바이트를 넘는 비밀번호(둘 다 라이브러리의 것), 그리고 실제 장치를 상대로 한 S7comm과 EtherNet/IP의 무응답 장치 테스트입니다.
