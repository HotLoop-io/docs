## 개요

1.0.0은 ID 및 거버넌스 작업과 새 에디터를 한 번에 담은 릴리스입니다. 0.1.2의 모든 것이 그대로 있고 이전처럼 동작합니다. 엔진, 커넥터, 가져오기 도구, Helm 차트, Quadlet 유닛, 워크플로 파일 형식이 그렇습니다. 달라진 것은 공장이 인스턴스로 할 수 있는 일과 그 모습입니다.

1.0.0이라고 부르는 이유는, 에디터가 이 번호에 우리 이름을 걸기 전에 필요했던 마지막 조각이기 때문입니다. 모든 화면은 실제 API로 동작하고, 아래의 모든 기능은 대용품이 아닌 실제로 연결되는 서버에서 시험했습니다.

## 새 에디터

Astro와 Svelte 아일랜드로 다시 만들었고, HotLoop 고유의 색상과 서체를 쓰며, 직접 고르기 전까지는 시스템의 라이트 또는 다크 모드를 따릅니다. 여전히 바이너리에 내장되어 있고 어디에서도 아무것도 가져오지 않으므로, 인터넷이 없는 서버에서도 있을 때와 똑같이 실행됩니다. 이전 에디터의 모든 화면이 그대로 있고 하던 일을 그대로 하며, 캔버스도 마찬가지입니다. 코드를 새로 쓰지 않고 옮겨 왔고, 빠진 것이 없는지 확인하려고 전후로 모든 화면, 버튼, 필드, API 호출을 세어 보았습니다.

저장해 둔 URL은 그대로 작동합니다. `#/w/<id>`, `#/x/<id>`, `#/executions`와 디버그 링크는 같은 화면을 열고, `/app/main.js`와 `/app/main.css`도 계속 응답합니다.

## 새로운 기능

Keycloak으로 시험한 SAML, 서명된 응답만 허용. OpenLDAP와 Samba 도메인 컨트롤러로 시험한 LDAP과 Active Directory, 그룹에서 가져오는 역할. scim2-tester로 시험한 SCIM, 공급자가 화면을 건드리지 않고 계정을 만들고 끌 수 있습니다. 프로젝트 권한으로 만드는 사용자 지정 역할. OpenBao 또는 HashiCorp Vault의 외부 시크릿, 자격 증명의 비밀번호가 저장소에 있고 거기서 교체됩니다. 감사 로그와 완료된 실행을 syslog(TCP, UDP 또는 TLS)와 OTLP로 보내는 로그 스트리밍, 실제 syslog 서버와 Loki로 시험했습니다. 변수, 폴더, 인사이트, 실행 주석, 마스킹 정책, S3와 Azure Blob 저장소, Garage와 Azurite로 시험했습니다.

에디터에는 각각을 위한 화면이 있습니다. 변수, 인사이트, 그리고 설정 아래의 역할, 마스킹, 외부 시크릿, 로그 스트리밍, 로그인 및 SCIM입니다. 사용자에게는 역할이 허용하는 것만 보이고, 나머지는 서버가 여전히 거부합니다.

## EmberOps 단계는 없어졌습니다

EmberOps 커넥터를 뺐습니다. 아홉 개 단계(`erpnext.trigger`, `getList`, `getDoc`, `create`, `update`, `delete`, `submit`, `cancel`, `call`), "EmberOps 문서가 생성되거나 변경될 때" 트리거, EmberOps 자격 증명 유형, 그리고 이를 제공하던 화면과 문서는 1.0.0에 없습니다. EmberOps에 접근해야 한다면 HTTP 단계가 자격 증명으로 REST API를 호출하며, 지금 바로 동작합니다.

이 단계를 쓰던 저장된 워크플로는 버려지지도, 조용히 바뀌지도 않습니다. 검증에 실패해 시작되지 않으며, 메시지에는 단계 이름과 EmberOps 단계가 1.0.0에서 제거되었다는 내용이 나옵니다. 단계를 삭제하거나 HTTP 단계로 바꾸면 다시 실행됩니다. EmberOps 유형의 자격 증명은 사용되지 않은 채 목록에 남으며 삭제할 수 있습니다. 가져오기 도구는 더 이상 EmberOps 노드를 가져오지 않습니다. 대응하는 단계가 없는 다른 노드처럼 비활성 상태로 들어오고 설정은 노트에 담깁니다.

## 0.1.2에서 업그레이드

1.0.0으로 `helm upgrade`하거나 `:stable`이 Quadlet 유닛을 옮기게 두세요. 올라가는 동안 마이그레이션 8개(0018부터 0025)가 실행됩니다. 역할, 변수, 폴더, 주석, 마스킹 정책, SCIM, 시크릿 공급자, 로그 대상을 위한 테이블을 만들고, 워크플로가 들어 있는 폴더라는 열 하나를 추가합니다. 기존 데이터는 건드리지 않으므로 워크플로, 자격 증명, 실행은 그대로 있고 키로 계속 열립니다. SAML, LDAP, SCIM, Blob 저장소는 `HOTLOOP_CASCADE_*` 설정을 지정하기 전까지 꺼져 있으며, 설정은 `docs/IDENTITY.md`와 `docs/GOVERNANCE.md`에 있습니다. 아무것도 지정하지 않은 인스턴스는 달라지는 것이 없습니다. 단, 워크플로가 EmberOps 단계를 쓰는 경우는 예외입니다(위 참조).

## 알아 둘 점

마이그레이션은 앞으로만 진행됩니다. 롤백은 이전 이미지를 되돌려 놓을 뿐 데이터베이스 마이그레이션을 되돌리지 않으므로, 업데이트하기 전에 백업하고 그 백업을 되돌아가는 길로 여기세요. 이 마이그레이션은 기존 데이터를 바꾸거나 지우지 않지만, 이전 이미지를 새 스키마에서 실행해 보지는 않았으므로 보장하지 않습니다.

외부 시크릿에는 허용 경로가 필요합니다. 경로가 없는 공급자는 일부러 거부됩니다. 저장소의 토큰은 보통 자격 증명을 편집하는 사람이 이름을 댈 수 있어야 하는 범위보다 훨씬 많이 읽을 수 있기 때문입니다.

SCIM은 인스턴스 소유자를 공급자에게 절대 보여 주지 않으며, 공급자의 DELETE는 계정을 지우는 대신 끄고 숨깁니다. 그래서 공급자가 로그인할 수 있는 마지막 사람을 제거할 수 없습니다. 다시 만들면 같은 계정이 돌아옵니다.

변수는 시크릿이 아닙니다. 프로젝트를 읽을 수 있는 사람은 그 변수를 읽으며, 값은 실행 데이터에서 가려지지 않습니다. 비밀번호는 자격 증명이나 외부 저장소에 넣으세요.
