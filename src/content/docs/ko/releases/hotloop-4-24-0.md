HotLoop 화면은 P&ID입니다. CODESYS PLC 자체의 알람이 HotLoop의 알람 목록에 나타나고 확인이 PLC로 되돌아가며, 스크립트 실행은 항상 끝나고, 박스의 데이터 볼륨은 항상 읽히며, UniFi Protect, Access, 전원 로드맵 항목이 제공되었습니다. amd64 전용으로 빌드되었고 멀티 아키텍처 빌드는 다음 버전으로 이어집니다.

## 바뀐 내용

- **화면이 P&ID입니다.** 탱크, 펌프, 밸브, 열교환기, 필터, 계기, 접합부를 심볼 페이지에 놓고 한 연결점에서 다른 연결점으로 드래그하세요. 배관은 페이지의 모든 것을 피해 직각으로 스스로 놓이고, 다른 배관 위에 놓은 곳에서 접합부로 분기하며, 심볼을 옮기는 동안 다시 배선됩니다. 모든 배관은 매체(물, 증기, 연료, 공기, 전력, 신호 등. 각각 색, 코드, 선 패턴이 있으므로 색만이 전달 수단이 되지 않습니다)를 가지며 자신의 tag나 규칙에 따라 움직입니다. 모든 심볼 페이지에 확대, 이동, 미니맵 표시, 회색 고성능 보기로의 전환을 위한 도구 모음이 생기고, P&ID는 같은 화면 파일로 저장, 내보내기, 가져오기가 됩니다. [대시보드](/ko/iot/dashboards/)와 [Screen files](/ko/iot/screen-file/)를 보세요.
- **CODESYS PLC 자체의 알람이 HotLoop의 알람 목록에 나타납니다.** 프로젝트의 Alarm Configuration은 알람 그룹과 클래스, 그리고 변수를 감시하는 알람을 보관합니다. CODESYS 장치는 이제 PLC의 알람 관리자가 가진 것(활성, 확인 대기, 조건이 아직 유지되는 상태에서 확인됨)을 읽고, HotLoop에서 한 확인은 PLC로 되돌아갑니다. 줄 것이 없는 PLC는 건드리지 않습니다. HotLoop Alarms 라이브러리와 프로젝트의 블록 하나가 필요합니다. CODESYS-ALARMS.md를 보세요.
- **박스의 데이터 볼륨이 항상 읽힙니다.** `/data` 아래에 아무것도 마운트되지 않은 박스에는 `/data`가 없으며, 박스 상태 tag `data_util_pct`는 「no such file or directory」로 불량으로 읽혔습니다. 이제는 데이터 폴더가 만들어질 볼륨을 읽습니다. [프로토콜과 드라이버](/ko/iot/protocols/#박스-상태)를 보세요.
- **스크립트 실행은 항상 끝납니다.** 데이터베이스가 스크립트 실행의 종료 기록을 거부하면 HotLoop은 로그만 남기고 포기했고, 그래서 슬롯은 오래전에 비었는데도 실행이 프로세스가 사는 동안 「running」으로 읽혔습니다. 이제 쓰기를 다시 요청하며, 사이에 짧은 대기를 두고 최대 다섯 번까지입니다.
- **UniFi Protect, Access, SmartPower PDU 아웃렛이 로드맵에서 제공됨으로 표시됩니다.** 4.23.6에서 장치로 도착했고 공개된 API에 맞춰 만들어졌으며, Protect의 모든 경로가 7.4.102 문서와 일치합니다. [HotLoop 로드맵](/ko/roadmap/)을 보세요.
- **TwinCAT 화면을 브라우저에서 검증했습니다.** TwinCAT PackML 예제를 프레임과 함께 가져와 렌더링했고, 램프가 실시간 레지스터를 따라갑니다.
- **테스트가 기다리는 것을 기다립니다.** 패널 throttle 대기는 산술로 확인하고, forSec 유지의 타이머는 sleep과 경쟁하지 않고 테스트의 손에 있으며, Apache Kafka topic 테스트는 topic을 즉시 삭제하고 느린 박스에 필요한 시간을 가지며, API 테스트는 로그인을 표본 하나로 한정하지 않습니다. 부하가 걸린 박스는 1초 전보다 네 배 느리게 응답하기 때문입니다.

## 마이그레이션

없습니다.

## API 변경 사항

없습니다. 라우트는 바뀌지 않았습니다. 심볼 페이지의 설정은 `pipes`, `view`, 심볼의 `rot`을 받으며, 저장된 화면 파일에 이들이 담깁니다.

## 4.23.6에서 업그레이드

평범한 `helm upgrade`입니다. 마이그레이션도 새 secret도 없습니다. 배관이 없는 심볼 페이지는 이전처럼 그려집니다.

## 검증되지 않은 것

- PLC 알람 경로는 알람 랩 프로그램이 있는 실제 CODESYS Control for Linux SL 4.22.0.0 런타임에서 실행했습니다.
- Protect, Access, PDU의 아웃렛은 공개된 API를 따르며, 실제 장비를 쓰는 벤치 실행은 사무실에서 이어집니다.
