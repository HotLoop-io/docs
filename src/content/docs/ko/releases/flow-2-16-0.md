HotLoop Flow 2.16.0은 하나의 플로 파일, 즉 FlowLab 다이어그램 한 세트를 테넌트가 EmberNet에서 운영하는 모든 Flow 설치에 푸시하고, 각각 뒤에 점검하며, 실패한 것은 되돌릴 수 있게 합니다. 또한 두 설치가 하나의 작업을 공유하게 하며, 리스로 한 번에 하나만 장비에 쓰도록 보장합니다. amd64가 먼저이고 arm64는 2.16.1에서 이어집니다.

## 새 기능

- **테넌트 스테이션에 푸시(#201).** `hotloop-flow stations list -tenant ID`와 `hotloop-flow stations push -tenant ID -file flows.json`은 EmberNet이 그 테넌트에서 실행 중이라고 보여 주는 각 Flow 설치에 플로 파일 하나를 한 번에 하나씩 올립니다. 스테이션은 EmberNet 대시보드에서 가져오며 직접 입력하지 않고, 다른 테넌트의 행은 버려집니다. 각 배포 뒤에 스테이션은 모든 스테이션이 가져야 하는 리비전으로 응답해야 하고, 시작에 실패한 노드가 없어야 하며, 파일의 자동 시작 다이어그램이 모두 존재하고 실행 중이거나 끝나 있어야 합니다. 실패한 스테이션은 있던 배포로 되돌려지고 푸시는 멈추며, 보고서에는 완료, 실패, 건너뜀, 시작하지 않은 스테이션이 적힙니다. 실행 중인 로거를 재시작하게 될 푸시는 운영자가 프롬프트에서 예라고 답하거나 `-confirm-restart`를 넘기거나 지금을 포함하는 `-window`를 줄 때까지 아무것도 바꾸지 않습니다. 자세한 내용은 `docs/stations.md`에 있습니다.
- **API와 MCP로 같은 푸시(#201).** `GET /stations`와 `POST /stations/push`, 그리고 MCP 도구 `list_stations`와 `push_to_stations`로, 도구가 43개가 됩니다. 스테이션 설정 네 가지가 지정된 곳에만 있습니다.
- **펜싱 리스가 있는 웜 스탠바이(#204).** 두 Flow 설치가 하나의 작업을 공유할 수 있습니다. PostgreSQL 행 하나가 리스와, 보유자가 바뀔 때마다 오르는 숫자를 가집니다. 보유자는 장비에 쓰기 직전마다 리스를 확인합니다. Modbus, S7, OPC UA, EtherNet/IP 쓰기 노드, HotLoop 스크립트와 레시피 노드, HotLoop, 계측기, 시리얼 포트로의 FlowLab 다이어그램 쓰기가 해당됩니다. 스탠바이나 리스를 잃은 보유자는 아무것도 전송되기 전에 집계되는 오류로 쓰기가 거부되고, 스탠바이는 활성 쪽의 리스가 만료되면 리스를 넘겨받습니다. `GET /failover`와 MCP 도구 `get_failover`(도구가 44개가 됩니다)는 이 설치가 활성인지, 스탠바이인지, 잃었는지, 누가 리스를 가졌는지, 쓰기가 몇 번 보류되었는지 알려 줍니다. 에디터는 스탠바이에서 13개 언어로 배너를 보여 주며, 자세한 내용은 `docs/failover.md`에 있습니다.
- **이를 위한 차트 값과 Quadlet 줄(#204).** 차트의 `failover.urlSecret`, `failover.name`, `failover.ttl`, `failover.renewEvery`, `failover.writeMargin`이 있고 PostgreSQL URL을 담은 Secret이 파일로 마운트됩니다. Quadlet 유닛용 환경 변수와 Podman 시크릿은 `docs/deploying.md`에 있습니다.
- **차트 값과 Quadlet 줄(#202).** 차트의 `stations.dashboardUrl`, `stations.tenant`, `stations.dashboardTokenSecret`, `stations.deployTokenSecret`이 있고 두 Secret이 파일로 마운트됩니다. Quadlet 유닛용 환경 변수 네 개와 마운트된 시크릿 두 개는 `docs/deploying.md`에 있습니다.

## 바뀐 내용

- 쓰기 여유 시간이 리스 길이와 같은 경우처럼, 갱신 사이에 활성 쪽이 리스 없이 남을 수 있는 페일오버 설정으로 시작하면 거부됩니다.
- 스테이션 설정 네 가지 중 일부만 지정한 시작은 거부되며, 일부만 지정한 차트 렌더링도 거부됩니다. 네 가지 모두 지정하거나 모두 비워야 합니다.
- 스테이션에 푸시하는 토큰에는 `flows.read`와 `flows.write` 외에 `status.read`도 필요합니다. 각 배포 뒤의 점검이 스테이션의 다이어그램을 읽기 때문입니다. `hotloop-flow token`이 이제 이를 출력하고 README와 스테이션 페이지에도 적혀 있습니다. 평범한 배포 토큰은 `deploy`에는 이전처럼 계속 동작합니다.
- 플로 세트를 저장한 뒤 갖게 될 리비전을 이제 저장하기 전에 알 수 있습니다. 저장도 같이 쓰는 하나의 함수에서 가져옵니다. 리비전에 관해 바뀐 것은 없습니다.
- 문서가 `mcp-server`라고 쓰던 곳에서 `hotloop-flow-mcp-server`라고 씁니다(#197, #199, #200).
- 정적 바이너리는 51,859,618바이트(49 MiB)로, `ci.yml`의 50 MiB 예산 안에 있습니다.

## 새 설정

설정 파일의 `stations.dashboardUrl`, `stations.tenant`, `stations.dashboardTokenFile`, `stations.deployTokenFile`, 또는 `HOTLOOP_FLOW_STATIONS_DASHBOARD_URL`, `HOTLOOP_FLOW_STATIONS_TENANT`, `HOTLOOP_FLOW_STATIONS_DASHBOARD_TOKEN_FILE`, `HOTLOOP_FLOW_STATIONS_DEPLOY_TOKEN_FILE`. 모두 기본값은 비어 있으며, 이 경우 기능은 꺼져 있습니다. 차트에서는 위의 `stations.*` 값입니다.

설정 파일의 `failover.urlFile`, `failover.name`, `failover.holder`, `failover.ttl`, `failover.renewEvery`, `failover.writeMargin`, 또는 `HOTLOOP_FLOW_FAILOVER_URL_FILE`, `HOTLOOP_FLOW_FAILOVER_NAME`, `HOTLOOP_FLOW_FAILOVER_HOLDER`, `HOTLOOP_FLOW_FAILOVER_TTL`, `HOTLOOP_FLOW_FAILOVER_RENEW_EVERY`, `HOTLOOP_FLOW_FAILOVER_WRITE_MARGIN`. 이름의 기본값은 `flow`, 보유자의 기본값은 호스트 이름, ttl은 15초, 갱신은 그 3분의 1, 쓰기 여유는 5초입니다. URL 파일이 없으면 기능은 꺼져 있고 모든 쓰기는 이전처럼 나갑니다. 차트에서는 위의 `failover.*` 값입니다.

## 업그레이드

2.16.0 이미지와 차트로 `helm upgrade`만 하거나 Quadlet 유닛의 새 태그를 쓰면 됩니다. 처음 시작할 때 일어나는 일은 없고 마이그레이션도 필요 없습니다. 플로 파일은 이전처럼 바이트 단위로 불러오고 저장됩니다. 이 릴리스는 amd64 전용입니다. arm64 머신은 2.16.1까지 2.15.1에 머물며, 2.16.1은 arm64 이미지를 더한 같은 코드입니다.

이미지: `ghcr.io/hotloop-io/hotloop-flow:2.16.0`, linux/amd64가 먼저이고 arm64는 2.16.1에서 이어집니다. 차트: `https://hotloop.io/hotloop-flow/`. 이 태그의 README에 나머지가 사진과 함께 있습니다: https://github.com/HotLoop-io/hotloop-flow/blob/v2.16.0/README.md
