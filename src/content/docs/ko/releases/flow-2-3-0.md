HotLoop Flow 2.3.0은 Flow가 플랜트의 나머지 부분에 세 가지 새로운 방식으로 닿고, 잘못된 형태의 메시지를 피해를 주기 전에 잡아내는 릴리스입니다. HotLoop과 통신하고, 에이전트가 MCP로 플로를 도구처럼 호출할 수 있으며, 플러그인은 npm 패키지가 아니라 서명된 WebAssembly 파일입니다. 이제 JSON Schema가 `json` 노드, 노드의 포트, 에디터의 와이어에서 메시지를 검사합니다. 이미 돌고 있는 플로에 영향을 줄 수 있는 변경이 하나 있으며, 변경 사항 맨 앞에 있습니다.

## 새 기능

**HotLoop 노드**
- `hotloop-flow-hotloop` 연결은 URL과 계정입니다. `POST /api/auth/login`으로 로그인하고, HotLoop이 돌려주는 베어러 토큰을 보내며, HotLoop이 세션이 없어졌다고 하면 다시 로그인합니다. 아래의 모든 기능에는 운영자 계정이면 충분합니다.
- `hotloop in`은 HotLoop의 실시간 피드를 따라가며 상태가 바뀌는 엔티티마다 메시지를 보냅니다. `msg.topic`은 엔티티 id, `msg.payload`는 새 상태이고, `msg.hotloop`에는 이전 상태, 속성, 품질, 타임스탬프가 담겨 있습니다. 연결이 끊기면 배지가 빨갛게 바뀌고, 재시도마다가 아니라 장애 한 번에 오류 하나가 Catch 노드에 도달합니다. 연결이 돌아오면 그사이 바뀐 엔티티는 전송되고 바뀌지 않은 엔티티는 전송되지 않습니다.
- `hotloop state`는 메시지가 도착하면 엔티티 하나를 읽습니다. `hotloop script`는 지정한 필드로 HotLoop 스크립트를 실행합니다. `hotloop recipe`는 매개변수와 함께 레시피를 적용하며, 일부러 요청하면 이전 버전도 적용합니다. HotLoop이 모든 필드와 매개변수를 검사하고, 모든 쓰기를 쓰기 게이트로 통과시키며, 기록을 남깁니다. Flow는 사유 `flow:<node id>`를 보내고, HotLoop은 이를 쓰기 감사와 로그북에 기록합니다.
- 거부되거나 실패한 호출은 HotLoop의 응답 문구와 상태와 함께 Catch 노드에 도착합니다. 이미 기록된 것은 되돌리지 않으며, 이것 역시 HotLoop의 규칙입니다.

**HotLoop의 게이트를 통한 쓰기**
- `modbus write`, `opcua write`, `s7 write`, `ethernetip write`에 새 필드 두 개, **HotLoop을 통해 쓰기**와 **HotLoop 태그**(`device/tag`)가 생겼습니다. HotLoop을 선택하면 값이 HotLoop의 쓰기 게이트로 가며, 게이트는 쓰기 켜짐, 태그 활성화, 값이 범위 안인지 순서대로 판단합니다.
- 게이트가 거부한 쓰기는 장비에 도달하지 않습니다. HotLoop에 연결할 수 없을 때도 쓰기는 실패합니다. 게이트가 보지 못한 쓰기가 되므로 직접 쓰기로 대체하는 일은 없습니다.
- 태그에는 HotLoop 자체의 주소, 데이터 형식, 스케일이 적용되므로 Flow 노드의 주소와 데이터 형식은 쓰이지 않습니다. HotLoop을 비우면 노드는 정확히 원래대로 돌아갑니다. 게이트는 쓰기 한 번에 bool, 숫자, 텍스트 하나만 받으므로 레지스터 목록은 그렇다는 메시지와 함께 거부됩니다.

**MCP, 양방향**
- `mcp tool`과 `mcp result`는 플로를 도구로 제공합니다. 도구 노드가 이름, 설명, 입력 스키마를 선언하면 Flow가 `/mcp`에서 제공하고, 결과 노드가 플로의 답을 돌려보냅니다. 에이전트는 다른 사람과 마찬가지로 세션이나 API 토큰으로 로그인하고, 호출은 그 토큰의 권한으로 실행되며, 모든 호출과 거부는 호출자 이름으로 감사 로그에 남습니다. 토큰이 없으면 호출도 없습니다.
- `mcp client`는 `hotloop-flow-mcp-server` 연결로 HotLoop 자체를 포함한 모든 MCP 서버의 도구를 호출하고 돌아온 결과를 사용합니다. 호출을 두 번 보내는 일은 없습니다. 도구가 장비를 움직일 수 있고, 끊어진 연결로는 실행 여부를 알 수 없기 때문입니다.
- `auth.tokens`의 API 토큰은 `calls`와 구간을 갖는 `rateLimit`을 가질 수 있으며, 생략하면 구간은 1분입니다. 한도를 넘은 호출은 플로에 도달하지 않고, 언제 다시 시도할지 알려 주는 도구 오류로 돌아오며, 사유와 함께 `mcp.refused` 행을 기록합니다. `rateLimit`이 없는 토큰은 제한되지 않습니다.
- 같은 엔드포인트에서 사양의 현재 개정판 2026-07-28과, 2025-11-25까지 거슬러 올라가는 핸드셰이크 개정판을 지원합니다. 이 노드를 하나도 쓰지 않는 플로는 MCP 호출을 하지 않으며, Flow는 주어지지 않은 도구를 제공하지 않습니다.

**npm 없는 플러그인**
- 플러그인은 WebAssembly 모듈, 에디터가 대화 상자를 그리는 기술자, 그리고 둘에 대한 ed25519 서명으로 이루어집니다. 서명되지 않았거나 변조된 플러그인은 로드를 거부하고 이유를 알려 줍니다. `hotloop-flow plugin keygen`이 키를 만들고, 나머지는 `docs/plugins.md`에 있습니다.
- 메모리 한도나 타임아웃을 넘긴 게스트는 Catch 노드로 트랩되고 나머지는 계속 실행됩니다. 운영자가 허용하지 않은 호스트 접근(`clock`, `random`, `context.flow`, `context.global`)을 요구하는 플러그인은 그것을 쓰는 모든 플로의 배포를 한 바이트도 쓰기 전에 실패시킵니다.
- 신뢰하는 키가 없으면 모든 플러그인이 거부되고, 허용 항목이 없으면 호스트 접근을 요구하는 모든 플러그인이 실패합니다. 기본적으로 로드되는 것은 없습니다.
- 차트는 이 모두를 `plugins` 아래에서 받으며, 어떤 Kubernetes 볼륨 소스든 받는 볼륨이 있습니다. 꺼 두면 아무것도 렌더링하지 않고, 기본값의 `helm template`은 이전과 같습니다.

**타입 와이어**
- `json` 노드 설정에 JSON Schema를 주면 노드가 처리하는 모든 값이 그에 대해 검사됩니다. 일치하지 않는 값은 와이어를 따라가는 대신 Catch 노드로 가며, 오류는 `payload.temp: got string, want number`처럼 잘못된 필드를 모두 짚어 줍니다. 설정에 스키마가 없으면 Node-RED의 `json` 노드처럼 `msg.schema`로 검증합니다. 스키마가 다른 드래프트를 지정하지 않으면 draft 2020-12이며, 다른 URL이나 파일을 가리키는 `$ref`는 가져오지 않고 거부합니다.
- 노드는 받아들이는 것과 각 출력이 약속하는 것을 플로 파일의 키 두 개로 선언할 수 있으며, 다른 도구는 이를 무시하므로 이 키를 가진 플로도 바이트 단위로 그대로 왕복합니다. 와이어 양 끝이 모두 스키마를 선언했는데 둘을 모두 만족하는 메시지가 있을 수 없으면 한 바이트도 쓰기 전에 배포가 거부됩니다. Flow가 미리 알 수 없는 불일치는 스키마를 깨는 지점에서 멈추고, 잘못된 필드마다 경로와 함께 Catch로 가며 `hotloop_flow_node_schema_mismatches_total`에 집계됩니다.
- 다음 노드가 절대 받을 수 없는 리터럴을 설정하는 `inject`, 예를 들어 0에서 100을 받는 노드에 숫자 250을 넣는 경우도 같은 방식으로 배포 시 거부됩니다. 타임스탬프, `env`, 컨텍스트, JSONata는 추측하지 않고 건너뜁니다.
- 에디터는 각 와이어에 보내는 쪽의 타입을 표시합니다. 한쪽 끝에만 타입이 있으면 흐리게, 두 쪽이 영원히 맞을 수 없으면 빨갛게 표시되며, 빨간색은 런타임 자체의 검사에서 나오므로 캔버스와 배포가 서로 어긋날 수 없습니다. 노드 대화 상자의 **타입** 섹션에서 설정합니다.

노드 종류가 아홉 개 늘어 모두 79개가 됩니다. HotLoop용 다섯 개(연결 포함)와 MCP용 네 개(연결 포함)입니다.

## 바뀐 내용

- `json` 노드는 `msg.schema`를 무시하곤 했습니다. 이제 `msg.schema`를 가진 메시지는 그것으로 검증되고, 일치하지 않으면 와이어를 따라가지 않고 Catch 노드로 갑니다. 다른 용도로 메시지에 `msg.schema`를 남겨 두는 플로는 이 변화를 보게 됩니다.
- 이제 배포가 타입 불일치(`deploy.refused`, 사유 `typed wires`)로 거부될 수 있지만, 포트에 스키마를 선언했거나 스키마를 선언한 노드에 `inject` 리터럴을 넣는 플로에 한합니다. 스키마가 어디에도 없는 플로는 이전과 똑같이 동작합니다.
- 쓰기 노드에는 기본값이 비어 있는 새 필드 두 개가 있습니다. HotLoop을 선택하지 않으면 쓰기 노드는 2.2.0과 같이 동작합니다.
- 스키마 검증기는 `santhosh-tekuri/jsonschema` v6(허용적 라이선스)이고 MCP는 Go SDK인 `modelcontextprotocol/go-sdk` v1.8.0입니다. 둘 다 새 Go 모듈이므로, 이미지가 `/usr/share/doc/hotloop-flow/`에 담는 라이선스 문서의 항목이 늘었습니다. WebAssembly 런타임은 이미 2.2.0에 있었습니다.
- 내구성 큐의 수정 세 가지. 제거된 내구성 와이어는 이제 늦게 온 쓰기를 거부하고 폐기로 집계하며, 제거할 때 메시지에 걸려 멈춘 대상을 위해 닫기 타임아웃 전체를 기다리지 않습니다. 이전에는 와이어가 사라진 뒤 되돌려진 메시지가 재시작 전까지 쿼터에 계속 잡혀 있었습니다. 가장 오래된 것을 버리는 와이어는 이미 확인된 메시지나 펌프가 방금 읽은 메시지를 더 이상 밀어내지 않습니다. 그전에는 같은 공간이 두 번 반환되어 큐 깊이와 쿼터가 디스크에 있는 양보다 낮아졌습니다. `docs/durable/README.md`의 내구성 쿼터 설명에는 우회된 메시지가 잠시 쿼터를 몇 개 초과할 수 있다고 적혀 있습니다.
- README와 `docs/bench/`에 Raspberry Pi 5 결과가 실렸고, 로드맵에서 Pi 5는 완료로 표시하고 Pi 4, Zero 2 W, SD 카드 쓰기는 열어 두었습니다.

## 업그레이드 노트

2.2.0에서는 이미지만 바꾸면 됩니다(`helm upgrade`, 또는 Quadlet 유닛의 새 태그). 마이그레이션도 플래그도 없고, 처음 시작할 때 새로 생기는 것도 없습니다. 2.2.0에서 돌던 `flows.json`과 설정 파일은 2.3.0에서도 돌고, 플로 파일의 바이트 단위 왕복은 그대로입니다.

- 새 노드나 키를 쓰지 않는 플로는 2.2.0으로 돌아가도 안전합니다. HotLoop, MCP, 플러그인 노드는 2.2.0에서 시작되지 않고(알 수 없는 노드 타입), HotLoop을 선택한 쓰기 노드는 2.2.0이 그 필드를 읽지 않으므로 거기서는 장비에 직접 씁니다. 돌아가기 전에 그 쓰기 노드에서 HotLoop 선택을 해제하세요.
- HotLoop은 Flow가 로그인한 계정을 기록합니다. API는 클라이언트가 자신의 행위자를 지정할 방법을 주지 않으므로, Flow 노드 id가 사유로 들어가고 계정은 연결에 설정된 계정입니다. 쓰기를 쉽게 찾고 싶다면 Flow 전용으로 만든 계정을 쓰세요.
- MCP는 Flow로 들어가는 새 경로이며 토큰이 필요합니다. 플로에 `mcp tool` 노드가 생기기 전에는 아무것도 제공되지 않고, 토큰이 없거나 지어낸 토큰으로 한 호출은 거부됩니다.

## 새 설정

| YAML | 환경 변수 | 기본값 |
|---|---|---|
| `plugins.dir` | `HOTLOOP_FLOW_PLUGINS_DIR` | 비어 있음, 즉 `data.dir`의 `plugins` |
| `plugins.trustedKeys` | `HOTLOOP_FLOW_PLUGIN_TRUSTED_KEYS` | 없음. 각 항목은 `ed25519:<base64>`, PEM 공개 키, 또는 그것을 담은 파일입니다. 하나도 없으면 모든 플러그인이 거부됩니다. |
| `plugins.grants` | `HOTLOOP_FLOW_PLUGIN_GRANTS` | 없음. 플러그인 이름과 `clock`, `random`, `context.flow`, `context.global`의 대응. 변수는 `name=cap,cap;name=cap` 형식입니다. |
| `plugins.maxMemoryMiB` | `HOTLOOP_FLOW_PLUGIN_MAX_MEMORY_MIB` | 64, 1에서 4095까지 |
| `plugins.maxTimeout` | `HOTLOOP_FLOW_PLUGIN_MAX_TIMEOUT` | `5s` |
| `auth.tokens[].rateLimit.calls`, `.per` | | 호출 0회, 즉 제한 없음. `calls`만 설정하고 `per`를 설정하지 않으면 `per`는 `1m`입니다. |

HotLoop과 MCP 연결은 에디터에서 설정합니다. URL, 계정, 타임아웃입니다. 차트에는 모든 플러그인 설정이 `values.yaml`의 `plugins` 아래에 `enabled: false`로 있고, 그 밖에 새로 생긴 것은 없습니다.
