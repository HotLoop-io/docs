## 개요

1.2.0은 MCP 서버의 도구 목록을 완성합니다. 엔진, 워크플로 파일 형식, 화면, REST API는 1.1.1과 같습니다.

## 네 가지 도구

HotLoop 제품군의 모든 MCP는 읽고 쓰는데, Cascade의 MCP에는 키가 호출할 수 있는 라우트 네 개가 빠져 있었습니다. 이제 모두 도구가 되어 총 83개입니다.

- `list_keys`와 `revoke_key`: 키 소유자의 키 목록과 그중 하나를 취소하는 기능입니다. 키는 자기 자신을 취소할 수 있으며, 유출된 키를 가진 사람이 가장 먼저 할 수 있어야 하는 일입니다. 호출자가 누구의 키를 취소할 수 있는지는 에디터와 마찬가지로 라우트 자체의 검사가 결정합니다.
- `listen_workflow`: 워크플로의 테스트 웹훅 URL을 1초에서 600초 동안 한 번의 호출용으로 엽니다.
- `start_oauth`: 사람이 OAuth2 자격 증명으로 로그인하려고 여는 주소를 돌려줍니다. 사람이 승인하는 단계는 그대로 필요합니다.

각 도구는 해당 라우트를 거치므로 권한 확인, 검증, 감사 기록은 라우트의 것이며, 쓰기 도구는 다른 쓰기 도구와 마찬가지로 이유를 요구합니다.

## 제외된 것

열 개의 라우트는 로그인한 사람을 요구하므로 키 자체를 거부합니다. API 키나 서비스 계정 키 만들기, SCIM 토큰 만들기, 시크릿 공급자나 로그 대상 추가, 변경, 삭제, 그리고 본인 비밀번호입니다. 키를 만들거나 감사 로그의 전달 대상을 바꿀 수 있는 키는 스스로 살아남는 유출된 키입니다. MCP 페이지에 목록과 이유가 있습니다.

## amd64 전용인 이유

이 릴리스는 amd64만 빌드합니다. 멀티 아키텍처는 별도의 실행으로 나가므로, 다음 릴리스는 둘 다 빌드하는 작은 버전 올림입니다.

## 업그레이드와 되돌리기

마이그레이션은 없습니다. 1.2.0으로 `helm upgrade`하거나 `:stable`이 Quadlet 유닛을 옮기게 두세요. 데이터베이스에서 바뀐 것이 없으므로 1.1.1로 되돌려도 안전합니다. 롤백으로 되돌릴 수 없는 것은 에이전트가 새 도구로 이미 한 일입니다.
