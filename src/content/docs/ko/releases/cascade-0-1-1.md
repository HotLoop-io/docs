## 개요

0.1.1은 후보 버전이 아닌 첫 릴리스입니다. 0.1.0 태그가 있었지만 아무것도 게시하지 못했습니다. 레지스트리에 무엇이든 도달하기 전에 취소되었기 때문입니다. 태그는 제자리에 남으므로, 이것은 같은 코드를 이제 게시한 것입니다.

정체: 공장 현장에서 쓰려고 만든 워크플로 엔진입니다. 정적 Go 바이너리 하나, 한 대에서는 SQLite, 더 필요할 때는 워커를 둔 Postgres, 그리고 바이너리에 내장된 에디터까지, 따로 실행할 것이 없습니다.

## 포함된 내용

모든 단계를 체크포인트로 저장하는 엔진이므로, 실행 도중 `kill -9`를 해도 멈춘 지점에서 이어집니다. 지속되는 대기, 재시도, 오류 포트, 오류 워크플로. 표현식, 그리고 별도 프로세스에서 격리해 JavaScript를 실행하는 Code 단계.

내구성 있는 수신함을 갖춘 웹훅, 메인 노드가 몇 개가 보고 있든 각 시각에 정확히 한 번 실행되는 스케줄, MQTT, 디렉터리에 들어오는 파일용 트리거. API가 있는 모든 것을 위한 HTTP 단계, 그리고 HotLoop, Postgres, EmberOps, 이메일, ntfy, Gotify, Discord용 커넥터. 그 밖의 것은 일부러 넣지 않았습니다.

키 교체를 지원하는 자격 증명 보관함, 공장에 필요한 모든 방식의 OAuth2, 비밀번호, TOTP, 패스키 또는 사용 중인 OpenID Connect 공급자로 로그인, 강제 MFA, 프로젝트와 역할, 검증할 수 있는 감사 로그, 저장할 때마다 버전으로 보관, 범위가 있는 API와 OpenAPI 문서. 저 말고도 누군가 멈춘 때를 알 수 있도록 메트릭, 트레이스, 프로브를 제공합니다.

## 실행 방법

이미지는 amd64와 arm64입니다. 움직이지 않는 배포를 원한다면 위의 다이제스트로 받으세요.

k3s에서는 Helm 차트를 단독으로 쓰거나 서버와 워커로 나누어 씁니다.

일반 서버에서는 `deploy/quadlet`의 Quadlet 유닛을 쓰며, 한 대에서는 SQLite, 워커를 늘릴 때는 Postgres를 씁니다. 유닛은 `:stable`을 따르고 Podman의 자동 업데이트 타이머가 이동시킵니다. 정상적으로 올라오지 않는 업데이트는 실행 중이던 이미지로 되돌려집니다. 두 방식 모두 실제로 돌려 보았습니다. systemd 아래 Podman 5.8.7에서 시작은 정상이 될 때까지 기다리고, 종료된 컨테이너는 다시 올라오고, 정상 업데이트는 적용되고, 잘못된 업데이트는 롤백되며, 매번 이후에 워크플로가 실행됩니다.

## 알아 둘 점

마이그레이션은 앞으로만 진행됩니다. 롤백은 이전 이미지를 되돌려 놓을 뿐 데이터베이스 마이그레이션을 되돌리지 않으므로, 업데이트를 켜기 전에 백업하세요.

이번 릴리스에서는 레지스트리가 비공개였기 때문에 먼저 root로 `podman login ghcr.io`가 필요했습니다. 0.1.2부터 이미지와 차트는 공개이며 로그인 없이 받을 수 있습니다.

저장된 자격 증명을 봉인하는 키를 잃어버리면 저장된 자격 증명을 모두 읽을 수 없게 됩니다. 서버가 아닌 다른 곳에 사본을 보관하세요.
