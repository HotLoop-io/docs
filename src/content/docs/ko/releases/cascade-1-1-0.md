## 개요

1.1.0은 Cascade에 MCP 서버와 에디터에 없던 화면들을 더하고, 로그인을 에디터 안으로 옮깁니다. 엔진, 워크플로 파일 형식, REST API는 1.0.2와 같습니다.

## MCP 서버

`/mcp`에 있으며 API와 같은 주소입니다. 기본으로 켜져 있고 쓰기가 됩니다. HotLoop 제품군의 모든 MCP는 읽고 쓰며, Cascade는 MCP가 아예 없던 마지막 제품이었습니다.

에이전트는 API 키로 로그인하고, 그 키 소유자가 할 수 있는 일을 키의 범위로 줄여서 받습니다. 도구는 79개이며 각각 REST API의 라우트 하나입니다. 호출은 라우트 자체의 핸들러를 거치므로 권한 확인, 검증, 쓰기, 감사 기록이 모두 라우트의 것입니다. MCP 서버에 복사한 것이 없어서 어긋날 수 없고, 빠뜨린 것이 없어서 건너뛰는 것도 없습니다.

- 무언가를 바꾸는 도구는 `reason`을 요구하며, 감사 로그는 변경 옆에 키와 클라이언트가 스스로 붙인 이름과 함께 이를 보관합니다.
- 자격 증명의 시크릿은 누구에게도 다시 돌아가지 않습니다. MCP로 만든 자격 증명은 시크릿이 도착하는 즉시 봉인됩니다.
- `HOTLOOP_CASCADE_MCP`와 `HOTLOOP_CASCADE_MCP_WRITES`는 배포의 스위치이며 둘 다 기본으로 켜져 있습니다. 어떤 도구나 API 라우트도 이를 바꿀 수 없으므로, 인스턴스 설정을 편집할 수 있는 에이전트도 쓰기를 다시 켤 수 없습니다.
- 키 자체를 거부하는 라우트(API 키, SCIM 토큰, 시크릿 공급자, 로그 대상 만들기)는 도구가 아닙니다. 키를 만들 수 있는 키는 스스로 살아남는 유출된 키이기 때문입니다. MCP 페이지에 모든 도구와 각 도구가 요구하는 권한이 나열되어 있습니다.

## 화면

자격 증명, 프로젝트, 내 계정, 그리고 소유자와 관리자를 위한 설정, 사용자, 감사 로그. 각 화면은 API와 같은 권한을 따릅니다. 사용자에게는 역할이 허용하는 것만 보이고, 나머지는 서버가 여전히 거부합니다.

- **자격 증명**은 만들고, 열고, 바꾸고, 다른 프로젝트와 공유하고, 삭제할 수 있습니다. 시크릿은 한 번 입력하며 화면에는 설정되었다는 표시만 나옵니다.
- **프로젝트**에는 구성원과 역할, 그리고 상시 통합이 로그인에 쓰는 서비스 계정 키가 있으며 키는 한 번만 표시됩니다.
- **계정**에서는 API와 MCP가 로그인에 쓰는 API 키를 만들고 취소하며 비밀번호를 바꿉니다.
- **사용자**에서는 사람을 만들고 끄거나 켭니다. **감사 로그**는 읽고, 필터링하고, 변조 여부를 검사할 수 있습니다. **설정**에는 두 번째 인증 요소 요구 사항과 오류 워크플로가 있습니다.

로그인은 이제 `/login`에 있는 에디터 자체의 페이지이며, 에디터의 색상으로 라이트와 다크를 지원하고 휴대폰에서도 데스크톱에서도 잘 보입니다. 이전 페이지가 하던 일을 모두 합니다. 첫 실행 설정, 비밀번호, 디렉터리 계정, 싱글 사인온, 패스키, 두 번째 인증 요소, 복구 코드입니다.

## amd64 전용인 이유

이 릴리스는 amd64만 빌드합니다. 멀티 아키텍처는 별도의 실행으로 나가므로, 다음 릴리스는 둘 다 빌드하는 작은 버전 올림입니다. 그때까지 `stable`, `latest`, 짧은 태그는 이 amd64 이미지를 이미 가리키던 arm64 이미지 옆에 함께 나열하므로 arm 장비도 계속 받을 수 있습니다. 버전 태그 `1.1.0`은 amd64 전용입니다.

## 업그레이드와 되돌리기

마이그레이션은 없습니다. 1.1.0으로 `helm upgrade`하거나 `:stable`이 Quadlet 유닛을 옮기게 두세요. 데이터베이스에서 바뀐 것이 없으므로 1.0.2로 되돌려도 안전합니다. 롤백으로 되돌릴 수 없는 것은 에이전트가 이미 한 일입니다. 에이전트가 바꾼 내용은 그대로 남고, 에이전트가 쓴 감사 기록은 행위자 유형 `mcp`로 로그에 남습니다. 업데이트 전에 백업하는 습관은 여전히 좋습니다.
