공장 옥상의 기상 관측소를 화면에서 하나의 대상으로 다룹니다. HotLoop은 비가 오는지 알아내려고 누구에게도 전화하지 않습니다. 관측소가 알려 줍니다. MQTT로 연결한 Ecowitt나 Tempest, Modbus로 연결한 Davis나 Vaisala, OPC UA로 연결한 무엇이든 가능합니다. 이들이 보내는 값은 이미 태그이고, 날씨 엔티티는 관측소 하나의 태그를 각자의 역할로 묶은 것입니다. 온도, 습도, 기압, 바람, 비, 일사량이 그 역할입니다.

기상 서비스도, API 키도, 인터넷도 필요 없습니다. 업링크가 3주 전에 끊긴 현장도 자기 옥상의 온도를 계속 보여 줍니다. (태양의 위치는 [태양](/ko/iot/sun/)을 보십시오. 현장의 위도와 경도로 계산하므로 관측소가 전혀 필요 없습니다.)

## 만드는 방법

날씨 엔티티는 모터를 만드는 방식과 같습니다([엔티티](/ko/iot/entities/#복합-설비) 참고). 관리자가 태그의 이름을 지정합니다. 엔티티 화면에서 새 장비, 날씨를 고릅니다. 또는 API로 만듭니다.

```json
POST /api/entities
{
  "domain": "weather",
  "name": "Roof station",
  "bindings": [
    {"role": "temperature", "device_id": "roof", "tag_name": "Temp"},
    {"role": "humidity",    "device_id": "roof", "tag_name": "Humidity"},
    {"role": "wind_speed",  "device_id": "roof", "tag_name": "Wind"},
    {"role": "wind_bearing","device_id": "roof", "tag_name": "Bearing"}
  ]
}
```

`temperature`만 필수입니다. 우량계가 없는 관측소는 `rain_rate`가 없고 비 행을 표시하지 않습니다. 모든 역할은 숫자 태그 하나를 받으며 어느 것도 쓰기 대상이 아닙니다. 관측소는 읽기만 하고 명령하지 않으므로 활성화할 태그가 없고 엔티티는 서비스를 받지 않습니다.

| 역할 | <span class="sr-only">세부 정보</span> | 만들어지는 속성 |
|---|---|---|
| `temperature` | 필수, 상태 | `unit_of_measurement` |
| `humidity` | 상대 습도, 퍼센트 | `humidity` |
| `pressure` | 기압, 태그의 단위 | `pressure` |
| `wind_speed` | 평균 풍속 | `wind_speed` |
| `wind_gust` | 최근의 가장 강한 돌풍 | `wind_gust` |
| `wind_bearing` | 바람이 불어오는 방향, 0도에서 360도 | `wind_bearing` |
| `rain_rate` | 지금 내리는 비의 세기 | `rain_rate` |
| `rain_today` | 자정 이후의 강수량 | `rain_today` |
| `solar_radiation` | 센서에 닿는 햇빛, 보통 W/m² | `solar_radiation` |
| `uv_index` | 자외선 지수 | `uv_index` |

각 속성에는 해당 태그의 단위를 담은 `<name>_unit`도 함께 붙으므로, 화면이 기압이 hPa인지 inHg인지 추측할 필요가 없습니다.

## 박스에서 계산하는 것

관측소가 거의 보내지 않는 값 세 가지를 관측소 자신의 측정값으로 계산합니다.

| 속성 | 출처 | 방법 |
|---|---|---|
| `dew_point` | 온도, 습도 | 0도에서 30 °C까지 건습구 표와 맞춘 Magnus 공식(Sonntag 1990) |
| `heat_index` | 온도, 습도 | 미국 기상청(NWS)의 Rothfusz 회귀식과 공표된 두 가지 보정. NWS가 사용을 멈추는 80 °F(26.7 °C) 이상에서만 존재합니다 |
| `wind_chill` | 온도, 풍속 | NWS 2001 지수. 보정 범위인 50 °F(10 °C) 이하이고 풍속이 3 mph를 넘을 때만 존재합니다 |

온도 자체의 단위로 돌려주므로, 화씨로 보내는 관측소는 화씨로 된 이슬점을 받습니다. HotLoop이 변환하는 온도 단위는 °C, °F, K이고 풍속 단위는 m/s, km/h, mph, 노트, ft/s이며, 태그의 단위에서 읽습니다. 단위가 없는 온도 태그는 추측으로 변환하지 않습니다. 엔티티의 `unit_of_measurement`가 그 단위를 알려 줄 수 있고, 둘 다 없으면 그 태그로는 아무것도 계산하지 않습니다.

열지수와 체감 바람 온도가 없는 것은 고장이 아닙니다. 80 °F 미만에서는 열지수가 없고, 바람이 약하거나 따뜻한 공기에서는 체감 바람 온도가 없으므로 카드에 해당 행이 없습니다.

## 없는 값은 0이 아닙니다

날씨 엔티티는 낙관하지 않으며 빈자리를 숫자로 채우지 않습니다.

* 연결되지 않은 센서는 행이 아닙니다.
* 연결되어 있지만 지금 읽을 수 없는 센서(태그가 불량이거나, 장치가 꺼져 있거나, 아직 아무것도 도착하지 않은 경우)는 속성에서 빠지고 `unavailable`에 이름이 올라갑니다. 카드는 그 숫자가 있을 자리에 **사용 불가**라고 표시합니다.
* 측정값일 수 없는 값도 같은 방식으로 다룹니다. 105퍼센트를 넘는 습도, 0도에서 360도를 벗어난 방위, 음수의 강수량이나 풍속입니다. 안개 속 센서가 읽는 101이나 102의 습도는 다음 값으로 표시합니다:
  100. 일사계가 밤에 내는 작은 음수는 0으로 표시합니다.
* 사용할 수 없는 값에서 계산한 값도 사용할 수 없으며 이름이 올라갑니다. 습도가 없으면 `dew_point`와 `heat_index`가 없습니다.
* 온도를 읽을 수 없으면 상태는 `unknown`(장치가 꺼져 있으면 `unavailable`)이고 품질은 평소와 같으며, 카드의 나머지는 다른 센서가 말하는 값을 계속 보여 줍니다.

## 화면에서

엔티티 화면에서 기상 관측소는 타일 하나입니다. 큰 글씨의 온도와 그 아래에 관측소가 주는 값마다 한 행이 정해진 순서로 나옵니다(습도, 기압, 바람, 풍향, 돌풍, 강우 강도, 오늘 강수량, 일사량, 자외선 지수, 이슬점, 열지수, 체감 바람 온도). 온도에는 평소의 추세선이 있습니다. 카드는 UI가 지원하는 모든 언어로 읽히며 아랍어에서는 오른쪽에서 왼쪽으로 배치됩니다.

## MCP

에이전트는 모든 엔티티가 가진 도구와, 관측소가 무엇을 받는지 알려 주는 도구로 관측소를 읽고 만듭니다.

| 도구 | 하는 일 |
|---|---|
| `list_composite_entities` | `create_entity`가 만들 수 있는 것을 읽습니다. 각 도메인의 역할, 필수 역할, 서비스가 쓰는 역할이 나옵니다. 날씨는 역할 10개에 필수 1개이고 서비스는 없습니다 |
| `create_entity` | `POST /api/entities`처럼 태그로 관측소를 만듭니다. 다른 모든 변경처럼 사유와 MCP 쓰기 스위치가 필요합니다 |
| `get_states` | 하나를 읽습니다. 상태는 온도이고, 모델이 읽는 텍스트에는 `unavailable`을 포함한 모든 속성이 함께 나열됩니다 |
| `list_entities` | `domain: weather`로 관측소를 찾습니다 |
| `delete_entity` | 하나를 삭제합니다 |

날씨 엔티티에 대한 `call_service`는 거부됩니다. 서비스를 받지 않기 때문입니다.

## 하지 않는 것

* 예보를 하지 않습니다. 다른 곳에 물어보지 않고는 예보가 없고, HotLoop은 그렇게 하지 않습니다.
* 어떤 센서도 그렇듯 관측소의 온도를 로그북 행으로 기록하지 않습니다. 이력은 태그의 것입니다. 타일의 추세선은 온도 태그의 것이고, 나머지 태그도 다른 태그처럼 히스토리언에 있습니다.
* 관측소를 대신 읽어 주지 않습니다. 관측소는 먼저 태그로 들어옵니다. 장치(MQTT, Modbus, OPC UA)를 추가한 다음 태그를 연결하십시오.
