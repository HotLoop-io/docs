---

대시보드는 누군가 만든 카드 페이지입니다. 게이지, 트렌드, 엔티티 목록, 펌프를 기동하는 버튼, 각 구역의 온도를 그 구역 위치에 놓은 평면도가 들어갑니다. 공장에 필요한 만큼 만들고, 각 대시보드를 그것이 필요한 역할이나 그것이 놓이는 화면 하나에 지정하면 됩니다. 예전의 Board는 그중 하나일 뿐입니다.

HotLoop IoT, Edge, Gateway에 있습니다. Edge Relay에는 UI가 없으므로 대시보드도 없습니다. Edge HMI는 이 페이지만으로 만들어지며, 나머지가 지금과 같은 모양인 이유도 거기에 있습니다.

## 이렇게 만든 이유

**카드는 아무것도 명령하지 않습니다.** 버튼이 있는 페이지를 설계할 때 가장 먼저 묻는 것은 그 페이지가 공장을 운전하는 두 번째 길이 아니냐는 점입니다. 아닙니다. 카드는 태그, 엔티티, 스크립트, 레시피 중 하나를 가리킬 뿐이고, 그것으로 무엇을 하는지는 브라우저가 다른 모든 화면과 똑같이 처리합니다. 쓰기 버튼은 `POST /api/write`를 보냅니다. 엔티티의 컨트롤은 `POST /api/services`를 호출합니다. 스크립트 버튼은 스크립트 화면의 실행 확인창을 열고, 레시피 카드는 레시피 화면의 적용 패널을 엽니다. 이들 모두 각자의 권한이 있고 쓰기 게이트를 거치므로, 대시보드가 우회로가 될 수도 없습니다. `dashboards.write`가 지키는 것은 버튼이 무엇이 될지 정하는 사람이 누구인가이며, 스크립트를 작성하는 것과 같은 이유로 그것은 엔지니어의 결정이고 관리자만 할 수 있습니다.

그 결과, 관리자가 저장한 대시보드는 운전원이 무언가를 누르기 전에는 아무것도 하지 않으며, 누르면 일어나는 일은 다른 화면에서 누를 때와 똑같습니다. 감사 기록의 행까지 같습니다.

**레이아웃은 좌표가 아니라 흐름입니다.** 카드는 읽는 순서대로 놓입니다. 각 카드는 12칸 중 너비가 몇 칸인지, 높이가 몇 행인지만 말하고, 자신이 어디에 놓일지는 모릅니다. 패널 PC에서는 12칸, 옆에 다른 창을 둔 노트북에서는 6칸, 태블릿에서는 2칸, 휴대폰에서는 1칸입니다. 픽셀 위치로 짠 레이아웃은 그것을 그린 화면에서만 맞습니다. Edge HMI는 기계에 달린 어떤 화면에서든 맞아야 합니다.

그 결과, 휴대폰용 버전을 따로 만드는 사람은 아무도 없습니다. 그런 버전은 없습니다.

**저장은 버전을 명시합니다.** 교대 시간에 한 대시보드를 두 사람이 동시에 편집하는 일은 실제로 일어납니다. 저장 요청은 연 시점의 `version`을 싣고 가며, 오래된 버전은 누가 먼저 저장했는지를 알려 주는 `409`로 거부됩니다. 그렇지 않으면 두 번째로 저장하는 사람이 첫 번째 사람의 오후 작업을 지워 버리고, 둘 다 그 사실을 보지 못합니다.

## 모델

```json
{
  "id": "line-2",
  "name": "Line 2",
  "description": "The extruder, for the floor.",
  "kind": "cards",
  "roles": ["operator", "admin"],
  "homeFor": ["operator"],
  "screens": ["line-2-panel"],
  "position": 1,
  "version": 3,
  "cards": [
    {"id": "temp", "type": "gauge", "title": "Zone 1", "w": 3, "h": 3,
     "config": {"tag": "press-01/Zone1_Temp"}},
    {"id": "go", "type": "button", "w": 3, "h": 1,
     "config": {"tag": "line-02/Speed", "value": 250, "label": "Run at 250", "confirm": true}}
  ]
}
```

- **`id`**는 소문자, 숫자, 하이픈, 밑줄로 이루어지며 문자로 시작합니다. 주소에 들어가고 바뀌지 않습니다. `wall`은 월 보드의 id입니다.
- **`kind`**는 `cards`이거나, 월 보드는 `wall`입니다.
- **`roles`**는 이 대시보드가 제공되는 역할입니다. 비어 있으면 모든 역할입니다. `dashboards.write`를 가진 사람은 설정과 무관하게 모든 대시보드를 봅니다. 아무도 열 수 없는 대시보드를 고칠 수 있어야 하기 때문입니다. 제공되지 않은 역할이 그 대시보드를 이름으로 요청하면 `404`를 받으므로, 어떤 대시보드가 존재하는지를 조회자가 물어서 알아낼 수는 없습니다.
- **`homeFor`**는 주소로 특별히 무엇을 요청하지 않고 들어온 역할이 처음 열게 되는 대시보드입니다. 역할당 최대 하나이며, 그 대시보드는 홈으로 지정된 역할에 제공되어야 합니다.
- **`screens`**는 이 대시보드가 놓이는 물리적 화면입니다. 화면 이름은 대시보드 하나에만 속합니다.
- **`position`**은 전환 막대의 순서를 정합니다. 새 대시보드는 맨 뒤에 갑니다.
- **`cards`**는 읽는 순서이며, 대시보드당 최대 60개, 전체 2 MB입니다.
- **`version`**은 저장할 때마다 1씩 올라갑니다.

카드는 `id`(대시보드 안에서 고유하며 페이지가 만듭니다), `type`, 선택 사항인 `title`, `w`(1에서 12까지), `h`(1에서 8까지), 그리고 타입에 따라 달라지는 `config`로 이루어집니다. `w`와 `h`를 생략하면 타입의 기본값이 쓰입니다. config는 엄격하게 검사됩니다. 타입에 없는 키는 오류이고, 저장되는 내용에는 모든 기본값이 채워집니다. 존재하지 않는 태그, 엔티티, 스크립트, 레시피를 가리키는 카드는 대시보드를 저장할 때 거부됩니다. 쓰기 가능으로 표시되지 않은 태그에 대한 버튼이나, 숫자가 태그의 범위를 벗어나는 버튼도 거부됩니다. 게이트가 모든 누름을 거부할 것이므로, 그 사실은 누르는 사람이 아니라 만드는 사람이 들어야 합니다.

## 카드

| 타입 | 내용 | 설정 | 기본 크기 |
|---|---|---|---|
| `status` | 연결된 장치, 보고 중인 태그, 알람, 히스토리안, 가동 시간: Board의 상단 띠 | 없음 | 12 x 1 |
| `gauge` | 태그 하나를 Board의 다이얼로 표시하며 범위와 알람 한계를 함께 표시 | `tag` | 3 x 3 |
| `value` | 태그 하나를 큰 숫자로 표시하며 알람 상태에 따라 색이 바뀜 | `tag`, `decimals` | 3 x 2 |
| `trend` | 태그 최대 6개를 15분에서 1주일 범위로 표시 | `tags`, `minutes`, `labels` | 6 x 3 |
| `entities` | 고른 엔티티를 각자의 컨트롤이 달린 타일로 표시 | `entities` (최대 30개) | 6 x 3 |
| `alarms` | 알람 목록, 권한이 있는 사람에게는 확인 버튼 포함 | `outstanding`, `limit`, `devices`, `equipment` | 6 x 3 |
| `button` | 확인을 거친 뒤 태그 하나에 값 하나를 씀 | `tag`, `value`, `label`, `confirm` | 3 x 1 |
| `script` | 스크립트 화면의 확인창을 거쳐 스크립트를 실행 | `script`, `label` | 3 x 1 |
| `recipe` | 최대 여덟 개의 레시피 중 하나를 골라 적용 패널을 엶 | `recipes` | 4 x 2 |
| `markdown` | 텍스트: 제목, 목록, 굵게, 기울임, 코드, http(s) 링크 | `text` | 4 x 2 |
| `camera` | 갱신되는 스냅샷 또는 모션 JPEG 스트림 | `url`, `stream`, `refreshSec` | 6 x 4 |
| `map` | 실시간 태그를 올려 둔 평면도 | `image`, `markers` | 6 x 5 |
| `setpoint` | 태그 하나에 입력하는 숫자: 한계, 단위, 확인 단계가 있고 장치가 되돌려 보고하는 값을 표시 | `tag`, `label`, `min`, `max`, `step`, `unit`, `decimals`, `confirm` | 3 x 3 |
| `symbols` | 기계 또는 공정의 그림: 배경 위에 픽셀 단위로 배치한 심볼을 배관으로 연결하고 태그에 따라 그립니다 | `image`, `width`, `height`, `symbols`, `pipes`, `view` | 8 x 5 |

뻔하지 않은 것들에 대해 알아 둘 점입니다.

- **`button`**은 `value`를 저장된 타입 그대로 보냅니다. 숫자는 숫자, `true`는 불리언, 문자열은 텍스트입니다. PLC에서 `1`과 `1.0`은 다른 쓰기이고 게이트는 JSON 타입으로 판단하므로, 카드가 한쪽을 다른 쪽으로 바꾸지 않습니다. `confirm`은 끄지 않는 한 켜져 있으며, 켜져 있으면 현재 값과 감사 기록에 남는 사유를 함께 보여 주며 "이 작업은 실제 설비를 명령합니다"라고 묻습니다(사유를 비워 두면 `dashboard <id> / <card>`가 들어갑니다). 끄는 것은 버튼을 누르고 있는 것 자체가 목적인 패널용이며, 엔지니어가 정할 일입니다. 설정 화면의 "쓰기 전에 확인"이 켜져 있으면 다시 켜집니다.
- **`alarms`**는 어디를 지정하지 않으면 공장 전체의 알람을 나열합니다. `devices`는 장치 id의 목록입니다. `equipment`는 `GET /api/equipment`의 설비 노드 id 목록이며, 사이트, 구역, 라인, 셀 등 어느 레벨이든 되고, 노드 하나는 그 위치 또는 그 아래에 놓인 모든 장치를 대표하므로 한 구역의 페이지에 그 구역의 알람만 표시할 수 있습니다. 둘 다 지정하면 어느 한쪽에 해당하는 알람이 나열됩니다. 생략하거나 비워 두면 카드는 공장 전체이며, 이 필드가 생기기 전에 저장된 모든 카드가 그랬습니다. 한도는 필터 뒤에 남은 개수를 셉니다. `outstanding`은 여전히 정상으로 돌아오고 확인된 알람을 제외합니다. 알람이 없는 장소로 한정한 카드는 "여기에는 없음"이라고 표시해 조용한 공장으로 읽히지 않게 하고, 그 사이에 설비가 삭제된 카드는 빈 목록 대신 그 사실을 표시합니다. 설비는 노드의 id로 저장되므로 노드의 이름을 바꾸거나 옮겨도 카드는 깨지지 않습니다. 장치나 노드가 없으면 저장할 때 대시보드가 거부됩니다. 빌더에서는 경로(`Plant 2 / Scrubbers / Kettle 3`)를 입력하면 id를 보관합니다. 이 카드는 트리를 읽으므로 역할에 `equipment.read`가 필요합니다(운전원과 조회자에게 있습니다).

  ```json
  {
    "id": "kettle-alarms", "type": "alarms", "title": "Scrubber alarms", "w": 6, "h": 3,
    "config": { "outstanding": true, "limit": 10, "equipment": [14], "devices": ["oven-1"] }
  }
  ```
- **`trend`**는 요청한 구간을 현재 시각까지 그립니다. 값이 우연히 기록된 구간만 그리지 않습니다. `minutes: 480`은 최근 여덟 시간의 축이며 정시마다 눈금이 있고, 보는 사람의 시간대를 따릅니다. 움직이지 않은 태그는 마지막 정상 값에서 이어지는 평평한 선입니다. 멈춘 밀이나 닫힌 밸브가 실제로 그렇게 보이기 때문입니다. 히스토리안은 값이 데드밴드를 넘어 움직일 때만 기록하므로, 구간 안에 기록이 하나뿐일 수도 없을 수도 있습니다. 선에 지어낸 것은 없습니다. 구간이 시작될 때 태그가 가지고 있던 값은 그 직전의 마지막 정상 값이며(`GET /api/history`가 `carry=true`로 알려 줍니다), 선은 구간 시작부터 구간 안의 첫 기록까지 그 값입니다. 마지막 기록 뒤에는 태그에서 마지막으로 응답을 받은 시각까지만 이어지고 현재를 넘지 않습니다. 누구에게도 첫 기록이 없던 시점 이전에는 선이 없고, 구간 직전의 마지막 값이 불량이었던 태그는 이어받는 값이 아예 없습니다. 그 값이 무엇이었는지 알 수 없기 때문입니다. 불량 값이 이어진 구간은 예전과 똑같이 끊어진 공백입니다. 기록 하나만 있으면 현재까지 이어진 선이 되고, 그릴 곳이 없으면 점입니다.

  범례는 각 선을 태그 자신의 이름, 즉 숫자 카드가 표시하는 이름에서 앞의 장치를 뺀 것으로 부릅니다. 서로 다른 장치의 같은 이름 두 선은 구분할 수 있도록 전체 id를 유지합니다. `labels`는 `tags`에 있는 태그에서 대신 표시할 텍스트(1자에서 80자)로 가는 선택적 객체이며, 그려지지 않는 태그의 레이블은 거부됩니다. 마우스를 올렸을 때 나오는 툴팁에는 항상 레이블 옆에 전체 id가 있습니다.

  ```json
  {
    "id": "mills", "type": "trend", "title": "Mill temperatures", "w": 6, "h": 3,
    "config": {
      "tags": ["plant-5-temperatures/Large Sand Mill Temperature", "plant-5-temperatures/Small Sand Mill Temperature"],
      "minutes": 480,
      "labels": { "plant-5-temperatures/Large Sand Mill Temperature": "Large mill" }
    }
  }
  ```
- **`camera`**는 서버가 아니라 브라우저에서 주소를 불러옵니다. 카드의 config는 대시보드를 여는 모든 역할이 읽을 수 있으므로, 로그인이나 토큰이 들어 있는 주소는 대시보드를 저장할 때 거부됩니다. 로그인이 필요 없는 공장 네트워크의 주소를 쓰거나, 로그인을 대신 붙여 주는 프록시를 쓰십시오. 정지 화상은 `refreshSec`초마다 `_hl` 쿼리 매개변수를 붙여 다시 가져오므로 브라우저가 첫 화상을 계속 보여 주지 않습니다.
- **`map`**은 그림과 마커입니다. 그림은 http(s) 주소이거나 카드에 업로드한 파일(png, jpeg, webp, gif, 최대 500 KB, 카드에 저장)입니다. 마커는 태그이며 그림 너비와 높이의 퍼센트로 놓이므로 크기가 달라져도 놓은 자리에 남습니다. 이것은 지도가 아니라 평면도입니다. 타일 지도에는 인터넷의 타일 서버가 필요하며, 공장의 패널 PC는 보통 거기에 닿지 못합니다.
- **`setpoint`**는 사람이 입력하는 숫자를 위한 것입니다. 온도, 속도, 레벨 등입니다. 이 필드는 태그의 단위(또는 카드의 `unit`)와 한계를 알고 있습니다. `min`과 `max`를 함께 지정하거나, 카드가 지정하지 않으면 태그 자체의 범위를 씁니다. 카드는 태그의 범위를 좁힐 수만 있고 넓힐 수는 없습니다. 카드가 무어라 하든 쓰기 게이트가 태그 범위 밖의 값을 거부하기 때문입니다. 더 넓게 제공하는 카드는 대시보드를 저장할 때 거부되며, 텍스트나 스위치를 가진 태그에 올린 카드도 마찬가지입니다(그런 태그에는 `button`을 쓰십시오). 한계를 벗어났거나, `step`에 맞지 않거나, 숫자가 아니면 필드 아래에 그렇게 표시되고 **Set**은 꺼진 채로 있습니다. **Set**은 먼저 현재 값과 감사 기록용 사유를 묻고(카드를 `confirm`을 끈 채 만들었고 설정이 이를 덮어쓰지 않는 경우는 제외), 그다음 `POST /api/write`를 거칩니다. 마스터 쓰기 스위치, 태그의 쓰기 가능 플래그, 역할의 권한, 감사 행은 다른 모든 쓰기와 같습니다. 카드는 이어서 장치의 읽기값에 그 값이 나타나기를 기다리고 2초 더 지켜본 뒤, 장치가 무엇을 가지고 있는지 알려 줍니다. "장치에서 70 C를 다시 읽었습니다: 보낸 값입니다". PLC가 쓰기를 받아들였다가 자체 한계로 되돌렸다면 "장치가 70 C를 받았다가 60 C로 바꿨습니다". 읽기값에 끝내 나타나지 않았다면 "장치는 70 C가 아니라 60 C를 보고합니다". "지금 장치에 있는 값" 줄은 항상 실시간 읽기값이므로, PLC 프로그램이 나중에 값을 덮어쓰는 것도 보여 줍니다. 장치에 정상 읽기값이 없는 동안(꺼져 있거나 연결할 수 없는 PLC) 필드와 Set은 꺼지고, 카드는 쓰기가 거부될 수밖에 없으므로 장치가 응답하지 않는다고 알려 줍니다.
- **`symbols`**는 기계의 그림입니다. `width`와 `height`는 페이지 자체의 크기(픽셀, 생략하면 800 x 450)이고, `image`는 선택 사항인 배경(http(s) 주소 또는 `map`과 같이 카드에 올린 그림)이며, `symbols`는 왼쪽 위 모서리부터 픽셀 단위로 배치한 항목의 목록입니다. `{"id": "p1", "type": "pump", "x": 120, "y": 300, "tag": "plc/bPumpRun"}`와 같습니다. 페이지는 크기를 조절한 한 장의 그림으로 그려지므로 모든 심볼은 카드 크기가 달라져도, 휴대폰에서도 제자리를 지킵니다. 유형은 `pump`, `motor`, `fan`(태그가 켜져 있는 동안 회전), `valve`(열림 또는 닫힘), `tank`(`min`과 `max` 사이, 또는 태그의 범위, 또는 0에서 100까지 채움), `heater`와 `lamp`(켜져 있는 동안 점등), `pipe`(선택 사항인 태그가 켜져 있는 동안 안의 내용물이 움직임), `readout`(`unit`과 `decimals`가 있는 숫자), `label`(고정 텍스트)입니다. `invert`는 태그를 반대로 읽고, 램프의 `tone`(`ok`, `warn`, `bad`, `info`)은 점등 색입니다. 운전 램프는 초록, 고장 램프는 빨강이며, 태그는 켜져 있는지 여부만 알려 줍니다. 모든 심볼은 태그를 읽는 규칙을 둘까지 가질 수 있습니다. `show`는 규칙이 성립하는 동안에만 심볼이 나타나게 합니다(`"show": {"tag": "plc/bDoorOpen", "op": "off"}`). 성립하지 않는 동안 심볼은 그려지지 않으며, 빌더는 선택할 수 있도록 흐리게 보여 줍니다. `colors`는 각각 `tone`(`ok`, `warn`, `bad`, `info`)을 가진 규칙 최대 네 개입니다. 처음으로 성립하는 규칙이 심볼 자신의 태그가 무엇이라 하든 그 톤으로 칠하고, 하나도 성립하지 않으면 원래대로 그려집니다. 규칙은 `tag`, `op`, 그리고 값이 필요한 비교에서는 `value`로 이루어집니다. 그 값은 `on`(태그가 0이 아님, 기본값), `off`, `eq`, `ne`, `gt`, `ge`, `lt`, `le`입니다. 태그에 정상 읽기값이 없는 규칙은 성립하지 않으며 아무것도 숨기지 않으므로, 연결이 끊겨도 심볼이 사라지지 않습니다. 규칙은 대신 규칙을 결합할 수도 있습니다. `{"all": [...]}`는 모두 성립하는 동안, `{"any": [...]}`는 하나라도 성립하는 동안 성립하며(PLC의 AND와 OR), 최대 세 단계 깊이에 여덟 부분까지이고 자체 태그는 없습니다. 태그를 잃으면 `all`은 성립하지 않고, `any`는 나머지를 통해 성립합니다. 램프는 비교나 결합으로 점등하는 경우 태그 대신 `lit` 규칙을 가질 수도 있으며(`"lit": {"tag": "plc/Mode", "op": "eq", "value": 3}`), 이 경우 태그가 필요 없습니다. 규칙의 태그는 화면이 이름을 지정하는 태그이므로, 화면 파일이 이를 나열하고 나머지와 함께 옮깁니다. 심볼은 색뿐 아니라 말로도 상태를 알려 주며(캡션과 제목), 태그가 알람 중이거나 알람에서 복귀한 상태이면 빨강 또는 따뜻한 색으로 그려지고, 태그에 정상 읽기값이 없으면 "no reading"과 함께 흐려집니다. 사용자가 시스템에 움직임 줄이기를 요청했다면 동작은 멈춥니다. 심볼은 HotLoop을 위해 HotLoop이 직접 그렸으며, 빌려 온 것은 없습니다. 태그가 있는 심볼은 클릭하면 그 태그를 엽니다. 평면도의 핀과 같습니다. 아무것도 명령하지 않으므로, 그렇게 하려면 옆에 `setpoint`나 `button` 카드를 두십시오. 빌더에서는 심볼을 포인터로 집어 옮기거나, 화살표 키로 옮기거나(Shift는 10픽셀), 픽셀 값을 숫자로 입력할 수 있습니다.

  **공정 심볼과 배관.** symbols 카드는 P&ID이기도 합니다. 위의 유형 외에 `controlvalve`, `checkvalve`, `compressor`, `heatexchanger`, `filter`, `vessel`, `flowmeter`, `instrument`(ISA 버블: `label`이 문자이고 태그의 숫자를 보여 줌), `junction`, `source`, `sink`를 배치합니다. 심볼에는 중심을 기준으로 90도씩 돌리는 `rot`(`90`, `180`, `270`)이 있으며, 텍스트는 돌아가지 않습니다. 대부분의 심볼에는 연결점이 있습니다. 펌프는 `in`과 `out`, 탱크는 `top`, `bottom`, `left-1`에서 `left-3`, `right-1`에서 `right-3`, 밸브는 `w`와 `e` 등입니다. 배관은 그중 두 개를 연결합니다.

  ```json
  "pipes": [
    { "id": "tank-out", "from": { "symbol": "tank-1", "port": "bottom" },
      "to": { "symbol": "p1", "port": "in" }, "medium": "water", "tag": "plc/Flow" }
  ]
  ```

  연결된 것만 저장됩니다. 경로는 페이지가 배관을 그릴 때마다 계산합니다. 직각이고, 페이지의 모든 심볼을 여유를 두고 돌아가며, 꺾임은 가능한 한 적고, 심볼에서 나가는 배관은 연결점이 향하는 쪽으로 나갑니다. 심볼을 옮기면 움직이는 동안 배관 경로가 다시 잡히며, 빌더에서도 저장된 파일에서도 마찬가지입니다. T는 배관 세 개가 붙은 `junction` 심볼이고(`n`, `e`, `s`, `w` 점이 모두 중심에 있음), 빌더에서 배관을 다른 배관 위에 놓으면 그 배관이 접합부로 자동으로 나뉩니다. `medium`은 `process`(기본값), `water`, `wastewater`, `fuel`, `oil`, `air`, `steam`, `gas`, `chemical`, `coolant`, `hydraulic`, `vacuum`, `nitrogen`, `power`, `signal` 중 하나입니다. 각각 고유한 색이 있으며, signal과 power는 선 모양도 따로 있어서 배관을 색만으로 구분하는 일은 없습니다. `tag`(`invert`와 함께)는 매체가 배관에서 `from`에서 `to`로 움직이는 때를 알려 주고, `flow`는 같은 내용을 규칙으로 알려 줍니다. 심볼의 `show`와 `colors`가 쓰는 것과 같은 규칙입니다. 둘 다 없는 배관은 가득 찬 채 정지한 모습으로 그려집니다. `label`은 배관을 따라 최대 24자입니다. 배관에는 태그 하나 또는 규칙 하나를 지정할 수 있으며 둘 다는 안 됩니다. 한 페이지에는 심볼 최대 120개와 배관 최대 240개가 들어갑니다.

  **도구 모음.** 모든 symbols 카드에는 보기 상태와 빌더 상태 모두에서 오른쪽 위에 도구 모음이 있습니다. 확대, 축소, 페이지 맞춤, 미니맵, 고성능 보기가 있습니다. 확대와 축소는 Ctrl과 휠(휠만 돌리면 대시보드가 계속 스크롤됩니다), 페이지에서 `+`, `-`, `0`으로도 할 수 있으며, 페이지를 끌어서 이동합니다. 확대하면 미니맵이 현재 위치를 프레임으로 표시한 전체 페이지를 보여 주며, 눌러서 끌면 그곳으로 이동합니다. 고성능 보기는 ISA-101 회색 페이지입니다. 장비와 배관은 회색이고, 운전 중이거나 열림 상태는 초록 대신 더 진한 채우기로 나타내며, 배관의 매체는 옆에 짧은 코드(물은 W, 증기는 S, 신호는 SIG)로 표시되고, 알람 중이거나 규칙으로 칠해진 것에만 색이 들어갑니다. `view`를 `hp`로 설정하면 페이지가 이 보기로 열리며, 보는 사람은 도구 모음에서 어느 쪽으로든 전환할 수 있고 그것으로 저장되는 것은 없습니다. 흐름 애니메이션은 사용자가 시스템에 움직임 줄이기를 요청하지 않은 경우에만 동작합니다.
- **`markdown`**은 HTML이 아니라 DOM 노드로 만들어지므로, 입력한 어떤 내용도 마크업이나 스크립트가 될 수 없습니다.
- **`gauge`, `value`, `map`, `setpoint`**는 대시보드를 저장한 뒤 태그가 삭제되면, 움직이지 않는 다이얼 대신 "이 게이트웨이에 더 이상 없음"이라고 표시합니다.

## 월 보드

월 보드는 `wall` 대시보드이며 kind가 `wall`입니다. 항상 존재하고 삭제할 수 없으며 카드가 없습니다. 게이지는 Board 화면에 고정한 태그이고, 예전부터 있던 보드 자체의 설정에 보관됩니다. `GET`과 `PUT /api/board`, `#board` 주소, 고정 태그 선택기, 끌어서 배치하는 기능은 그대로입니다.

대시보드가 됨으로써 얻는 것은 전환 막대(모든 대시보드에서 첫 번째 알약이며 Board에도 막대가 있습니다)와 지정 기능입니다. 일부 역할에 제공할 수 있고, 어느 역할의 홈이 될 수 있고, 물리적 화면 하나의 대시보드가 될 수 있습니다. 벽에 걸린 TV가 `/?screen=wall-tv`를 열면 헤더와 탭이 없는 Board가 나옵니다.

## 역할과 화면

**역할별.** `roles`는 누구에게 대시보드를 제공할지 정하고, `homeFor`는 역할이 처음 도착하는 곳을 정합니다. 홈이 `line-2`인 운전원은 HotLoop을 열면 2라인이 나옵니다. 주소에 URL 프래그먼트(`#alarms`)가 있으면 페이지는 주소가 가리키는 곳에서 열립니다.

**화면별.** 화면은 물리적 디스플레이입니다. HotLoop을 `/?screen=<name>`으로 열면 `screens`에 그 이름이 있는 대시보드가 헤더도 탭도 없이, 더 큰 터치 영역으로 나옵니다. 패널 PC 앞을 지나가는 사람에게 페이지를 빠져나갈 길은 필요 없기 때문입니다. 어떤 대시보드에도 없는 이름은 다른 것을 보여 주지 않고 그렇다고 알려 줍니다.

**패널은 사람을 로그인시키지, 자기 자신이 로그인하지 않습니다.** 아무도 로그인하지 않은 상태에서는 "PIN 또는 배지" 입력란 하나만 표시됩니다. 운전원이 PIN을 입력하거나 배지를 스캔하면(키보드 웨지 리더가 입력란에 입력해 줍니다) 패널이 대시보드를 엽니다. 그 사람의 이름과 **로그아웃** 버튼은 모서리에 있습니다. 그것을 보여 줄 헤더가 없기 때문입니다. 그 대시보드의 버튼이 하는 모든 쓰기는 그 사람으로서 쓰기 게이트를 거치며, 감사 기록과 로그북에는 "panel-3"이 아니라 "olga가 line-02/Speed에 250을 씀"이 남습니다. 15분 동안(설정입니다) 아무도 화면을 건드리지 않으면 패널은 그 사람을 로그아웃시키고 입력란으로 돌아가며, 그 뒤에 보낸 쓰기는 거부됩니다. 관리자는 **설정, 사용자**에서 각 사람에게 코드를 줍니다. 배지가 무엇인지, 코드가 어떻게 저장되는지, 무엇을 하지 않는지를 포함한 전체 내용은 [인증과 사용자](/ko/iot/authentication/#키오스크-패널-pin-또는-배지-그리고-유휴-로그아웃)에 있습니다.

본인의 컴퓨터에서는 이 중 어느 것도 적용되지 않습니다. 비밀번호로 로그인하므로 버튼의 쓰기는 곧바로 게이트를 통과하고 본인으로 기록되며, 유휴 로그아웃도 없습니다. PIN이 나오기 전에 패널을 운영해야 했던 방식인 고정 운전원 계정으로 로그인된 패널은 지금도 동작하며 그 계정으로 씁니다. 공용 패널에는 그런 로그인을 주지 마십시오.

Edge HMI가 바로 이것입니다. `screens`가 지정된 대시보드를 그 주소를 여는 기계에서 사용하며, 앞에 있는 사람들이 PIN이나 배지로 로그인합니다.

## 만들기

`dashboards.write`를 가진 사람(관리자)에게는 대시보드에 **편집**이, 막대에 **새 대시보드**가 표시됩니다. 편집하는 동안에는 다음과 같습니다.

- 카드는 동작하지 않으므로, 옮기려고 버튼을 잡아도 눌리지 않습니다.
- 카드를 다른 카드 위로 끌어다 놓거나, 카드 도구 막대의 화살표를 사용합니다. 터치스크린은 끌기를 시작하지 못하므로 휴대폰에는 화살표가 있습니다.
- 모서리를 끌어 크기를 바꿉니다. 너비는 12칸 중 한 칸에, 높이는 한 행에 맞춰집니다.
- 톱니바퀴는 카드를 편집하고, 복사 버튼은 복제하고, 십자는 삭제합니다.
- **설정**은 이름, 제공 대상, 처음 열리는 대상, 물리적 화면, 전환 막대에서의 위치입니다.

**저장**하기 전에는 아무것도 저장되지 않습니다. **취소**는 변경을 버립니다. 저장할 때 `409`가 나오면 누군가 먼저 저장했다는 뜻이며, 페이지가 그 사람의 것을 불러오겠느냐고 묻습니다.

**내보내기**(편집 옆)는 화면의 대시보드를 파일로 저장하고, **가져오기**(`dashboards.write`를 가진 사람에게 새 대시보드 옆 막대에 있음)는 파일을 이 설치본에 불러옵니다. 화면은 고객의 데이터이므로 아무도 다시 만들지 않고도 설치본 사이를 옮겨 다닙니다. [화면 파일](/ko/iot/screen-file/)을 참고하십시오.

## 레이아웃

| 너비 | 열 | `w`인 카드가 차지하는 칸 |
|---|---|---|
| 1100 px 초과 | 12 | `w` |
| 700 px 이상 1100 px 이하 | 6 | `w`의 절반, 올림 |
| 480 px 이상 700 px 이하 | 2 | 1칸, `w`가 4를 넘으면 2칸 |
| 480 px 미만 | 1 | 전체 |

넓은 레이아웃에서 행은 76 px이고 간격은 16 px입니다. 휴대폰에서 카드의 높이는 내용에 맞고 행 수에서 오는 최소 높이가 있으므로, 잘리는 것이 없습니다. 전환 막대는 자기 안에서 가로로 스크롤되며 페이지 전체는 가로로 스크롤되지 않습니다.

## 휴대폰에서

웹 UI는 휴대폰에 설치할 수 있고 연결이 없어도 열립니다. 같은 페이지에 매니페스트, 아이콘, 서비스 워커가 붙은 것이며 HotLoop이 직접 제공하므로 서버에 빌드할 것도 설치할 것도 없습니다.

**설치.** Android에서는 Chrome 메뉴에 **앱 설치**가 있습니다. iPhone에서는 Safari 공유 시트에 **홈 화면에 추가**가 있습니다. 공장 이름이 표시된 전체 화면으로 열리며, Android에서는 아이콘을 길게 누르면 알람과 대시보드를 바로 열 수 있습니다. 브라우저는 **https** 또는 `localhost`에서만 페이지를 설치하고 서비스 워커를 실행합니다. 공장의 일반 `http://` 주소에서는 HotLoop이 지금까지처럼 탭에서 열리지만, 설치할 수 없고 오프라인에서 동작하지도 않습니다. 휴대폰용으로 앞에 인증서를 두십시오(이미 있는 인그레스나 리버스 프록시입니다). 설치되지 않는 이유는 브라우저가 알려 줍니다. Chrome 개발자 도구의 Application, Manifest에서 볼 수 있습니다.

**보관하는 것.** 페이지 자체와, 사람이 보는 읽기 요청의 마지막 응답입니다. 알람 목록, 대시보드, 읽기값과 엔티티 상태, 장치와 태그, 상태, 설비 트리, 보드입니다. 페이지가 열려 있고 연결된 동안에는 열 때 보여 줄 것이 있도록 1분에 한 번 이것들을 요청하며, 휴대폰이 주머니에 있을 때는 요청하지 않습니다. 연결 없이 열면 페이지가 로드되고, 알람 목록과 대시보드에는 휴대폰이 마지막으로 본 내용이 표시되며, 아래쪽 막대가 시각과 함께 그 사실을 알려 줍니다.

```
Offline. This is what this phone last saw as of 10/22/2026, 05:42:23. Nothing you
do here is sent until the connection is back.
```

연결이 돌아오면 몇 초 안에 막대가 사라지고, 화면이 실시간 응답으로 갱신되며, 실시간 피드가 다시 연결됩니다.

**오프라인이고 로그인한 적이 없을 때.** 앱은 있지만 로그인하지 않은 휴대폰(한 번도 하지 않았거나, 로그아웃해서 보관한 내용이 비워진 경우)은 연결이 없으면 보여 줄 것이 없으므로, 로그인 화면을 표시하고 이유를 알려 줍니다. 여기서는 HotLoop이 응답하지 않으며 계속 시도한다는 것입니다. HotLoop이 응답하는 순간 페이지가 저절로 다시 로드되어 실제 로그인 화면이 됩니다. 아무것도 들어 있지 않은 앱을 보여 주는 일은 없습니다.

**절대 하지 않는 것.** 무언가를 바꾸는 요청은 오프라인 페이지에서 전혀 보내지 않습니다. 태그에 값을 쓰거나, 스크립트를 실행하거나, 레시피를 적용하거나, 알람을 확인하는 쓰기는 페이지를 떠나기 전에 이유와 함께 거부됩니다.

```
You are offline, so nothing was sent. Everything here is as of 10/22/2026, 05:42:23.
Try again when the connection is back.
```

서비스 워커는 쓰기에 응답하지도, 보관하지도, 대기열에 넣지도 않으며, 그 안에 백그라운드 동기화도 없습니다. 설비에 대한 명령은 실시간 응답을 보고 있는 사람만 보낼 수 있고, 연결이 없을 때 누른 버튼이 어딘가에서 기다리다가 나중에 나가는 일은 없습니다. 알림에서 확인하는 것은 별개이며 마찬가지로 네트워크가 필요합니다. ntfy 앱이 자기 버튼을 누릅니다.

**보관하지 않는 것.** 실시간 피드, 트렌드와 이력, 로그북, 설정, 사용자, 에스컬레이션 정책, 알림에 관한 모든 것입니다. 너무 크고 매번 달라서 보관할 가치가 없는 것도 있고, 휴대폰의 캐시에 두어서는 안 되는 것(사람들의 ntfy 토픽, 계정)을 담고 있는 것도 있으므로, 이 화면들은 HotLoop이 응답해야 합니다.

**휴대폰에서.** 보관되는 것은 그 휴대폰의 브라우저 캐시 저장소에 있으며 최대 200개의 응답이고, 오래된 것부터 버려집니다. **로그아웃하면 비워지며**, 만료되었거나 철회된 세션도 마찬가지입니다(첫 `401`이 비웁니다). 로그인된 세션만 보관되므로 오프라인 휴대폰이 다른 사람의 데이터를 열 일은 없습니다. 새 HotLoop 버전은 자기만의 페이지 캐시를 받고 이전 것은 삭제됩니다. 연결이 있으면 페이지는 항상 실시간으로 가져오므로, 새 버전이나 바뀐 공장 이름은 다음에 열 때 나타납니다.

같은 테스트가 페이지와 워커 모두에서 서버를 없애고 다시 로드합니다. 페이지가 열리고, 알람 목록과 대시보드에는 보관된 내용이 표시되고, 태그 쓰기와 알람 확인이 모두 거부되며, 연결이 돌아온 뒤에도 알람은 여전히 확인되지 않은 상태이고 쓰기 감사 기록은 비어 있으며, 로그아웃하면 보관한 내용이 비워집니다. 베어메탈에서 실행했습니다(2026-11-17). 실제 휴대폰 설치, iPhone의 Safari, 실제 공장 Wi-Fi가 끊기는 상황을 포함합니다.

## 권한

| 권한 | 조회자 | 운전원 | 관리자 |
|---|---|---|---|
| `dashboards.read` | 예 | 예 | 예 |
| `dashboards.write` | 아니요 | 아니요 | 예 |

읽기는 모든 역할의 권한이며 `roles`로 걸러집니다. 쓰기는 관리자의 권한입니다. 카드를 눌렀을 때 할 수 있는 일은 누르는 사람 자신의 권한입니다. 조회자에게는 쓰기 버튼이 비활성으로 보이고, 그것을 넘어서더라도 서버가 거부합니다.

## API

| 메서드 | 경로 | 권한 |
|---|---|---|
| `GET` | `/api/dashboards` | `dashboards.read` |
| `POST` | `/api/dashboards` | `dashboards.write` |
| `GET` | `/api/dashboards/{id}` | `dashboards.read` |
| `PUT` | `/api/dashboards/{id}` | `dashboards.write` |
| `DELETE` | `/api/dashboards/{id}` | `dashboards.write` |
| `GET` | `/api/dashboards/{id}/export` | `dashboards.read` |
| `POST` | `/api/dashboards/import` | `dashboards.write` |

본문과 오류를 포함한 레퍼런스는 [HTTP API](/ko/iot/api/#대시보드)에 있습니다. 모든 생성, 저장, 삭제는 주체 `dashboard:<id>`에 대한 `config` 이벤트로 기록에 남으므로, 로그북에서 패널에 표시되는 내용을 누가 바꿨는지 알 수 있습니다.

테이블은 `dashboards`이며 PostgreSQL, TimescaleDB, SQLite용 마이그레이션 0023에서 추가되었습니다. 추가만 합니다([마이그레이션은 추가만 합니다](/ko/iot/migrations/)). 월 보드의 행은 마이그레이션이 아니라 애플리케이션이 처음 요청받을 때 만들므로, 대시보드가 생기기 전에 만든 백업에서 복원한 데이터베이스에도 다시 생깁니다.

## 여기에 없는 것

- **픽셀 단위 레이아웃.** 위에서 설명한 대로 의도한 것입니다. 기계의 HMI에서 컨트롤이 정확히 고정된 자리에 있어야 한다면, 그것은 그 기계를 위해 만든 화면이며 이 기능이 하는 일이 아닙니다.
- **카드별 표시 여부.** 대시보드는 역할에 제공되고, 카드는 그렇지 않습니다. 카드가 서로 다른 두 독자는 대시보드 두 개입니다.
- **타일 지도.** `map` 카드를 참고하십시오.
- **버튼 누르고 있기.** 버튼은 누를 때 한 번 씁니다. 누를 때 쓰고 뗄 때 다시 쓰는 순간 컨트롤은 다른 카드이며, 만들어져 있지 않습니다.
- **Edge Relay의 대시보드.** UI가 없습니다.
