title: "CODESYS 화면 가져오기"
description: "IDE에서 CODESYS 비주얼라이제이션을 내보내 PLC 변수 위의 HotLoop 화면으로 가져옵니다. 배치하지 못한 요소는 가장 먼저 목록으로 알려 줍니다."
---

운영자에게는 이미 CODESYS 화면이 있습니다. IDE에서 내보내 HotLoop으로 가져오면, 같은 PLC의 변수 위에 HotLoop 화면으로 열립니다. WebVisu에서 벗어나는 방법입니다. PLC는 계속 자기 프로그램을 실행하고, HotLoop은 OPC UA 커넥터로 그것을 읽으며, 화면은 HotLoop의 것입니다. HotLoop for CODESYS는 Edge를 실행하므로 이것이 그 가져오기이기도 합니다.

## 사용 방법

CODESYS IDE의 프로젝트 트리에서 비주얼라이제이션을 선택하고 **프로젝트, 내보내기**(CODESYS 고유의 내보내기이며 `.export` 파일)를 사용합니다. **PLCopenXML 내보내기**가 아닙니다. 그 파일에는 비주얼라이제이션이 없으며, 선택하면 HotLoop이 그렇게 알려 줍니다.

대시보드 화면에서 **가져오기**를 누르고 `.export` 파일을 고른 뒤 **파일 읽기**를 누릅니다. 다음을 알려 줍니다.

* 찾은 비주얼라이제이션(여러 개가 든 파일이면 어느 것인지 묻습니다),
* 화면이 읽지만 이 설치에는 없는 모든 태그. 변수는 `plc/<GVL>.<variable>` 형태로 들어옵니다. 장치 `plc`를 PLC가 연결된 HotLoop 장치에 매핑하면 모든 태그가 한꺼번에 옮겨지며, 태그를 하나씩 매핑할 수도 있습니다.
* **확인할 것**: 화면에 놓지 못한 모든 요소와 그 이유로, 아무것도 저장하기 전에 보여 줍니다.

막는 것이 없을 때까지는 아무것도 저장되지 않습니다. 가져오기에는 `dashboards.write`가 필요하며, 쓰기 가능으로 표시되지 않은 태그의 버튼이나 설정값은 빌드할 때와 같이 여기서 거부되므로, 게이트가 거절할 컨트롤이 화면에 생기지 않습니다.

API로는 `file` 대신 `codesys`(파일 텍스트)를 넣어 `POST /api/dashboards/import`를 호출하고, 여러 개 중 하나를 지정하려면 `visualization`을 씁니다.

```json
{"codesys": "<ExportFile>...", "visualization": "Overview", "dryRun": true,
 "remap": {"devices": {"plc": "line-3"}}}
```

보고서에는 평소의 `problems`, `warnings`, `remapped`가 있고, `mapped`(각 요소가 무엇이 되었는지)와 `unmapped`(각 요소가 왜 안 되었는지)를 담은 `conversion`이 있습니다.

## 가져와지는 것

| CODESYS 요소 | HotLoop에서 |
|---|---|
| 사각형, 둥근 사각형, 텍스트와 변수가 있는 타원(`Temperature: %2.1f C`) | 값 표시: 변수의 태그, 앞의 텍스트는 캡션, 뒤의 텍스트는 단위, 소수 자릿수는 서식에서 가져옴 |
| 같은 모양에 텍스트만 있고 변수가 없는 경우 | 레이블 |
| 램프 | 변수로 켜지고 램프 자체의 색으로 칠해지는 램프(빨강은 고장, 노랑은 경고, 파랑은 정보, 그 밖은 운전 램프). `NOT x`는 태그를 반대로 읽음 |
| 미터, 포텐쇼미터 | 변수의 값 표시. 값을 설정하던 노브는 다이얼의 눈금을 한계로 하는 설정값 카드도 받음 |
| 로커 스위치, 토글, 푸시 버튼 | 상태를 보여 주는 램프와 버튼 카드: 토글은 켜기와 끄기, 탭은 하나의 값 |
| 다각형, 폴리라인, 텍스트도 변수도 없는 도형(배관, 용기, 프레임) | 심볼 뒤의 그림으로, 점과 색에서 그려짐 |
| 그룹 | 구성원이며 그룹의 모서리에서부터 배치됨 |
| 요소의 **Invisible** 변수(`bInvisible`) 또는 그 요소가 속한 그룹의 변수 | 심볼의 `show` 규칙: 변수가 요소가 보일 것이라고 말하는 동안에만 그려집니다(`NOT x`는 반대로 뒤집습니다) |
| 요소의 **Toggle color** 변수 | 심볼의 `colors` 규칙: 변수가 켜져 있는 동안 요소 자신의 알람 색에 가장 가까운 톤으로 칠해집니다(빨강은 `bad`, 노랑과 주황은 `warn`, 파랑은 `info`, 초록은 `ok`이며, 자체 알람 색이 없는 요소는 CODESYS의 기본 알람 프레임이 빨강이므로 `bad`입니다) |

모든 요소는 픽셀 위치를 유지합니다. 페이지는 심볼 카드이며 하나의 확대·축소 그림으로 그려지므로, 화면은 어떤 크기에서도, 휴대폰에서도 모양을 유지합니다.

## 가져와지지 않는 것

가져오기 중에 하나씩 한 줄로 알려 주며, 조용히 빠뜨리지 않습니다.

* HotLoop 심볼이 없는 요소 종류(트레이스, 표, 슬라이더, 이미지 요소와 도구 상자의 나머지),
* 식인 변수(`Temp * 2`, `a AND b`, 배열 요소): HotLoop은 태그를 보여 주므로, 식을 위한 태그를 추가하고 값 표시가 그것을 가리키게 하십시오,
* 배경 그림에 그려지는 도형(배관, 용기, 프레임)의 Invisible 또는 Toggle color 변수: 그림은 한 장의 이미지이므로 도형은 항상 있고 색을 유지합니다. 가져오기 결과에 변수와 함께 표시됩니다.
* PLC 값으로 구동되는 그 밖의 설정(채우기, 프레임, 텍스트의 색 변수, 움직임, 깜박임, 텍스트 목록): 심볼은 그려진 그대로 있으며, 그 변수가 일반 변수이면 규칙이 보고됩니다.
* 베지어 곡선은 점 사이의 직선으로 그려지고, 회전된 요소는 회전되지 않습니다,
* 내보내기 파일에 없는 페이지 크기: 페이지는 가장 바깥쪽 요소의 크기에 여백을 더한 크기입니다,
* 40자를 넘는 텍스트는 잘리고, 다이얼은 다이얼이 아니라 숫자입니다.

CODESYS 스타일의 텍스트 스타일, 글꼴, 색은 HotLoop의 것입니다. 화면은 HotLoop의 테마를 따릅니다.

## 파일을 읽는 방식

CODESYS는 기본 내보내기가 있고 XML이라는 것만 문서화하며, 그 안에 무엇이 있는지는 문서화하지 않습니다. 여기의 리더는 IDE 자체가 쓰는 내용을 따릅니다(CODESYS 3.5 SP22, Visualization 4.10). 모든 요소는 설정을 번호가 붙은 멤버 목록으로 저장하며, 번호는 요소 설명 안에서 멤버 경로의 CRC-32입니다. 예를 들어 `m_StaticPosition.iX`이며 IDE가 자기 옆에 설치합니다. IDE의 요소 트리는 모든 경로를 ID와 함께 나열하며(`ITypeNode.CompletePath`와 `CRCIdNumber`), Invisible 변수(`m_pStateVariables..State.bInvisible`, 2880254039)와 Toggle color 변수(`m_pColorVariables..ToggleColor`, 1999528970)의 ID는 거기서 가져온 것입니다. 앞의 ID는 CODESYS Refrigerator 예제가 그룹의 `NOT Glob_Var.DoorOpen`을 저장하는 ID입니다. 테스트에는 IDE 자체의 내보내기에서 읽은 값이 들어 있습니다. 변수를 가지고 있지만 읽지 못하는 설정은 위와 같이 보고되므로, 화면이 완전하지 않은데 완전한 것처럼 가져와지는 일은 없습니다.

## 다음 단계

화면을 열어 값 표시를 공장과 대조해 보고, 설정값 카드와 버튼 카드를 운영자가 기대하는 위치에 두십시오. 손으로 만든 화면과 가져온 화면은 이때부터 같습니다. [화면 파일](/ko/iot/screen-file/)로 내보낼 수 있고, 저장할 때마다 버전이 남으며, 같은 방법으로 다른 설치로 옮길 수 있습니다.

## TwinCAT 시각화(.TcVIS)

TwinCAT의 `.TcVIS` 파일은 IDE의 오브젝트 아카이브 XML에 담긴 같은 시각화이며, 요소 유형과 멤버 ID도 같으므로 같은 변환기를 거칩니다. 실제 TwinCAT PackML 예제로 확인했습니다.

- 버튼: 버튼의 입력 동작에 있는 단순 대입(`X := 5`, `X := TRUE`, `X := E_PMLCommand.ePMLCommand_Start`)은 그 값을 X에 쓰는 버튼 카드가 되고, 캡션은 레이블로 넘어옵니다. 구성된 Toggle 입력은 켜기와 끄기 버튼 한 쌍이 됩니다. 대입 이상의 코드(조건, 호출, 산술)는 그 텍스트와 함께 보고됩니다.
- 열거형: OMAC PackML 멤버(`E_PMLCommand`, `E_PMLUnitMode`)는 알려져 있으며, 번호는 Beckhoff의 PackML_HMI_Example 구성과 SPT-Libraries의 `E_PMLUnitMode` 선언에서 가져왔습니다. 그 밖의 열거형은 가져오기의 `enums`에 넣습니다(`{"E_Own.eOwn_Go": 7}`). 알려진 번호가 없는 멤버는 이름으로 기록되며 보고서가 그 사실을 알려 줍니다.
- 식: 램프의 변수와 Invisible 변수는 태그 하나를 숫자, TRUE, FALSE, 열거형 멤버와 비교한 것(`=`, `<>`, `<`, `<=`, `>`, `>=`)이거나 NOT, AND, OR와 괄호를 쓴 식일 수 있습니다. 이것은 심볼 규칙이 됩니다(DASHBOARDS.md 참조: 램프의 `lit` 규칙, 심볼의 `show`와 `colors` 규칙이며, 규칙은 `all`과 `any`로 결합할 수 있습니다). 태그 두 개의 비교, 산술, 호출은 표현할 수 없으며, 표현하지 못한 부분과 함께 보고됩니다.
- 프레임: 프레임은 다른 시각화를 보여 줍니다. 프로젝트의 다른 파일을 첫 번째 파일과 함께 보내십시오(API에서는 `codesysRelated`, 대화 상자에서는 여러 파일을 선택하면 첫 번째가 화면). 프레임의 시각화가 프레임 안에 놓이고, 받는 입력마다 프레임에 지정된 변수에 연결됩니다(V_Module의 `HMI`는 `MAIN.VFFSDemo.Sealer.PackMLBaseModule_HMI`가 됩니다). 시각화가 파일 중에 없는 프레임은 이름과 함께 보고됩니다.

PackML 세트(V_Main과 V_Module, V_MachineModule): 요소 60개가 매핑되었고 매핑되지 않은 것은 없습니다.
