화면은 고객의 것이며 파일로 옮겨 다닙니다. 한 설치에서 대시보드를 내보내 다른 설치로 가져오면, 레이아웃도 태그 이름도 텍스트도 HotLoop의 코드에 남아 있지 않습니다. 같은 파일이 HotLoop IoT, Edge, Gateway에서 모두 동작합니다. 세 제품이 하나의 대시보드 세트를 실행하기 때문입니다([대시보드](/ko/iot/dashboards/)).

Edge Relay에는 UI도 화면도 없습니다. Flow의 대시보드는 플로의 일부이며 플로에는 자체 가져오기와 내보내기가 있습니다. HotLoop for CODESYS의 화면은 Edge의 화면입니다.

## 사용 방법

대시보드 화면에서 **내보내기**(현재 표시된 대시보드의 편집 옆)를 누르면 `<id>.hotloop-screen.json`이 저장됩니다. **가져오기**(새 대시보드 옆 막대에 있음)는 파일을 읽고, 필요한 것과 여기에 없는 것을 알려 주며, 없는 태그, 장치, 엔티티, 스크립트, 레시피를 각각 존재하는 것에 매핑하게 한 뒤 다시 검사하고 저장합니다. 가져오기에는 `dashboards.write`가 필요하므로 관리자의 일입니다. 내보내기에는 `dashboards.read`가 필요하며 대시보드는 목록에 보이는 것이어야 합니다.

API로는 [`GET /api/dashboards/{id}/export`](/ko/iot/api/#get-apidashboardsidexport)와 [`POST /api/dashboards/import`](/ko/iot/api/#post-apidashboardsimport)이며, 화면이 호출하는 것이 바로 이것입니다. 가져오기는 같은 대시보드를 만들 때 거부될 내용을 저장하지 않습니다.

## 파일

UTF-8 JSON이며 최대 4 MiB입니다.

```json
{
  "format": "hotloop-screen",
  "formatVersion": 1,
  "exported": { "product": "edge", "version": "4.22.1", "at": "2026-11-19T16:00:00Z" },
  "screen": {
    "id": "line-2",
    "name": "Line 2",
    "kind": "cards",
    "roles": ["operator", "admin"],
    "homeFor": ["operator"],
    "screens": ["line-2-panel"],
    "position": 1,
    "cards": [
      { "id": "temp", "type": "gauge", "title": "Zone 1", "w": 3, "h": 3, "config": { "tag": "press-01/Zone1_Temp" } }
    ]
  },
  "requires": {
    "tags": [ { "key": "press-01/Zone1_Temp", "dataType": "float", "unit": "C", "writable": false } ],
    "entities": [], "scripts": [], "recipes": [], "devices": [], "equipment": []
  }
}
```

**`format`과 `formatVersion`.** `format`은 항상 `hotloop-screen`입니다. `formatVersion`은 1부터 시작하는 정수입니다. HotLoop은 자기 버전과 그 이전 버전을 읽고, 더 새로운 버전은 파일의 버전과 자신이 읽는 버전을 알려 주며 거부합니다. 파일에 필드를 추가하면 새 버전이 됩니다. 리더는 모르는 필드를 거부하며, 말없이 버려진 필드는 거부보다 나쁘기 때문입니다. 이것은 버전 1입니다.

**`exported`.** 어느 제품과 버전이 언제 썼는지입니다. 파일을 읽는 사람을 위한 것입니다. 이것으로 결정되는 것은 없습니다. HotLoop이 화면을 표시할 수 있는지는 카드 타입이 결정하며, 모르는 카드 타입은 이름과 함께 거부됩니다.

**`screen`.** 대시보드 API가 보관하는 대로의 대시보드이며, 설치 자체의 관리 정보(`version`, `updatedBy`, `createdAt`, `updatedAt`)는 없습니다. `description`은 비어 있으면 빠집니다. 카드는 읽는 순서로 놓이며 각각 크기(12열 기준 `w`, 행 단위 `h`)와 `config`를 가집니다. 각 타입은 [대시보드](/ko/iot/dashboards/#the-cards)가 설명하는 그대로입니다. 레이아웃은 이것이 전부입니다. 카드의 흐름이며 픽셀 좌표는 없습니다. 심볼 카드는 자기 페이지 위에 심볼을 픽셀 단위로 배치하며, 이는 카드의 config 안에 있습니다.

**자산은 안에 들어 있습니다.** 지도 카드의 평면도와 심볼 카드의 배경은 카드 `config` 안의 base64 PNG 데이터 URL이므로, 파일 하나가 화면 전체이고 파일을 보내면 그림도 함께 보내는 것입니다. 한도는 대시보드의 한도로, 그림 하나당 700 KB, 화면 하나당 2 MiB입니다.

**`requires`.** 화면이 도착한 설치에서 필요로 하는 것을 카드에서 계산한 것입니다. 화면이 읽는 모든 태그(내보낸 곳에서의 타입과 단위, 버튼이나 설정값이 그 태그에 쓰는지 여부 포함)와 카드가 이름을 든 엔티티, 스크립트, 레시피, 장치, 설비의 ID입니다. 사람과, 가져오기 전에 미리 보려는 도구를 위한 것입니다. 가져오기는 카드에서 다시 계산하며 이 블록을 결코 믿지 않습니다. 파일의 태그 타입이 도착한 태그와 다르면 경고입니다.

**월 보드는 내보내지 않습니다.** 월 보드는 설치에 고정된 게이지이지 레이아웃이 아닙니다. 내보내면 `400`이 되며 `kind`가 `wall`인 파일은 거부됩니다.

**할당.** `roles`, `homeFor`, `screens`, `position`은 화면이 나간 그대로 돌아오도록 파일에 들어 있습니다. 이것들은 한 설치에 가장 강하게 묶인 부분이기도 합니다. 패널 이름은 한 설치에서 하나의 대시보드에 속하고, 역할에는 하나의 홈이 있습니다. 가져오기는 이를 적용하며, 이 설치가 이미 그 화면 이름이나 그 역할의 홈을 다른 대시보드에 주고 있으면 그렇게 알립니다(`assignment`). **할당 건너뛰기**는 `screens`와 `homeFor`를 빼고 `roles`는 유지합니다.

## 가져오기

검사는 이 순서로 실행되며, 모두 통과할 때까지 아무것도 저장되지 않습니다.

1. **파일.** JSON, 올바른 `format`, 이 빌드가 읽는 버전, 모르는 필드 없음, 종류 `cards`.
2. **사용자의 변경.** 새 ID 또는 이름, 할당 없음, 그리고 **매핑**: `tags`(전체 키에서 전체 키로, 파일에 적힌 태그 이름 그대로 또는 장치가 옮겨진 뒤의 이름으로), `devices`(ID에서 ID로, `tags` 매핑에 없는 모든 태그의 장치 부분도 함께 옮기므로 화면을 한 PLC에서 다른 PLC로 옮기는 것은 항목 하나입니다), `entities`, `scripts`, `recipes`, `equipment`(ID는 만들어진 곳에서만 의미가 있는 숫자이므로 하나씩 매핑합니다). 추세의 범례 텍스트는 태그와 함께 옮겨집니다. 어떤 카드도 쓰지 않은 매핑 항목은 경고입니다. 아무 일도 하지 않은 매핑은 화면이 옛것을 가리키게 되는 원인이기 때문입니다.
3. **대시보드 자체의 규칙.** ID, 이름, 모든 카드의 config, 크기, 바이트 한도를 저장되는 형태로 검사합니다.
4. **카드가 이름을 든 모든 것, 예외 없이.** 없는 태그, 엔티티, 스크립트, 레시피, 장치, 설비 ID를 첫 번째만이 아니라 모두 나열하므로 한 번에 무엇을 매핑해야 하는지 알 수 있습니다. 쓰기 불가능한 태그의 버튼이나 설정값은 `writable`입니다. 태그의 범위를 벗어난 버튼 값이나 설정값 한계, 존재하지 않는 역할은 `screen`입니다.
5. **ID와 할당.** 이미 쓰고 있는 ID는 `exists`이며, **교체**를 요청한 경우는 예외입니다. 교체는 그 대시보드를 지금의 버전 위에 저장합니다(따라서 보는 동안 다른 저장이 있었다면 덮어쓰기가 아니라 `409`입니다).

드라이 런은 이 모든 것을 하고 아무것도 저장하지 않습니다. 가져오기는 대시보드에 `config` 이벤트로 기록됩니다. 누가, 어느 제품과 버전에서, 카드 몇 장인지입니다.

## 화면 옮기기

첫 번째 설치에서 내보냅니다. 두 번째 설치에서는 화면이 읽는 장치와 태그가 있는지 확인하십시오(주소는 공장의 것이므로 화면 파일에는 들어 있지 않습니다). 가져오기를 합니다. 태그 이름이 다르면 대화 상자에서 매핑하고, 장치만 다르면 장치를 매핑합니다. 화면은 두 번째 설치에서 첫 번째 설치와 같은 모습으로 열립니다.

## CODESYS 비주얼라이제이션

같은 가져오기가 CODESYS 비주얼라이제이션(IDE의 고유 내보내기)을 읽어 화면을 만들며, 빠뜨린 것을 알려 줍니다. [CODESYS 화면 가져오기](/ko/iot/codesys-screen-import/)를 참고하십시오.

## 버전 1에 없는 것

화면이 읽는 장치와 태그(주소는 화면이 아니라 공장의 것), 월 보드, 한 파일에 여러 화면, 파일의 서명입니다. 파일은 평범한 JSON입니다. 받은 파일을 가져오기 전에 먼저 읽어 보십시오.
