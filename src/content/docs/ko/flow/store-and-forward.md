title: "HotLoop Flow의 저장 후 전달"
description: "연결을 지속형으로 표시하면 뒤쪽 노드가 응답을 멈출 때 메시지가 순서대로 디스크에 저장되고 kill -9 이후에도 남습니다."
---

연결을 지속형으로 표시하면, 반대편 노드가 따라오는 동안에는 평범한 연결이며 디스크에 아무것도 쓰지 않습니다. 그 노드가 메시지를 받지 못하게 되는 순간, 보내는 쪽이 넘어가기 전에 연결이 같은 SQLite 파일로 넘쳐 쓰고, 펌프가 대상이 하나씩 받아들일 때까지 가장 오래된 것부터 전달합니다. 대상이 데이터베이스에 한 번에 쓰는 경우(InfluxDB가 그렇습니다)에는 최대 256개씩 묶어서, 나머지는 하나씩 전달합니다. 그래서 히스토리안이 멈추면 측정값은 플로를 막거나 버려지는 대신 디스크에 쌓이고, 복구되면 순서대로 들어갑니다. 정상일 때 아무것도 쓰지 않는 대가는, 그때 `kill -9`가 메모리에 있던 것, 즉 폴링 한 번 분량을 잃는다는 점이며, 직접 알게 되시는 것보다 여기서 말씀드리는 편이 낫다고 생각합니다.

```json
{ "id": "count", "type": "function", "ew_durable": ["influx"], "wires": [["influx", "reply"]] }
```

키를 직접 작성할 필요는 없습니다. 편집기에서 연결을 더블클릭하고 *Durable*을 체크하십시오.

재시작에도 유지되고, 순서를 지키고, 디스크 할당량(기본 256 MiB이며, 가득 찼을 때 무엇이 양보할지는 반대편 노드의 오버플로 정책이 정합니다)을 준수하고, 깊이를 `hotloop_flow_durable_wire_depth`로 보여 줍니다. 정확히 한 번이 아니라 최소 한 번 전달이며, 사후 분석에서 알게 되시는 것보다 여기서 말씀드리는 편이 낫습니다. 정확한 표현과 그럼에도 `influxdb out`이 어떻게 정확하게 유지되는지는 [docs/durable](/ko/flow/durable-state/)에 있습니다.

증거는 `docs/durable/store-and-forward.sh`입니다. Podman 안의 실제 InfluxDB 2.9.1에 초당 측정값 스무 개를 보내다가 10분 동안 멈추고 복구했으며, 중단 중간에 한 번, 비우는 중간에 한 번 런타임을 `kill -9`로 종료했습니다. 측정값 15,982개를 받아 15,982개 행이 저장되었고, 누락도 중복도 없었습니다. 정상 상태의 지속형 연결은 자체로는 아무것도 쓰지 않으며, 컨텍스트를 30초마다 비웠을 때 전체 프로세스는 초당 메시지 스무 개에서 시간당 1.7 MiB(하루 0.04 GB)를 썼습니다. 표와 명령어는 [docs/durable](/ko/flow/durable-state/)에 있습니다.

## 대상이 영원히 거부하는 메시지

기본적으로 연결은 대상이 처리에 실패한 메시지를 최대 5초까지 늘어나는 간격으로 계속 다시 시도하며, 그 메시지 뒤의 것은 아무것도 움직이지 않습니다. 멈춘 히스토리안에는 그것이 정확히 맞습니다. 히스토리안이 결코 받아들이지 않을 잘못된 측정값 하나라면 영구히 막힌 연결이 되므로 빠져나갈 방법이 있으며, 요청하실 때까지는 꺼져 있습니다.

```json
{ "id": "count", "type": "function", "ew_durable": ["influx"], "ew_durable_attempts": { "influx": 20 }, "wires": [["influx", "reply"]] }
```

편집기의 연결 대화 상자에서 또는 위처럼 연결에 시도 횟수를 지정하면, 대상이 큐의 메시지 하나를 그 횟수만큼 거부한 뒤에 연결은 그 메시지를 거부한 노드의 오류로 플로에 올리고, 모든 노드 오류가 메시지를 싣는 방식대로 메시지를 첨부하며, 다음 메시지로 넘어갑니다. 그 플로의 Catch 노드가 그것을 받아 보관하거나, 경보를 보내거나, 다른 곳에 기록할 수 있습니다. Catch가 없으면 오류는 디버그 사이드바에 그래도 표시되고 메시지는 사라지므로, 하나를 연결해 두십시오. 메모리에서의 첫 번째 거부는 예전처럼 Catch에 도달하므로, Catch는 같은 메시지를 두 번 봅니다. 처음 실패했을 때 한 번, 연결이 포기했을 때 한 번입니다. 횟수는 메시지별이며 메모리에 있으므로 재시작하면 처음부터 다시 셉니다. `hotloop_flow_durable_wire_given_up_total`이 깊이 옆에서 이를 집계합니다. 1 이상의 정수가 아닌 한도는 보고되며 연결은 계속 재시도합니다. 조용히 무시하면 누군가 멈추라고 지정해 둔 연결이 막힌 채로 남기 때문입니다.
