FlowLab은 Flow에서 테스트 벤치와 데이터 로거를 위한 부분이며, 그 단위는 다이어그램입니다. Flow가 탭을 실행하는 또 하나의 방식입니다. 플로에서는 메시지가 노드를 지나가고 어느 입력이든 노드를 깨웁니다. 다이어그램에서는 와이어가 연결된 모든 입력에 값이 들어오면 각 노드가 실행당 한 번 실행됩니다. 사이에 와이어가 없는 두 노드는 동시에 실행됩니다. 이렇게 테스트 벤치나 데이터 로거를 만듭니다. 장치를 읽고, 값을 해석하고, 안정적인지 판단하고, 보여 주고, 기록합니다.

이 모든 것은 플로에 영향을 주지 않습니다. `ew_diagram`이 있는 탭은 메시지 런타임에서 제외되며, 다른 모든 탭은 이전과 똑같이 실행됩니다.

이것이 의미하는 바는 이렇습니다. 로직을 한 번 그리고 실행을 누른 뒤 와이어 위로 값이 움직이는 것을 지켜봅니다. 패널 주소만 있으면 누구나 휴대폰으로 같은 실행을 볼 수 있습니다.

## 파일

다이어그램은 `ew_diagram` 객체가 있는 탭입니다. 노드는 플로 파일의 일반 항목입니다. `wires`는 늘 그렇듯 와이어가 가는 노드를 지정하고, 출발 노드의 `ew_in`은 각 와이어가 대상의 어느 입력에 연결되는지를 같은 형태로 알려 줍니다.

```json
{ "id": "a", "type": "dia-const", "z": "d", "value": "1", "x": 100, "y": 80,
  "ew_in": [["a"], []], "wires": [["sum"], []] }
```

파일은 이 키들이 들어 있는 상태 그대로 바이트 단위로 불러오고 저장됩니다. 탭의 설정은 다음과 같습니다.

| 키 | 하는 일 |
|---|---|
| `autostart` | `true`는 Flow가 시작될 때와 배포할 때마다 브라우저를 열지 않고 실행을 시작합니다. |
| `role` | 루프가 실행하는 다이어그램에는 `"body"`를 씁니다. 본문은 혼자 실행되지 않습니다. |

모든 노드에는 선택 입력 `after`와 출력 `done`도 있습니다. 한 노드의 `done`을 다른 노드의 `after`에 연결하면 둘째 노드가 첫째를 기다리며, 그 사이에는 아무것도 없습니다. 순서가 눈으로 보고 diff로 비교할 수 있는 와이어가 됩니다.

## 실행

다이어그램은 배포된 내용으로 실행됩니다. 에디터에서 다이어그램 탭을 열고 실행을 누르세요. 캔버스 위의 막대에는 다음이 있습니다.

- **실행 강조 표시**: 따라갈 수 있도록 각 노드가 실행 전에 잠시 기다리고, 값이 지나간 와이어가 켜집니다. 10분 뒤 저절로 꺼집니다.
- **일시 정지, 재개, 안으로 이동, 건너뛰기, 밖으로 이동**: 단계 실행은 노드 하나씩 진행합니다. 건너뛰기는 루프의 본문 전체를 실행합니다. 안으로 이동은 그 안의 첫 노드에서 멈춥니다.
- **선택 항목에서 중단**: 선택한 노드에 중단점을 둡니다. 와이어를 두 번 누르면 프로브가 되어 마지막 100개 값을 보관하거나, 값이 올라올 때 멈추게 할 수 있습니다. 프로브는 실행을 절대 바꾸지 않습니다.
- **패널 열기**: 운전원용 페이지입니다.

실행이 끝난 뒤 아무 와이어에나 마우스를 올리면 그 와이어가 마지막으로 전달한 값이 보입니다. 문제 버튼은 다이어그램을 실행할 수 없는 모든 이유를 노드와 입력과 함께 나열합니다.

| 호출 | 하는 일 |
|---|---|
| `GET /diagrams`, `GET /diagrams/{id}` | 배포된 내용, 패널, 각 와이어의 마지막 값입니다. |
| `GET /diagrams/{id}/trace` | 마지막 실행이 한 일을 순서대로 보여 줍니다. 시작하거나 끝난 모든 노드와 와이어를 지난 모든 값을 실행 시작 후 밀리초와 함께 담습니다. 배포한 뒤 한 번도 실행하지 않은 다이어그램은 404로 응답합니다. |
| `POST /diagrams/{id}/run`, `/stop`, `/debug` | `diagram.run`이 필요합니다. 각 호출은 누가 했는지와 함께 감사 로그에 남습니다. |
| `POST /diagrams/{id}/sub` | `{flows, nodes, name}`을 보내면 해당 노드를 하위 다이어그램으로 바꾼 플로 파일을 돌려받습니다. 읽고 계산만 하며, 저장하거나 배포하지 않습니다. |
| `PUT /diagrams/{id}/controls/{node}` | 컨트롤 값을 설정합니다. 종류, 범위, 선택지에 맞는지 검사합니다. |
| `PUT /diagrams/{id}/breakpoints`, `/probes` | 키는 노드 id, `wire:<wire key>` 또는 `diagram:<tab>`입니다. |

실행 이벤트는 에디터와 같은 소켓으로 `diagram/<id>/node`, `token`, `run`, `paused`, `values`라는 이름으로 나갑니다.

## 노드

| 노드 | 하는 일 |
|---|---|
| `dia-const`, `dia-math`, `dia-compare`, `dia-logic` | 값과 산술입니다. 수학 연산은 배열에서 요소별로 동작합니다. |
| `dia-wait` | 기다린 뒤 입력을 그대로 내보냅니다. |
| `dia-bundle`, `dia-field`, `dia-array` | 레코드와 배열입니다. |
| `dia-while`, `dia-for` | 루프입니다. 본문은 탭 이름으로 지정하는 별도의 다이어그램입니다. 이월 값은 와이어 또는 Start values에서 시작해 마지막 회차의 값으로 나옵니다. for 루프는 횟수나 배열을 받습니다. while 루프는 최소 한 번 실행됩니다. |
| `dia-case` | 케이스 구조입니다. `selector`의 값이 실행할 본문 하나를 고르고, 그 본문만 실행됩니다. 불리언은 `true` 또는 `false`를 고르고, 숫자는 어떻게 쓰였든 그 값의 케이스를 고르며, 문자열이나 enum은 그 이름의 케이스를 고릅니다. 케이스는 케이스 이름에서 다이어그램으로 가는 JSON 객체이며, 어떤 케이스도 지정하지 않은 값은 기본 케이스를 실행합니다. 기본값이 없으면 노드는 오류 와이어에 오류를 내보내고, 배포 시 기본값이 없다고 경고합니다(두 케이스를 모두 가진 불리언은 예외입니다). 모든 본문은 각 결과를 같은 이름으로 내보내야 하며, 그렇지 않은 본문은 배포 시 문제가 됩니다. 출력 `case`는 어느 케이스가 실행됐는지 알려 줍니다. |
| `dia-body-in`, `dia-body-out` | 본문의 두 끝입니다. `iter`는 회차 번호입니다. `stop`은 while 루프를 끝냅니다. 이월 값의 이름이 그 값을 다음 회차로 보냅니다. |
| `dia-serial-open`, `dia-serial-read`, `dia-serial-write` | 시리얼 포트입니다. 읽기는 종결 문자 또는 바이트 수에서 끝납니다. |
| `dia-instr-open`, `dia-instr-query`, `dia-scpi-parse` | 주소로 지정하는 시험 계측기입니다. 아래의 계측기를 참고하세요. |
| `dia-parse-reading`, `dia-stable` | 한 줄에서 숫자와 단위를 뽑고, 마지막 몇 개의 값이 일치하는지 알려 줍니다. |
| `dia-log-text` | 레코드를 텍스트 파일의 한 행으로 추가하며, 시간 열이 붙습니다. |
| `dia-daq-read` | NI의 gRPC Device Server를 통해 NI 하드웨어의 데이터 수집 작업에서 샘플을 읽습니다. 아래의 데이터 수집을 참고하세요. |
| `dia-mqtt-out` | 플로 파일이 설정한 MQTT 서버로 값을 발행하며, MQTT 노드가 쓰는 것과 같은 연결입니다. durable로 표시하면 브로커가 놓친 메시지가 디스크에 기록되었다가 브로커가 돌아오면 순서대로 전송되며, 재시작해도 유지됩니다. |
| `dia-postgres-out` | 플로 파일이 설정한 서버로 레코드를 PostgreSQL 또는 TimescaleDB 테이블의 한 행으로 기록하며, postgres 노드가 쓰는 것과 같은 연결입니다. durable로 표시하면 데이터베이스가 놓친 행이 디스크에 보관되었다가 돌아오면 순서대로 기록됩니다. 아래의 중단되는 데이터베이스를 참고하세요. |
| `dia-log-tdms` | 필드마다 채널 하나로 TDMS 파일에 레코드를 추가합니다. 아래를 참고하세요. |
| `dia-control`, `dia-indicator`, `dia-chart` | 패널입니다. |
| `dia-stats` | 배열의 평균, RMS, 최솟값, 최댓값, 표준편차입니다. 표준편차는 n에서 1을 뺀 값으로 나누므로 값이 두 개 필요합니다. |
| `dia-integral` | 사다리꼴 법칙으로 구한 배열 아래의 넓이이며, 숫자 하나 또는 샘플마다 누적된 넓이로 나옵니다. |
| `dia-derivative` | 배열의 각 샘플에서의 기울기입니다. |
| `dia-filter` | 차단 주파수를 헤르츠로 지정하는 1차에서 10차의 Butterworth 저역 통과, 고역 통과, 대역 통과, 대역 저지 필터입니다. |

### 필터

필터 노드는 Butterworth 필터입니다. 통과 대역이 평탄하고 리플이 없으며, 차단 주파수에서 3 dB 내려갑니다. 아날로그 필터에서 쌍선형 변환으로 설계하고 차단 주파수를 미리 보정하므로 3 dB 지점이 입력한 주파수에 놓이며, 2차 구간의 사슬로 실행되어 높은 차수에서도 정확합니다. n차 대역 통과 또는 대역 저지 필터는 극이 2n개입니다. 차단 주파수는 0보다 크고 샘플링 주파수의 절반보다 작아야 하며, 만들 수 없는 설계는 실행 전에 문제 목록에 나타납니다. 샘플링 주파수는 속성이거나, 속성보다 우선하는 입력입니다. 필터는 한 번의 실행 안에서 호출 사이에 상태를 유지하므로 루프가 조각내어 넘긴 배열도 통째로 필터링한 것처럼 나오며, 새 실행은 정지 상태에서 시작합니다.

할 수 없는 일도 있습니다. 선형 위상 필터가 아니므로 주파수마다 지연이 다르고, 앞뒤로 필터링하는 영위상 모드도 없습니다. 두 신호 사이의 타이밍이 맞아야 하거나 파형의 모양이 보존되어야 하는 곳에서는 맞지 않는 필터입니다. 적분과 미분은 샘플 사이의 시간을 초 단위 `dt` 입력, 헤르츠 단위 `rate` 입력 또는 Samples per second 속성에서 가져옵니다.

### TDMS 로그

`dia-log-tdms`는 테스트 벤치가 측정한 값을 TDMS 파일에 기록합니다. 데이터 수집과 분석 도구가 여는 형식입니다. 레코드를 `row`에 연결하세요. 레코드의 각 필드는 한 그룹 안의 채널이 되므로 `pressure`, `ok`, `operator`가 있는 레코드는 채널 세 개가 됩니다. 숫자는 64비트 float로, 참과 거짓은 bool로, 그 밖의 것은 텍스트로 저장됩니다. 숫자 목록을 담은 필드는 목록 전체를 추가하며, 이렇게 샘플 블록이 들어갑니다. 설정은 다음과 같습니다.

| 설정 | 의미 |
|---|---|
| `path` | 파일입니다. 이미 있는 파일에는 이어서 기록하므로 실행이 거듭되어도 파일 하나가 만들어집니다. |
| `group` | 채널이 들어가는 그룹입니다. |
| `columns` | 기록할 필드를 순서대로 적습니다. 비워 두면 모든 필드를 이름으로 기록합니다. |
| `properties` | 파일의 속성을 담은 JSON 객체이며, 예를 들어 `{"title": "bench 4", "station": 4}`처럼 쓰고 실행이 시작될 때 기록됩니다. |
| `sync` | 기본값은 켜짐입니다. 노드가 끝나기 전에 각 행이 디스크에 도달합니다. |

각 행은 한 번에 기록되는 세그먼트 하나입니다. 행 하나를 쓰는 도중 전원이 나가면 파일이 어디서 끊겼는지 보여 주고, 리더는 그 앞의 모든 행을 돌려주며, 다음 실행이 파일 끝을 복구하고 계속합니다. 필드의 타입은 실행의 첫 행이 정합니다. 숫자 열에 텍스트가 들어온 것처럼 맞지 않는 이후의 행은 잘못된 입력으로 오류 와이어에 보내지고 파일은 건드리지 않습니다. 없는 숫자는 not-a-number로 기록됩니다.

파일을 열려면 아무 TDMS 리더나 쓰면 됩니다. `unit_string` 같은 채널 속성과 파형 속성 `wf_start_time`, `wf_increment`, `wf_samples`는 라이브러리가 지원하지만, 노드가 아직 설정하지는 않습니다.

리더가 받아들이는 것은 little endian과 big endian 세그먼트, 인터리브 및 연속 데이터, 변하지 않았을 때 세그먼트에서 생략된 메타데이터, 새 객체 목록, 8, 16, 32, 64비트 정수, 32, 64비트 float, bool, 텍스트, 타임스탬프입니다. 파일을 반쯤 읽는 일 없이 이름을 밝히고 거부하는 것은 데이터 수집 드라이버가 쓴 원시 데이터, 스케일되었거나 압축된 데이터, 확장 정밀도 float, 고정 소수점 수와 복소수입니다. 작성기가 쓰는 것은 little endian, 연속 데이터와 같은 타입들입니다. big endian은 쓰지 않습니다.

### 오류 와이어

외부와 통신하는 노드에는 `err` 입력과 `err` 출력이 있습니다. 오류는 레코드이며, 플래그, 숫자 코드, 원본 텍스트, 발생한 노드로 이루어집니다. 오류가 들어온 노드는 작업을 하지 않고 오류를 넘기므로, 사슬 앞쪽의 장애 하나가 뒤의 모든 것을 건너뛰고 끝에서 한 번만 나타납니다. 오류를 루프의 `err` 본문 출력에 연결하면 루프가 그 오류에서 멈추며, 오류는 루프의 오류 출력에 나옵니다. 패널의 오류 표시기는 장애가 나면 빨갛게 바뀌고 다음 값이 오류 없이 도착하면 꺼집니다.

### 중단되는 대상

durable `dia-mqtt-out`은 브로커가 응답하는 동안 곧바로 브로커로 보냅니다. 응답하지 않으면 노드가 끝나기 전에 메시지가 Flow의 durable 저장소에 기록되고, 연결이 돌아오면 펌프가 가장 오래된 것부터 큐를 전달합니다. 다른 것이 기다리는 동안 들어온 것은 그 뒤에 서므로 아무것도 앞지르지 않습니다. 큐에서의 전달은 최소 한 번입니다. 클라이언트가 연결이 끊긴 것을 알아채지 못해 전송이 시간 초과된 메시지도 클라이언트가 다시 연결되면 전달될 수 있으므로, 시간 초과된 전송마다 한 번씩 두 번 도착할 수 있습니다. 큐는 durable 와이어와 같은 저장소와 같은 디스크 할당량 안에 있으며, 실행도 브라우저도 없이 재시작 후에 비워집니다. durable이 아니면 브로커가 놓친 메시지는 오류 와이어의 오류가 됩니다.

### 중단되는 데이터베이스

`dia-postgres-out`은 받은 레코드마다 `hotloop-flow-postgres` 서버를 통해 지정한 테이블에 한 행씩 기록합니다. 레코드의 필드는 같은 이름의 열로 들어가므로 `n`과 `sensor`가 있는 레코드는 `n`과 `sensor` 열을 채웁니다. 일부 열만 기록하거나 순서를 정하려면 열을 쉼표로 구분해 나열하세요. 목록을 비우면 노드가 레코드의 필드를 사용합니다. 노드는 루프의 회차마다 한 번 실행되므로 루프는 회차당 한 행을 기록합니다. 일반 이름이 아닌 테이블이나 열은 실행 도중의 문장이 되는 것이 아니라 배포 시 문제가 됩니다. 정수는 integer, float, numeric 열 어디에나 들어가고, 레코드나 배열은 그대로 들어가며 json 또는 jsonb 열이 받는 형태입니다.

**시간 열**의 이름을 지정하면 모든 행에 노드에 도착한 시각이 붙습니다. 이는 값을 기록한 시각이 아니라 측정이 이루어진 시각이므로, 디스크에서 5분을 기다린 행도 만들어진 그 분을 그대로 가집니다.

**데이터베이스가 놓친 것을 유지**가 꺼져 있으면, 데이터베이스가 받지 않은 행은 노드의 오류 와이어에 오류로 나가고 사라집니다. 켜져 있으면 데이터베이스가 응답하는 동안 행은 곧바로 들어갑니다. 데이터베이스가 응답하지 않으면 노드가 끝나기 전에 행이 Flow의 durable 저장소에 기록되고 노드의 `sent` 출력은 `false`를 알립니다. 행은 디스크에서 기다리고, 재시작해도 살아남으며, 데이터베이스가 돌아오면 그 뒤에 들어온 것에 앞지르기당하지 않고 순서대로 기록됩니다. 밀린 행은 문장당 최대 256행으로 묶어 기록하므로, 데이터베이스가 없는 동안 쌓인 것도 행마다 한 번씩 왕복하는 속도가 아니라 몇 초 안에 따라잡습니다. 테스트는 초당 100행으로 5분 분량인 30,000행을 디스크에 대기시키고, 데이터베이스가 돌아온 지 몇 초 안에 전부 순서대로 기록합니다.

디스크에서의 전달은 최소 한 번입니다. 연결이 끊어질 때 insert가 전송된 행은 응답만 유실된 채 커밋되었을 수 있으며 다시 전송되므로 최대 한 배치만큼 두 번 기록될 수 있습니다. 이것이 중요하면 테이블에 고유 키를 주고 충돌 시에서 **행 건너뛰기**를 선택하세요. 그러면 둘째 행은 데이터베이스가 버립니다.

열에 비해 너무 큰 값이나, 충돌 시가 오류 발생으로 되어 있는데 이미 있는 키처럼 내용 때문에 데이터베이스가 거부하는 행은 매번 거부될 것입니다. 그런 행은 행을 담은 감사 이벤트 `diagram.row_rejected`와 함께 버려지고, 뒤에 있는 행은 기록됩니다. 그렇게 하지 않으면 불량 행 하나가 로그를 멈추게 합니다. 중단된 데이터베이스, 아직 없는 테이블, 잘못된 비밀번호는 여기에 해당하지 않으며 그런 행은 기다립니다.

### 계측기

`dia-instr-open`은 주소를 받습니다. 원시 소켓의 LAN 계측기는 `10.0.0.5:5025`, 시리얼 계측기는 `serial:///dev/ttyUSB0?baud=19200&data=8&parity=E&stop=1`, 9600 8N1은 `/dev/ttyUSB0` 또는 `COM3`만 적으면 됩니다. 실행이 끝나면 세션이 닫힙니다. 연결이 끊어지면 다음 질의가 다시 열고 끊김이 세션에 집계됩니다.

`dia-instr-query`는 명령과 종결 문자를 쓴 뒤 응답을 읽습니다. 텍스트(`reply`로 나오는 한 줄), none(단순 쓰기), block 중에서 고르세요. block은 `#41024...` 바이너리 블록을 읽어 `samples`로 샘플을 배열로 내보내며, int8, uint8, int16, uint16, int32, float32, float64와 big 또는 little endian을 지원합니다. 길이가 정해지지 않은 `#0` 블록은 첫 줄 끝에서 끝납니다. 제때 오지 않은 응답은 주소를 밝힌 시간 초과로 오류 와이어에 나갑니다.

`dia-scpi-parse`는 텍스트 응답을 숫자 목록, 숫자 하나, 식별 정보(`*IDN?`을 제조사, 모델, 일련번호, 펌웨어로), 상태 바이트(`*STB?` 또는 `*ESR?`를 켜진 비트의 이름으로)로 읽습니다.

### 시리얼

케이블을 뽑거나 어댑터를 빼서 포트가 사라지면 읽기의 오류 와이어에 장애로 나타납니다. 다음 읽기가 초당 한 번 다시 열기를 시도하고 끊김과 복귀를 집계합니다. 포트의 흐름 제어는 없음, 하드웨어(RTS와 CTS), 소프트웨어(XON과 XOFF)이며 Linux에서 터미널 자체에 설정됩니다. 의사 터미널에서는 설정이 전달되었다는 것까지 확인되었고, 실제 어댑터에서 신호선이 하는 일은 아직 확인되지 않았습니다.

### 데이터 수집

`dia-daq-read`는 CompactDAQ 섀시 같은 NI 하드웨어의 작업을 NI의 공개 gRPC Device Server를 통해 읽습니다. Flow는 네트워크로 그 서버와 통신하므로 하드웨어가 Flow와 다른 장비에 있어도 되고, Flow에는 NI 드라이버도 벤더 라이브러리도 필요하지 않습니다. 정적 바이너리 하나로 유지됩니다.

**하드웨어가 연결된 장비**에는 NI의 DAQmx 드라이버와 NI의 gRPC Device Server(https://github.com/ni/grpc-device, MIT 라이선스)를 설치하세요. 서버는 설정 파일이 달리 정하지 않는 한 그 장비에서만(`localhost`, 포트 31763) 수신합니다. 다른 장비의 Flow에서 연결하려면 서버의 `server_config.json`에서 `address`를 `[::]` 또는 원하는 인터페이스로 설정하고, 설정 옆의 `certs` 폴더에 파일을 두고 `server_cert`, `server_key`, 상호 TLS라면 `root_cert`를 설정해 TLS를 켜세요. 사용하는 버전의 자세한 내용은 NI의 README에 있습니다. 서버의 기본값인 보호되지 않는 포트를 공장 네트워크에 열어 두지 마세요. 접근할 수 있는 사람은 누구나 하드웨어를 조작할 수 있습니다.

**노드에서** 다음을 설정하세요.

* `address`는 서버의 `host:port`입니다.
* `tls`는 `off`(같은 장비의 서버에만), `on`(Flow가 서버 인증서를 `caFile`로, 비어 있으면 시스템 인증 기관으로 검사), `mutual`(Flow가 `certFile`과 `keyFile`도 제시하고 서버가 자신의 `root_cert`로 검사) 중 하나입니다. `serverName`은 `address`의 호스트가 아닐 때 서버 인증서에서 찾을 이름입니다.
* `device`와 `channels`로 하드웨어를 지정합니다. 예를 들어 `cDAQ1Mod1`과 `ai0:3`, 또는 `ai0, ai2` 같은 목록입니다. `kind`는 `voltage`, `current`, `thermocouple`이며, 예상 범위를 위한 `min`과 `max`, 배선을 위한 `terminal`이 있습니다. 열전대는 `tcType`과 `unit`을 받고 모듈 자체의 냉접점 보상을 사용합니다.
* `mode`, `rate`, `samples`입니다. 유한 모드는 호출할 때마다 채널당 `samples`개를 `rate`로 한 번 수집하고 매번 다시 시작합니다. 연속 모드는 첫 호출에서 작업을 시작하고 호출마다 다음 `samples`개를 읽으므로, 루프 본문 안의 노드는 스트림을 블록 단위로 읽습니다. `trigger`는 `/cDAQ1/PFI0` 같은 단자의 디지털 에지에서 작업을 시작합니다.

`y`는 채널 하나의 샘플 배열이거나, 지정한 순서대로 채널마다 하나씩 담은 배열의 배열입니다. `dt`는 샘플 사이의 초, 곧 주파수의 역수이므로 블록의 길이(초)는 샘플 수에 `dt`를 곱한 값입니다. 초당 1,000샘플로 1,000샘플이면 1.000 s입니다. 샘플의 시간은 늘 그렇듯 장치 자체의 클럭이 정하며, Flow는 데이터를 옮길 뿐입니다. 서버나 드라이버의 거부는 드라이버 자체의 코드와 텍스트와 함께 `err`로 나오고, `callTimeoutSec` 안에 응답하지 않는 서버는 시간 초과입니다. 작업은 실행 동안 유지되고 실행이 끝나면 서버에서 지워지므로 하드웨어는 다시 비워집니다.

지원되는 것은 아날로그 전압 입력, 아날로그 전류 입력, 열전대 온도 입력이며, 유한 또는 연속, 샘플 클럭, 선택적인 디지털 시작 트리거를 갖춥니다. 지원되지 않는 것은 디지털 입출력과 카운터(다른 읽기 호출을 쓰므로 구현되지 않았습니다), 쓰기, 다른 종류의 트리거, 모듈이 하는 것 이상의 스케일링입니다.

이 노드는 같은 호출을 처리하고 사인파로 응답하는 대체 서버와, 실제 하드웨어에서 실행해 보았습니다(2026-11-17).

## 패널

런타임의 `/panel/<diagram id>`는 다이어그램의 컨트롤, 표시기, 차트가 있는 페이지를 열며, 에디터와 같은 방식으로 로그인합니다. 엄지손가락으로 쓰도록 만들었으며, 손가락보다 작은 요소는 없습니다. 차트는 바꾸지 않는 한 마지막 1,024개 점을 유지하고 버린 개수를 알려 줍니다. 그래프는 배열이 들어올 때마다 데이터를 교체합니다. XY 차트는 x를 y에 대해 그리고 이력도 유지합니다. 강도 차트는 길이가 모두 같은 숫자 행의 배열인 격자(최대 512 곱하기 512)를 받아 각 값을 그 안의 최솟값에서 최댓값까지의 색으로 그리며 격자마다 그림을 교체합니다. 평평한 배열이나 길이가 들쭉날쭉한 격자는 노드의 오류 와이어에 오류가 됩니다.

여러 사람이 하나의 실행을 볼 수 있습니다. 브라우저에서 컨트롤을 설정하려면 `diagram.run`이 필요하고, 서버에서 검사하며, 감사 로그에 기록됩니다.

## 컨트롤

`dia-control`에는 **종류**(무엇을 담는지)와 **모양**(패널이 그리는 방식)이 있습니다. 서버는 모양과 관계없이 모든 값을 종류에 맞게 검사하므로, `PUT /diagrams/{id}/controls/{node}`를 호출하는 스크립트도 손가락과 같은 규칙을 따릅니다. 운전원이 설정한 값은 다이어그램이 배포되는 즉시, 첫 실행 전에 패널에 나타나며, 컨트롤 노드는 실행될 때마다 그 값을 다이어그램에 넘깁니다.

| 종류 | 모양 | 다이어그램이 읽는 값 |
|---|---|---|
| `number` | `entry`(입력), `spin`(입력, `step`씩 움직이고 범위에서 멈추는 빼기와 더하기 버튼 포함), `slider`, `knob` | 숫자이며, `min`과 `max`가 설정되어 있으면 그 범위로 제한됩니다 |
| `bool` | `switch`, `button`(누르면 true가 되고 다이어그램이 읽을 때 `latch`가 되돌림), `led`(누르는 LED) | 참 또는 거짓 |
| `string` | 텍스트 상자 | 텍스트 |
| `enum` | `options`의 드롭다운 | 선택지 중 하나 |
| `array` | 운전원이 항목을 추가하고 삭제하는 목록 | `elem`에 따른 숫자, 스위치 또는 텍스트의 목록이며, `min`과 `max`가 각 숫자 항목을, `maxlen`이 길이를 제한합니다 |
| `record` | 필드마다 입력 하나 | 정확히 `fields`(`rate:number, on:bool, note:string`)를 가진 객체이며, 모든 필드가 항상 있습니다 |

slider와 knob에는 최솟값과 최댓값이 필요합니다. 둘 다 없는 knob은 배포 시 경고가 되고, 값이 생길 때까지 입력 칸으로 그려집니다(slider는 이미 그렇게 했습니다). knob은 270도를 쓸어 가는 다이얼입니다. 마우스나 손가락으로 돌리듯 끌거나, 누르면 그 위치에 놓이거나, 화살표 키(`step` 한 번), Page Up과 Page Down(열 단계), Home과 End를 쓰세요. 놓을 때 값이 기록됩니다. 배열의 시작값은 JSON(`[1, 2, 3]`) 또는 쉼표로 구분한 일반 목록(`1, 2, 3`)이고, 레코드의 시작값은 JSON 객체(`{"rate": 3}`)이며, 생략된 필드는 빈 상태로 시작합니다. 필드가 없는 레코드, 알 수 없는 필드 이름, 맞지 않는 시작값은 배포 시 문제가 됩니다.

패널의 모든 버튼, 입력, 스위치, 다이얼은 가로와 세로 모두 최소 44픽셀이며, 390픽셀 폭의 휴대폰에서도 페이지가 옆으로 스크롤되지 않습니다.

컨트롤은 바뀔 때 기록되고, 다이어그램은 컨트롤 노드가 실행될 때 그것을 읽습니다. 바뀔 때 스스로 실행을 시작하거나 노드를 작동시키는 컨트롤은 없습니다. 그것은 이벤트 구조이며, 아직 구현되지 않았습니다.

## 이 기능이 아닌 것

다이어그램은 범용 운영체제 위의 Go 프로세스에서 실행됩니다. 가비지 컬렉션과 스케줄러가 노드를 수 밀리초 지연시킬 수 있으므로 노드는 마감 시간을 약속할 수 없습니다. 마감을 지켜야 하는 작업은 PLC나 그것을 위해 만든 런타임에 속합니다. 데이터 수집 장치에서 오는 샘플의 타이밍은 이 모든 것의 영향을 받지 않습니다. 장치 자체의 클럭이 처리하고 Flow는 데이터를 옮길 뿐입니다.

## 다이어그램 테스트

플로 테스트 파일에는 메시지 테스트 옆에 다이어그램 테스트를 넣을 수 있습니다. 다이어그램의 컨트롤을 설정하고, 실제 다이어그램 엔진으로 한 번 실행하며, 표시기가 담고 있는 값을 알려 줍니다.

```yaml
tests:
  - name: weighs and flags a heavy load
    diagram:
      name: Scale logger          # the diagram's name or id
      controls: {Limit: 10}       # by label or id, checked like an operator's entry
      expect:
        Weight: 12.5              # a number matches to within a millionth
        Heavy: true
        Reading: {min: 12, max: 13}
```

다이어그램에 없는 컨트롤, 거부하는 값, 표시기가 아닌 것, 두 항목이 공유하는 이름, 실행할 수 없는 다이어그램은 이유와 함께 오류가 됩니다. 테스트 밖으로 나가는 노드(시리얼 포트, 계측기, 데이터 수집 장치, MQTT 출력, HotLoop 쓰기, 로그 파일)가 있는 다이어그램은 거부됩니다. 다이어그램 테스트에는 이들의 대역이 없기 때문입니다. 케이블 뽑기나 쓰레기 프레임 연속을 시험하는 스크립트 시리얼 장치는 구현되지 않았습니다.

## CI/CD의 오류 목록

`hotloop-flow test`와 배포 게이트는 플로 파일의 모든 다이어그램에 에디터의 검사를 실행합니다. 실행할 수 없는 다이어그램은 `--- DIAGRAM: <diagram>: <node> input <port>: <reason>`으로 나열되며, 모든 테스트가 통과해도 파일을 실패시킵니다. JUnit 보고서는 각각을 `diagram` 타입의 오류로 담습니다. 기본값이 없는 케이스 구조 같은 경고는 나열되지만 실패시키지 않습니다.

## 파형

파형은 간격이 일정한 샘플 블록으로, 언제 시작했고 샘플 사이가 얼마인지 알고 있으며 와이어 위에서 레코드로 전달됩니다. `{"type": "waveform", "t0": "2026-11-14T12:00:00Z", "dt": 0.001, "y": [...], "attrs": {"unit_string": "V"}}` 형태입니다. `dia-wave`는 배열로 파형을 만들고(간격은 `dt`, 없으면 `rate`, 없으면 노드 설정에서, 시작은 `t0`, 없으면 실행되는 순간에서 가져옵니다), `dia-wave-parts`는 파형을 분해하며 걸치는 길이도 알려 줍니다. 파형은 최대 `maxSamples`개의 샘플(기본값 1,048,576)을 담으며 나머지는 잘려 `dropped`에 집계됩니다. 분석 노드는 배열을 받는 곳에서 파형도 받아 그 간격을 사용합니다. `dia-log-tdms`는 파형 열을 `wf_start_time`, `wf_increment`, `wf_samples`를 가진 채널로 쓰고 속성을 채널 속성으로 기록합니다.

## 하위 다이어그램

`dia-sub`는 노드로 쓰는 다이어그램입니다. 입력과 출력이 커넥터이며, 각 입력은 본문 안의 같은 이름의 `dia-body-in`, 각 출력은 `dia-body-out`입니다. 이름이 `?`(선택) 또는 `~`(권장: 없어도 실행되며 연결되지 않았을 때 배포가 경고)로 끝나지 않는 한 입력은 필수입니다. 노드를 선택해 하위 다이어그램으로 만들면(`POST /diagrams/{id}/sub`) 노드가 새 본문 탭으로 옮겨지고 그 자리에 `dia-sub`가 들어서며, 커넥터는 선택 영역의 경계를 가로지르는 와이어에서 정해집니다. 선택 영역에 들어오는 출처 출력마다 입력 하나, 바깥 노드로 나가는 선택된 출력마다 출력 하나입니다. 바깥 와이어는 다시 연결되므로 실행 결과는 이전과 같습니다.

## 공유 레코드 타입

레코드 타입은 다이어그램 탭의 설정에서 `types` 아래에 한 번 이름을 지정하며, `shape`를 그 이름으로 설정한 모든 `dia-bundle` 또는 `dia-field`는 그 하나의 정의에 맞는지 검사합니다.

```json
{"types": {"Reading": {"fields": {"pressure": "number", "ok": "boolean", "state": {"enum": ["idle", "run"]}}}}}
```

필드는 `number`, `integer`, `boolean`, `string`, `timestamp`, `array`, `waveform`, `record:Name`(다른 공유 타입) 또는 enum입니다. 정의에서 필드 이름을 바꾸면 옛 이름을 쓰는 모든 bundle이 다음 배포에서 문제가 되며, 연결되지 않은 입력과 같은 오류 목록에 노드와 필드가 함께 나타납니다. bundle은 실행할 때 각 값을 필드의 종류에 맞추며, 맞지 않는 값은 오류 와이어가 전달합니다. `Set.Schema`는 같은 타입을 JSON Schema로 제공하며, 타입이 있는 와이어가 검사하는 것이 바로 이것입니다.

## 회전과 보존

`dia-log-text`와 `dia-log-tdms`는 현재 파일이 `rotateMB` 메가바이트 또는 `rotateHours` 시간에 이르면 새 파일을 시작하고 가장 최근의 완료된 파일 `keep`개만 남길 수 있습니다. 완료된 파일은 확장자 앞에 닫힌 시각이 붙은 로그 이름을 받으며(`bench.csv`는 `bench-20261114T120000Z.csv`가 됩니다), 로그는 새 머리글과 함께, TDMS의 경우 파일 속성을 다시 쓴 채로 `bench.csv`에서 계속됩니다. 보존은 그 패턴과 일치하는 파일만 삭제하며, 현재 로그나 단지 옆에 있는 파일은 절대 삭제하지 않습니다. 나이는 실행이 파일에 처음 쓴 때부터 셉니다. 텍스트 로그는 스프레드시트에서 열리고, TDMS 로그는 큰 데이터를 위한 바이너리 형식입니다.

## 케이스 구조 편집과 다이어그램 선택

케이스 구조의 케이스는 케이스 이름과 다이어그램 선택기로 이루어진 행이며, 기본 케이스를 위한 두 번째 선택기가 있습니다. 루프나 하위 다이어그램이 실행하는 다이어그램을 지정하는 속성도 선택기입니다. 선택기는 플로 파일의 FlowLab 다이어그램을 나열하고 탭의 id를 저장합니다. 이전 플로 파일에 손으로 쓴 이름은 그 탭으로 표시되고 id로 저장되며, 런타임이 같은 방식으로 읽습니다. 저장되는 값은 이전과 같은 JSON(`cases`는 케이스 이름에서 다이어그램으로 가는 객체)이므로 대화 상자에서 편집한 플로 파일과 손으로 편집한 플로 파일은 같은 파일입니다.

## 하위 다이어그램을 그 자리에서 열기

하위 다이어그램 노드의 오른쪽 위 모서리에는 작은 상자가 있습니다. 이것을 누르거나, 노드를 선택하고 다이어그램 막대의 **그 자리에서 열기**를 누르면 노드가 있던 자리에 열린 모습으로 그려집니다. 하위 다이어그램 이름이 붙은 프레임, 양쪽 가장자리에 이름이 붙은 커넥터(왼쪽에 입력, 오른쪽에 출력, 다른 노드처럼 `after`와 `done` 포트와 오류 와이어 포함), 그리고 그 안에 본문의 노드와 와이어가 보입니다. 두 번째 창이 열리지 않으며 지금 보고 있는 탭도 바뀌지 않습니다. 노드로 향하던 와이어는 프레임의 커넥터로 향하고, 각 커넥터 이름에서 같은 이름의 body in 또는 body out 노드로 희미한 점선이 이어집니다. 프레임 제목 막대의 상자(또는 **그 자리에서 닫기**)를 누르면 다시 닫힙니다.

프레임 안에 그려진 것은 복사본이 아니라 본문 자신의 노드입니다. 하나를 선택하고, 끌고, 두 번 클릭해 속성을 열고, 값을 바꾸거나 삭제하면 본문을 편집한 것이며, 되돌릴 수 있는 한 단계이고 배포하면 저장됩니다. 제목 막대로 프레임을 옮기면 하위 다이어그램 노드가 이동하고 본문도 함께 갑니다. 와이어는 한 다이어그램의 두 노드를 잇기 때문에 바깥 노드에서 안쪽 노드로 가는 와이어는 말로 설명하며 거부됩니다. 프레임의 커넥터에 연결하세요. 확대, 이동, 맞춤, 범위 선택은 다른 곳과 똑같이 동작합니다.

어느 하위 다이어그램이 열려 있는지는 다이어그램을 보는 방식일 뿐입니다. 플로 파일에 들어 있지 않고, 되돌리기 단계도 아니며, 새로 고치면 모두 닫히므로 하나를 연다고 배포가 보내는 내용이 바뀌지는 않습니다. 열린 하위 다이어그램 안의 하위 다이어그램도 자기 상자가 있고 세 단계 깊이까지 열 수 있습니다. 이미 다른 곳에서 열려 있는 본문은 두 번 열리지 않으며, 본문이 이미 열려 있는 다이어그램으로 이어지는 하위 다이어그램은 닫힌 채로 그려지므로 자기 자신을 포함하는 다이어그램이 에디터를 무한 반복시킬 수 없습니다. 아무것도 지정하지 않았거나 두 다이어그램이 공유하는 이름으로 지정된 본문은 런타임도 찾을 수 없기 때문에 상자가 없습니다. 루프와 케이스 구조도 본문을 가지지만 아직 그 자리에서 열리지는 않습니다.

## 에디터에서 하위 다이어그램 만들기

다이어그램에서 노드를 선택한 상태로 막대의 **선택 항목을 하위 다이어그램으로**를 누르면 이름을 묻고, 에디터가 가진 플로 파일로 `POST /diagrams/{id}/sub`를 호출한 뒤, 응답을 되돌릴 수 있는 한 번의 편집으로 불러옵니다. 노드는 자기 탭으로 옮겨지고 하위 다이어그램 노드가 그 자리를 차지하며, 입력과 출력은 선택 영역을 가로지르는 와이어에서 정해집니다. 배포하기 전에는 아무것도 저장되지 않습니다.

## 실행 다시 보기

실행 강조 표시는 실행 중에 속도를 늦춥니다. 캔버스 아래쪽의 **마지막 실행 다시 보기**는 이미 끝난 실행을 기록된 내용으로 재생하므로 나중에 따라갈 수 있습니다. 실제 실행과 같은 방식으로 와이어를 켜고 노드에 표시하며, 이벤트를 하나씩 고른 속도(느리게, 보통, 빠르게, 매우 빠르게)로 재생하고, 끝나면 캔버스에 실행이 남긴 결과를 보여 줍니다. **다시 보기 중지**는 일찍 끝냅니다. 런타임에서 아무것도 바꾸지 않고 아무것도 시작하지 않습니다. 실행 중에는 버튼이 꺼지고, 다른 탭으로 가면 다시 보기가 끝납니다.

모든 실행은 노드의 시작과 끝, 와이어를 지난 모든 값을 최대 20,000개 이벤트까지 기록합니다. 더 긴 실행은 처음 20,000개를 유지하고 다시 볼 때 그렇다고 알려 주며, 다시 보기는 그 처음 부분을 보여 줍니다. 중간에서 시작하는 다시 보기는 출발할 곳이 없기 때문입니다. 값은 와이어가 보여 주는 짧은 미리보기로 저장되므로 수천 샘플의 배열은 길이와 처음 몇 개의 값으로 남습니다. 기록은 마지막 실행의 것이며 새 실행이 대체하고, 재시작하면 저장되지 않습니다. `GET /diagrams/{id}/trace`는 스크립트용으로 같은 기록을 제공합니다.

## 레이아웃 정리

탭 막대의 **레이아웃 정리**는 보이는 노드를 데이터가 왼쪽에서 오른쪽으로 읽히고 어떤 와이어도 노드를 관통하지 않게 배치합니다. 노드의 열은 그 노드로 이어지는 가장 긴 와이어 사슬로 정해집니다. 열을 건너뛰는 와이어는 그 열들을 지나는 통로를 얻고, 열 안의 노드는 교차가 풀리도록 정렬되며, 이어서 각 긴 와이어가 실제로 그려지는 곡선을 따라 지나는 열의 노드들과 대조되어 길을 막은 노드는 비켜 납니다. 블록은 왼쪽 위 모서리를 유지하며 전체가 되돌릴 수 있는 한 번의 편집입니다. 배선에 루프가 있으면 이를 닫는 와이어는 순위에서 빠지므로 레이아웃이 무한 반복하는 대신 거꾸로 달립니다.

## 와이어 이름

다이어그램의 와이어는 가운데에 그 와이어가 나오는 출력의 이름(`sum`, `result`, `iterations`)으로 표시되고, 어느 한쪽 끝이 타입을 선언하면 그 옆에 타입도 표시되며, 마우스를 올리면 그 와이어가 마지막으로 전달한 값이 여전히 보입니다.

캔버스는 포인터를 중심으로 5퍼센트에서 400퍼센트까지 확대와 축소를 하며, 배율을 캔버스의 `data-zoom`으로 읽습니다.

## 이름으로 패널 객체 설정하기

`dia-panel-set`은 다이어그램이 실행되는 동안 객체의 레이블(또는 id)로 컨트롤이나 표시기의 속성 하나를 바꿉니다. `visible`과 `enabled`는 true 또는 false, `color`는 red, amber, green, blue, gray 또는 default, `label`은 텍스트를 받고, `min`과 `max`는 숫자 컨트롤에 대한 숫자를 받습니다. 비활성화된 컨트롤은 운전원이 설정한 값을 거부하고, 숨긴 객체는 그려지지 않으며, 운전원이 열어 둔 패널이 따라옵니다. 객체와 일치하지 않거나 둘 이상과 일치하는 이름은 노드에 직접 입력했으면 배포 시 문제가 되고 와이어로 들어왔으면 와이어의 오류가 되며, 실행은 설계된 상태의 패널에서 시작합니다.

## 심볼

모든 FlowLab 노드 타입은 텍스트 레이블 옆, 노드 본체 가운데에 우리가 만든 심볼로 그려집니다(수학은 더하기, 통계는 시그마, 파형은 사인파, 시리얼 포트는 플러그). `web/src/lib/symbols.ts`에 그려진 단순한 선이며 아이콘 폰트나 다른 사람의 작품이 아니고, 다이어그램 노드 타입이 그려지지 않은 아이콘을 지정하면 테스트가 실패합니다.

## 설비에 쓰기: 쓰기 게이트

다이어그램이 설비에 명령하는 방법은 `dia-hotloop-write` 하나뿐입니다. 이 노드는 값을 HotLoop의 태그(`device/tag`, 노드에 설정하거나 와이어로 입력)로 HotLoop의 쓰기 게이트를 통해 보내며, 게이트는 자신의 순서대로 쓰기가 켜져 있는지, 태그가 활성화되어 있는지, 값이 범위 안인지 판단합니다. Flow는 기계에 직접 쓰지 않습니다. HotLoop는 거부 여부와 관계없이 모든 시도를 `flow:<diagram>/<node id>`라는 사유로 기록하므로 감사 기록에 다이어그램과 노드가 남습니다. 거부는 게이트 자체의 사유(코드 5006)와 함께 노드의 오류 와이어에 오류로 나가며, HotLoop에 연결할 수 없는 경우도 마찬가지입니다. 두 경우 모두 쓰기는 일어나지 않고, HotLoop를 선택하지 않으면 노드는 배포를 거부합니다. 원시 시리얼 노드와 계측기 노드는 HotLoop에 태그가 없는 벤치 계측기(멀티미터, 전원 공급기, 부하)와 통신하므로 별도의 스위치가 있습니다(아래).

## 계측기 쓰기 스위치

계측기를 읽는 것은 아무것도 바꾸지 않으며 항상 열려 있습니다. 계측기에 쓰는 것은 바꿀 수 있습니다. 전원 공급기의 출력, 고전압 시험기의 고전압, 부하의 전류가 그렇습니다. 그래서 모든 계측기는 쓰기가 **꺼진** 상태로 시작하며, `instrument.write` 권한이 있는 사람이 그 계측기의 쓰기를 한 번에 하나씩 켤 때까지 다이어그램의 쓰기는 거부됩니다.

- **쓰기로 치는 것.** `dia-serial-write`는 항상 쓰기입니다. `dia-instr-query`는 명령이 질의일 때(안의 모든 SCPI 문장이 `*IDN?`나 `MEAS:VOLT?;MEAS:CURR?`처럼 `?`로 끝날 때) 읽기이고 그 밖에는(`OUTP ON`, `VOLT 5`, `*RST` 또는 `VOLT 5;MEAS:VOLT?`) 쓰기입니다. 와이어로 들어온 명령은 쓸 수 있는 명령으로 셉니다.
- **어느 계측기인가.** 계측기는 주소로 정해집니다. `tcp://host:port` 또는 `serial:///dev/ttyUSB0`이며 시리얼 설정은 제외하므로, 두 가지 방식으로 연 계측기도 스위치는 하나입니다.
- **거부**는 그 계측기에 대한 쓰기가 꺼져 있다고 알리는 노드의 오류 와이어 오류(코드 5007)이며, 계측기는 명령을 전혀 받지 못합니다.
- **켜기.** `PUT /instruments/writes`에 `{"instrument": "tcp://10.0.0.5:5025", "allowed": true, "note": "bench 2"}`를 보내며, `instrument.write`가 필요하고(관리자에게 있음) 데이터 디렉터리의 `instrument-writes.json`에 보관되므로 재시작해도 아무것도 바뀌지 않습니다. `GET /instruments`는 스위치가 있거나 그 계측기에 쓸 배포된 다이어그램이 있는 모든 계측기를, 누가 설정했는지와 관련된 다이어그램과 노드와 함께 나열합니다.
- **감사.** 스위치의 모든 변경은 `instrument.switch`이고, 다이어그램의 모든 쓰기는 `instrument.write`, 거부되면 `instrument.refused`이며, 다이어그램, 노드, 계측기, 명령이 함께 기록됩니다.
- **배포가 알려 줍니다.** 계측기에 쓰게 될 노드는 다이어그램의 참고 사항(막대의 **참고**와 `hotloop-flow test`가 출력하는 목록)으로 나타나며, 계측기를 밝히고 누군가 켜기 전까지 쓰기가 꺼져 있다고 알려 줍니다. 읽기만 하는 플로 파일은 달라지지 않습니다.

## LabVIEW VI 가져오기

에디터의 가져오기 대화 상자(또는 MCP의 `import_vi`, 또는 `POST /flows/import-vi`)에서 `.vi`를 가져오면 FlowLab이 읽을 수 있는 것을 읽고, 무엇이든 추가하기 전에 읽지 못한 것을 나열합니다. docs/labview-import.md를 읽어 보세요. 무엇이 넘어오고 무엇이 넘어오지 않는지 정확히 설명합니다. 간단히 말하면 VI의 이름, 설명, 버전, 프런트 패널 이름, 호출하는 VI가 별도 플로의 참고 사항으로 넘어옵니다. 블록 다이어그램의 와이어와 프리미티브는 넘어오지 않으므로 그 이름들을 옆에 두고 다이어그램은 직접 그려야 합니다.
