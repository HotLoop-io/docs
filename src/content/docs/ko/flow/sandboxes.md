---
title: "HotLoop Flow의 샌드박스 두 가지"
description: "Function 노드와 WebAssembly 샌드박스가 어떻게 격리되는지, 각각 무엇을 건드릴 수 있는지, 두 번째 샌드박스에서 플러그인이 어떻게 실행되는지 설명합니다."
---

Function 노드는 JavaScript 인터프리터에서 실행됩니다([보안 태세](/ko/flow/security/) 참고). 호출 한 번에 11.6 ~ 13.7 µs가 듭니다. 메모리에 대한 경계는 아닙니다. 반복문에서 메모리를 할당하는 함수는 파드가 죽을 때까지 Go 힙을 키우며, JavaScript 인터프리터가 이에 대해 할 수 있는 일은 실제 시간 기준의 타임아웃뿐입니다.

호출당 184 ~ 196 µs가 들며, JavaScript 인터프리터 호출의 열다섯 배에서 열여섯 배입니다. 완전히 신뢰하지 않는 코드를 실행할 때에만 치를 만한 가치가 있고, 그 밖에는 그렇지 않습니다.

플로는 플러그인을 통해 WASM 게스트를 실행합니다. 편집기가 대화 상자를 그리는 근거가 되는 기술자가 들어 있는 서명된 모듈이며, 요청하고 여러분이 승인하지 않으면 호스트 접근 권한을 얻지 못합니다. 메모리는 노드마다 상한이 있고, 메시지마다 타임아웃이 있으며, 둘 중 하나를 넘는 게스트는 중단되어 이유와 함께 Catch 노드에 도달하고 다른 어떤 것도 끌어내리지 않습니다. 모든 내용은 [npm 없는 플러그인](/ko/flow/plugins/)에 있으며, 게시자의 키를 신뢰하는 방법과 거부 메시지가 말하는 내용도 포함됩니다. 여러분에게 의미하는 바는 이렇습니다. Node-RED가 npm과 Node.js 전체 설치를 필요로 하는 일을, Flow는 불러오기 전에 검증할 수 있는 샌드박스 파일로 실행합니다.

플러그인은 JavaScript 대신 Rust, TinyGo, Zig, AssemblyScript로도 작성할 수 있으므로, OT 플로가 실제로 원하는 신호 처리가 컴파일된 상태로 실행되며 이의를 제기할 수 없는 메모리 상한이 걸립니다.

게스트 ABI는 내보내기 세 개이며 그중 둘은 할당자 훅으로, 일부러 이렇게 작게 만들었습니다. 모든 내보내기는 공격 표면이고, 모든 게스트 작성자가 정확하게 해야 하는 일이 하나 더 늘어나는 것입니다.

| 내보내기 | 시그니처 | 필수 |
|---|---|---|
| `hotloop_flow_process` | `(ptr i32, len i32) -> i64` | 예 |
| `hotloop_flow_alloc` | `(size i32) -> i32` | 예 |
| `hotloop_flow_free` | `(ptr i32, size i32)` | 아니요 |

`i64` 결과는 상위 32비트에 오프셋을, 하위 32비트에 길이를 담아, 게스트 자신의 메모리에 있는 JSON 응답을 가리킵니다. 모든 것이 JSON으로 오가므로, 어떤 언어의 게스트든 공유 스키마 컴파일러 없이 이를 만들 수 있습니다.

한도는 일부러 작게 잡았습니다. 이것은 정말 중요한 플로 옆의 엣지 하드웨어에서 실행되며, 더 필요한 노드는 그렇다고 밝혀야 하기 때문입니다.

| 한도 | JavaScript 인터프리터 | WASM |
|---|---|---|
| 호출당 타임아웃 | 5 s | 5 s |
| 메모리 상한 | 강제할 수 없음 | 플러그인이 달리 정하지 않으면 노드당 16 MiB, `plugins.maxMemoryMiB`를 올리지 않으면 최대 64 MiB, 하드 한도 |
| 최대 출력 | 16 MiB | 8 MiB |

두 런타임 모두 cgo 없는 순수 Go입니다.
