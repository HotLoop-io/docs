Cascade는 공장이 다른 모든 시스템과 대화하게 합니다. 알람, 웹훅, 일정, 새로 들어온 행, MQTT 메시지 폭주가 항목 묶음이 되고, 그 항목들은 실제 자격 증명으로 실제 시스템을 호출하는 단계를 거칩니다. API가 멈추거나 도중에 장비가 재부팅되어도 작업은 끝까지 완료됩니다. 모든 단계에 체크포인트가 있고 재시도는 데이터베이스의 한 행이기 때문입니다.

정적 Go 바이너리 하나입니다. Raspberry Pi에서는 SQLite, k3s에서는 원하는 만큼의 워커와 함께 Postgres를 쓸 수 있습니다. Postgres가 대기열 역할도 하므로 공장 클러스터에서 따로 돌보아야 할 Redis가 없습니다.

## 하지 않는 일

**설비에 쓰지 않습니다.** Cascade는 읽기와 구독만 합니다. 밸브를 움직이거나 설정값을 바꾸는 모든 동작은 HotLoop의 쓰기 게이트를 거치므로, 어떤 워크플로가 시작했든 게이트의 감사가 모든 쓰기를 봅니다. PLC로 통하는 뒷문이 있는 워크플로 엔진은 감사 기록이 정직하지 않게 되는 지름길입니다.

**필드에서 JavaScript를 실행하지 않습니다.** 필드 표현식은 HotLoop 자동화가 쓰는 것과 같은 작은 언어인 expr을 사용합니다. 운영체제, 네트워크, 파일 시스템에 접근할 수 없고 항상 종료됩니다. JavaScript는 Code 단계라는 단 한 곳에만 있으며, 비밀 정보도 네트워크도 파일 시스템도 없는 별도의 격리된 프로세스에서 실행됩니다. 다른 모든 필드에서 JavaScript를 빼 두면 원격 코드 실행도 그 필드들에서 사라집니다.

**기능을 잠그지 않습니다.** SSO, 강제 MFA, RBAC, 감사, 버전 기록, 범위가 지정된 API 키, HA 워커가 모두 하나의 바이너리에 들어 있습니다. 코드 어디에도 라이선스 확인이 없습니다.

**외부로 정보를 보내지 않습니다.** 라이선스 서버도 클라우드 의존성도 없습니다. 텔레메트리는 직접 켜야 하는 옵트인이며 기본값은 꺼짐이고, 도입되면 필드 단위까지 문서로 공개됩니다.
