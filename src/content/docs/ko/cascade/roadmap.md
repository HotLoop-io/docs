## 0.1.0, MVP

완료. 엔진, 내구성 있는 실행, Postgres 대기열과 워커, 표현식, 격리된 Code 단계, 자격 증명 보관함과 OAuth2, 웹훅·일정·MQTT, MFA를 강제하는 사용자, OIDC, 프로젝트와 RBAC, 감사, 버전 이력, API, 편집기, 승인 목록의 커넥터, 워크플로 가져오기, 메트릭과 트레이스, Helm 차트와 Quadlet 유닛. `RELEASE_CHECKLIST.md`를 거쳐 배포했으며, 그 전에는 배포하지 않았습니다.

## 0.2.0, 인증과 거버넌스

완료. 새 편집기와 함께 1.0.0에 포함되어 배포되었습니다. SAML, LDAP과 AD, SCIM, 사용자 지정 역할, 외부 시크릿, 로그 스트리밍, 변수, 폴더, 인사이트, 실행 주석, S3와 Azure blob 저장소, 실행 마스킹 정책. 각 기능은 실제로 연결되는 서버를 상대로 시험했고, 편집기에 각각 화면이 있습니다.

## 1.0.x가 가져온 것

1.0.0은 0.1.0에 0.2.0과 새 편집기를 더해 한 번에 낸 릴리스입니다. 편집기는 그 번호에 우리 이름을 걸기 전에 마지막으로 원했던 조각이었습니다.

1.0.1은 로그인의 오류 하나를 고쳤습니다. 데이터베이스를 읽을 수 없을 때 "로그인하지 않음"으로 응답하고 쿠키를 지워서, 짧은 장애가 모두를 로그아웃시키고 올바른 두 번째 인증 요소를 잘못된 코드로 만들 수 있었습니다. 이제는 "다시 시도하세요"로 응답하고 세션을 유지합니다. 1.0.2는 Code 단계가 자격 증명으로 저장한 HMAC 키로 서명하고 검증할 수 있게 했고, 웹훅이 브라우저에서 자신을 호출할 수 있는 웹 출처를 지정할 수 있게 했습니다. 1.0.0과 1.0.2 사이에는 마이그레이션할 것이 없었습니다.

저장된 워크플로가 오늘 지키는 것: 파일은 자신이 형식의 어느 버전인지 말하고(`cascade: 1`), 모든 단계는 자기 버전을 가지며, 더는 없는 단계를 가리키는 워크플로는 조용히 바뀌는 대신 검증에 실패하고 시작하지 않습니다. 1.0.0에서 EmberOps 단계를 뺀 방식이 이것입니다. 모든 릴리스는 내보내기 전에 이전 릴리스의 데이터 위에서 먼저 시작해 봅니다. 워크플로는 그대로 있고 자격 증명도 그대로 열립니다.

## 1.3.0, 14개 언어의 편집기

완료. 영어, 스페인어, 프랑스어, 이탈리아어, 독일어, 노르웨이어 보크몰, 불가리아어, 그리스어, 한국어, 일본어, 베트남어, 힌디어, 중국어 간체, 아랍어. 상단 표시줄과 로그인 페이지에 언어 선택기가 있으며, 모든 화면, 단계 제목과 도움말, 서버의 거부 메시지가 번역됩니다. 날짜, 숫자, 기간은 언어를 따르고, 아랍어는 오른쪽에서 왼쪽으로 쓰되 캔버스와 코드는 왼쪽에서 오른쪽입니다. 각 언어를 데스크톱과 휴대폰 너비의 모든 화면에서 실제 브라우저로 시험하며, 한 줄이라도 빠진 언어는 빌드가 거부합니다. 용어는 HotLoop 공용 용어집에서 가져왔습니다.

## 1.5.0, 사람 삭제

구축 완료. 인스턴스 소유자는 사용자 화면, REST API(`DELETE /api/v1/users/{user}`), MCP 서버(`delete_user`)에서 사람을 삭제할 수 있습니다. 그 사람의 계정, 세션, 패스키, 로그인 ID, API 키는 사라지고, 감사 로그에는 누가 했고 무엇이 사라졌는지가 남습니다. 워크플로, 자격 증명, 실행 기록은 남습니다. 개인 프로젝트는 그 사람 이름에 "(removed)"가 붙은 공유 프로젝트가 되어, 소유자나 관리자가 작업을 옮기거나 다른 사람에게 넘길 수 있습니다. 누구도 자기 계정을 삭제할 수 없고, 마지막 소유자는 삭제할 수 없습니다. 계정을 유지하고 싶을 때를 위해 사람을 비활성화하는 기능도 그대로 있습니다.

## 1.4.2, 로그인 페이지

구축 완료. 로그인 페이지는 차분한 페이지 한가운데 놓인 카드이며, 위에 제품 마크와 이름이 있고, 주 버튼은 HotLoop 주황색이며, 다른 로그인 방법(패스키, SSO)은 그 옆에 단순한 버튼으로 있습니다. 밝은 테마와 어두운 테마, 휴대폰에서도 같습니다. SSO 버튼은 공급자가 Vord이면 그 공급자의 아이콘을 표시합니다. 모든 필드, ID, 로그인 경로는 이전과 같습니다.

## 1.4.1, 설정 페이지

완료. 저장 응답이 사용자가 필드를 바꾼 뒤에 도착해도 설정 페이지가 그 필드를 되돌리지 않습니다. 보낸 값 그대로인 필드는 서버의 값을 받고, 그 뒤에 수정한 필드는 수정한 값을 유지합니다. 그리고 언어 폴더의 검토 목록은 없어졌습니다.

## 1.4.0, 대기, 보존, 제한, 백업

완료. 데이터베이스보다 먼저 시작되는 파드는(차트가 분리 구성에서 그렇게 합니다) 이제 데이터베이스를 기다리며 그 사실을 알리고, 두세 번씩 재시작하지 않습니다(차트 시험에서 설치는 재시작이 없었습니다). 그리고 보존: 끝난 실행을 며칠 보관할지 정하는 설정이 있으며 기본값은 꺼짐이고, 한 시간마다 오래된 실행을 단계 데이터와 함께 지우는 작업이 있습니다. 같은 작업이 어떤 실행도 가리키지 않는 blob 저장소의 파일도 지웁니다. 데이터베이스에 넣기에 너무 컸던 출력과 첨부 파일이 해당하며, 공유 파일은 그것을 쓰는 마지막 실행이 사라졌을 때만 지웁니다. 그리고 API 키마다 요청 빈도 제한이 있으며(API와 MCP 모두), 기본값은 꺼짐이고, 429와 함께 기다려야 할 시간을 알려 줍니다. (웹훅에는 자체 제한이 있고, 잘못된 비밀번호가 반복되면 계정이 잠기는 것은 전과 같습니다.) 그리고 `hotloop-cascade backup`과 `restore`: SQLite 데이터베이스, 키, blob 파일을 해시 매니페스트와 함께 담고, PostgreSQL은 키와 blob에 더해 데이터베이스 몫을 위한 `pg_dump` 명령을 사용합니다.

## 1.2.0, MCP 서버의 마지막 도구 네 개

완료. MCP 서버에는 키가 호출할 수 있는 경로 네 개가 빠져 있었습니다. 자기 키 목록과 폐기, 워크플로의 테스트 웹훅 열기, OAuth2 로그인 시작입니다. 이제 이것들도 도구가 되어 모두 83개이며, 각각 자기 경로를 거치므로 편집기와 같은 권한 확인이 적용됩니다. 로그인한 사람이 필요한 열 개의 경로(키, SCIM 토큰, 시크릿 공급자, 로그 대상 만들기, 그리고 자신의 비밀번호)는 계속 제외됩니다. 이를 만들 수 있는 키는 스스로를 살려 둘 수 있기 때문이며, 어떤 경로이고 왜 그런지는 MCP 페이지에 있습니다.

## 1.1.0, MCP와 빠져 있던 화면

완료. 이것이 그 릴리스입니다. `/mcp`의 MCP 서버: 도구 79개, 각각 REST API의 경로 하나이므로 경로 자체의 핸들러가 권한을 확인하고, 본문을 검증하고, 변경을 수행하고, 감사 행을 기록합니다. HotLoop 제품군의 모든 MCP처럼 읽기와 쓰기가 켜진 상태로 제공되며, 그 두 스위치(`HOTLOOP_CASCADE_MCP`, `HOTLOOP_CASCADE_MCP_WRITES`)는 배포 쪽에 속해 어떤 도구나 경로도 바꿀 수 없습니다. MCP 페이지에 모든 도구와 각 도구가 요구하는 것이 있습니다.

그리고 편집기에 빠져 있던 화면: 자격 증명, 프로젝트(구성원과 서비스 계정), 사용자, 감사 로그, 설정, API 키가 있는 계정 페이지. 각 화면은 API와 같은 권한을 가지며 모든 역할로 실제 브라우저에서 시험했습니다. 로그인 페이지는 이제 옛 Go 페이지가 아니라 편집기의 색과 글꼴을 쓰는 편집기의 것입니다.

## 1.6.0, 승인, AI, Git, 커넥터

완료. 이 페이지에서 미구현으로 적혀 있던 네 가지가 한 릴리스에 들어옵니다. 사람이 승인하는 단계가 있는 양식, AI 단계, 환경과 보호된 인스턴스를 갖춘 Git 소스 관리, 그리고 선언형 커넥터 사양과 그 주변 도구입니다. 각각 아래에 자기 섹션이 있습니다.

## 사람이 승인하는 단계가 있는 양식

완료. 승인 요청 단계는 실행을 멈추고 한 사람에게 묻습니다. 그 사람은 휴대폰에서 실행의 승인 링크를 열어 작성한 내용을 읽고, 양식이 있으면 채운 뒤, 승인 또는 거부를 누릅니다. 실행은 승인됨 또는 거부됨으로 이어지며 누가, 언제, 무엇이라고 답했는지가 함께 전달되고, Cascade는 그 답을 편집기, API(`GET /api/v1/approvals`), MCP 서버(`list_approvals`)에서 읽을 수 있는 기록으로 남기며 각각 감사 행도 남깁니다. 페이지는 스크립트 없는 단순 HTML이고 편집기의 14개 언어로 제공됩니다. 승인자는 직접 입력한 이름이나 로그인한 계정으로 기록됩니다.

## Git 소스 관리, 환경, 보호된 인스턴스

완료. 프로젝트의 워크플로는 Git 저장소에 파일 하나씩, 워크플로 이름과 id를 담아 보관됩니다. push는 그것들을 쓰고 push한 사람의 이름으로 커밋합니다. pull은 프로젝트를 저장소와 일치시키며 id를 유지하고, 새 워크플로는 꺼진 채로 두고, 바뀐 것은 새 버전으로 만들며, 양쪽에서 바뀐 것은 누가 이기는지 정해 주기 전에는 건드리지 않습니다. 프로젝트의 화면 하나, API 경로 6개, MCP 도구 6개입니다. 인스턴스에 이름을 붙이면 모든 화면 위쪽에 표시되고, 보호된 인스턴스는 편집기, API, MCP에서 워크플로를 손으로 만들거나 고치거나 복원하거나 삭제하지 못하게 합니다. 워크플로는 Git에서 pull로 들어오며, 자격 증명, 변수, 실행, 워크플로 켜기와 끄기는 열려 있습니다.

## 규모

이 단계에서 만든 것: 웹훅 역할(차트 분리 구성의 전용 Deployment), 워크플로별 동시 실행 제한, 하나의 데이터베이스를 쓰는 여러 main. 하지 않은 것은 이 단계를 위해 정한 시험입니다. 분 단위 일정이 돌아가는 동안 main 하나를 종료하고, 한 시간 동안 중복 실행도 누락된 실행도 없음을 확인하는 것입니다.

## 커넥터

승인 목록 중 만든 커넥터는 들어 있습니다. HTTP, ntfy, Discord, Gotify, 이메일, HotLoop, MQTT, 데이터베이스, 파일, S3와 Azure blob 저장소. EmberOps 커넥터는 0.1.x에 있었고 1.0.0에서 빠졌습니다.

이제 커넥터는 파일일 수 있습니다. 선언형 커넥터 사양이 공개되어 있고(버전이 있는 형식과 JSON Schema), 파일이 설명하는 모든 API가 코드 없이 단계가 됩니다. 커넥터를 작성하고, 시험하고, 게시하고, 설치하는 도구는 바이너리에 들어 있으며(`connector init`, `validate`, `call`, `index`, `install`), 인덱스는 누구나 호스팅할 수 있는 정적 파일이고 파일마다 해시가 있습니다.

## AI 단계

완료. 모델에게 묻기와 에이전트 실행. 모델은 내 것입니다. Ollama 같은 로컬 서버이거나 내 키로 쓰는 호스팅 서비스이며 자격 증명으로 지정하고, OpenAI와 Anthropic 프로토콜을 모두 지원합니다. 에이전트는 다른 워크플로를 도구로 쓰고 턴 사이에는 데이터베이스에서 기다립니다.

미구현, 일정 없음: 내 모델로 워크플로를 써 주는 도우미. 호스팅 서비스는 없고 앞으로도 없을 것입니다. (에이전트가 바깥에서 Cascade를 다루게 해 주는 MCP 서버는 완료되었습니다. 1.1.0을 보세요.)

## 새 편집기 UI

완료, 1.0.0에 포함. 편집기는 Svelte 아일랜드를 쓰는 Astro로 다시 작성되어 정적 자산으로 빌드되고, 이전처럼 Go 바이너리에 내장됩니다. 그래서 새로 실행할 것이 없는 바이너리 하나라는 방식은 그대로입니다. 색, 글꼴, 마크는 HotLoop 브랜드 파일에서 가져오고 시스템의 밝은 모드와 어두운 모드를 따릅니다. 이전 편집기의 모든 화면이 들어 있고 하던 일을 그대로 합니다(캔버스 코드는 그대로 옮겨 왔습니다). 0.2.0 기능에는 화면이 있으며, 브라우저 시험이 실제 Chrome에서 실제 서버를 상대로 각 화면을 구동합니다. 이 중 어느 것도 API, 파일 형식, Go 쪽을 바꾸지 않았습니다.
