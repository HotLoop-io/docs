## ما هذا

1.1.0 يمنح Cascade خادم MCP والشاشات التي كانت تنقص المحرر، وينقل تسجيل الدخول إلى المحرر. المحرك وصيغة ملف سير العمل وREST API هي نفسها في 1.0.2.

## خادم MCP

يوجد على `/mcp`، على العنوان نفسه مع API، ويأتي مفعّلاً ويكتب. كل MCP في عائلة HotLoop يقرأ ويكتب، وكان Cascade الأخير الذي لا يملك MCP على الإطلاق.

يسجّل الوكيل الدخول بمفتاح API ويحصل على ما يستطيع فعله صاحب ذلك المفتاح، مقلَّصاً إلى نطاقات المفتاح. هناك 79 أداة، وكل واحدة مسار من REST API: يمر الاستدعاء عبر معالج المسار نفسه، فالتحقق من الصلاحيات والتحقق من الصحة والكتابة وسطر التدقيق هي للمسار. لم يُنسخ شيء إلى خادم MCP، فلا شيء يمكن أن ينحرف، ولم يُترك شيء خارجه، فلا شيء يُتخطى.

- الأداة التي تغيّر شيئاً تطلب `reason`، ويحتفظ بها سجل التدقيق بجانب التغيير، مع المفتاح والاسم الذي أعطاه العميل لنفسه.
- سر بيانات الاعتماد لا يعود أبداً، لأي أحد. بيانات الاعتماد المنشأة عبر MCP تُختم أسرارها فور وصولها.
- `HOTLOOP_CASCADE_MCP` و`HOTLOOP_CASCADE_MCP_WRITES` هما مفتاحا النشر، وكلاهما مفعّل افتراضياً. لا أداة ولا مسار API يستطيع تغييرهما، فالوكيل الذي يستطيع تحرير إعدادات النسخة لا يزال لا يستطيع إعادة تفعيل الكتابة.
- المسارات التي ترفض المفتاح بنفسها (إنشاء مفاتيح API ورموز SCIM ومزوّدي الأسرار ووجهات السجلات) ليست أدوات، لأن مفتاحاً يستطيع إنشاء مفاتيح هو مفتاح مسرَّب يبقي نفسه حياً. تسردها صفحة MCP مع كل أداة والصلاحية التي تطلبها.

## الشاشات

بيانات الاعتماد، المشاريع، حسابك، وللمالكين والمسؤولين الإعدادات والمستخدمون وسجل التدقيق. كل منها يتبع صلاحيات API نفسها: يُعرض لكل شخص ما يسمح به دوره فقط، ولا يزال الخادم يرفض الباقي.

- **بيانات الاعتماد** تُنشأ وتُفتح وتُغيَّر وتُشارك مع مشاريع أخرى وتُحذف. يُدخل السر مرة واحدة وتكتفي الشاشة بالقول إنه مضبوط.
- **المشاريع** فيها الأعضاء وأدوارهم، ومفاتيح حسابات الخدمة التي يسجّل بها تكامل دائم الدخول، وتُعرض مرة واحدة.
- **الحساب** ينشئ مفاتيح API الخاصة بك ويلغيها، وهي ما يسجّل به API وMCP الدخول، ويغيّر كلمة مرورك.
- **المستخدمون** ينشئ أشخاصاً ويعطّلهم أو يفعّلهم. **سجل التدقيق** يُقرأ ويُصفّى ويُفحص بحثاً عن العبث. **الإعدادات** فيها اشتراط العامل الثاني وسير عمل الأخطاء.

تسجيل الدخول هو الآن صفحة المحرر نفسه، على `/login`، بألوان المحرر، فاتحة وداكنة، على الهاتف كما على المكتب. يفعل كل ما كانت الصفحة القديمة تفعله: الإعداد عند أول تشغيل، وكلمات المرور، وحسابات الدليل، وتسجيل الدخول الموحد، ومفاتيح المرور، والعامل الثاني، ورموز الاسترداد.

## amd64 فقط، ولماذا

يُبنى هذا الإصدار لـ amd64 فقط. تصدر البنية المتعددة في تشغيل خاص بها، لذا الإصدار الذي يلي هذا رفع صغير للإصدار يبني الاثنين. إلى ذلك الحين تسرد `stable` و`latest` والوسوم القصيرة صورة amd64 هذه بجانب صورة arm64 التي كانت تشير إليها، فيستمر جهاز arm في السحب. وسم الإصدار `1.1.0` هو amd64 وحده.

## الترقية والعودة

بلا ترحيلات. نفّذ `helm upgrade` إلى 1.1.0، أو دع `:stable` يحرّك وحدات Quadlet. إعادة 1.0.2 آمنة، لأن شيئاً لم يتغير في قاعدة البيانات. ما لا يستطيع التراجع إلغاءه هو ما فعله وكيل بالفعل: تبقى تغييراته قائمة، وتبقى سطور التدقيق التي كتبها في السجل بنوع الفاعل `mcp`. نسخة احتياطية قبل أي تحديث تبقى عادة جيدة.
