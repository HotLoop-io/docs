---
title: "واجهة API الإدارية"
description: "استدعاءات HTTP وwebsocket التي يستخدمها المحرر وسطر الأوامر، وما يحتاجه كل منها وما يعيده."
---

| الطريقة والمسار | الإذن | ملاحظات |
|---|---|---|
| `GET /health` | بلا | فحص الحياة. لا يحمل kubelet رمزًا، والمصادقة على هذا المسار ستجعل الـ pod يعيد التشغيل في حلقة إلى الأبد. |
| `GET /ready` | بلا | فحص الجاهزية، يُبلَّغ عنه منفصلًا، فيغادر وقت التشغيل الذي فشل في البدء الـ Service دون أن يقتل kubelet الـ pod. |
| `POST /auth/token` | بلا | تسجيل الدخول. الرمز 429 مع `Retry-After` أثناء الإغلاق. |
| `POST /auth/revoke` | بلا | تسجيل الخروج. |
| `GET /auth/mode` | بلا تسجيل دخول | هل يُفتح وقت التشغيل هذا من لوحة EmberCORE: `{"dashboard": bool, "hideLogin": bool}`. يسأل المحرر عن ذلك قبل أن يسجّل أحد دخوله. |
| `GET /auth/mfa`, `POST /auth/mfa/setup`, `/confirm`, `/disable` | مستخدم مسجّل الدخول | تسجيل دخولك الخاص بعاملين. يعيد Setup المفتاح ورابط `otpauth://` ورمز QR. يقبل Confirm وdisable القيمة `{"code": ...}`. |
| `POST /auth/mfa/reset` | `auth.admin` | يوقف تسجيل الدخول بعاملين لشخص آخر: `{"username": ...}`. |
| `GET /metrics` | بلا | Prometheus. أعداد ومعرّفات عقد فقط، ولا محتوى رسائل ولا إعدادات أبدًا. |
| `GET /settings` | `settings.read` | |
| `GET /nodes` | `nodes.read` | السجل، وهو ما يشغّل لوحة المحرر وحواراته. |
| `GET /plugins` | `nodes.read` | الإضافات التي حُمّلت، وما يطلبه كل منها وما مُنح، وتلك التي رُفضت مع السبب. |
| `GET /flows` | `flows.read` | |
| `GET /flows/export` | `flows.read` | ملف التدفقات تمامًا كما هو على القرص، من أجل git. |
| `POST /flows` | `flows.write` | النشر. يقبل ملاحظة اختيارية لسجل عمليات النشر. |
| `GET /deployments` | `flows.read` | سجل عمليات النشر، الأحدث أولًا، دون الحمولات. يحدّه `?limit=N`. |
| `GET /audit` | `audit.read` | من فعل ماذا ومن أين، الأحدث أولًا. `?event=` و`?user=` و`?since=` و`?limit=`. |
| `GET /deployments/{seq}` | `flows.read` | سجل واحد، مع تدفقاته محلَّلة. وليس بيانات اعتماده أبدًا. |
| `GET /deployments/{seq}/flows` | `flows.read` | ملف تدفقات عملية النشر تلك، بايتًا ببايت. |
| `GET /deployments/{from}/diff/{to}` | `flows.read` | فرق عقدة بعقدة بين عمليتي نشر، منظَّم وكنص. |
| `POST /flows/diff` | `flows.read` | الفرق بين ما هو قيد التشغيل والمستند في الجسم. لا ينشر شيئًا. |
| `POST /flows/types` | `flows.read` | فحص الأسلاك المنوَّعة الذي تجريه عملية نشر، على المستند في الجسم: `{"wires": [...]}`، فارغ عندما لا يوجد خطأ. يرسم المحرر الجواب. لا ينشر شيئًا. |
| `POST /deployments/{seq}/rollback` | `flows.write` | ينشر تدفقات ذلك السجل وبيانات اعتماده مرة أخرى كعملية نشر جديدة. يقبل ترويسة rev و`{"note": ...}` اختيارية. |
| `GET /tests` | `flows.read` | مجموعة اختبارات التدفق المحفوظة بجانب ملف التدفقات، واسم ملفها، وهل تتوقف عمليات النشر عليها. |
| `PUT /tests` | `flows.write` | يستبدل المجموعة. الجسم هو YAML؛ وما لا يمكن تحليله يعطي 400 مع السبب. |
| `POST /tests/run` | `flows.read` | يشغّل المجموعة، أو `"tests"` من الجسم، على `"flows"` من الجسم أو على ما هو قيد التشغيل. يعيد التقرير. لا ينشر شيئًا. |
| `POST /tests/from-debug` | `flows.read` | يصوغ اختبارًا من `{"node", "msgId"}`، رسالة عرضتها عقدة Debug. لا يحفظ شيئًا. |
| `POST /tests/cases` | `flows.write` | يضيف الاختبارات الموجودة في الجسم، وهي ملف اختبارات مستقل، إلى نهاية المجموعة. |
| `GET /traces` | `flows.read` | الآثار المحفوظة، الأحدث أولًا، مع ما يحتويه المخزن المؤقت وحدوده. `?limit=N`. 404 مع `trace.enabled: false`. |
| `GET /traces/find` | `flows.read` | الأثر الذي كانت فيه رسالة، من `?msgId=` و`?node=`، المعرّف وعقدة Debug اللذين يعرضهما الشريط الجانبي. يعيد كل قفزة والمسار إلى القفزة المسؤول عنها. |
| `GET /traces/{id}` | `flows.read` | أثر واحد، كل قفزة بتوقيتها والرسالة كما سُلِّمت للعقدة. |
| `POST /traces/{id}/test` | `flows.read` | يصوغ اختبار تدفق من الأثر. لا يحفظ شيئًا. |
| `POST /traces/{id}/replay` | `flows.read` | يضع الرسالة التي بدأت الأثر في `"flows"` من الجسم، أو ما هو قيد التشغيل، في عملية فرعية، ويعيد أين تنتهي مقابل أين انتهت. لا ينشر شيئًا. |
| `GET /runtime/stats` | `status.read` | |
| `POST /inject/{id}` | `inject.write` | يُطلق عقدة Inject. |
| `GET /comms` | `status.read` | websocket الحالة والتصحيح الخاص بالمحرر. أرسل الرمز كبروتوكول فرعي `hotloop-flow.bearer.<token>`، يُعرض بجانب `hotloop-flow`. هذا ما يفعله المحرر. ما زال `?access_token=<token>` في عنوان URL يعمل للنصوص التي تستخدمه بالفعل، ويسجّل تحذيرًا لكل اتصال يفعل ذلك، لأن عنوان URL ينتهي في سجلات الوكيل والوصول. |
| `POST /mcp` (و`GET` و`DELETE`، لإصدارات البروتوكول الأقدم) | `mcp.call` | [نقطة نهاية MCP](/ar/flow/mcp/)، حيث تُقدَّم التدفقات كأدوات. رمز جلسة أو رمز API كأي رمز آخر. الأدوات المعروضة على المتصل، والتي يمكنه استدعاؤها، هي التي تبلغها صلاحياته. 403 عند إيقاف المصادقة. |

كون `/metrics` و`/health` بلا مصادقة قرار وليس سهوًا. لا يحمل جامع Prometheus رمز حامل، لذا فاشتراط رمز يعني إما تسليم بيانات اعتماد لمنظومة المراقبة لديك أو عدم وجود مراقبة.

يرسل المستخدم المفعَّل لديه تسجيل الدخول بعاملين `"code"` مع اسم المستخدم وكلمة المرور إلى `POST /auth/token`. وبدونه يكون الجواب 401 مع `"mfa": "required"`.

الصلاحيات هي `"*"` لكل شيء، أو سلسلة مطابقة تمامًا مثل `flows.read`، أو منح بالبادئة مثل `flows.*`. يحتاج الوكيل الذي يستدعي التدفقات كأدوات MCP إلى `mcp.call`. وحساب للقراءة فقط للوحة معلومات تريد فقط عرض حالة التدفقات هو `["flows.read", "status.read"]` ولا شيء أكثر.

تقبل عمليات النشر ترويسة اختيارية `HotLoop-Flow-Deployment-Rev`. أرسل المراجعة التي قرأتها آخر مرة، فتُرفض عملية النشر التي تتسابق مع محرر آخر بـ 409 بدلًا من الكتابة فوق عمل أحد بصمت، وهو الإخفاق الذي لا تسمع عنه إلا ممن ضاع عليه عصره.

لا يعيد النشر تشغيل إلا ما غيّرته. تبقى العقدة قائمة حين لا يتحرك شيء تعتمد عليه: إعداداتها وعلامة تبويبها ومجموعتها وبيئتها وبيانات اعتمادها وكل عقدة إعداد تسميها. سحبها عبر اللوحة أو إعادة توصيلها لا يُحتسب، لأن الأسلاك الجديدة تُركَّب على العقدة العاملة. لذا فإصلاح خطأ مطبعي في عقدة دالة واحدة لم يعد يُسقط كل جلسات MQTT على الصندوق، وعقدة Delay التي تحتفظ بعشر دقائق من القراءات تواصل الاحتفاظ بها. هذا هو سبب وجودها كله: حين يهز كل حفظ المصنع، يتوقف المشغّلون عن الحفظ أثناء الوردية وينتظر الإصلاح حتى السبت.

اختر مقدار ما يُعاد تشغيله بترويسة `HotLoop-Flow-Deployment-Type`. كما تعمل `Node-RED-Deployment-Type` في Node-RED، فيحصل نص نشر لديك أصلًا على إعادة التشغيل التي يطلبها.

| النوع | ما الذي يُعاد تشغيله |
|---|---|
| `nodes` (الافتراضي) | العقد التي غيّرتها، إضافة إلى كل ما يسمّي عقدة إعداد غيّرتها. |
| `flows` | كل عقدة في أي تدفق فيه تغيير. |
| `full` | كل شيء. مثل إعادة تشغيل العملية. |

تذكر الاستجابة ما فعلته: `type` و`started` و`restarted` و`stopped` و`unchanged`. لا يضيع شيء قيد المعالجة في الطريق. العمل المصطف أصلًا عند عقدة يجري استبدالها ينتهي على النسخة القديمة، وكل ما يصل أثناء التبديل ينتظر الجديدة، والرسالة المتجهة إلى عقدة حذفتها تُحتسب وتظهر كإهمال بدلًا من أن تتبخر.
