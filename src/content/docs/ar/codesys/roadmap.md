هذه قائمة بما أُنجز وما بقي، بالترتيب الذي يُنجز به. لا تعد بشيء غير موجود في الشيفرة أو في خطة اختبار، وتذكر صفحة [الحالة](/ar/codesys/where-it-stands/) إلى أي مدى جرى تشغيله.

## بُني

- [x] chart حول HotLoop Edge بإعدادات افتراضية لبيئة تشغيل على عقدة: SQLite ونسخة واحدة وتحمّلات تُبقي كلا الـ pod عند فقدان مستوى التحكم.
- [x] provisioner يطبّق ملفًا تعريفيًا ويُبقيه سليمًا، مع مراجعة تحمي ما غيّره شخص.
- [x] ملف تعريفي يحمل قائمة أجهزة من أي بروتوكول يتحدثه HotLoop، فيعود المستمع (listener) مهيّأً دون حاجة إلى PLC.
- [x] الجهاز والـ tags والإنذار والشاشة تُنشأ دون خطوة يدوية، على بيئة تشغيل CODESYS Control for Linux SL 4.22.0.0 في حاوية.
- [x] التعافي من إعادة تشغيل بيئة التشغيل دون تدخل، في نحو 88 ثانية.
- [x] تسجيل دخول موقَّع من لوحة EmberCORE، مع حالات الرفض.

## صدر

- [x] HotLoop 4.22.0، الإصدار الذي يغلّفه الـ chart.
- [x] الـ chart منشور على `https://hotloop.io/hotloop-codesys/`، وأحدثه 0.3.8.
- [x] صورة الـ provisioner عامة، فتُسحب دون تسجيل دخول، 0.3.3.
- [x] صورة provisioner متعددة المعماريات، amd64 وarm64، من 0.3.3 والـ chart 0.3.8.
- [x] مستمعان OPC UA PubSub على منفذ UDP واحد، مع HotLoop 4.22.0 والـ chart 0.3.7.
- [x] [ملاحظات الإصدار](/ar/releases/codesys-0-3-10/) لكل chart، من 0.3.0 إلى 0.3.10.

## أُثبت على عتاد مباشر

- [x] شُغّل على عتاد مباشر بلا نظام تشغيل (2026-11-17)، بما في ذلك تثبيت من صفحة App Store الحقيقية كما يفعل الموظفون، وk3s v1.35.7، وعقدة تفقد اتصالها بمستوى التحكم فعلًا مع بقاء الـ pods، وتنزيل من بيئة تطوير CODESYS بينما تبقى بيئة التشغيل قائمة، وبيئة تشغيل على شبكة المضيف نفسه بجانب pod HotLoop على عقدة واحدة، وبيئة تشغيل بإدارة مستخدمين مفعّلة ونقطة نهاية OPC UA مؤمّنة بشهادة.
