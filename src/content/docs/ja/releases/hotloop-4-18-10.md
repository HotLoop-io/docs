HotLoop が 1 つのイメージではなくなるリリースです。IoT、Edge、Gateway、Edge Relay はすべてこの 1 つのタグから、歩調を合わせて、それぞれ専用のイメージとチャートで出ます。さらに、MQTT で自分から名乗り出るデバイス、プラント自身のデータベースに書き出される履歴、選べるデータベース(SQLite、Postgres、TimescaleDB)、WAN が切れても動き続ける Edge、`:stable` に追従して悪い更新を自分で巻き戻すボックスが加わります。4.17.0 からの Gateway は通常の `helm upgrade` です。既定値がいくつか変わっているため、稼働中のプラントに触れる前に、下の「4.17.0 からのアップグレード」を読んでください。

インストールすべき 4.18.0、4.18.1、4.18.2、4.18.3、4.18.4、4.18.5、4.18.6、4.18.7、4.18.9 はなく、4.18.8 も実行すべきものではありません。そのうち 9 つのタグは何も公開しませんでした。4.18.8 は ghcr.io にチャートもリリースもないままイメージだけを残し、Gateway、Edge Relay、IoT の `:stable` と `:latest` を動かしたので、`:stable` に追従するボックスは更新されるまで 4.18.8 を実行していた可能性があります。4.18.10 がこれを置き換え、それらのタグのすべての修正を含みます。発見されたデバイスの値が、自身の「まだなし」という読み取りより古いタイムスタンプを付けられ、キャッシュに捨てられることがありました。ダッシュボードは変化のないゲージを再描画しなくなります。HotLoop に組み込まれたブローカーは、リスナーのサブスクリプションのパケット ID が同じクライアントに送信中のメッセージの ID と一致すると拒否していたため、そのサブスクリプションの先のデバイスは発見されませんでした。また、ブローカーがまだ送る義務のある QoS 1 または 2 のメッセージと同じパケット ID でパブリッシュしたクライアントがいると、ブローカーが自分のメッセージを捨て、再接続後も再送しませんでした。ブローカーは現在、2 つの方向を別々のテーブルで管理しており、サブスクリプションを拒否したブローカーはログにそう記録します。読み込み中のダッシュボードが、ユーザーが直前に移動した先のアドレスを自分のアドレスで上書きすることもなくなりました。HotLoop がパブリッシュするのと同じアドレスのパスワードでスマートフォンが ntfy にログインしている場合は、そのユーザーにも tier を付与してください。4.18.10 は 4.18.0 になるはずだったものすべてに、4.18.3 のタグ以降の変更を加えたものです。

完全なノートは README にあります。4.18.10 の変更点をご覧ください。

## 要点

- 同じ 4 つのイメージ、同じタグ、同じアーキテクチャです。
- **4.18.4 のタグ以降。** 発見されたデバイスの値が自身の「まだなし」という読み取りの陰で失われることがありましたが、もうありません。説明を読み取れなかった UPnP デバイスは、15 分後ではなく数秒で再読み取りされます。カードエディターの OK は 1 回のクリックで効き、エンティティドロワーの Save は動かず、ダッシュボードは変化のないものを再描画せず、2 つのプロセスが叩き続けるカウンターは負け続ける側を拒否しなくなりました。
- **ライセンスが変わりました。** 4 つの製品はすべて HotLoop の Business Source License 1.1 のもとにあります。家庭とラボでの利用は無料で、学校、非営利団体、官公庁の利用も無料、企業での利用は EmberNet を通します。各バージョンは初めて公開されてから 4 年後に GPL-3.0 以降になります。それまではオープンソースではなく、そうだと偽るつもりもありません。プラントに入れる前に LICENSE を読んでください。
- **4.18.3 のタグ以降。** 壁掛けボードとスマートフォンでの UniFi:ネットワークマップはズームとピンチができ、WAN レイテンシとポートのトラフィックにトレースが付き、ボタン 1 つでよく使うアラームを作れます。エージェントは MCP でネットワークのマップ(`get_network_topology`)と、コンソールが今言ったこと(`get_network_events`)を尋ねられます。logbook は UniFi のイベントを、関係するスイッチの下に表示します。1 台の MQTT デバイスが同じ ID の 2 つのクライアントを持ち、ブローカーが交互に追い出すことがありましたが、修正しました。アラームのメッセージは値カードと同じ形式で値を表示し、アラームカードはデバイスや設備を指定でき、動かないタグのトレンドはウィンドウ全体を横切る線になります。
- **4 つの製品、4 つのイメージ、4 つのチャート、1 つのタグ。** `hotloop-iot` と `hotloop-edge` は ghcr.io とチャートリポジトリに新しく登場します。Gateway は `ghcr.io/hotloop-io/hotloop` とチャート `hotloop` のままなので、使っている人は何も変える必要がありません。製品は設定ではなくビルドです。IoT イメージでは OPC UA サーバーがオフになっているのではなく、そもそも入っていません。[製品ページ](/ja/products/)をご覧ください。
- **MQTT ディスカバリー。** ESPHome、Zigbee2MQTT、Tasmota、Shelly をブローカーに向けると、読み取りつきで現れます。管理者が受け入れて各ポイントを手動で有効にするまで、何も命令できません。ネットワークディスカバリー(mDNS、SSDP、DHCP)は待ち受けるだけで、探索するネットワークを指定しない限り何も送りません。
- **Historian ターゲット。** HotLoop が保持するすべての読み取り値は、プラント自身の PostgreSQL、TimescaleDB、SQL Server、InfluxDB、MySQL/MariaDB にも送られ、同じ行と同じ品質が書き込まれます。
- **データベースは設定です。** 同じバイナリから、製品ごとに SQLite、PostgreSQL、TimescaleDB を選べます。Pi に 300 MB のデータベースイメージは要りません。
- **Edge は WAN が切れてもプラントを動かし続け**、ストアアンドフォワードのキューは、停止中の起動、リセットなしで死ぬリンク、プラントを追い越さなければならない再送といった厄介なケースにも耐えます。
- **すべてのボックスが `:stable` に追従して自分で更新し**、起動できないリリースは巻き戻されます。マイグレーションは追加のみで、アプリは自分より 2 リリース先のスキーマでは起動を拒否するため、その巻き戻しは常に安全です。
- **Edge Relay** は、プッシュされた設定を再起動せず Sparkplug セッションも失わずにそのまま反映し、Gateway と同じようにブローカー上のデバイスを発見します。
- **すべてのイメージにサードパーティのライセンスがすべて含まれ**、GPL モジュールがあるとビルドが止まります。
- **太陽。** 日の出、日の入り、太陽の高度を、緯度と経度からボックス上で計算します。

### API の変更

- 新しいルート:`/api/discovery`、`/api/network-discovery`、`/api/mqtt/brokers`、`/api/broker/logins`、`/api/historian/targets`、`GET /api/entities/{entity_id}/image`、`POST /api/fleet/{id}/update`。すべて docs/API.md にあります。
- `GET /api/status` が `product`、`features`、イメージのダイジェストを返します。話している製品にない機能のルートは、取り繕わず、その機能を持つ製品を示す `404` で答えます。すべてのルートは、引き続きすべての製品にあります。
- 新しい権限 `fleet.update`、管理者のみ。operator ロールは変わりません。

### 4.17.0 からのアップグレード

- `helm upgrade <release> hotloop/hotloop --version 4.18.10 --reset-then-reuse-values`。4.17.0 と 4.18.10 の Gateway チャートを並べてレンダリングしました。同じ 8 個のオブジェクト、同じ selector、同じ volume claim です。今回は素の `--reuse-values` でもレンダリングできますが、4.17.0 の値を再生して新しい既定値がすべて抜けるため、reset 形式か values ファイルを使ってください。
- マイグレーション 0016 から 0024 が起動時に実行されます(MQTT ディスカバリー、ブローカーのログイン、MQTT ソース、historian ターゲット、ネットワークで見つかったもの、MQTT ソースが話す内容のための 2 つ、ダッシュボードの保存先テーブル、既存のすべてのタグでは空になるタグの `no_data` 列)。すべて追加型です。いつも通り先に `pg_dump` を取ってください。
- **`edgePublish.queueMaxBytes` の既定値は無制限ではなく 64 MiB になりました。** 上限を超えると最も古い読み取り値が捨てられ、数えられます。無制限のキューは長い停止中にボリュームを埋め尽くし、その方が悪い結果でしたが、既定値が変わったことに違いはありません。自分の読み取り速度(1 件あたり約 180 バイト)から大きさを決めるか、従来の動作を保つなら `0` にしてください。`--reuse-values` でのアップグレードは、元の値をそのまま保ちます。
- **ブローカーのログイン。** Settings、MQTT で作ったログインは、プロファイルのトピックルールを持ちます。`HOTLOOP_BROKER_USERS` のログインには手を加えず、以前とまったく同じく何でもできます。`HOTLOOP_BROKER_USERS` のないブローカーも起動するようになり、入れるのは HotLoop とその中で作ったログインだけです。
- 今後アプリは、データベースがどれだけ先に進んでいるかも数え、2 リリース差では名指しで拒否するため、巻き戻しが不意打ちになることはありません。
- **Edge Relay:** こちらも `--reset-then-reuse-values` でアップグレードしてください。Quadlet を使う場合は、4.17.0 に固定せず `:stable` に追従する新しい `edge-relay.container` と、悪い更新を巻き戻させる healthcheck を取り込んでください。
- **IoT、Edge、Gateway の Quadlet ユニットは新規です。** 4.17.0 にはリレーのものしかありませんでした。`deploy/quadlet/` の下に、製品ごとに 1 つのディレクトリがあります。
