HotLoop の画面は P&ID です。CODESYS PLC 自身のアラームが HotLoop のアラーム一覧に表示され、確認は PLC に戻り、スクリプトの実行は必ず終わり、ボックスのデータボリュームは必ず読み取られ、UniFi Protect、Access、電源のロードマップの項目が提供されました。amd64 のみでビルドされています。マルチアーキテクチャビルドは次のバージョンで続きます。

## 変更点

- **画面は P&ID です。** タンク、ポンプ、バルブ、熱交換器、フィルター、計器、ジャンクションをシンボルページに置き、ある接続点から別の接続点へドラッグします。配管は、ページ上のすべてを避けて直角に自分で敷設され、別の配管の上に落とした場所でジャンクションで分岐し、シンボルを動かしている間も引き直されます。すべての配管は媒体(水、蒸気、燃料、空気、電力、信号など。それぞれ色、コード、線のパターンがあるので、色だけが伝達手段になることはありません)を持ち、自身のタグまたはルールに従って動きます。すべてのシンボルページに、ズーム、パン、ミニマップの表示、グレーの高性能ビューへの切り替えのツールバーが付き、P&ID は同じ画面ファイルで保存、エクスポート、インポートされます。[ダッシュボード](/ja/iot/dashboards/)と [Screen files](/ja/iot/screen-file/)をご覧ください。
- **CODESYS PLC 自身のアラームが HotLoop のアラーム一覧に表示されます。** プロジェクトの Alarm Configuration は、アラームグループとクラス、そして変数を監視するアラームを保持します。CODESYS デバイスは、PLC のアラームマネージャーが持つもの(アクティブ、確認待ち、条件が成り立つ間に確認済み)を読み取るようになり、HotLoop で行った確認は PLC に戻ります。渡すものがない PLC には手を出しません。HotLoop Alarms ライブラリとプロジェクト内の 1 つのブロックが必要です。CODESYS-ALARMS.md をご覧ください。
- **ボックスのデータボリュームは必ず読み取られます。** `/data` の下に何もマウントされていないボックスには `/data` がなく、ボックスの状態のタグ `data_util_pct` は「no such file or directory」で不良と読まれていました。今は、データフォルダーが作られるボリュームを読み取ります。[プロトコルとドライバー](/ja/iot/protocols/#ボックスの状態)をご覧ください。
- **スクリプトの実行は必ず終わります。** データベースがスクリプト実行の終了の書き込みを拒否したとき、HotLoop はそれをログに残して諦めていたため、枠はとうに空いているのに、実行はプロセスが生きている間ずっと「running」と読まれていました。今は書き込みを再度求め、間に短い待ちを置いて最大 5 回です。
- **UniFi Protect、Access、SmartPower PDU のアウトレットはロードマップで提供済みになりました。** 4.23.6 でデバイスとして登場し、公開された API に沿って作られ、Protect のすべてのパスが 7.4.102 のドキュメントと一致します。[HotLoop のロードマップ](/ja/roadmap/)をご覧ください。
- **TwinCAT の画面をブラウザーで検証しました。** TwinCAT PackML のサンプルをフレームとともにインポートしてレンダリングし、ランプがライブのレジスターに追従します。
- **テストは待っているものを待ちます。** パネルの throttle の待ちは算術として確認され、forSec 保持のタイマーは sleep と競争せずテストの手の中にあり、Apache Kafka の topic テストは topic をすぐに削除して遅いボックスが必要とする時間を持ち、API テストはサインインを 1 つのサンプルで制限しなくなりました。負荷のかかったボックスは、1 秒前の 4 倍遅く応答するからです。

## マイグレーション

ありません。

## API の変更

なし。ルートは変わっていません。シンボルページの設定は `pipes`、`view`、シンボルの `rot` を受け付け、保存された画面ファイルがそれらを運びます。

## 4.23.6 からのアップグレード

通常の `helm upgrade` です。マイグレーションも新しい secret もありません。配管のないシンボルページは以前どおり描かれます。

## 検証していないこと

- PLC のアラーム経路は、アラームラボのプログラムを載せた実際の CODESYS Control for Linux SL 4.22.0.0 ランタイムに対して実行しました。
- Protect、Access、PDU のアウトレットは公開された API に従っており、実機でのベンチ実行はオフィスで続きます。
