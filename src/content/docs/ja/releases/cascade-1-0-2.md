## 概要

1.0.2 では、シークレットがアイテムデータに入ることなく、ワークフローが署名と検証を行えます。また、別のウェブサイト上の公開フォームが、ブラウザーから Webhook を呼び出せます。それ以外は 1.0.1 から変わっていません。

## Code ステップの新機能

- **暗号ヘルパー。** `sha256(text)`、`hmacSHA256(key, text)`、`randomHex(bytes)`、`base64Encode(text)`、`base64Decode(text)`、`safeEqual(a, b)`。Go で計算するので結果は標準ライブラリのものであり、スクリプトには引き続き `require`、ネットワーク、ファイルがありません。
- **ステップ用の認証情報。** Code ステップには `secret` 認証情報スロットがあります。`HMAC key` 認証情報(シークレットのフィールド `key` が 1 つだけの新しい組み込みタイプ)を割り当てると、スクリプトは `credential.key` として読みます。キーは他のシークレットと同じくボールトにあり、スクリプトが返しても、実行が保存するあらゆる場所からボールトが伏せます。認証情報のないステップには空の `credential` オブジェクトが見えます。

理由は次のとおりです。公開フォームは HMAC でプルーフ・オブ・ワークを確認します。これまでワークフローでそれを行うには、キーをアイテムか変数に入れるしかなく、どちらも保存された実行か平文に残ります。今はキーが認証情報で、保存された実行には署名だけが残ります。

## Webhook の新機能

- **`corsOrigins`。** Webhook トリガーは、ブラウザーから呼び出せるページのウェブオリジンのリスト(`https://example.com` または `*`)を受け取ります。Cascade はブラウザーのプリフライトに自分で応答し、実行は開始せず、リストにあるオリジンには応答に `Access-Control-Allow-Origin` を付けます。リストのない Webhook はこれまでとまったく同じ動きで、CORS ヘッダーがないため、ブラウザーのページは応答を読めません。エントリーはパスのないオリジンである必要があります。

## アップグレードと戻し方

マイグレーションはありません。1.0.2 に `helm upgrade` するか、`:stable` に Quadlet ユニットを進めさせてください。新しいヘルパーを使わないワークフローはこれまでとまったく同じ動きなので、1.0.1 に戻しても安全です。新しいヘルパーを呼ぶワークフローは、1.0.1 ではヘルパーが未定義で失敗します。更新の前にバックアップを取る習慣は、これからも有効です。
