## 概要

1.1.0 では、Cascade に MCP サーバーと、エディターに足りなかった画面が加わり、サインインがエディターの中に移ります。エンジン、ワークフローのファイル形式、REST API は 1.0.2 と同じです。

## MCP サーバー

`/mcp` にあり、API と同じアドレスです。最初からオンで、書き込みもできます。HotLoop ファミリーのすべての MCP は読み書きができ、Cascade は MCP がまったくなかった最後の製品でした。

エージェントは API キーでサインインし、そのキーの持ち主ができることを、キーのスコープに絞って受け取ります。ツールは 79 個あり、それぞれが REST API のルートです。呼び出しはルート自身のハンドラーを通るので、権限チェック、検証、書き込み、監査の行はルートのものです。MCP サーバーにコピーしたものはないのでずれようがなく、省いたものもないので飛ばされるものもありません。

- 何かを変更するツールは `reason` を求め、監査ログは変更の隣に、キーとクライアントが自分に付けた名前とともにそれを残します。
- 認証情報のシークレットは、誰にも返されません。MCP で作成した認証情報は、シークレットが届いた時点で封印されます。
- `HOTLOOP_CASCADE_MCP` と `HOTLOOP_CASCADE_MCP_WRITES` はデプロイのスイッチで、どちらも初期状態でオンです。どのツールも API ルートもこれを変更できないため、インスタンスの設定を編集できるエージェントでも、書き込みを再びオンにすることはできません。
- キー自体が拒否するルート(API キー、SCIM トークン、シークレットプロバイダー、ログの送信先の作成)はツールではありません。キーを作れるキーは、自分で生き延びる漏えいしたキーだからです。MCP のページに、すべてのツールと、それぞれが求める権限が載っています。

## 画面

認証情報、プロジェクト、自分のアカウント、そして所有者と管理者向けの設定、ユーザー、監査ログ。どの画面も API と同じ権限に従います。各ユーザーにはロールが許可するものだけが表示され、それ以外はサーバーが引き続き拒否します。

- **認証情報** は作成、表示、変更、他のプロジェクトとの共有、削除ができます。シークレットは一度だけ入力し、画面には設定済みと表示されるだけです。
- **プロジェクト** には、メンバーとそのロール、そして常時稼働する連携がサインインに使うサービスアカウントキー(表示は一度だけ)があります。
- **アカウント** では、API と MCP がサインインに使う自分の API キーの作成と取り消し、パスワードの変更ができます。
- **ユーザー** では、ユーザーの作成と、無効化や有効化ができます。**監査ログ** は閲覧、絞り込み、改ざん検査ができます。**設定** には、第 2 要素の必須化とエラーワークフローがあります。

サインインは、`/login` にあるエディター自身のページになり、エディターの色でライトとダークに対応し、スマートフォンでもデスクでも使えます。以前のページができたことはすべてできます。初回セットアップ、パスワード、ディレクトリアカウント、シングルサインオン、パスキー、第 2 要素、リカバリーコードです。

## amd64 のみの理由

このリリースは amd64 のみをビルドします。マルチアーキテクチャは別の実行で出すため、この次のリリースは、両方をビルドする小さなバージョンアップになります。それまでは、`stable`、`latest`、短いタグには、すでに指していた arm64 イメージと並んでこの amd64 イメージが載るので、arm のマシンも引き続き取得できます。バージョンタグの `1.1.0` は amd64 のみです。

## アップグレードと戻し方

マイグレーションはありません。1.1.0 に `helm upgrade` するか、`:stable` に Quadlet ユニットを進めさせてください。データベースには何も変わりがないので、1.0.2 に戻しても安全です。ロールバックで元に戻せないのは、エージェントがすでに行ったことです。その変更は残り、書き込まれた監査の行は、アクタータイプ `mcp` としてログに残ります。更新の前にバックアップを取る習慣は、これからも有効です。
