HotLoop Flow 2.7.0 は FlowLab の最初のカットで、試験装置やデータロガー向けにタブを実行する第二の方法です。フローはこれまでとまったく同じように動き、今お持ちのフローファイルはバイト単位でそのまま読み込み、保存されます。FlowLab はタブを追加したときにだけ起動するので、追加しなければ、あなたに起きる変化は下の最後の項目のセッションの修正だけです。

## 新機能

**FlowLab ダイアグラム。** ダイアグラムは、接続されたすべての入力に値が入ると各ノードが 1 回実行され、互いにワイヤーのない 2 つのノードが同時に実行されるタブです。サブフローのボタンの隣にある新しい FlowLab ボタンで追加します。キャンバスの上に実行と停止のバーが付き、描かれるものはすべてワイヤー上にあります。実行後の各ワイヤーの最後の値、最後の 100 個の値を保持する任意のワイヤー上のプローブ、ノードまたはワイヤーのブレークポイントです。一時停止、ステップイン、ステップオーバー、ステップアウトはノード単位で動き、実行のハイライトは追えるだけ実行を遅くして、10 分後に自動的にオフになります。デバッグのどれも実行の動作を変えず、プローブを付けた実行が、付けない実行と全ワイヤーで同じ値で終わることをテストが確認します。

**入っているもの。** 1 回の反復から次へ値を持ち越す while と for のループ、回数や配列に対する for ループ、そしてエラーワイヤー。エラーを受け取ったノードは何もせずそれを渡し、ループにつながれたエラーは、ループのエラー出力に出どころとコードを付けてループを止めます。`after` ワイヤーは、データを共有しない 2 つのノードの順序を決めます。パレットの新しい FlowLab セクションにはノードの種類が 21 あります。定数、算術、比較、論理、待機、バンドル、フィールド、配列の作成、2 つのループとその本体の入力と出力、読み書きができるシリアルポート、読み取り値のパーサー、安定値の検出器、テキストファイルへのログ、そしてパネル用のコントロール、インジケーター、チャートです。docs/diagrams.md にそれぞれの説明があります。

**オペレーターが携帯電話で開けるパネル。** `/panel/<diagram id>` はエディタと同じ方法でサインインし、実行中のダイアグラムのコントロール、インジケーター、チャートを表示します。チャートは変更しない限り最後の 1,024 点を保持し、手放した数を数えます。コントロールはサーバー側で種類、範囲、選択肢に照らして検証され、誰が設定したかは監査ログに残ります。

**ケーブルを抜いても生き残るシリアルポート。** 何も受け取れなかった読み取りや、消えたポートは、エラーワイヤー上の障害になります。次の読み取りは 1 秒に 1 回ポートを開き直そうとし、喪失と復帰を数えます。`examples/diagram-scale-logger` の例は、はかりを読み、重さと単位を解析し、直近 5 回の読み取りが一致したことを知らせ、トレンドチャートとともにすべてをパネルに表示し、CSV ファイルに追記します。タブに `autostart` を設定すると、ブラウザを開かなくても実行され、デプロイのたびに再び実行されます。

**新しい API。** `GET /diagrams`、`GET /diagrams/{id}`、`run`、`stop`、`debug` 用の `POST`、`controls/{node}`、`breakpoints`、`probes` 用の `PUT`。読み取りには `status.read` が必要です。実行、停止、コントロールの設定、デバッグには新しい権限 `diagram.run` が必要で、それぞれ誰が行ったかとともに監査ログに残ります。

**読み取りに失敗してもセッションは上書きされません。** 存在するのに読めないセッションファイル、I/O エラー、遅れて立ち上がったボリュームは、次のサインインで置き換えられなくなり、JSON が読めないファイルは失われずに元のファイルの隣に保管されます。

## 変更点

- `ew_diagram` を持つタブは、メッセージランタイムから除外されます。ほかのタブはこれまでどおり実行されます。新しいキーはタブの `ew_diagram` とノードの `ew_in` で、どちらも往復で保たれ、新しいテスト 2 つと既存のテスト 1 つがそれを確認します。
- README はノードタイプ 79 と「約 36,000 行の Go」と書いていましたが、どちらも古くなっていました。今はメッセージ用に 79、FlowLab 用に 21 のノードタイプと書いてあります。
- HotLoop MCP クライアントノードのテストは、HotLoop が MCP の書き込みをオンにして出荷されるため、HotLoop のゲートを通して書き込むようになりました。
- デプロイは、変更していないものも含め、すべてのダイアグラムの実行を再起動します。
- FlowLab はバイナリを約 370 KB 増やしました。1 台のマシンで前後を測った値です。バイナリは 41.4 MB、amd64 のイメージは 45.34 MB です。
- README の画像は、新しいボタンと新しいパレットのセクションに合わせて撮り直しました。

## 新しい設定

ありません。権限 `diagram.run` は新しいものです。権限リストが `["*"]` のユーザーは持っています。明示的なリストを持つユーザーは、`status.read` でダイアグラムとそのパネルを読めますが、`diagram.run` を追加するまで実行はできません。

## アップグレード

amd64 では 2.7.0 のイメージとチャートへの単純な `helm upgrade` を、arm64 では 2.7.1 まで今の状態のままにするか、Quadlet ユニットの新しいタグを使ってください。初回起動で起きることはなく、移行するものもなく、フロー、デプロイの記録、認証情報には手を触れません。ダイアグラムを含むフローファイルを保存した後にロールバックすると、古いビルドはファイルをバイト単位で保持し、FlowLab の各ノードについて `unknown node type` と表示し、それらのノードは実行されません。このビルドの 1 つ前のビルドで確認しました。

イメージ: `ghcr.io/hotloop-io/hotloop-flow:2.7.0`、linux/amd64 のみ。まず amd64 をビルドして本番で安定と確認され、その後、ほかに何も含まない小さな 2.7.1 が arm64 を加えます。それまでは `2` タグが新しい amd64 イメージと 2.6.0 の arm64 イメージを持つので、`2` または `2.6` を追っている arm64 のマシンは今あるものをそのまま保ち、`2.7.0` に固定されたマシンには amd64 が必要です。チャート: `https://hotloop.io/hotloop-flow/`。このタグの README に、画像付きで残りがあります: https://github.com/HotLoop-io/hotloop-flow/blob/v2.7.0/README.md
