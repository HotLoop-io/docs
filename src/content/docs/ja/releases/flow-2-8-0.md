HotLoop Flow 2.8.0は、試験台やデータロガー向けのダイアグラムタブであるFlowLabに、4つの機能を加えます。分析ノード、NIハードウェア向けのデータ収集ノード、ブローカーが取りこぼしたものを保持するMQTT出力、そしてTDMSログです。フローはこれまでとまったく同じに動き、今お持ちのフローファイルはバイト単位で同じように読み込まれ、保存され、ダイアグラムではないタブにはこれらは何も見えません。

## 新機能

**解析。** 4 つのノードが読み取り値の配列を扱います。統計(平均、RMS、最小、最大、標準偏差)、積分(台形則による配列の下の面積を、1 つの数値または累積面積として)、微分(各サンプルでの傾き)、そしてローパス、ハイパス、バンドパス、バンドストップとして使える次数 1 から 10 のバターワースフィルタで、カットオフ周波数はヘルツで指定します。

**データ収集ノード。** `read DAQ task` は、NI の gRPC Device Server 経由で、CompactDAQ シャーシなどの NI ハードウェアからサンプルを読みます。クライアントはできる限り小さくしてあります。手書きのメッセージを Go 自身の HTTP/2 で送るので、バイナリに gRPC ライブラリは入りませんでした。

**何も失わないMQTT出力。** `mqtt out`は、フローファイルで設定されたブローカーを通して発行します。MQTTノードが使うのと同じ接続です。永続に設定すると、ブローカーが取りこぼしたメッセージはノードが終わる前にディスクへ書き込まれ、ブローカーが戻ると古いものから順に送られます。再起動をまたいでも同じです。先に待っているものを追い越すものはありません。送信済みの出力は、メッセージがすぐに出ていったかどうかを伝えます。

**TDMS ログ。** `log to TDMS file` は、フィールドごとに 1 チャネルで TDMS ファイルにレコードを追記し、ファイルは研究室がすでに持っているツールで開けます。最後の書き込みが停電で途切れたファイルも、最後の完全な値までは読めます。

## 変更点

- パレットのFlowLabセクションのノードタイプは21から28に増え、READMEにもそう書かれています。
- 2.7.1の実行で一度失敗したステップは何も出力しませんでした。原因は、コレクターのテストが、読み取るログに区間の全体が入る前にその区間を比較していたことでした。今は区間の全体を待ちます。ほかの2つのテストも、確認する対象を待つようにしました。これらはいずれも出荷物には含まれません。
- READMEの画像を撮り直し、上部のバーにv2.8.0と表示されるようにしました。
- READMEのバイナリとイメージのサイズを、このリリースに合わせて読み直しました。

## 新しい設定

ありません。

## アップグレード

amd64では、イメージとチャートの2.8.0への`helm upgrade`を1回実行するか、Quadletユニットのタグを新しいものにします。arm64では、このリリースにarm64を加えただけの2.8.1が出るまで、そのままにしてください。初回起動では何も起こらず、移行するものもありません。

イメージ: `ghcr.io/hotloop-io/hotloop-flow:2.8.0`、linux/amd64 のみ。まず amd64 をビルドして本番で安定と確認され、その後、ほかに何も含まない小さな 2.8.1 が arm64 を加えます。それまでは `2` タグが新しい amd64 イメージと 2.7.1 の arm64 イメージを持つので、`2` または `2.7` を追っている arm64 のマシンは今あるものをそのまま保ち、`2.8.0` に固定されたマシンには amd64 が必要です。チャート: `https://hotloop.io/hotloop-flow/`。このタグの README に、画像付きで残りがあります: https://github.com/HotLoop-io/hotloop-flow/blob/v2.8.0/README.md
