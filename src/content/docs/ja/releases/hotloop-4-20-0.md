新しい Web UI が `/` の画面になり、エージェントは MCP で読めるものをすべて変更できます。マイグレーションはなく、通常の `helm upgrade` か Quadlet の自動更新で取り込まれます。前のリリースの [4.19.11](/ja/releases/hotloop-4-19-11/) は、既定の画面が旧画面だった最後のリリースです。

このビルドは amd64 のみで、次のリリースは、2 回に分けて進める方式のとおり、arm イメージをビルドする小さなバージョンアップです。それまでの間、`stable` は持っている arm イメージをそのまま保ちます。

## 変更点

- **新しい Web UI が既定になり、旧 UI はなくなりました。** すべての画面を静的ページ(Astro と一部 Svelte)として作り直し、1 つのバイナリに埋め込みました。ボックスに Node も CDN も要りません。4.19.x では `/next` にありました。`/` では、viewer、operator、管理者に対して、同じ 19 の画面が、同じコントロール、フィールド、列、フォーム、言葉で表示されます。意図的に違って見えるのは次の点です。
  - 色は、サイト、Flow、Cascade と同じ HotLoop の暖かい地色とオレンジで、マークは公式のものです。
  - 画面は、デスク上のレールで Operate、Plant、Build、System にまとめられています。スマートフォンでは 5 つのバー(Board、Alarms、Dashboards、Entities、More)があり、More がすべての画面を開きます。
  - テーマの操作は、以前は月のアイコンでしたが、Dark または Light と表示されます。
  - インストールしたアプリのアイコン、テーマカラー、スプラッシュの色が新しい見た目に合わせられます。
  - ドロワーはスクロールバーの分の余白を確保するため、中のカードは履歴が読み込まれても動きません。
- **HotLoop に届かないときのサインインは理由を示し、自分で復旧します。** サインインしたことがない、またはサインアウトしたスマートフォンが、接続なしでページを開くと、ここからは HotLoop が応答しないという一文つきのサインイン画面が表示されます。ページは 3 秒ごとに再確認し、接続が戻ると触れなくても再読み込みします。以前の動作をそのまま残したものです。
- **MCP は、読めるものをすべて変更できます。** プラントを読んで設備に命令するツールは 27 個でしたが、今は 128 個です。さらに 64 個が設定を変更します。デバイスとタグ、ディスカバリーとブローカー、UniFi ネットワーク、エンティティ、helper、設備とラベル、アラーム、オートメーションと blueprint(エージェントは、これまでプレビューしかできなかった blueprint からのルール作成ができるようになりました)、スクリプト、レシピ、ダッシュボード、そして画面が保存できるそのほかのものです。37 個は管理者自身の機能に届きます。ユーザーと PIN、設定、バックアップ、エスカレーション、historian ターゲット、ブローカーのログイン、edge relay のフリート、レポートです。どれも 2 つ目の実装ではありません。それぞれが REST API のルート 1 つを、そのルート自身のハンドラーで実行するものなので、検証、権限チェック、ランタイムの再読み込み、監査の行はそのルートのもので、エージェントが操作主体として記録されます。
- **変更の前に立ちはだかるもの。** スイッチ `HOTLOOP_ALLOW_MCP_WRITES`(既定でオン)がオンで、`HOTLOOP_MCP_OIDC_WRITE_ROLE` を設定している場合の呼び出し元はそのロールを持っている必要があります。呼び出しには、そのルートが求めるちょうど 1 つの権限(`devices.write`、`alarms.write`、`users.manage`、`settings.write` など)が必要で、なければルート自身の言葉で拒否されます。すべての変更に必須の `reason` があり、システムログにルート自身の行と並んで `config` の行として記録されます。設備への命令は引き続き `write_tag`、`call_service`、`run_script`、`apply_recipe`、`trigger_automation` で、`HOTLOOP_ALLOW_WRITES`、タグの書き込み可マーク、その範囲の後ろにあります。タグ、ルール、レシピを書き込み可能にするのは設定であり、使われるまでは何も命令しません。そのときに命令するものは、同じゲートに当たります。2 つの書き込みスイッチにはルートがないので、Settings 画面と同じく `save_settings` はエージェントにはこれを拒否し、エージェントは自分の書き込みが待っているスイッチをオンにできません。ユーザーのパスワードは API と同じように呼び出しを通り、監査の行には決して載りません。ツールは `--mcp-stdio` でも使えます。すべてのツールとそのルートと権限は [MCP](/ja/iot/mcp/#構成の変更) にあります。

## API の変更

- `GET /next` と `GET /next/` はルートへの `301` になるため、新 UI が旧 UI の隣にあったときに作ったブックマークも到達します。`Location` は相対なので、ベースパスの下でも正しく動きます。
- `GET /static/` はなくなり、`GET /next/manifest.webmanifest` もなくなりました。ページ、そのファイル、アイコン、`/manifest.webmanifest`、`/sw.js` は以前どおりルートから配信され、旧スタイルシートとスクリプトはどこからもリンクされておらず配信されません。
- `HOTLOOP_UI` はもう読まれません。設定しても何も起きません。
- ほかのルートは変わっていません。MCP のツールは REST のルートではなく、新しい面です。

## 4.19.11 からのアップグレード

通常の `helm upgrade`、または Quadlet の自動更新です。マイグレーションも設定するものもありません。最初の読み込みで新しいページを取得し、service worker が古いキャッシュを置き換えるため、アプリをインストール済みのスマートフォンは、次に開いたときに新しい画面を表示します。アップグレードで元に戻せなくなるものはなく、データベースには何も変わっていないため、4.19.11 へのロールバックは安全です。

## 既知の問題

- 新しいものはありません。[ロードマップ](/ja/roadmap/)の Broken or missing の下にまだ残っているのは、OPC UA の X.509 ユーザートークン、当社の OPC UA サーバーが提供する非推奨の `Basic128Rsa15` と `Basic256` ポリシーと 64 バイトを超えるパスワード(どちらもライブラリのもの)、そして実機に対する S7comm と EtherNet/IP の無応答デバイステストです。
