最初のリリースです。SysSocket の UDP 上で Structured Text で書かれた CODESYS ライブラリで、PLC の値を OPC UA PubSub(パート 14、UADP)としてネットワークに送り出します。ライブラリを追加し、ファンクションブロックを 1 つ宣言し、送り出したい変数を追加して、サイクルごとに 1 回呼び出すだけです。OPC UA PubSub を購読するものなら何でも読め、4.19.4 以降は HotLoop core も読めます。

これが意味すること:PubSub ライブラリのない PLC でも、約 15 行の Structured Text で PubSub 購読側に値を渡せ、コントローラにほかのものをインストールする必要はありません。

## 内容

* ブロックは 1 つ、`HLTX.FB_HLTX_Publisher`。公開間隔ごとに NetworkMessage 1 つ、DataSetMessage 1 つ、Data Key Frame 1 つで、すべてのメッセージがすべてのフィールドを持ちます。
* パブリッシャーごとに選べる Variant と RawData のフィールドエンコーディング。Variant は自分の型を持ちます。RawData は何も持たないので、受信側にレイアウトを伝える必要があり、[ワイヤーフォーマットのページ](/ja/transmitter/wire-format/)にバイト単位で書いてあります。
* BOOL、SINT、USINT、INT、UINT、DINT、UDINT、LINT、ULINT、REAL、LREAL、STRING、TIME のフィールドと、STRING を除くそれらの配列を、1 メッセージあたり最大 128 フィールド、1472 バイトまで扱えます。メッセージが分割されることはありません。
* ユニキャストまたはマルチキャスト。入力はパブリッシャー ID、ライターグループ ID、データセットライター ID、公開間隔、グループバージョン、構成バージョンです。
* ノンブロッキング送信。誤ったアドレス、死んだソケット、大きすぎるフィールド一覧は、ブロックを読み取れるエラー状態にするだけで、アプリケーションをフォールトさせることはありません。

## 実行したことと結果

すべて CODESYS Control for Linux SL 4.22.0.0 上で、下記のファイルを使って実行しました。

* ライブラリは CODESYS 3.5.22.30 でエラー 0、警告 0 でビルドできます。サンプルアプリケーションもこれに対してエラー 0、警告 0 でビルドできます。
* パブリッシャー 2 つ、Variant と RawData が 1 つずつで、それぞれ 17 フィールド。ネットワーク上のすべての値が、PLC が自身の OPC UA サーバーで報告する値と一致し、シーケンス番号に欠けはありません。
* 独立した PubSub スタックが、Variant メッセージの全体と RawData のスカラーをデコードします。RawData の配列と長い RawData 文字列はまったく読めませんが、これはライブラリではなくそのスタックの限界です。
* HotLoop core のサブスクライバー(この実行時は main ブランチ、そして HotLoop core 4.19.4 以降のすべてのリリース)は、文字列、TIME、2 つの配列、読み取りの間に動く 2 つのカウンターを含め、両方のパブリッシャーを読み、拒否するものはありません。
* 2 つ目のデコーダーが、キャプチャした 222 個のデータグラムをすべて読みます。
* 20 ms タスク、パブリッシャー 2 つでのコスト:1 サイクルあたり平均約 10.6 us の追加。送信するサイクルは 10 から 100 us かかります。ばらつきの原因は `sendto` 呼び出しで、混み合った共有ホストでは 12 000 サイクルに 1 回 14.3 ms に達しました。制御ロジックに影響する場合は、パブリッシャーを優先度の低い専用タスクに置いてください。[タイミングのページ](/ja/transmitter/timing/)に表があります。

## コントローラーで確認すること

* ビッグエンディアンのターゲット向けのバイト順の処理は書かれていますので、お使いのコントローラーで確認してください。
* マルチキャスト:ブロックはグループの TTL、ループバック、送信インターフェースを設定しますので、お使いのネットワークでグループを確認してください。
* ネットワークが消えたりアドレスがなかったりすると、ブロックは失敗を数えて再試行の間隔を空け、プログラムはスキャンを続けます。
* デモモードでは、CODESYS の説明どおり、2 時間の枠が終わるとランタイムが停止します。

## このリリースに含まれないもの

DataSetMessage と NetworkMessage のタイムスタンプ、KeepAlive と Delta Frame、1 つの NetworkMessage に複数の DataSetMessage、WSTRING、フィールドごとのステータス、メッセージのセキュリティ、サブスクライバー側。次に来るものは[ロードマップ](/ja/transmitter/roadmap/)に書いてあります。

## 別のパブリッシャーから移る場合

タイムスタンプ、KeepAlive、Delta Frame を求める受信側は、このバージョンでは満足しません。どれも送らないからです。すべてのメッセージが Key Frame で、どの受信側も事前知識なしで読めます。ここでの RawData 配列は、Int32 の長さ、要素、宣言したサイズまでのゼロ詰めで、これは OPC Foundation のリファレンススタックの書き方です。長さなしで要素が連続した配列を期待する受信側には、フィールドが別々のスカラーであることを伝える必要があります。

## すでに使っているプロジェクトの場合

以前のバージョンはありません。ワイヤーフォーマットは `udiConfigMajor` が変わるときだけ変わり、このライブラリバージョンに固定した PLC プロジェクトは同じフィールドと同じバイトを保ちます。
