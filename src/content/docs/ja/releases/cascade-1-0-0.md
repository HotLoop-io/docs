## 概要

1.0.0 は、ID とガバナンスの取り組みと新しいエディターを 1 つにまとめたリリースです。0.1.2 の機能はすべてそのまま残り、これまでどおり動きます。エンジン、コネクター、インポーター、Helm チャート、Quadlet ユニット、ワークフローのファイル形式です。変わったのは、プラントがインスタンスでできることと、その見た目です。

1.0.0 と呼ぶのは、この番号に私たちの名前を載せる前に欲しかった最後のピースがエディターだったからです。すべての画面は実際の API に対して動き、以下のすべての機能は、代用品ではなく実際に接続するサーバーで試しました。

## 新しいエディター

Astro と Svelte アイランドで作り直し、HotLoop 独自の色と書体を使い、自分で選ぶまではシステムのライトまたはダークに従います。引き続きバイナリに組み込まれ、どこからも何も取得しないので、インターネットのないマシンでもあるマシンと同じように動きます。以前のエディターの画面はすべてそのままあり、キャンバスも含めて同じ働きをします。コードは書き直さずに移し、抜けがないよう、前後ですべての画面、ボタン、フィールド、API 呼び出しを数えました。

保存していた URL はそのまま使えます。`#/w/<id>`、`#/x/<id>`、`#/executions` とデバッグ用リンクは同じ画面を開き、`/app/main.js` と `/app/main.css` も引き続き応答します。

## 新機能

Keycloak で試した SAML(署名付きレスポンスのみ)。OpenLDAP と Samba ドメインコントローラーで試した LDAP と Active Directory(グループからロールを付与)。scim2-tester で試した SCIM。プロバイダーが画面に触れずにアカウントを作成、無効化できます。プロジェクトの権限から作るカスタムロール。OpenBao または HashiCorp Vault の外部シークレット。認証情報のパスワードはストアにあり、そこでローテーションされます。監査ログと完了した実行を syslog(TCP、UDP、TLS)と OTLP へ送るログストリーミング。実際の syslog サーバーと Loki で試しました。変数、フォルダー、インサイト、実行へのアノテーション、マスキングポリシー、S3 と Azure の Blob ストア。Garage と Azurite で試しました。

エディターには、それぞれ専用の画面があります。変数、インサイト、そして設定の下にある、ロール、マスキング、外部シークレット、ログストリーミング、サインインと SCIM です。各ユーザーにはロールが許可するものだけが表示され、それ以外はサーバーが引き続き拒否します。

## EmberOps ステップはなくなりました

EmberOps コネクターを外しました。9 つのステップ(`erpnext.trigger`、`getList`、`getDoc`、`create`、`update`、`delete`、`submit`、`cancel`、`call`)、「EmberOps のドキュメントが作成または変更されたとき」トリガー、EmberOps の認証情報タイプ、それらを提供していた画面とドキュメントは 1.0.0 にありません。EmberOps に接続する必要がある場合は、HTTP ステップが認証情報を使ってその REST API を呼び出せます。これは今日から動きます。

これらのステップを含めて保存したワークフローは、破棄されることも、黙って変更されることもありません。検証に失敗して開始されず、メッセージにはステップ名と、EmberOps ステップが 1.0.0 で削除されたことが表示されます。ステップを削除するか HTTP ステップに置き換えれば、再び動きます。EmberOps タイプの認証情報は未使用のまま一覧に残り、削除できます。インポーターは EmberOps ノードを持ち込まなくなりました。対応するステップがないノードと同様に、無効の状態で、設定はそのノートに入って取り込まれます。

## 0.1.2 からのアップグレード

1.0.0 へ `helm upgrade` するか、`:stable` に Quadlet ユニットを進めさせてください。アップグレード中に 8 つのマイグレーション(0018 から 0025)が実行されます。ロール、変数、フォルダー、アノテーション、マスキングポリシー、SCIM、シークレットプロバイダー、ログの送信先のテーブルを作成し、ワークフローが入っているフォルダーの列を 1 つ追加します。既存のデータには触れないので、ワークフロー、認証情報、実行はそのままで、キーでも引き続き開けます。SAML、LDAP、SCIM、Blob ストアは、`HOTLOOP_CASCADE_*` 設定を行うまでオフです。設定は `docs/IDENTITY.md` と `docs/GOVERNANCE.md` にあります。どれも設定しないインスタンスでは何も変わりません。ただし、ワークフローが EmberOps ステップを使っている場合は別です(上記参照)。

## 知っておくこと

マイグレーションは前にしか進みません。ロールバックは古いイメージを戻すだけで、データベースのマイグレーションは元に戻りません。更新の前にバックアップを取り、それを戻る手段としてください。これらのマイグレーションは既存のものを変更も削除もしませんが、古いイメージを新しいスキーマで動かしてはいないため、保証はしません。

外部シークレットには許可するパスが必要です。パスのないプロバイダーは、意図的に拒否されます。ストアのトークンは通常、認証情報を編集する人が指定できる範囲よりはるかに多くを読めるためです。

SCIM はインスタンスの所有者をプロバイダーに見せることはなく、プロバイダーからの DELETE はアカウントを消さずに無効にして非表示にします。そのため、プロバイダーがサインインできる最後の 1 人を削除することはできません。再作成すると同じアカウントが戻ります。

変数はシークレットではありません。プロジェクトを読める人はその変数を読め、値は実行データ内でも伏せられません。パスワードは認証情報か外部ストアに入れてください。
