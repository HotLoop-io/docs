HotLoop Flow 2.6.0 は、耐久ワイヤーが配信をやめたことを知らせる手段を提供します。フローの動き方は何も変わりません。プラントのラインで耐久ワイヤーを使っているなら、以前は静かなキューのように見えていた唯一の障害に対して、アラートを設定できるカウンターが手に入ります。

## 新機能

**詰まった耐久ワイヤーを数え、説明します。** 耐久ワイヤーのポンプは、ワイヤーがメッセージが待っていると言っているのに、キューに読めるものがなく、短い再確認の後もその状態が続いている場合に気づくようになりました。`hotloop_flow_durable_wire_stranded_total{wire=...}` に 1 を加え、障害の種類ごとに 1 回、ランタイムログに警告を 1 つ書き、そのテーブルの中身と並べてワイヤーのカウンターを記します。ポンプがどこまで進んだか、深さ、ディスク上の行、処理中のもの、追加、配信、破棄の数です。正常なワイヤーではカウンターは 0 のままなので、0 を超える値はアラートに値します。

これを加えたのは、最も古いものを捨てるワイヤーが数千回のテスト実行に 1 回、うまく空にならず、その理由を捕まえられなかったからです。このリリースは修正ではなく計測器です。お使いのラインで作動したときは、そのログの 1 行が私たちの必要とするものです。

## 変更点

- イメージに同梱されるライセンス文面は、EmberNet を正本と同じ綴りで書きます。3 行で、綴りだけです。
- README の画像は、ライト、ダークの順の通常の画像なので、docs.hotloop.io でも表示されます。

## 新しい設定

ありません。メトリクスはオンで、スイッチはありません。

## アップグレード

2.6.0 のイメージとチャートへの単純な `helm upgrade`、または Quadlet ユニットの新しいタグです。初回起動で起きることはなく、移行するものもなく、フロー、デプロイの記録、認証情報には手を触れません。

イメージ: `ghcr.io/hotloop-io/hotloop-flow:2.6.0`、linux/amd64およびlinux/arm64。Chart: `https://hotloop.io/hotloop-flow/`。このタグのREADMEに残りが図つきであります: https://github.com/HotLoop-io/hotloop-flow/blob/v2.6.0/README.md
