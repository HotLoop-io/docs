## 概要

1.5.0 では、所有者がユーザーを削除できます。エンジン、ファイル形式、その他すべての画面は 1.4.2 と同じで、マイグレーションはありません。

## ユーザーの削除

以前は、アカウントを取り除く方法は無効にすることだけで、アカウントは一覧に残り続けました。今は、ユーザー画面に無効にするの隣に削除ボタンがあり、所有者には自分以外の全員に対して表示され、何かを行う前に確認を求めます。同じ呼び出しは REST API の `DELETE /api/v1/users/{user}` と、MCP サーバーの `delete_user` にもあり、規則も同じです。インスタンスの所有者のみ、自分自身のアカウントは不可、最後の所有者も不可です。

アカウント、そのセッション、パスキー、サインイン ID、API キーはすぐに消えるので、その人としてまだサインインしているものは、次のリクエストで動かなくなります。監査ログには、誰が誰を削除したかが、メール、ロール、消えたセッションとキーの数とともに記録され、そのチェーンは引き続き検証できます。

その人の作業は残ります。個人プロジェクトは、その人の名前の後ろに「(removed)」が付いた共有プロジェクトになり、あったすべてのワークフロー、認証情報、実行を保持します。所有者と管理者は、そのどれでも別のプロジェクトに移したり、誰かに渡したりできます。同じメールアドレスは後で新しいアカウントの作成に使え、新しいアカウントは自分のプロジェクトから始まります。

無効にするは変わらず、アカウントを残したいときに適した選択です。ID プロバイダーが SCIM で削除した人は、削除ではなく、これまでどおり無効化されて非表示になります。

## 元に戻す

マイグレーションはないので、以前のイメージは同じデータで動きます。削除したアカウントは戻りません。必要な場合は、削除の前に取ったバックアップを復元してください。

## amd64 のみの理由

このリリースは amd64 のみをビルドします。マルチアーキテクチャは別の実行で出すため、この次のリリースは、両方をビルドする小さなバージョンアップになります。`stable`、`latest`、`1.5`、`1` は、すでに指していた arm64 イメージと並んで、新しい amd64 イメージを載せます。
