HotLoop Flow 2.16.8 は、Node-RED から持ち込んだフローがそちらと同じように動くようにし、1 つの変わった値でプラントの Flow が落ちることが決してないようにします。フロー、設定、チャートに変更はありません。

## 変更点

- **自分自身を含む値で Flow が止まらなくなりました。** Node-RED では、change ノードがリストを自分自身の中に書き込めます。たとえば `msg.payload[0]` を `msg.payload` に設定しても、そのまま続行します。Flow はそのループをスタックが尽きてプロセス全体が終了するまで追っていました。今は、ループが自分自身に戻るところで断ち切られ、そのノードがほかのノードエラーと同じように「値が自分自身を参照しています」と報告し、ほかのすべてのフローは動き続けます。そのような値を返す、送る、設定する function ノードにも同じ保護が働きます。実際のプラントのフロー、Modbus シミュレーターに応答する 13,737 ノードで再現しました。古いビルドは 1 分以内に落ち、今回のビルドは動き続けました。
- **function ノードが現代の JavaScript を話します。** `await`、本体が返す promise、解決するまで最初のメッセージを保持する Setup の promise、`node.linkcall` がすべて動くので、Node-RED 4 向けに書かれた関数が書かれたとおりに動きます。どの Catch ノードにも拾われないエラーは、Node-RED と同じく未処理としてマークされます。
- **Node-RED 自身のサンプルフローが Node-RED の出力を返します。** 記録された 62 のサンプルすべてが、本物の Node-RED が出したものと一致します。このリリースでは、switch が書き込む部品の数、csv ノードが行に付ける型、csv の `msg.columns` と `msg.reset`、delay が保持しているメッセージのリセットとフラッシュを修正しています。
- **FlowLab が LabVIEW の VI のブロックダイアグラムを読みます。** ノード、ワイヤー、定数、コントロール、インジケーター、構造の本体が移り、FlowLab に対応するものがないものは、名前付きのノードとして見える形で残るので、ダイアグラムがどこで止まるかが分かります。
- **大きくなりましたが、引き続き自己完結したバイナリ。** Flow はエディタを内蔵した 1 つの静的バイナリのままです。上記すべてを収めるため、58 MiB まで大きくなることが許されました。

## 新しい設定

ありません。

## アップグレード

2.16.8 のイメージとチャートへの単純な `helm upgrade`、または Quadlet ユニットの新しいタグです。初回起動で起きることはなく、移行も不要です。フローファイルは以前どおりバイト単位で読み込み、保存されます。このリリースは amd64 のイメージをビルドします。`2.16` と `2` のタグは、2.16.1 からすでに持っている arm64 のイメージをそのまま保ち、ほかに何も含まない小さな後続リリースが arm64 を戻します。arm64 の場合は、それまで 2.16.1 にとどまってください。

イメージ: `ghcr.io/hotloop-io/hotloop-flow:2.16.8`、linux/amd64。Chart: `https://hotloop.io/hotloop-flow/`。このタグのREADMEに残りが図つきであります: https://github.com/HotLoop-io/hotloop-flow/blob/v2.16.8/README.md
