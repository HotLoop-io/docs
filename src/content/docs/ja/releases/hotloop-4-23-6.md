ロードマップの Protect、Access、電源ボックスの項目にコードが入り、Shelly デバイスが Shelly と直接話し、OPC UA PubSub にメッセージセキュリティとメタデータが加わります。amd64 のみでビルドされています。マルチアーキテクチャビルドは次のバージョンで続きます。

## 変更点

- **UniFi Protect、デバイスとして。** プロトコル `unifi-protect`。コンソールの Integrations ページの API キーを使い、コンソールのパスワードと同様に封印し、証明書をピン留めします。カメラ、センサー、ライト、サイレンは、自分で加わるタグです。カメラの動きとスマート検知(人、車両、荷物、ナンバープレート、顔、動物)はイベントの websocket から来て、切断されている間は「動きなし」ではなく不良と読まれます。サイレンは鳴らすように有効にでき、`alarm.<trigger>.fire` はアラームマネージャーの webhook を送るので、HotLoop のアラームでカメラが録画します。カメラのスナップショットは 1 つのルートです。すべてのイベントが logbook にあります。[UniFi Network](/ja/iot/unifi/#unifi-protect)をご覧ください。
- **UniFi Access、デバイスとして。** プロトコル `unifi-access`。API トークンを使います。各ドアの位置と施錠はタグで、通知の websocket が最新に保ち、すべての変更が logbook にあります。解錠は、人が有効にする書き込みで、書き込みゲートを通り、監査されます。[UniFi Network](/ja/iot/unifi/#unifi-access)をご覧ください。
- **SmartPower PDU のアウトレット。** アウトレットのリレー、電力、電流、電圧、力率は UniFi Network デバイスのタグで、PDU の総消費量も 1 つです。アウトレットの `on` に書き込むとそれがオンになり、ほかのすべてのアウトレットの名前は保たれます。`cycle` はオフにし、待ち、再びオンにし、15 分に 1 回までで、常にオンで終わります。[UniFi Network](/ja/iot/unifi/#smartpower-pduのコンセント)をご覧ください。
- **Shelly デバイス。** プロトコル `shelly`:デバイス自身の digest ログインを使う Gen2 以降の RPC、報告するすべてのコンポーネントのタグ、スイッチ、ライト、カバー、サーモスタットへの書き込みです。Gen1 は MQTT に案内するメッセージとともに拒否されます。
- DataSetMetaData とディスカバリーの応答は、大きいときはチャンクに分け、Siemens のパブリッシャーのキャプチャしたメッセージから読み取りました。パブリッシャーは既定で 10 区間ごとにメタデータを通知します(`HOTLOOP_UADP_PUBLISH_METADATA_EVERY`、0 でオフ)。[プロトコルとドライバー](/ja/iot/protocols/)をご覧ください。
- **転送キューのドレイナーは再び確認し、失敗したときはそう伝えます。** 読み取り値が待っているのに何も送らなかったパスは、静かなポーリングが決して送らない合図を待ち、失敗したパスはログに 1 行もなく 30 秒後退していました。
- **テストは待っているものを待ちます。** 6 つのエネルギーテストが、固定の sleep の代わりに装置の読み取り値を待ちます。

- **応答しない Modbus デバイスはすべてのポイントが不良と読まれます。** シリアル回線では、タイムアウトしたリクエストがポーリングの期限をすべて使っていたため、最初のブロックだけが不良になり、それ以降のポイントは、ケーブルが抜かれている間、最後の正常値を保っていました。今は、何も応答しないデバイスは、同じポーリングですべてのポイントを不良にします。[プロトコルとドライバー](/ja/iot/protocols/)をご覧ください。
- **完成した機能はオンで出荷されます。** Helm チャートとバイナリで:組み込みの MQTT ブローカー(ログインは HotLoop で作ります)、OPC UA サーバー(認証オン、Settings が管理者に見せる生成済みの `opcua-reader` ログインつき)、スケジュールされたレポート、毎日のローカルバックアップ(24 時間ごと、5 Gi のボリューム)、ServiceMonitor(Prometheus オペレーターの CRD がある場所でだけレンダリングされるので、ないクラスターは以前どおりインストールされます)、ホスト名のない Ingress(`ingress.hosts[0].host` を設定するまで、クラスが扱うどのホストにも応答します)です。レポート、バックアップ、OPC UA の証明書、edge キューは、既定で HotLoop のデータディレクトリの下の書き込み可能なディレクトリを使い、ほかのサービスがすでに握っているポートはアイドルのままになってその旨を伝えます。チャート `hotloop` と、生成された IoT と Edge のチャートに入っています。
- **アラームのチャネルと edge パブリッシャーはオンで、宛先を待ちます。** webhook、メール、ntfy、Gotify、Discord webhook、Discord ボットのチャネルと `edgePublish` は、最初の起動からオンです。送り先のないものは、インストールも起動も止めなくなり、待って、そう伝えます。管理者は Settings の「Where alarms and readings go」で各宛先を入力し、そこに保存されたものがチャートの値より優先されます。アラームのチャネルは保存時に適用され、edge パブリッシャーの宛先は次の再起動で適用されます。Settings には、エンドポイントと生成されたログインを示す OPC UA サーバーのカードもあります。
- **Kafka ターゲットは、ブローカーが新しい topic を配置するのを待ちます。** 忙しいホストが一瞬フェンスした単独のブローカーは、最初の確認を `INVALID_REPLICATION_FACTOR` で失敗させていましたが、ターゲットは今は、自身の時間が尽きるまで待ち、ブローカーが答えたことを伝えます。
- **転送キューのドレイナーは再び確認し、失敗したときはそう伝えます。** 読み取り値が待っているのに何も送らなかったパスは、静かなポーリングが決して送らない合図を待ち、失敗したパスはログに 1 行もなく 30 秒後退していました。

- **4.23.4 と 4.23.5 から引き継ぎ。** TwinCAT の `.TcVIS` と、cds-text-sync と codescribe の画面が、ボタン、フレーム、ランプ、式のルールとともにインポートされ、UniFi 画面の更新は読み込み中のビューを待ちます。どちらのバージョンも公開されなかったので、両方がここにあります。[4.23.4](/ja/releases/hotloop-4-23-4/)と[4.23.5](/ja/releases/hotloop-4-23-5/)をご覧ください。

## マイグレーション

ありません。

## API の変更

`GET /api/unifi-protect/{id}/cameras/{camera}/snapshot` は、カメラの現在の JPEG を返します。プロトコルの一覧に `unifi-protect` と `unifi-access` があります。[HTTP API](/ja/iot/api/)をご覧ください。

## 4.23.5 からのアップグレード

通常の `helm upgrade` です。マイグレーションも新しい secret もありません。4.23.4 と 4.23.5 はタグが付けられましたが、何かが公開される前にテストジョブでリリースの実行が失敗したため、この前のリリースは 4.23.3 で、これは両方の変更を含みます。上の機能のどれかを設定する values ファイルは今も優先され、1 つを `false` にすると、listener、Service、ボリューム、Ingress はレンダリングされません。

## 検証していないこと

- Protect、Access、PDU のアウトレットは、公開されている API から作り、状態を保持する代役のコンソールで検証しました。どれも実際のコンソールや PDU では動かしていないため、ロードマップのそれぞれのボックスにはチェックを付けていません。
- アラーム通知に添付するスナップショットは実装していません。
- PubSub:Security Key Service は実装しておらず(鍵は静的です)、Siemens、CODESYS、Beckhoff のパブリッシャーをベンチで動かしたことはありません。
- UniFi のポート無効化は、実際の 10.6 コンソールの Web UI からのリクエストを今も待っています。
