8月の 4.3.1 以来、初めて公開されるリリースです。4.4.0 から 4.15.3 まではマージされただけで公開されていないため、4.3.1 を使っている場合は、新しい名前、新しいイメージ、新しいチャート、新しいライセンスのもとで、すべてを一度に受け取ります。**4.3.1 からの移行は、単純な `helm upgrade` では済みません。** 稼働中のプラントに触れる前に、下の「4.3.1 からのアップグレード」を読んでください。

完全なノートは README にあります。4.16.0 の変更点が先にあり、その下に 4.4.0 までのすべてのバージョンが続きます。

## 要点

- **HotLoop Core:エンティティ。** すべてのタグは安定した ID を持つエンティティで、ISA-95 の設備ツリーに置かれます。モーター、バルブ、PID ループなどは、それぞれのタグから作られる複合エンティティで、すべてのアラームもエンティティであり、エンティティへのすべてのコマンドはタグ書き込みと同じ書き込みゲートを通ります。エージェント(MCP)、オートメーション、新しい Entities 画面と Plant 画面がすべてこれを使います。サービス呼び出しは `?dry_run=true` で先に問い合わせることができ、コマンドプロンプトは確定する前に「Would be refused: ...」と教えてくれます。
- **スマートフォンに届く通知:** Acknowledge ボタン付きの ntfy と Discord ボット、Gotify、Discord webhook に対応し、通知が殺到したときはレート制限が 1 件の要約にまとめます。
- **稼働中のプラントで効く修正:** 保留解除(unshelve)で未確認のアラームが消えることがありました。OPC UA サブスクリプションが、セッションは接続済みと表示したまま永久に沈黙することがありました。応答しない Modbus デバイスがダウンと判定されるまで最大 15 分かかっていました。失敗した webhook が URL をログに残していましたが、Discord と ntfy ではその URL がパスワードです。リストアが列を位置で読み込んでいました。再デプロイのたびに OPC UA サーバーの証明書が置き換わり、Ignition が信頼しなくなっていました。Discover tags がすべての OPC UA ノードを float として取り込んでいました。Settings 画面が、何も読まないポーリング変数を挙げていました。
- **Ignition 8.3.9 が OPC UA サーバーを読み取ります。** エンドツーエンドで検証済みで、サーバーは製造元として `HotLoop` を報告するようになりました。
- **Edge Relay が登場します。** 専用のイメージとチャートを備え、Gateway と歩調を合わせます。TimescaleDB 2.30.1 で、拡張機能は自動で更新されるようになりました。

### API の変更

- 空のリストは、ストリームも含めどこでも `null` ではなく `[]` です。
- 有効な読み取り値がない `/api/history` の区間は `null`(欠測)で、不良な読み取り値は平均に含まれません。
- API が分類できないエラーは 400 ではなく、ログ参照付きの 500 です。書き込みや参照でエラーになるデバイスは 502 です。
- アラームエンティティが受け付けないサービス(`alarm.turn_on`)は 400 です。以前は成功と答えて何もしませんでした。
- 保留されていないアラームの保留を解除すると 409 です。
- タグの JSON には必ず `minValue`、`maxValue`、`hasRange` が含まれます。
- 新機能:`POST /api/services/{domain}/{service}` の `?dry_run=true`。`true` か `false` のみで、それ以外は 400 です。

### 4.3.1 からのアップグレード

- イメージは `ghcr.io/hotloop-io/hotloop`(以前は `ghcr.io/embernet-ai/industrial-iot`)、チャートリポジトリは `https://hotloop.io/hotloop`、チャートは `hotloop`(以前は `industrial-iot`)で、すべての `IIOT_` 変数が `HOTLOOP_` になります。
- チャート名はワークロードの selector に含まれており、Kubernetes はその場では変更できません。リリース名と namespace は変えずに、次の手順で進めます。データベースを `pg_dump` する。古い Deployment(`<release>`)と StatefulSet(`<release>-postgresql`)を削除する(データベースのボリュームはそのまま残ります)。`helm upgrade <release> hotloop/hotloop -f your-4.3.1-values.yaml` を実行する。`--reuse-values` は使いません。`extraEnv` の `IIOT_` はすべて名前を変え、`image.repository` の上書きは削除します。新しいデータベース pod が古いボリュームをマウントし、Gateway が起動時にそれを新しい形へ移行します。
- ライセンス:4.3.1 に付属していた条件ではなく、HotLoop 独自のライセンス条件です。家庭とラボでの利用は無料で、企業は EmberNet から無料で登録できます。現在の条件は LICENSE にあります。
- ログインが加わり、書き込みは既定でオフ、タイムゾーンを読み込めない場合は UTC で動かし続けずに起動を止めます。
