オートメーション基盤のフェーズ 2、読み取り専用の UniFi、そして保存されるデバイスパスワードの暗号化です。4.16.0 からなら通常の `helm upgrade` ですが、デバイスのパスワードは初回起動で暗号化され、それ以降は鍵がデータの一部になります。稼働中のプラントに触れる前に、下の「4.16.0 からのアップグレード」を読んでください。

完全なノートは README にあります。4.17.0 の変更点をご覧ください。

## 要点

- **オートメーション基盤、フェーズ 2。** Helper(プラントの人が所有する値で、拒否はしても切り詰めはしません)、logbook(状態変化、書き込み、アラーム、実行、設定を 1 本にまとめたタイムライン)、条件・待機・停止のステップと状態トリガーの `forSec`、スクリプト(CIP サイクルを一度書けばどこからでも実行)、レシピ(ある品種のすべての setpoint が一緒に送られるか、1 つも送られないかで、デバイスから読み戻して確認)、blueprint(一度書いたルールをポンプごとに埋めて使い、誰かがアップグレードを確認するまでそのバージョンに固定)が加わります。MCP のツールは 16 から 25 になります。
- **UniFi Network、読み取り専用。** スイッチ、ポート、PoE、WAN、クライアントをタグとして取り込み、コンソールごとにログインは 1 つ、証明書はピン留めします。応答のない PLC のドロワーには、どのスイッチポートにつながっていてリンクが上がっているかが表示され、OT と指定したネットワークに見知らぬ機器が現れるとアラームが上がります。実機のコンソールで読み取り専用として検証済みです。**まだ検証していないこと:** 監視対象のデバイスで実際にケーブルを抜く場合と、スマートフォンが OT と指定したネットワークに参加する場合です。この 2 つのアラームはテストで検証済みで、誰かがラックで両方を試すまで、ほかでは検証されていません。
- **デバイスのパスワードを暗号化します。** データベースとバックアップの両方で暗号化され、鍵はチャートが `<release>-secret-key` に生成して保持します。
- **4.16.0 のプラントでつまずく可能性があった修正:** チャートまたは Quadlet ユニットの Edge Relay が、プッシュされた設定をすべて無視していました。永続化をオフにした Edge Relay は起動しませんでした。ルールエディターで手動編集すると、ルールの実行バジェットがリセットされていました。コマンドプロンプトの判定で、クリックの直前に Set が動くことがありました。遅れて届いた更新で Entities 画面が過去に戻ることがありました。一度も実行されていないルールが 739887 日前に実行されたと表示していました。App Store のデプロイに tenant が付いていませんでした。

### API の変更

- まだ起きていない時刻は、`0001-01-01T00:00:00Z` として送らず省略します。`lastRun`、`lastPoll`、`lastGood`、`clearedAt`、`ackedAt`、`shelvedUntil`、`raisedAt` などがその対象で、ライブフィードも同じです。
- 新しいルート:`/api/helpers`、`/api/logbook`、`/api/scripts`、`/api/recipes`、`/api/blueprints`、`POST /api/automations/{id}/blueprint-upgrade`、`/api/devices/{id}/network`、`/api/unifi/{id}/...`、`DELETE /api/fleet/{id}/config`。すべて docs/API.md にあります。
- 新しい権限で、operator ロールに付与されています:`helpers.write`、`scripts.run`、`recipes.apply`、`blueprints.apply`。スクリプト、レシピ、blueprint を書けるのは管理者です。
- タグには `deviceClass` が、ルールには `blueprintId`、`blueprintVersion`、`blueprintInputs` が付きます。

### 4.16.0 からのアップグレード

- `helm upgrade <release> hotloop/hotloop --version 4.17.0 --reset-then-reuse-values`。`--reuse-values` は使いません。新しい既定値が抜け落ち、レンダリングに失敗します。selector と volume claim は変わらず、新しく増えるオブジェクトは鍵の Secret だけです。
- マイグレーション 0009 から 0015 が起動時に実行されます(helper、logbook、スクリプト、タグのデバイスクラス、レシピ、blueprint、UniFi)。すべて追加型です。先に `pg_dump` を取ってください。
- `HOTLOOP_SECRET_KEY_FILE`:このアップグレードでチャートが鍵を生成し、Gateway はその起動時に保存済みのすべてのデバイスパスワードを暗号化します。その後に鍵がないと、該当するデバイスは鍵を名指しするエラーとともにダウンしたままになります。アップグレード後に取ったバックアップは、その鍵があるか、`--restore-keep-unreadable-credentials` を付けた場合にしか復元できず、後者では誰かがパスワードを入れ直すまで該当デバイスはダウンのままです。Secret はバックアップとは別に保管してください。4.16.0 に戻すには、アップグレード前に取った dump を復元します。
- チャートをインストールせずに `helm template` でレンダリングしていますか。`secretKey.existingSecret` に自前の鍵を渡してください。そうしないと、レンダリングのたびに新しい鍵が作られます。
- Edge Relay:プッシュされたデバイスファイルは `/data/pushed-devices.json` にあり、存在する間はチャートの `devices` より優先されます。`DELETE /api/fleet/{id}/config` で消せます。4.16.0 で失敗したプッシュはブローカーに保持されたままで、4.17.0 の最初の起動時に届きます。Quadlet を使う場合は新しいユニットを取り込んでください。`persistence.enabled=false` でも起動するようになりましたが、pod が入れ替わるたびに転送キュー、プッシュされたファイル、OPC UA 証明書が失われます。
