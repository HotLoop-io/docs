HotLoop Flow 2.3.0 は、Flow がプラントのほかの部分へ 3 つの新しい方法で届き、形の誤ったメッセージを被害が出る前に捕まえるリリースです。HotLoop と話し、エージェントが MCP 経由でフローをツールとして呼び出せ、プラグインは npm パッケージではなく署名された WebAssembly ファイルです。JSON Schema は、`json` ノード、ノードのポート、エディタのワイヤーでメッセージを検査するようになりました。すでに動いているフローに影響しうる変更が 1 つあり、「変更点」の最初に書いています。

## 新機能

**HotLoop ノード**
- `hotloop-flow-hotloop` 接続は、URL とアカウントです。`POST /api/auth/login` でサインインし、HotLoop が返すベアラートークンを送り、HotLoop がセッションが切れたと言えば再びサインインします。以下のすべてにはオペレーターアカウントで足ります。
- `hotloop in` は HotLoop のライブフィードを追い、状態が変わったエンティティごとにメッセージを送ります。`msg.topic` はエンティティ ID、`msg.payload` は新しい状態、`msg.hotloop` には変更前の状態、属性、品質、タイムスタンプが入ります。リンクが切れるとバッジが赤くなり、再試行ごとではなく停止につき 1 件のエラーが Catch ノードに届きます。復帰すると、その間に変わったエンティティは送られ、変わっていないものは送られません。
- `hotloop state` は、メッセージが届いたときに 1 つのエンティティを読みます。`hotloop script` は、指定したフィールドで HotLoop のスクリプトを実行します。`hotloop recipe` は、パラメータ付きでレシピを適用し、意図して指定すれば古いバージョンも適用します。HotLoop がすべてのフィールドとパラメータを検査し、すべての書き込みを書き込みゲートに通し、記録を残します。Flow は理由として `flow:<node id>` を送り、HotLoop はそれを書き込み監査とログブックに記録します。
- 拒否または失敗した呼び出しは、HotLoop 自身の文言とステータスとともに Catch ノードに届きます。書き込まれたものは取り消されません。これも HotLoop のルールだからです。

**HotLoop のゲートを通した書き込み**
- `modbus write`、`opcua write`、`s7 write`、`ethernetip write` に 2 つの新しいフィールド、**HotLoop 経由で書き込む**と **HotLoop タグ**(`device/tag`)が加わりました。HotLoop を選ぶと値は HotLoop の書き込みゲートに渡り、ゲートは、書き込みがオンか、タグが武装されているか、値が範囲内かの順に判断します。
- ゲートが拒否した書き込みは機器に届きません。HotLoop に到達できない場合も書き込みは失敗します。ゲートが見ていない書き込みになってしまうため、直接の書き込みへ切り替えることは決してありません。
- タグには HotLoop 自身のアドレス、データ型、スケールが適用されるため、Flow ノード側のアドレスとデータ型は使われません。HotLoop を空にすると、ノードは完全に元の状態に戻ります。ゲートは 1 回の書き込みにつき bool、数値、テキストのいずれか 1 つを受け付けるので、レジスタのリストは、その旨のメッセージとともに拒否されます。

**MCP、双方向**
- `mcp tool` と `mcp result` は、フローをツールとして提供します。ツールノードが名前、説明、入力スキーマを宣言すると、Flow が `/mcp` で提供し、結果ノードがフローの答えを返します。エージェントはほかの人と同じようにセッションまたは API トークンでサインインし、呼び出しはそのトークンの権限で実行され、すべての呼び出しと拒否は呼び出し元の名前で監査ログに残ります。トークンがなければ呼び出しもありません。
- `mcp client` は、`hotloop-flow-mcp-server` 接続を通して、HotLoop 自身を含むあらゆる MCP サーバーのツールを呼び出し、戻ってきたものを使います。呼び出しを 2 回送ることは決してありません。ツールは機器を動かすことがあり、切れた接続では実行されたかどうか分からないからです。
- `auth.tokens` の API トークンには、`calls` と時間枠を持つ `rateLimit` を付けられます。省略すると時間枠は 1 分です。上限を超えた呼び出しはフローに届かず、いつ再試行すべきかを伝えるツールエラーとして返り、理由付きの `mcp.refused` 行を書きます。`rateLimit` のないトークンは制限されません。
- 同じエンドポイントで、仕様の現行リビジョン 2026-07-28 と、2025-11-25 までさかのぼるハンドシェイクのリビジョンに対応します。これらのノードを 1 つも使わないフローは MCP 呼び出しを一切行わず、Flow は与えられていないツールを提供しません。

**npm のないプラグイン**
- プラグインは、WebAssembly モジュール、エディタがダイアログを描くための記述子、そして両方に対する ed25519 署名で構成されます。署名のないプラグインや改ざんされたプラグインは、読み込みを拒否し、その理由を示します。`hotloop-flow plugin keygen` で鍵を作り、残りは `docs/plugins.md` にあります。
- メモリ上限やタイムアウトを超えたゲストは Catch ノードへトラップされ、ほかはすべて動き続けます。オペレーターが許可していないホストアクセス(`clock`、`random`、`context.flow`、`context.global`)を要求するプラグインは、それを使うすべてのフローのデプロイを、1 バイトも書く前に失敗させます。
- 信頼する鍵がなければすべてのプラグインが拒否され、許可がなければホストアクセスを要求するすべてのプラグインが失敗します。既定では何も読み込まれません。
- チャートはこれらすべてを `plugins` の下で受け取り、あらゆる Kubernetes ボリュームソースを受け付けるボリュームを備えます。オフならば何も出力せず、既定値の `helm template` はこれまでどおりです。

**型付きワイヤー**
- `json` ノードの設定に JSON Schema を与えると、ノードが扱うすべての値がそれに照らして検査されます。一致しない値はワイヤーを流れる代わりに Catch ノードへ送られ、エラーは `payload.temp: got string, want number` のように誤ったフィールドをすべて挙げます。設定にスキーマがなければ、Node-RED の `json` ノードと同じく `msg.schema` で検証します。スキーマが別のドラフトを指定しない限り draft 2020-12 で、別の URL やファイルへの `$ref` は取得せずに拒否します。
- ノードは、受け付けるものと各出力が約束するものを、ほかのツールが無視するフローファイル内の 2 つのキーで宣言できるため、それらを持つフローもバイト単位でそのまま往復します。ワイヤーの両端がスキーマを宣言し、両方を満たすメッセージがありえない場合、デプロイは 1 バイトも書く前に拒否されます。Flow が事前に見抜けない不一致は、スキーマに違反した場所で止まり、誤ったフィールドごとのパスとともに Catch へ送られ、`hotloop_flow_node_schema_mismatches_total` に数えられます。
- 次のノードが決して受け取れないリテラルを設定する `inject`、たとえば 0 から 100 を受け取るノードに数値 250 を入れる場合も、デプロイ時に同じように拒否されます。タイムスタンプ、`env`、コンテキスト、JSONata は推測せずに除外します。
- エディタは、各ワイヤーに送り手の型を書きます。片端にしか型がないときは淡く、両者が決して一致しないときは赤く表示され、赤はランタイム自身のチェックから来るので、キャンバスとデプロイが食い違うことはありません。設定する場所は、ノードのダイアログの**型**セクションです。

ノードの種類がさらに 9 つ増えて合計 79 になります。HotLoop 用が接続を含めて 5 つ、MCP 用が接続を含めて 4 つです。

## 変更点

- `json` ノードは以前 `msg.schema` を無視していました。今は `msg.schema` を持つメッセージはそれに対して検証され、一致しなければワイヤーを流れずに Catch ノードへ送られます。別の目的でメッセージに `msg.schema` を残しているフローは、この変化に気づくことになります。
- デプロイが型の不一致(`deploy.refused`、理由 `typed wires`)で拒否されることがありますが、ポートにスキーマを宣言しているフロー、またはスキーマを宣言したノードに `inject` のリテラルを設定しているフローだけです。スキーマがどこにもないフローは、以前とまったく同じように動作します。
- 書き込みノードには新しい 2 つのフィールドがあり、既定では空です。HotLoop を選んでいなければ、書き込みノードは 2.2.0 と同じように動作します。
- スキーマの検証器は `santhosh-tekuri/jsonschema` v6(寛容なライセンス)で、MCP は Go SDK の `modelcontextprotocol/go-sdk` v1.8.0 です。どちらも新しい Go モジュールなので、イメージが `/usr/share/doc/hotloop-flow/` に含めるライセンス文面の項目が増えました。WebAssembly ランタイムはすでに 2.2.0 に入っていました。
- 耐久キューの修正が 3 つあります。削除された耐久ワイヤーは、遅れて来た書き込みを拒否して破棄として数えるようになり、削除時にメッセージで詰まった宛先のために閉じるタイムアウト全体を待つこともなくなりました。以前は、ワイヤーが消えた後に返されたメッセージが、再起動までクォータに計上されたままでした。最も古いものを捨てるワイヤーは、すでに確認済みのメッセージやポンプが読んだばかりのメッセージを押し出さなくなりました。以前は同じ空きを 2 回返してしまい、キューの深さとクォータがディスク上の量を下回っていました。`docs/durable/README.md` の耐久クォータの説明には、迂回したメッセージがクォータを一時的に数件超えることがあると書かれています。
- README と `docs/bench/` に Raspberry Pi 5 の結果を載せ、ロードマップでは Pi 5 にチェックを入れ、Pi 4、Zero 2 W、SD カードへの書き込みは未了として残しています。

## アップグレードの注意

2.2.0 からはイメージを替えるだけです(`helm upgrade`、または Quadlet ユニットの新しいタグ)。移行もフラグも要らず、初回起動で新しく生じるものもありません。2.2.0 で動いていた `flows.json` と設定ファイルは 2.3.0 でも動き、フローファイルのバイト単位の往復は手つかずです。

- 新しいノードやキーを使わないフローなら、2.2.0 に戻しても安全です。HotLoop、MCP、プラグインのノードは 2.2.0 では起動せず(不明なノードタイプ)、HotLoop を選んだ書き込みノードは、2.2.0 がそのフィールドを読まないため、そこでは機器へ直接書き込みます。戻す前に、それらの書き込みノードから HotLoop を外してください。
- HotLoop は Flow がサインインしたアカウントを記録します。API はクライアントが自分自身のアクターを名乗る手段を与えないため、Flow のノード ID が理由として入り、アカウントは接続に設定したものになります。書き込みを見つけやすくしたいなら、Flow 用に作ったアカウントを使ってください。
- MCP は Flow への新しい入口で、トークンが必要です。フローに `mcp tool` ノードができるまで何も提供されず、トークンがない、または偽のトークンでの呼び出しは拒否されます。

## 新しい設定

| YAML | 環境変数 | 既定値 |
|---|---|---|
| `plugins.dir` | `HOTLOOP_FLOW_PLUGINS_DIR` | 空。`data.dir` 内の `plugins` を意味します |
| `plugins.trustedKeys` | `HOTLOOP_FLOW_PLUGIN_TRUSTED_KEYS` | なし。それぞれ `ed25519:<base64>`、PEM 公開鍵、またはそれを収めたファイルです。1 つもなければすべてのプラグインが拒否されます。 |
| `plugins.grants` | `HOTLOOP_FLOW_PLUGIN_GRANTS` | なし。プラグイン名と `clock`、`random`、`context.flow`、`context.global` の対応です。変数は `name=cap,cap;name=cap` の形式です。 |
| `plugins.maxMemoryMiB` | `HOTLOOP_FLOW_PLUGIN_MAX_MEMORY_MIB` | 64、1 から 4095 まで |
| `plugins.maxTimeout` | `HOTLOOP_FLOW_PLUGIN_MAX_TIMEOUT` | `5s` |
| `auth.tokens[].rateLimit.calls`, `.per` | | 0 回、つまり制限なし。`calls` を設定して `per` を設定しない場合、`per` は `1m` です。 |

HotLoop と MCP の接続はエディタで設定します。URL、アカウント、タイムアウトです。チャートには、プラグインのすべての設定が `values.yaml` の `plugins` の下に `enabled: false` で入っており、ほかに新しいものはありません。
