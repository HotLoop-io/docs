CODESYS の画面が HotLoop の画面として取り込まれるようになり、ボックスは自身の状態を EmberNet ダッシュボードに報告し、エネルギーメーターは需要料金を持てます。また、遅いノードで出ていたテストスイートの失敗を一掃したもので、1 つ 1 つが実際の待ちや競合の修正です。amd64 のみでビルドされています。マルチアーキテクチャビルドは次のバージョンで続きます。

## 変更点

- **CODESYS のビジュアライゼーションを画面としてインポートします。** IDE からエクスポートし(Project、Export、PLCopenXML ではなくネイティブの `.export` ファイル)、Dashboards 画面の Import がそれを PLC の変数上の HotLoop 画面として読み込みます。画面が読み取るタグのうちこのインストールにないものはすべて、デバイスのマッピングとともに一覧され、HotLoop が配置できなかった要素は、何かを保存する前に理由とともにすべて一覧されます。書き込み可能でないタグのボタンや設定値は、ビルドと同様に拒否されます。[Import a CODESYS screen](/ja/iot/codesys-screen-import/)をご覧ください。
- **EmberNet ダッシュボード向けのボックスの状態。** Kubernetes ノード名にちなんだデバイスが、ボックスの CPU、メモリ、ディスク、データボリュームの使用量を公開し、エージェントがファイルを書き出す場合は 3 コアのリアルタイムジッターも公開します。読み取れない値は、ゼロではなく理由つきの不良品質になります。OPC UA サーバーがその履歴を提供します。[OPC UA サーバー](/ja/edge/opc-ua-server/#embernet-ダッシュボード向けのボックスの状態)と[プロトコルとドライバー](/ja/iot/protocols/#ボックスの状態)をご覧ください。
- **読み取りしかできないログイン。** デプロイは、ちょうど `tags.read` と `values.read` だけを持つアカウントを 1 つ作れます(`HOTLOOP_READER_USER` と `HOTLOOP_READER_PASSWORD_HASH`)。チャートは初回インストールで `embernet-dashboard-read` を作り、パスワードを Secret `<release>-opcua-dashboard` に保持し、アップグレードで決してローテーションしません。
- **ダッシュボードの証明書は Secret から信頼されます。** チャートは `<release>-opcua-trust`(任意)をマウントし、OPC UA サーバーは信頼フォルダーをそれに合わせて保ちます。新しい証明書は 30 秒以内に追加され、Secret から外れたものは取り除かれ、運用者が手で置いたファイルには決して触れません。サーバーは引き続き Basic256Sha256 SignAndEncrypt のみを受け付け、匿名セッションも全面信頼もありません。リリースの Service は、サーバーがオンのときポート 4840 を一覧に載せるようになりました。
- **エネルギー:需要料金とシフト。** Wh、kWh、MWh のメーターは `demand_price` を受け付けます。これはウィンドウ内で最も高い 15 分間の 1 キロワットあたりのコストで、サマリーはピーク、その開始時刻、その 15 分のうちどれだけが読み取られたかを示します。シフトはウィンドウで、最後に始まったものは `shift:06:00-14:00`、その前のものは `last_shift:06:00-14:00` です。Energy 画面には Shift ボックスと需要価格があり、13 言語すべてで使えます。
- **生産単位あたりのコストが無料と読まれなくなりました。** 何かが生産されたのに、価格のあるメーターがまだ使用量を数えていない場合、答えはゼロではなく、理由 `nothing_counted` つきの「なし」です。
- **テスト中の CODESYS ランタイムを文書化しました。** 実際のランタイムの OPC UA サーバーを、CODESYS が文書化している PLC シェルのコマンドで安全にし、それに対して Basic256Sha256 SignAndEncrypt の読み取りを検証しました。本物のアラームが発生し、確認され、動作中の PLC が報告するとおりに解除されます。ライセンスのないランタイムの 2 時間のデモ期間が終わったときにデバイスが何をするかは、タイムラインのスクリプトとともに記録しました。これらは[プロトコルとドライバー](/ja/iot/protocols/)のテストとメモで、ドライバーは変わっていません。
- **スイートが見つけた修正。** エネルギーエンジンは、メーターが削除または変更されている間はそのメーターを読まなくなりました(データベースが削除を失敗させてデッドロックを解いていました)。バックアップのマニフェストは一時的な名前で書かれてその場で名前が変えられるため、一覧が半分のファイルを見ることはありません。historian の追いつきは、あるマークまでのすべてを書き終えるまで待ちます。残りは、負荷のかかったノードで、固定の秒数ではなく自分が主張することを待つようになったテストです。

## ボックスの状態はデフォルトでオンです

チャートはホストのルートを `/host` に、その `/proc` を `/host/proc` に、どちらも読み取り専用でマウントし、権限は追加しません。読まれるのは statfs と CPU、メモリのカウンターだけです。Pod Security の restricted プロファイルを強制するクラスターは hostPath を拒否します。その場合は、`opcuaServer.dashboard.boxHealth.enabled: false`(デバイスもマウントもなし)か `hostMount: false`(デバイスはあり、ボックスのディスクと CPU は不良と読まれ、何をマウントすべきかを示します)を設定してください。Quadlet の drop-in は `deploy/quadlet/opcua-dashboard.conf` です。

## マイグレーション

1 つで、追加のみです。`0030_energy_demand`(メーターとそのバケットの `demand_price` 列、既定は 0 なので、すでに集計または価格づけされたものは変わりません)。4.23.1 で取ったバックアップはここで復元でき、ここで取ったバックアップは古いリリースには復元できません。

## API の変更

エネルギーメーターの料金表の `demand_price`、サマリーの行の `demand` ブロック、エネルギーの期間としての `shift:` と `last_shift:`、そして `cost_per_unit` が null のときの `reason` です。`POST /api/dashboards/import` は `file` の代わりに `codesys` と `visualization` を受け付け、そのレポートには `conversion` が含まれます。[HTTP API](/ja/iot/api/)をご覧ください。

## 4.23.1 からのアップグレード

通常の `helm upgrade` です。マイグレーションは初回起動時に実行されます。チャートは、このバージョンの初回インストールで読み取り専用アカウントとその Secret を作り、決してローテーションしません。ボックスにすでにあるものは何も変わりません。

## 検証していないこと

- 知らない要素は一覧にして外し、決して推測しません。別のプロジェクトの画面では、より多く一覧されることがあります。
- リアルタイムジッターのタグには、ファイルを書くエージェントが必要で、このリリースはそれをインストールしません。
- 読み取り専用ログインと証明書の信頼は、HotLoop自身のクライアントで検証されています。EmberNetダッシュボード側はそれ自体のリリースです。
- CODESYS のセキュアエンドポイントは、テストで 1 つのランタイムバージョンに対して検証しました。そのために HotLoop のドライバーは変わっておらず、セキュアエンドポイントの設定画面はこのリリースには含まれません。
- 需要料金は、記録された読み取り値で確認したもので、電力会社の請求書では確認していません。
