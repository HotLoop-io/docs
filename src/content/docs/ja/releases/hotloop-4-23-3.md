WebVisu の画面は、取り込むときに非表示とアラームの色を保ち、どの画面のどのシンボルも、タグのルールで表示し、色を付けられるようになりました。バックアップ一覧の小さな修正も同梱されています。amd64 のみでビルドされています。マルチアーキテクチャビルドは次のバージョンで続きます。

## 変更点

- **シンボルをルールで表示し、色を付けられます。** `show` は、タグのルールが成り立っている間だけシンボルを描くため、1 つの状態のために描かれたドア、ガード、ポンプは、その状態のときだけ表示されます。`colors` は最大 4 つのルールで、それぞれにトーン(`ok`、`warn`、`bad`、`info`)があります。最初に成り立ったものがシンボルをそのトーンで塗り、どれも成り立たなければ元のとおり描かれます。ルールは、タグと比較(`on`、`off`、`eq`、`ne`、`gt`、`ge`、`lt`、`le`)です。タグに有効な読み取り値がないルールは、何も成り立たせず何も隠さないため、接続が失われてもシンボルが消えることはありません。ビルダーのシンボルフォームには両方があり、画面ファイルはルールのタグをそのほかと一緒に一覧にして移動します。[ダッシュボード](/ja/iot/dashboards/)をご覧ください。
- **CODESYS の画面インポートが Invisible と Toggle color を引き継ぎます。** 要素の Invisible 変数(そのグループのものも)は `show` ルールになり、`NOT x` で反転させ、Toggle color 変数は、その要素自身のアラーム色にいちばん近いトーンの `colors` ルールになります。これらは CODESYS IDE 自身の要素ツリーが与える id で見つかります。引き継げないものは、変数とともにインポートで示されます。背景画像に描かれた図形(配管、容器、枠)に対するこの 2 つ(画像は 1 枚の画像だからです)と、変数で駆動されるそのほかのすべての設定(塗りつぶし、枠やテキストの色、動き、点滅、テキストリスト)です。[Import a CODESYS screen](/ja/iot/codesys-screen-import/)をご覧ください。
- **バックアップを整理している間もバックアップ一覧が失敗しなくなりました。** 定期バックアップは自身の goroutine で古いバックアップを整理しており、その途中に当たった一覧取得は、なくなったファイルで失敗し、API はそれをサーバーエラーとして返していました。なくなったバックアップは、一覧から外されるようになりました。

## マイグレーション

ありません。

## API の変更

シンボルの設定は `show` と `colors` を受け付けます。ルートは変わっていません。[HTTP API](/ja/iot/api/)をご覧ください。

## 4.23.2 からのアップグレード

通常の`helm upgrade`です。移行も新しいシークレットも不要です。どちらのルールもないシンボルは、これまでどおり描かれます。

## 検証していないこと

- CODESYS のインポートは、IDE 自身が書き出した 1 つのビジュアライゼーションと、CODESYS の Refrigerator サンプルのグループ変数に対して検証しました。別のプロジェクトの画面では、配置できなかったものがより多く一覧されることがあります。
- 新しいシンボルのルールは、スイートのテストで検証したもので、プラントの画面では検証していません。
