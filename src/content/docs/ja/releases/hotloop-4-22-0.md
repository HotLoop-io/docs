パネルとして開いた画面(`/?screen=<name>`)が、どのサイズでもディスプレイいっぱいに端から端まで広がるようになり、Alarms 画面は CODESYS のアラームファイルをインポートでき、いくつかの修正が入りました。amd64 のみでビルドされています。マルチアーキテクチャビルドは次のバージョンで続きます。

## 変更点

- **パネルページが画面いっぱいに広がります。** 1920x1080、1366x768、3840x2160 で、無駄な空きなくディスプレイを覆います。プラント名のヘッダー、オンラインのデバイス数を示す Live ステータス、日付つきの 24 時間時計があります。数字とゲージは画面とともに大きくなり、トレンドの軸と凡例も同様です。変わるのはパネルページだけで、ダッシュボードはそのままであり、顧客のカード、サイズ、名前は顧客のものです。
- **Alarms 画面が CODESYS の Export Alarms ファイルをインポートします。** 管理者のみです。デバイスを選び、アプリケーションに名前をつけ、ファイルを選び、取り込まれるものとそうでないもののプレビューを読んでから、インポートします。API のルートはすでにありました。
- **同じアドレスとポートの OPC UA PubSub デバイスは 1 つのソケットを共有します。** 2 台目のデバイスはバインドできず、再利用オプションはパブリッシャーのデータグラムをそれらの間で分けてしまっていました。
- **遅い応答が積み重なることはなくなりました。** 更新より遅いカメラカードは画像を表示するようになり、カードと UniFi 画面は最後の応答のあとにだけ再び問い合わせ、一度失敗したディスカバリーのバッチは再試行され、ホスト名の SNMP デバイスは応答に対する自分の待ち時間を保ちます。
- **コア製品は HotLoop Free Use License 1.0 のもとにあります。** 以前のバージョンは、公開されたときの条件を保ちます。NOTICE をご覧ください。
- **チャートページの App Store アイコン**は、HotLoop のブランドマークです。

## API の変更

ありません。

## 4.21.1 からのアップグレード

通常の `helm upgrade` です。マイグレーションも、新しい secret も、元に戻せないものもありません。

## テスト

パネルページは、上の 3 つのサイズで、Emberburn が Gateway にデータを供給する状態でテスト中に確認しました。
