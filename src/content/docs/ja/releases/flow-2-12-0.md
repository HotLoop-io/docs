HotLoop Flow 2.12.0は、FlowLabのパネルとキャンバスを仕上げます。ノブ、スピン入力、LED、配列、レコードは本物のコントロールになり、サブダイアグラムは追いかけるべき2つ目のタブではなくキャンバス上でその場に開き、すべての機器の書き込みは誰かがオンにするまでオフです。また、最初の実行の前に設定できなかったコントロールを直し、新しいライセンスを含みます。お使いのダイアグラムが機器を動かす場合は、アップグレードの前に「変更点」をお読みください。

## 新機能

- **仕上がったパネルコントロール。** ノブは270度回るダイヤルです。指やマウスで周りをなぞるようにドラッグするか、押してそこに置くか、矢印キー(1段)、Page UpとPage Down(10段)、HomeとEndを使え、離したときに書き込みます。スピンの見た目は、入力する数値にマイナスとプラスのボタンが付いたもので、`step`ずつ動き、範囲で止まります。スイッチのLEDの見た目は、押すLEDです。**配列**コントロールは、オペレーターが追加と削除をする数値、スイッチ、テキストのリストで、`elem`、`min`、`max`、`maxlen`で決まります。**レコード**コントロールは、`fields`(`rate:number, on:bool, note:string`)の各フィールドに1つの入力で、ダイアグラムはすべてのフィールドを持つオブジェクトを読みます。サーバーは、何で設定しても各コントロールをその種類と範囲に合わせ、どの項目やフィールドがおかしいかを伝えます。パネル上のすべてのコントロールのタッチ領域は縦横とも44ピクセル以上で、幅390ピクセルでページは横にスクロールしません。
- **サブダイアグラムがその場で開きます。** サブダイアグラムのノードには角に小さな四角があり、ダイアグラムバーには選択中のものに対する**その場で開く**があります。ノードは元の場所で開いた状態で描かれます。左右の端に名前付きのコネクターがあるフレームで、中に本体のノードとワイヤーがあります。本体自身のノードなので、1つを動かす、ダブルクリックでプロパティを開く、2つをつなぐ、1つを削除する、いくつかの上に範囲選択を描くことは、元に戻せる手順で本体を編集することであり、デプロイで保存されます。閉じるとノードは元に戻ります。開いたサブダイアグラムは、開いたサブダイアグラムを3段まで含められ、すでに開いているものに戻る本体は閉じた状態で描かれるので、自分自身を含むダイアグラムがエディターを無限ループに陥れることはありません。何が開いているかはダイアグラムの見方であって、フローファイルにはないので、デプロイは以前と同じものを送ります。
- **機器の書き込みスイッチ。** 機器を読むことは何も変えず、常に開いています。書き込みは変えうるので、すべての機器は書き込みをオフにして始まり、ダイアグラムからの書き込みは、`instrument.write`の権限を持つ人がその機器の書き込みをオンにするまで拒否されます。`dia-serial-write`は常に書き込みです。`dia-instr-query`は、中のSCPI文がすべて`?`で終わっていれば読み取りで、そうでなければ書き込みであり、外から配線されたコマンドは書き込みうるものとして数えます。機器はそのアドレス(`tcp://host:port`または`serial:///dev/ttyUSB0`)なので、2通りの方法で開かれた1つの機器は1つのスイッチです。拒否はノードのエラーワイヤーに流れるエラー(コード5007)で、機器はそのコマンドを一切受け取りません。`PUT /instruments/writes`に`{"instrument": "tcp://10.0.0.5:5025", "allowed": true, "note": "bench 2"}`を送ると1つがオンになり、`GET /instruments`が一覧を返し、スイッチはデータディレクトリの`instrument-writes.json`にあります。スイッチの変更はすべて`instrument.switch`、書き込みはすべて`instrument.write`、拒否はすべて`instrument.refused`として監査されます。デプロイは、ダイアグラムが書き込むことになる機器を、ダイアグラムバーのメモに一覧で示します。

## 変更点

- **機器を動かすダイアグラムは、その機器をオンにするまで止まります。** 2.11.xでは、生のシリアルノードと機器ノードは何にでも書き込めました。2.12.0では、管理者(または`instrument.write`を持つ誰でも)がその機器の書き込みをオンにするまで、最初の書き込みはコード5007で拒否されます。読むだけのダイアグラムには影響しません。これは意図したもので、2.11.0のノートで予告しており、このリリースで実行中のダイアグラムを止めうる変更です。
- **ノブとLEDの見た目が、名前どおりに描かれます。** ノブの見た目で範囲のある数値コントロールは入力ボックスを描いていましたが、今はダイヤルを描きます。LEDの見た目のスイッチはチェックボックスを描いていましたが、今はLEDボタンを描きます。最小値と最大値のないノブは、引き続き入力欄を描き、デプロイがそのことをダイアグラムのメモで伝えるようになりました。スライダーは変わりません。
- **コントロールを最初の実行の前に設定できます。** パネルは実行が始まったときにしかコントロールを知らなかったため、先に設定すると「is not a control on this panel」で拒否されていました。今はデプロイされたダイアグラムからコントロールを知り、デプロイで変わったコントロールにもう合わない保存値は、コントロールの開始値に戻ります。
- **キャンバス。** 表示を合わせたキャンバスで描いた範囲選択が、内容がキャンバスより高いとき、ポインターが動いた場所とは別の場所から始まることがありましたが、直りました。幅820ピクセルより狭い画面では、FlowLabバーが何行にも折り返され、すべてのノードの上に載っていました。今は自分の場所を取ります。より広い画面はこれまでどおり描かれます。
- **ライセンス。** `LICENSE`、`NOTICE`、イメージのライセンスラベルが、Business Source License 1.1 から EmberNet Source License 1.0(`LicenseRef-EmberNet-Source-1.0`)に変わりました。これらはイメージ内の `/usr/share/doc/hotloop-flow` に入っています。それ以前に公開されたバージョンは、公開されたときの条件のままです。頼る前に、このリリースの `LICENSE` を読んでください。
- それ以外は、2.11.1と動作が変わるものはありません。

## 新しい設定

設定ファイルにも環境変数にもありません。`dia-control` は種類 `array` と `record`、見た目 `spin`、プロパティ `elem`、`maxlen`、`fields` を受け付けます。権限 `instrument.write` とデータディレクトリの `instrument-writes.json` ファイルが計測器のスイッチです。サブダイアグラムをその場で開くことに設定はありません。

## アップグレード

イメージとチャートの2.12.0への`helm upgrade`を1回実行するか、Quadletユニットのタグを新しいものにします。初回起動では何も起こらず、移行するものもありません。すべての機器は書き込みをオフにして始まり、誰かが1つをオンにするまでファイルもありません。このリリースはamd64が先で、arm64ビルドは2.12.1で続くため、arm64のマシンはそれまで2.11.1にとどまります。機器の書き込みをオンにすると、誰が行ったかとともに監査ログに記録されるので、メモを残してください。

イメージ: `ghcr.io/hotloop-io/hotloop-flow:2.12.0`、まずlinux/amd64で、arm64は2.12.1で続きます。チャート: `https://hotloop.io/hotloop-flow/`。このタグのREADMEに残りが写真つきであります: https://github.com/HotLoop-io/hotloop-flow/blob/v2.12.0/README.md
