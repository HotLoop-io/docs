4.19.0、4.19.1、4.19.2、4.19.3 はタグが付けられただけで公開されたことがないため、これらの名前を持つものは存在せず、`stable` もそのどれにも移っていません。今回は、それらのノートに挙げられたすべてを含む最初のリリースで、4.19.1 以降に新しくなったことが 1 つあります。チャートが `hostNetwork` を受け付けます。

- 4.19.1 にはその修正と、もう 1 つ(聞こえるようになる前に稼働中と言っていたディスカバリーリスナー、下記)が入っていましたが、リリースされる前にスキップされました。
- 4.19.2 で `hostNetwork` が加わりました。
- どちらも下記で修正されています。
- 4.19.0 のノートにあったすべて(MCP、スケール付き書き込み、ストアのサインイン、CODESYS、Kafka イベントストリーム、UADP 上の OPC UA PubSub、そして修正)は、下のノートに含まれています。

4.19.1 以降の新機能:チャートに `hostNetwork` 設定があります。

## hostNetwork

pod を持つすべての HotLoop チャート(Gateway、IoT、Edge のチャートと Edge Relay のチャート)が `hostNetwork: true` を受け付けます。既定ではオフで、オフのときのチャートは 4.19.1 のものとまったく同じ結果をレンダリングします。

- **用途。** ノードが聞くものを聞く必要がある pod のためです。ノードのループバック上の UDP マルチキャスト(同じボックスの PLC ランタイムが、ループバック経由でマルチキャストグループに OPC UA PubSub をパブリッシュする場合)や、2 枚目のネットワークカードがその例です。pod ネットワークはどちらも運びません。
- **動作。** Deployment に `hostNetwork: true` と `dnsPolicy: ClusterFirstWithHostNet` が設定されるため、クラスターの DNS 名は引き続き解決されます。
- **pod への影響。** ノードのアドレスとポートを使います。ページはノードのすべてのアドレスの `service.targetPort` で応答するため、ノード上で誰も使っていないポートを選び、認証を有効にしておいてください。NetworkPolicy は host-network の pod には適用されません(クラスターのネットワークプラグインが無視します)。`nodeSelector` で pod をノードに固定してください。
- **ループバック上のリスナー。** OPC UA PubSub のサブスクライバーは、名前付きのカード上のグループに名前またはアドレスで参加します。デバイスのオプションの `"interface": "127.0.0.1"` はループバックカードで参加します。
- **それ以外はありません。** コードは 4.19.1 が出荷したはずのものです。リリースガードは、すべてのチャートをこの設定ありとなしでレンダリングし、どちらかが誤っていれば失敗します。

---

このリリースの残りは、4.19.0 と 4.19.1 からのものです。

4.19.4 の 2 つの点は、既存のプラントの動作を変えるため、稼働中のものに触れる前に読んでください。MCP 経由のエージェントが書き込めるようになり、MCP エンドポイントには常にトークンがあります。また、スケール付きのタグに書いた値が、ようやく意図したとおりにレジスターに入るため、以前の動作を回避していた人はやめる必要があります。この 2 つ以降はすべて新機能か修正です。

完全なノートは README にあります。4.19.4 の変更点をご覧ください。

### MCP はオンで、書き込みができ、常にトークンがあります

- **operator が書き込める場所では、エージェントも書き込めるようになりました。** MCP はすべての HotLoop 製品でオンで、読み書きします。`allowMcpWrites` は、コードと 3 つのチャートのすべてで既定が true です。`allowWrites` がオンで `allowMcpWrites` を一度も設定していないデプロイは、このアップグレード後、画面と同じゲートを通ってエージェントの書き込みが可能になります。ユーザーの権限、タグの書き込み可マーク、範囲は、すべてそのまま適用されます。
- **`allowWrites` は変わっていません。** 既定ではオフで、UI もエージェントも含め、何かが書き込めるかどうかを今も決めます。オフなら、MCP を含め何も書き込めません。
- **`allowMcpWrites: false` を保存したデプロイはオフのままです。** すべての回答を保存する App Store からインストールしたデプロイも含みます。エージェントに書き込ませたい場合は切り替えてください。
- **エンドポイントが開いたままになることはありません。** チャートは常に MCP トークンを設定します。`HOTLOOP_MCP_TOKEN` なしで起動した HotLoop(Quadlet ユニットや単体のバイナリ)は、ポートに届く誰にでも `/mcp` を提供し、警告をログに残すだけでした。現在は初回起動時に 24 バイトのトークンを作ってデータベースに保存するため、すべてのレプリカとすべての復元が同じトークンを持ちます。トークンなしの呼び出しは `401` です。設定したトークンが置き換えられることはありません。
- **単体または Quadlet のインストールでトークンを得るには:** `hotloop mcp-token` が表示します。そのようなインストールの `/mcp` をトークンなしで指していたエージェントは、このアップグレードでそのトークンを渡すまで動かなくなります。意図したものです。
- **誰が呼び出したか。** 静的トークンは、どのクライアントが呼んだかを示すだけで、どの人かは示しません。OIDC 設定をオンにすると、`/mcp` での Vord ログインまたは hub assertion により、監査に人の名前(`mcp:pat@example.com`)が残り、任意の書き込みロールは、上のスイッチに加えて呼び出し元ごとに書き込みを絞り込みます。設定しない限りオフで、トークンはその隣で引き続き動作します。設定方法は [MCP のページ](/ja/iot/mcp/)にあります。

### スケール付きタグへの書き込み

- **何が誤っていたか。** スケールのあるタグ、たとえば 10 分の 1 度を保持する温度レジスターに 0.1 のスケールがあると、エンジニアリング値が表示されます。レジスターは 555、画面は 55.5 です。書き込みは同じ配慮なしに逆方向へ進んでいました。設定値として 55.5 を入力すると、HotLoop はレジスターに 55 を入れ、それが 5.5 として読み戻されました。すべての画面、API、オートメーション、スクリプト、レシピ、ループ、MCP 経由でも同じでした。すべて同じ書き込みゲートを通るためです。監査の行はずっと 55.5 と記録していたので、ログでは何もおかしく見えませんでした。
- **何が変わるか。** 書き込む数値は、読む数値と同じく、タグ自身の単位です。HotLoop は送る前にスケールとオフセットを元に戻します。0.1 のスケールのタグに 55.5 を書くとレジスターに 555 が入り、55.5 として読み戻されます。スケールもオフセットもないタグには一切手を加えません。ビット、コイル、文字列、フラグに対する Sparkplug と MQTT の書き込みもスケールされません。
- **回避していたなら、やめてください。** 正しい数値を得るために、スケール付きのタグに生のカウント値を入力していた人、つまり 55.5 を得るために 555 を入力していた人がいるなら、それは今後 5550 を送り、555 として読み戻されます。エンジニアリング値を入力してください。アップグレード前にスケール付きのタグを確認してください。スケールが 1 でない、またはオフセットがあり、人が手で、オートメーションから、またはレシピから書き込むタグは、確認する価値があります。カウント値を書いていたレシピとオートメーションは、アップグレードと同じ手順で数値をエンジニアリング値に変える必要があります。
- **レジスターが保持できない値は拒否されます。** スケールを戻したあと、レジスターに収まらないカウント、たとえば 0.1 のスケールの `uint16` に 7000 は、カウントとレジスターを示すわかりやすいメッセージとともに拒否され、何も送られません。以前は黙って折り返していました。16 ビットのレジスターに 70000 が 4464 として出ていきました。Modbus、S7、EtherNet/IP、OPC UA の整数型すべてに当てはまります。
- **収まらない値を持つレシピは丸ごと拒否されます。** 最初の書き込みの前にすべてのターゲットが検査されるため、レシピが途中まで適用されてから拒否されることはありません。Modbus、S7、EtherNet/IP では、検査は各タグのアドレスからレジスター型を知っています。CODESYS ランタイムへの経路である OPC UA では、そのタグの最後の読み取りが届いた型を使います。HotLoop の起動後に一度も読み取られていないタグには、まだ照合する型がないため、それを対象とするレシピは、その前のターゲットが書き込まれた後、そのタグ自身の書き込みで拒否され、アプリケーションはどれが書き込まれたかを記録します。接続の 1 秒以内にポーリングが行う読み取りが一度あれば、これは解消します。
- **カウントの端数は切り捨てられます。** レジスターは整数のカウントを保持するため、10 分の 1 のスケールのレジスターに 12.34 を書くと 12.3 が入ります。これまでと同じです。
- **変わらないこと。** タグの範囲チェックと監査の行は、入力した数値を使います。書き込みゲート、権限、拒否のルールは同じです。

### ストアのインストールは本人としてサインインさせます

チャートは、tenant が読めない Secret にランダムな管理者パスワードを作っていたため、ストアのインストールは入る手段のないログインに行き着いていました。ダッシュボードの公開鍵が設定されていると、この tenant とこの Service に対する有効な署名付き assertion を持つリクエストは、その人をサインインさせ、初回にはユーザーを作成し、ダッシュボードが送ったものにロールを合わせ続け、監査記録にその人の名前が残ります。不正、期限切れ、別の tenant、別のアプリの assertion は拒否され、ローカルのログインには手を加えません。鍵が設定されない限りオフで、3 つの製品チャートはストアから鍵を取得します。設定は[認証とユーザー](/ja/iot/authentication/)にあります。

### CODESYS、プログラマーが変数に付けた名前で

HotLoop は、CODESYS が文書化しているとおり、ランタイム自身の OPC UA サーバーを通して CODESYS の PLC を読み書きします。アプリケーションの Symbol Configuration が、PLCopen IEC 61131-3 モデルの下で公開されます。ディスカバリーは、アプリケーションがエクスポートするものを、プログラマーが与えた型とアクセス権とともに一覧にし、配列や構造体の中まで入っていきます。タグは、プロジェクトが PLC とアプリケーションに付けた名前の下で見つかる IEC シンボルです。再起動、ダウンロード、切断されたリンクは理由つきで bad と読まれ、手を借りずに戻ります。テストで、実際の 4.22.0.0 ランタイムに対して、当社自身のプログラムを動かし、PLC 自身のロジックが応答する書き込みを含めて、また 10 万を超える変数を持つ 2 つ目のプログラムに対して、2.4 秒で読み取ることで検証しました。

これはプラントが動かしているドライバーに触れるため、はっきり書きます。OPC UA ドライバーは 1 回のリクエストで 200 ノードを要求し、サーバーが許可する上限を読んでいませんでした。CODESYS のランタイムは OperationLimits を 100 と公開してそれを超えると拒否しますが、ドライバーは、見つけたすべてのタグを float と宣言し、100 を超えるデバイスのタグを 1 つも読まないという形で応じていました。現在は、リクエストが接続時にサーバーが公開する上限に合わせて分割され、上限を公開しないサーバーが多すぎると言った場合は半分にされます。標準型のサブタイプであるデータ型(CODESYS の STRING、BYTE、TIME)は標準型までたどられ、その型として型付けされ書き込まれます。これは CODESYS だけでなくすべての OPC UA デバイスに適用されます。

### Kafka イベントストリーム

- **何か。** HotLoop は、読み取り値とシステムログを Kafka API を話すあらゆるブローカーに送れます。Apache Kafka、Redpanda、その系統のほかのものが対象です。Settings、Historian targets にある新しい種類の historian ターゲットなので、キュー、HotLoop 自身の履歴からの追いつき、それらが持つステータスを備えています。読み取り値は 1 つの topic に、システムログ(アラーム、デバイスのダウンと復帰、変更)は別の topic に JSON で送られます。
- **TLS と SASL。** SCRAM-SHA-256、SCRAM-SHA-512、PLAIN(PLAIN は TLS 上のみ)に対応し、ブローカーの証明書が公的なものでない場合は独自の CA を使えます。クライアント証明書、Kerberos、OAuth ログインはまだ非対応です。
- **少なくとも 1 回の配信です。** 追いつきがすでに送ったものと意図的に重なるため、停止後に読み取り値が 2 回届くことがあります。`deviceId`、`tag`、`ts` で重複を特定できます。イベントはライブフィードで追いつく履歴がないため、ブローカーが不在の間に生成されたものは失われ、ターゲットのステータスがその数を数えます。
- **書き込み中に消えるブローカー。** ターゲットは 25 秒以内にダウンし、その書き込みの読み取り値は未送信として残ります。キューがあふれたままアップの状態にとどまることはありません。
- **作成されたばかりの topic。** 作成されたばかりの topic を最初に確認するとき、あなたが作ったものでもターゲット自身の直前の試行が作ったものでも、ターゲットをダウンと報告せず、topic が存在してリーダーを持つまで待ちます。
- **コスト。** データベースを持つすべての製品のバイナリが約 5 MiB 増えます。Edge Relay には historian ターゲットがないので含みません。クライアントは franz-go で、`NOTICE` にクレジットがあります。
- **アップグレード。** マイグレーション 0026 が historian ターゲットに `options` 列を追加し、既存のすべてのターゲットでは空です。それらには何も変わりません。レコード形式と、検証済みのものと未検証のものは [Historian ターゲット](/ja/iot/historian-targets/#kafka-apiイベントストリーム)にあります。

### UADP 上の OPC UA PubSub

- **サブスクライブ。** `opcua-pubsub` プロトコルのデバイスは、パブリッシャーが UDP のユニキャストまたはマルチキャストで UADP として送る DataSet を待ち受けます。タグのアドレスは `<DataSetWriterId>/<field index>` です。Variant、DataValue、RawData の各フィールドと、key、delta、keep alive の各フレームに対応します。メッセージが失われると、その writer のタグは次の key フレームまで uncertain になり、沈黙した writer は bad と読まれます。
- **パブリッシュ。** Edge と Gateway は、layout が指定するタグを UADP としてパブリッシュでき、`HOTLOOP_UADP_PUBLISH_ENABLED` を設定するまでオフです。値が変わると key フレーム、変わらないと keep alive を送ります。bad のタグは、最後の値ではなくそのステータスとしてパブリッシュされます。
- **まだです。** メッセージのセキュリティ(署名または暗号化されたメッセージ)は名指しで拒否され、チャンク化されたメッセージ、ディスカバリー、イベント、構造体フィールドも同様です。delta フレームは読み取りますが、送信はしません。
- **配列。** 配列のフィールドは Variant と DataValue のメッセージで読み取られ、デバイスの DataSet がレイアウトを示す場合は RawData でも読み取られます(個数つきの配列は `"Float[250]"`、250 個の別々のフィールドは `"Float*250"`)。タグは 1 つの要素を `1000/3[17]` のように指定し、Browse がそれらを一覧にします。
- **どこで待ち受けるか。** グループ、ポート、ネットワークカードはデバイス自身のものです。名前付きカード上のマルチキャストグループも、このマシン上のユニキャストポートも動作します。
- セットアップと制限は[プロトコルとドライバー](/ja/iot/protocols/#opc-ua-pubsub-uadp)にあります。

### イメージと、2 つ目の画面セット

- **今回だけ amd64 のみです。** 4.19.4 のイメージは amd64 向けにビルドされています。バージョンタグは amd64 だけを挙げ、`stable` と `latest` は、すでにあった arm64 と arm/v7 のイメージ(前のリリースのもの)の隣に新しい amd64 イメージを持ちます。`stable` に追従する arm のボックスは、引き続きプルして、動かしていたものを動かし続けます。次のリリースですべてのアーキテクチャを再びビルドし、ほかに何も入らないバージョンアップです。
- **新しい画面は `/next` にあります。** 作り直した Web UI がすべてのイメージに旧 UI の後ろに入っており、`/` では今も旧 UI が表示されます。どのインストールでも `/next` で試せます。既定の画面は変わりません。

### 修正

- **プロセスが、自分自身の停止が戻ってきてスクリプトの次の実行を止めることがなくなりました。** スクリプトの停止は、それを行ったプロセスを含むすべてのプロセスに通知され、少しあとに再び聞こえた通知が、そのとき進行中だったスクリプトの実行をキャンセルしていました。負荷時には、待っていた実行が開始 8 ms 後にキャンセルされ、別の実行は終わりませんでした。プロセスは自分で通知した停止を無視し、他のプロセスが通知した停止は引き続き受けて止まります。
- **ディスカバリーリスナーは、ブローカーがサブスクリプションに応答したときだけアップになります。** タイムアウトした待機も、すでに切れた接続での応答も、応答として数えられていました。今はどちらも数えず、遅れて届く応答は引き続き数えます。
- **ディスカバリーリスナーは、聞こえるようになったときにアップと言います。** MQTT セッションは、ブローカーが受け付けた瞬間に自分を接続済みと数え、そのあとでサブスクリプションを出してブローカーの許可を待っていました。それでアップと報告したリスナーは次のメッセージをその隙間に送り、保持されないデバイスのステータスや設定が失われました。今は、初回接続でも再接続のたびでも、サブスクリプションが許可されたときにアップと報告します。
- **ボードにピンを留めてもボードが消えなくなりました。** ページはボード画面が開いたときにしかボードを読まなかったため、タグ画面での再読み込みは空のリストを持ち、最初のピンが保存済みのボードをその 1 つのタグで置き換えていました。ページは起動時にボードを読むようになり、読むまではピンが拒否され、保存にはボードの `rev` が付くので、読んだあとで変わったボードへの保存にはサーバーが `409` を返します。`rev` は API では任意で、省略すると保存は検査されません。
- **止まった OPC UA サブスクリプションを検知します。** ライブラリは keep alive を自分で処理するため、止まったパブリッシュループは静かなプラントに見え、最後の値を良好として出し続けました。パブリッシュ間隔 10 回分(最低 30 秒)の沈黙のあと、ドライバーはノードを一度読み、保持している値と比較し、どれかが違えば読み取り方式に切り替えます。
- **ソケットが開いたまま黙る PLC は、低下ではなくダウンです。** Modbus、S7、EtherNet/IP は、ポーリングがセッションを判断する前に戻っていたため、TCP が諦めるまで最後の値を保持していました。今は判断します。テストでは、まだ S7 や CIP のサーバーがワイヤー上になく、ロードマップにもそう書かれています。
- **URL や自由入力テキストに入力した資格情報は、保存時に暗号化されます。** すべての画面はすでに `mqtt://user:pass@host` と `?token=` を人から隠していましたが、データベースとバックアップには入力したままの形で残っていました。マスキングが隠すのと同じ判定でそれらを含む文字列は、全体が封印され、書いたとおりに戻ってくるため、ドライバーは与えられた URL をそのまま受け取ります。あとからオンにした鍵は、それ以前に保存されたものを封印し、復元は、アドレスだけが必要なときには鍵を求めません。
- **API が書く時刻はすべて UTC です。** ニューヨークに設定されたプラントは、UTC のプラントが `Z` と書くところを `-04:00` と書いていました。約 30 のフィールドにわたり、`created_at`、`updated_at`、アラームの `raisedAt`、イベントの時刻、デバイスの `lastPoll`、タグのタイムスタンプ、logbook のエントリ、レポートの次回実行がそうでした。今はどちらも同じに読めます。ローカルのオフセットを前提にこれらを解析するスクリプトは、今後 `Z` を受け取ります。
- **月次パーティションが 31 日にスキップされていました。** 履歴と logbook のテーブルは、今日に 1 か月を足して次のパーティションを作っていたため、31 日には 1 か月が飛ばされ、その月の行が既定のパーティションに入っていました。今は月の 1 日から数えます。
- **UniFi のイベントログは、フレームがここに届いた時刻ではなく、イベントが起きた時刻で並びます。** 再接続後のリプレイが先頭に居座ることがなくなります。
- **スイッチのフェースプレートがスマートフォンに収まります。** 8 つのポートが 390 ピクセルの画面より広く、ページが横に 113 ピクセルスクロールしていました。ポートは密なタイルになり、PoE のワット数はポートの詳細に入り、それでもカードからはみ出すフェースプレートはその中でスクロールします。
- **セッションも接続もないスマートフォンは、空のアプリではなくサインイン画面と理由を表示し、** HotLoop が応答すると再読み込みします。
- **ロールバックはコマンド 1 つです。** チャートのインデックスは、リリース自身のチャートから作り直されるのではなく、稼働中のものにマージされるため、古いバージョンも引き続き解決されます。

### 4.18.11 からのアップグレード

- 稼働中のプラントで何かをする前に、上の最初の 2 つのセクションを読んでください。
- マイグレーションは 0026 のみです。追加型で、既存のすべての行は動き続けます。
- 単体または Quadlet のインストールは、初回起動時に MCP トークンを取得します。`hotloop mcp-token` が表示します。
- いつもどおり `helm upgrade` を実行してください。Quadlet ユニットは `:stable` に追従するため何も要りません。このリリースでは 4.18.11 への `helm rollback` で問題ありません。データベースはすでに PostgreSQL 17 で、ここでは何も変わりません。
