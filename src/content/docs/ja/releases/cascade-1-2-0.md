## 概要

1.2.0 で、MCP サーバーのツール一覧が完成します。エンジン、ワークフローのファイル形式、画面、REST API は 1.1.1 と同じです。

## 4 つのツール

HotLoop ファミリーのすべての MCP は読み書きができますが、Cascade のものには、キーが呼び出せるルートが 4 つ抜けていました。これらがツールになり、合計 83 個になります。

- `list_keys` と `revoke_key`: キーの持ち主のキーの一覧と、そのうち 1 つの取り消し。キーは自分自身を取り消せます。漏えいしたキーの持ち主が最初にできるべきことです。呼び出し元が誰のキーを取り消せるかは、エディターと同じく、ルート自身のチェックが決めます。
- `listen_workflow`: ワークフローのテスト用 Webhook URL を、1 回の呼び出しのために 1 秒から 600 秒の間開きます。
- `start_oauth`: OAuth2 認証情報でサインインするために人が開くアドレスを返します。人が許可する手順はそのまま必要です。

それぞれがルートを通るので、権限チェック、検証、監査の行はルートのものであり、書き込みは他の書き込みツールと同じく理由を求めます。

## 含まれないもの

10 のルートは、サインインした人を必要とするため、キー自体を拒否します。API キーまたはサービスアカウントキーの作成、SCIM トークンの作成、シークレットプロバイダーやログの送信先の追加、変更、削除、そして自分のパスワードです。キーを作れる、または監査ログの送信先を変えられるキーは、自分で生き延びる漏えいしたキーです。MCP のページに一覧と理由があります。

## amd64 のみの理由

このリリースは amd64 のみをビルドします。マルチアーキテクチャは別の実行で出すため、この次のリリースは、両方をビルドする小さなバージョンアップになります。

## アップグレードと戻し方

マイグレーションはありません。1.2.0 に `helm upgrade` するか、`:stable` に Quadlet ユニットを進めさせてください。データベースには何も変わりがないので、1.1.1 に戻しても安全です。ロールバックで元に戻せないのは、エージェントが新しいツールですでに行ったことです。
