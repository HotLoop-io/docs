すべてのメッセージが PLC の時計のタイムスタンプを持つようになり、ライブラリは CODESYS の `.package` からインストールできるようになりました。

これが意味すること:値がいつサンプリングされたかを知りたいサブスクライバーは、到着時刻から推測する代わりにパケットから得られ、ライブラリはほかのアドオンと同じように CODESYS Installer でインストールできます。

## 1.0.0 を使うプロジェクトでの変更点

* **タイムスタンプ、既定でオン。** NetworkMessage と DataSetMessage がそれぞれ Timestamp(パート 14、7.2.4.4.2 と 7.2.4.5.4)を持ち、どちらも PLC のリアルタイムクロックからメッセージごとに 1 回読む同じ DateTime です。ExtendedFlags1 は `01` から `21` に、DataSetFlags1 は `69` または `6B` から `E9` または `EB` に変わり、DataSetFlags2 のバイト `10` が加わります。メッセージは 17 バイト長くなります。フィールド一覧と値は変わらず、`udiConfigMajor` も同じです。
* **`bTimestamp := FALSE` は 1.0.0 と同じバイトをそのまま送ります。** 受信側がタイムスタンプを拒否する場合はこれに固定してください。確認済みです:1142 バイトと 1144 バイトのメッセージで、タイムスタンプなし、1.0.0 が送っていたサイズです。
* **分解能は 1 秒です。** 時計は整数秒を返す `SysTimeRtcGet` で読むため、受信側は 1 秒以内のすべてのメッセージで同じタイムスタンプを見ることになり、メッセージが作られた瞬間より最大 1 秒遅れることがあります。1 秒未満のタイムスタンプはロードマップにあります。
* **新しい出力 `diLastClockResult`。** 時計を読めない場合、メッセージはタイムスタンプなしで出ます。これはパート 14 が認めている動作で、この出力が理由を示します。
* **新しいシステムライブラリ SysTimeRtc。** ライブラリは SysSocket と同様にこれをプレースホルダーとして指定し、ランタイムが提供します。Control for Linux SL 4.22.0.0 は提供します。これがないターゲットはタイムスタンプ付きの 1.1.0 を使えないので、1.0.0 のままにしてください。
* **`.package`。** `HotLoopTransmitter-1.1.0.package` は CODESYS 自身の PackageManagerCLI で作られ、Installer を通じて同じライブラリをライブラリリポジトリに入れます。[インストールのページ](/ja/transmitter/install/)を参照してください。

## 実行したことと結果

すべて CODESYS Control for Linux SL 4.22.0.0 上で、下記のファイルを使って実行しました。

* ライブラリは CODESYS 3.5.22.30 でエラー 0、警告 0 でビルドできます。サンプルアプリケーションもこれに対してエラー 0、警告 0 でビルドできます。
* パブリッシャー 2 つ、Variant と RawData、タイムスタンプあり。仕様から書いた独立したデコーダーがすべてのメッセージをデコードし、すべての値が PLC が自身の OPC UA サーバーで報告する値と一致します。すべてのメッセージに両方のタイムスタンプがあり、同じ時刻で、後戻りせず、キャプチャを実行した時計の整数秒の許容範囲内にあり、11 秒のキャプチャでスタンプは 11 秒進みました。コンテナはホストの時計を共有するので、これはスタンプが作り物ではなく PLC の時計の読み取り値であることを示すもので、時計が狂ったコントローラーの試験ではありません。
* 独立した PubSub スタックが、各ライターの 113 メッセージすべての NetworkMessage と DataSetMessage の Timestamp を自前のヘッダーデコーダーで読み、値は 1.0.0 のときと同様にデコードします。
* HotLoop core のサブスクライバー(この実行時は main ブランチ、そして HotLoop core 4.19.4 以降のすべてのリリース)が、稼働中のランタイムに対して両方のパブリッシャーを読みます。各 21 値、カウンターは両方とも進み、拒否されたものはありません。各読み取りは、パブリッシャーの整数秒タイムスタンプをその時刻として持ち、3 秒の待機の間、スタンプは PLC の時計とともに進みました。
* `.package` は `PackageManagerCLI --install` でインストールでき、ライブラリが System リポジトリに現れ(以前はありませんでした)、サンプルは Installer が置いたとおりのライブラリに対してエラー 0、警告 0 でビルドできます。
* 20 ms タスク、パブリッシャー 2 つでのコスト:1 サイクルあたり平均約 9.6 us の追加、送信するサイクルでは 10 から 100 us、この実行で最長のサイクルは 81 us でした。この実行で公開スロットを 3 回飛ばし、拒否された送信はありませんでした。タイムスタンプ自体は数値には表れません。[タイミングのページ](/ja/transmitter/timing/)に表があります。

## コントローラーで確認すること

* ビッグエンディアンのターゲット向けのバイト順の処理は書かれていますので、お使いのコントローラーで確認してください。
* マルチキャスト:ブロックはグループの TTL、ループバック、送信インターフェースを設定しますので、お使いのネットワークでグループを確認してください。
* ネットワークが消えたりアドレスがなかったりすると、ブロックは失敗を数えて再試行の間隔を空け、プログラムはスキャンを続けます。
* デモモードでは、CODESYS の説明どおり、2 時間の枠が終わるとランタイムが停止します。
* リアルタイムクロックが未設定または誤っているコントローラーは、時計が示す値をスタンプします。

## このリリースに含まれないもの

KeepAlive と Delta Frame、1 つの NetworkMessage に複数の DataSetMessage、WSTRING、フィールドごとのステータス、1 秒未満のタイムスタンプ、メッセージのセキュリティ、サブスクライバー側。次に来るものは[ロードマップ](/ja/transmitter/roadmap/)に書いてあります。

## 元に戻す

1.0.0 に固定した PLC プロジェクトは動作を続け、1.0.0 のバイトを送り続けます。1.1.0 でも `bTimestamp := FALSE` は同じバイトです。
