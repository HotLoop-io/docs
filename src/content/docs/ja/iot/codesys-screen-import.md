description: "IDE から CODESYS のビジュアライゼーションをエクスポートし、PLC の変数に対する HotLoop の画面としてインポートします。配置できなかった要素は最初に一覧で示します。"
---

オペレーターの手元には、すでに CODESYS の画面があります。IDE からエクスポートして HotLoop にインポートすれば、同じ PLC の変数に対する HotLoop の画面として開きます。WebVisu から移る方法です。PLC はこれまでどおりプログラムを実行し、HotLoop は OPC UA コネクターで読み取り、画面は HotLoop のものになります。HotLoop for CODESYS は Edge を実行するので、これはそのインポートでもあります。

## 使い方

CODESYS IDE のプロジェクトツリーでビジュアライゼーションを選び、**プロジェクト、エクスポート**(CODESYS ネイティブのエクスポートで、`.export` ファイル)を使います。**PLCopenXML のエクスポート**ではありません。そのファイルにはビジュアライゼーションが含まれておらず、選ぶと HotLoop がそう伝えます。

ダッシュボード画面で**インポート**を押し、`.export` ファイルを選び、**ファイルを読み込む**を押します。次のことが示されます。

* 見つかったビジュアライゼーション(複数入ったファイルでは、どれにするか尋ねます)、
* 画面が読み取るのに、このインストールにないすべてのタグ。変数は `plc/<GVL>.<variable>` として届きます。デバイス `plc` を PLC がつながっている HotLoop のデバイスに対応付ければ、すべてのタグが一度に移ります。タグを 1 つずつ対応付けることもできます。
* **確認が必要なもの**: 画面に置けなかったすべての要素とその理由で、何かを保存する前に表示されます。

妨げるものがなくなるまで、何も保存されません。インポートには `dashboards.write` が必要で、書き込み可能と示されていないタグへのボタンや設定値は、ビルドのときと同じようにここで拒否されます。そのため、ゲートが拒否するコントロールが画面に残ることはありません。

API では、`file` の代わりに `codesys`(ファイルのテキスト)を付けて `POST /api/dashboards/import` を呼び、複数のうち 1 つを指定するには `visualization` を使います。

```json
{"codesys": "<ExportFile>...", "visualization": "Overview", "dryRun": true,
 "remap": {"devices": {"plc": "line-3"}}}
```

レポートには通常の `problems`、`warnings`、`remapped` があり、`mapped`(各要素が何になったか)と `unmapped`(各要素がなぜ変換されなかったか)を持つ `conversion` があります。

## 変換されるもの

| CODESYS の要素 | HotLoop では |
|---|---|
| 四角形、角丸四角形、テキストと変数を持つ楕円(`Temperature: %2.1f C`) | 値の表示: 変数のタグ、その前のテキストがキャプション、後ろのテキストが単位、小数桁数は書式から |
| 同じもので、テキストがあり変数がないもの | ラベル |
| ランプ | 変数で点灯し、ランプ自身の色で色付けされるランプ(赤は故障、黄は警告、青は情報、それ以外は運転ランプ)。`NOT x` はタグを逆に読む |
| メーター、ポテンショメーター | 変数の値の表示。値を設定していたつまみには、ダイヤルの目盛りを上下限とする設定値カードも付く |
| ロッカースイッチ、トグル、押しボタン | 状態を示すランプとボタンカード: トグルならオンとオフ、タップなら 1 つの値 |
| 多角形、折れ線、テキストも変数もない図形(配管、容器、枠) | シンボルの背後の絵で、点と色から描かれる |
| グループ | そのメンバーで、グループの角を基準に配置される |
| 要素の**Invisible**変数（`bInvisible`）、またはそのグループの変数 | シンボルの`show`ルール：変数が要素は見えるはずだと示している間だけ描画されます（`NOT x`で反転します） |
| 要素の**Toggle color**変数 | シンボルの`colors`ルール：変数がオンの間、要素自身のアラーム色にいちばん近いトーンで塗られます（赤は`bad`、黄とオレンジは`warn`、青は`info`、緑は`ok`。自前のアラーム色がない要素は、CODESYSの既定のアラーム枠が赤なので`bad`です） |

すべての要素はピクセル単位の位置を保ちます。ページはシンボルカードで、1 枚の拡大縮小される絵として描かれるので、画面はどのサイズでも、スマートフォンでも形を保ちます。

## 変換されないもの

インポート時に 1 つずつ 1 行で示し、黙って落とすことはありません。

* HotLoop のシンボルがない要素の種類(トレース、表、スライダー、画像要素、ツールボックスのその他)、
* 式である変数(`Temp * 2`、`a AND b`、配列の要素): HotLoop が表示するのはタグなので、式用のタグを追加し、値の表示をそれに向けてください、
* 背景の絵に描かれた図形（配管、容器、枠）にあるInvisibleまたはToggle colorの変数：絵は1枚の画像なので、図形は常にそこにあり、色もそのままです。取り込みの結果に、変数とともに記されます。
* PLCの値で動くそのほかの設定（塗り、枠、文字の色の変数、動き、点滅、テキストリスト）：シンボルは描かれたままそこにあり、その変数が単純な変数である場合はルールが報告されます。
* ベジェ曲線は点と点の間の直線として描かれ、回転した要素は回転されません、
* エクスポートに含まれないページサイズ: ページは最も外側の要素の大きさに余白を足した大きさです、
* 40 文字を超えるテキストは切り詰められ、ダイヤルは数値であってダイヤルではありません。

CODESYS スタイルのテキストスタイル、フォント、色は HotLoop のものです。画面は HotLoop のテーマに従います。

## ファイルの読み方

CODESYSは、ネイティブのエクスポートがありXMLであることは文書化していますが、その中身は文書化していません。ここのリーダーは、IDE自身が書き出す内容に従います（CODESYS 3.5 SP22、Visualization 4.10）。各要素は設定を番号付きメンバーのリストとして保存し、その番号は要素の記述内でのメンバーのパスのCRC-32です。たとえば`m_StaticPosition.iX`で、IDEが自分の隣にインストールします。IDE自身の要素ツリーは、すべてのパスをIDとともに一覧にしており（`ITypeNode.CompletePath`と`CRCIdNumber`）、Invisible変数（`m_pStateVariables..State.bInvisible`、2880254039）とToggle color変数（`m_pColorVariables..ToggleColor`、1999528970）のIDはそこから得たものです。前者は、CODESYSのRefrigeratorの例がグループの`NOT Glob_Var.DoorOpen`を保存するIDです。テストには、IDE自身のエクスポートから読んだ値が入っています。変数を持つのに読まれない設定は上記のように報告されるため、画面が完全でないのに完全なものとして取り込まれることはありません。

## 次のステップ

画面を開き、値の表示を工場と照らし合わせ、設定値カードとボタンカードをオペレーターが期待する場所に置いてください。手で作った画面とインポートした画面は、ここから先は同じものです。[画面ファイル](/ja/iot/screen-file/)としてエクスポートでき、保存のたびにバージョンが残り、同じ方法で別のインストールに移せます。

## TwinCATのビジュアライゼーション（.TcVIS）

TwinCATの`.TcVIS`ファイルは、IDEのオブジェクトアーカイブXMLで表された同じビジュアライゼーションで、要素タイプとメンバーIDも同じなので、同じコンバーターを通ります。TwinCAT本物のPackMLの例で確認しています。

- ボタン：ボタンの入力アクションにある単純な代入（`X := 5`、`X := TRUE`、`X := E_PMLCommand.ePMLCommand_Start`）は、その値をXに書き込むボタンカードになり、キャプションはラベルとして取り込まれます。設定されたToggle入力は、オンとオフのボタンのペアになります。代入以上のコード（条件、呼び出し、演算）は、そのテキストとともに報告されます。
- 列挙型：OMAC PackMLのメンバー（`E_PMLCommand`、`E_PMLUnitMode`）は既知で、番号はBeckhoffのPackML_HMI_Example構成とSPT-Librariesの`E_PMLUnitMode`宣言によります。そのほかの列挙型は、取り込みの`enums`に入れます（`{"E_Own.eOwn_Go": 7}`）。番号が不明なメンバーは名前で書かれ、レポートにその旨が記されます。
- 式：ランプの変数とInvisible変数は、1つのタグと数値、TRUE、FALSE、列挙型メンバーの比較（`=`、`<>`、`<`、`<=`、`>`、`>=`）、NOT、AND、ORを、括弧つきで使った式にできます。これらはシンボルのルールになります（DASHBOARDS.mdを参照：ランプの`lit`ルール、シンボルの`show`と`colors`ルールで、ルールは`all`と`any`で組み合わせられます）。2つのタグの比較、演算、呼び出しは表現できず、できなかった部分とともに報告されます。
- フレーム：フレームは別のビジュアライゼーションを表示します。プロジェクトのほかのファイルを最初のファイルと一緒に送ってください（APIでは`codesysRelated`、ダイアログでは複数のファイルを選び、最初のものが画面になります）。フレームのビジュアライゼーションはフレーム内に置かれ、受け取る各入力はフレームに渡された変数に結び付けられます（V_Moduleの`HMI`は`MAIN.VFFSDemo.Sealer.PackMLBaseModule_HMI`になります）。ビジュアライゼーションがファイルの中にないフレームは、その名前とともに報告されます。

PackMLのセット（V_MainとV_Module、V_MachineModule）：60要素がマッピングされ、マッピングされなかったものはありません。
