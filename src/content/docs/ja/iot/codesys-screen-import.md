オペレーターの手元には、すでに CODESYS の画面があります。IDE からエクスポートして HotLoop にインポートすれば、同じ PLC の変数に対する HotLoop の画面として開きます。WebVisu から移る方法です。PLC はこれまでどおりプログラムを実行し、HotLoop は OPC UA コネクターで読み取り、画面は HotLoop のものになります。HotLoop for CODESYS は Edge を実行するので、これはそのインポートでもあります。

## 使い方

CODESYS IDE のプロジェクトツリーでビジュアライゼーションを選び、**プロジェクト、エクスポート**(CODESYS ネイティブのエクスポートで、`.export` ファイル)を使います。**PLCopenXML のエクスポート**ではありません。そのファイルにはビジュアライゼーションが含まれておらず、選ぶと HotLoop がそう伝えます。

ダッシュボード画面で**インポート**を押し、`.export` ファイルを選び、**ファイルを読み込む**を押します。次のことが示されます。

* 見つかったビジュアライゼーション(複数入ったファイルでは、どれにするか尋ねます)、
* 画面が読み取るのに、このインストールにないすべてのタグ。変数は `plc/<GVL>.<variable>` として届きます。デバイス `plc` を PLC がつながっている HotLoop のデバイスに対応付ければ、すべてのタグが一度に移ります。タグを 1 つずつ対応付けることもできます。
* **確認が必要なもの**: 画面に置けなかったすべての要素とその理由で、何かを保存する前に表示されます。

妨げるものがなくなるまで、何も保存されません。インポートには `dashboards.write` が必要で、書き込み可能と示されていないタグへのボタンや設定値は、ビルドのときと同じようにここで拒否されます。そのため、ゲートが拒否するコントロールが画面に残ることはありません。

API では、`file` の代わりに `codesys`(ファイルのテキスト)を付けて `POST /api/dashboards/import` を呼び、複数のうち 1 つを指定するには `visualization` を使います。

```json
{"codesys": "<ExportFile>...", "visualization": "Overview", "dryRun": true,
 "remap": {"devices": {"plc": "line-3"}}}
```

レポートには通常の `problems`、`warnings`、`remapped` があり、`mapped`(各要素が何になったか)と `unmapped`(各要素がなぜ変換されなかったか)を持つ `conversion` があります。

## 変換されるもの

| CODESYS の要素 | HotLoop では |
|---|---|
| 四角形、角丸四角形、テキストと変数を持つ楕円(`Temperature: %2.1f C`) | 値の表示: 変数のタグ、その前のテキストがキャプション、後ろのテキストが単位、小数桁数は書式から |
| 同じもので、テキストがあり変数がないもの | ラベル |
| ランプ | 変数で点灯し、ランプ自身の色で色付けされるランプ(赤は故障、黄は警告、青は情報、それ以外は運転ランプ)。`NOT x` はタグを逆に読む |
| メーター、ポテンショメーター | 変数の値の表示。値を設定していたつまみには、ダイヤルの目盛りを上下限とする設定値カードも付く |
| ロッカースイッチ、トグル、押しボタン | 状態を示すランプとボタンカード: トグルならオンとオフ、タップなら 1 つの値 |
| 多角形、折れ線、テキストも変数もない図形(配管、容器、枠) | シンボルの背後の絵で、点と色から描かれる |
| グループ | そのメンバーで、グループの角を基準に配置される |

すべての要素はピクセル単位の位置を保ちます。ページはシンボルカードで、1 枚の拡大縮小される絵として描かれるので、画面はどのサイズでも、スマートフォンでも形を保ちます。

## 変換されないもの

インポート時に 1 つずつ 1 行で示し、黙って落とすことはありません。

* HotLoop のシンボルがない要素の種類(トレース、表、スライダー、画像要素、ツールボックスのその他)、
* 式である変数(`Temp * 2`、`a AND b`、配列の要素): HotLoop が表示するのはタグなので、式用のタグを追加し、値の表示をそれに向けてください、
* PLC の値で動く表示、色、動きのルール: シンボルは常に表示され、色は変わりません、
* ベジェ曲線は点と点の間の直線として描かれ、回転した要素は回転されません、
* エクスポートに含まれないページサイズ: ページは最も外側の要素の大きさに余白を足した大きさです、
* 40 文字を超えるテキストは切り詰められ、ダイヤルは数値であってダイヤルではありません。

CODESYS スタイルのテキストスタイル、フォント、色は HotLoop のものです。画面は HotLoop のテーマに従います。

## ファイルの読み方

CODESYS は、ネイティブのエクスポートがあり XML であることは文書化していますが、中身は文書化していません。ここのリーダーは、IDE 自身が書き出すもの(CODESYS 3.5 SP22、Visualization 4.10)に従います。各要素は設定を番号付きメンバーのリストとして保存し、その番号は要素の記述内のメンバーのパス(`m_StaticPosition.iX` など)の CRC-32 です。この記述は IDE が自分の隣にインストールします。テストには IDE 自身のエクスポートから読み取った値が含まれます。変数を持つのに読み取られない設定は上記のとおり報告されるので、不完全な画面が完全なものとしてインポートされることはありません。

## 次のステップ

画面を開き、値の表示を工場と照らし合わせ、設定値カードとボタンカードをオペレーターが期待する場所に置いてください。手で作った画面とインポートした画面は、ここから先は同じものです。[画面ファイル](/ja/iot/screen-file/)としてエクスポートでき、保存のたびにバージョンが残り、同じ方法で別のインストールに移せます。
