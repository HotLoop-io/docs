HotLoop for CODESYS は、CODESYS ランタイムと同じノードで動く HotLoop です。ランタイム自身の OPC UA サーバー経由で PLC の変数を読み、パネル PC、スマートフォン、壁面で動く画面に表示し、それに対するアラームを出し、履歴を保存します。CODESYS には何もインストールせず、PLC に書き込むものもありません。本来は CODESYS WebVisu で作る画面を、ランタイムの外で描くものです。得られるもの: オペレーターは PLC へのダウンロードなしで画面を使え、PLC はノード上のほかの何にも依存しない、もう 1 組の目を得ます。

HotLoop の 8 つの製品の 1 つで、独自のリリースラインを持ちます。最新のチャートは 2026-11-16 公開の 0.3.8 です。その下には HotLoop Edge があるため、[Edge のページ](/ja/edge/overview/)の内容はここにもすべて当てはまります。

![同じ画面、ダークモード](/codesys/screen-dark.png)

これは実際の実行です。HotLoop の標準インターフェースが CODESYS Control for Linux SL 4.22.0.0 ランタイムを読んでいます。PLC のプログラムは HotLoop 自身のデモプログラムなので、数値はデモのものです。ラベル (Line 2、Mixer temperature、Riverside Bottling) は架空のもので、[プロファイル](/ja/codesys/profile/)が付けています。

## 3 つの部分

| 部分 | 内容 | 場所 |
|---|---|---|
| チャート `hotloop-codesys` | ノード上のランタイム向けの既定値を持つ `hotloop-edge` のラッパー: SQLite、レプリカ 1 つ、PLC の隣で不要なものはオフ。HotLoop チャートの修正はすべてここにも届きます。 | `https://hotloop.io/hotloop-codesys/` |
| プロビジョナー | プロファイルを HotLoop に適用し、正しい状態に保つ静的な Go バイナリ 1 つ。プロファイルは持ちません。 | `ghcr.io/hotloop-io/hotloop-provision` |
| プロファイル | JSON ファイル 1 つ: デバイス、保持する変数、アラーム、画面 1 つ。利用者が与える唯一の入力。 | インストールの名前空間にある Secret、[こちらで説明](/ja/codesys/profile/) |

## PLC の読み方

CODESYS がサードパーティにコントローラーの変数の読み取り方として文書化しているのは 1 つだけで、ランタイム自身の OPC UA サーバーです。PLC は IDE の Symbol Configuration で見せたいものを公開し、HotLoop はその変数を、ノード ID ではなくプログラマーが付けた名前、たとえば `Application.GVL_Line.rTemp` で読みます。Symbol Configuration が、PLC プロジェクトに必要な唯一の変更です。CODESYS Gateway のチャネルプロトコルはサードパーティ向けに文書化されておらず、この製品はそれを話しません。

読み取りは HotLoop core の CODESYS コネクターが行います。これは OPC UA ドライバーに、CODESYS PLC に必要なものを加えたものです。アプリケーションがエクスポートするものと型の検出、フィールドごとに 1 ポイントになるまで展開した配列と構造体、再起動やダウンロードのあとに人手なしで行う再接続、ランタイムが公開する上限に合わせたすべての要求です。[プロトコルのページ](/ja/iot/protocols/)に HotLoop 4.19.4 以降のコネクターのリファレンスがあり、何に対して検証し、何に対して検証していないかも書かれています。

## 自動で行うこと

HotLoop とノード上のランタイムの両方が応答すると、プロビジョナーがプロファイルのデバイス、変数、アラーム、画面を設定します。その後は 5 分ごとに再確認します。その間に PLC に増えたプロファイルの変数は追加され、PLC からなくなった変数は、サーバーが示す理由つきで不良として読まれます。画面とアラームは、なければ作られ、プロファイルの `revision` が作成時より高いときだけ置き換えられます。そのため、人が行った変更は、意図的に新しいプロファイルが配備されるまで残ります。

## しないこと

- **PLC には書き込みません。** プロビジョナーが設定するタグはすべて読み取り専用で、プロファイルに書き込み可能にする指定はありません。あとから人がタグを有効にでき、そのときは[書き込みゲート](/ja/gateway/write-gate/)と PLC 自身のシンボル権限の両方が関わります。
- **ランタイムには何も入れません。** ライブラリも、タスクも、エージェントもありません。
- **データベースのポッドは不要です。** ノード自身のストレージ上の SQLite、レプリカ 1 つ。
- **リンクが切れても画面を保てるように作られています。** 両方のポッドが、到達不能または未準備のノードを時間制限なしで許容し、その許容設定はチャートに入っています。実機のノードで何を動かしたかは[現状](/ja/codesys/where-it-stands/)にあります。
