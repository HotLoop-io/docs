2 つの Flow は 1 つ分の仕事を分担できます。一方はライターで、設備に何かを送るのはこれだけです。もう一方はスタンバイで、同じフローを実行し、読み取り、サブスクライブし、コンテキストを温めておきますが、ライターの代わりになるまで設備への書き込みをすべて保留します。ライターが落ちる、固まる、リンクを失うといった場合、スタンバイはリース 1 つ分ほどの時間で引き継ぎ、ライターだったほうはリースを取り戻すまで再び書き込めません。

これは、再起動では十分に速くなく、2 つ目のライターが短い待ち時間より悪い場合のためのものです。再起動で十分に速いなら、インストールを 1 つにして Kubernetes に再スケジュールさせるほうが簡単で、チャートの既定の動作でもあります。

## 仕組み

リースは、両方のインストールから到達できる PostgreSQL の 1 行です。ライターは数秒ごとにそれを更新します。スタンバイは同じ間隔で取得を試み、期限が切れた後にだけ取得できます。保持者が変わるたびに、その行のフェンシング番号が上がり、Flow がそれを報告します。

設備への書き込みは、送信する直前に同じ問いを立てます。書き込みに必要な分より多くのリースが残った状態で、自分はリースを保持しているか。そうでなければ、書き込みはカウントされるエラーとともに拒否されてフローの Catch ノードに届き、接続すら含めて何も送られません。書き込みのたびにその瞬間に行うこの確認が、2 つのインストールが同時に書き込むのを防ぎます。

- 保持者はリースを、リクエストした時点から数えます。応答が返ってきた時点からは数えないので、データベースより長い時間があると思い込むことはありません。
- 保持者は、残りのリースが書き込みに必要な分(`writeMargin`)を下回ると書き込みを止めます。これはリースが切れる前です。スタンバイがリースを取れるのは、期限が切れた後だけです。したがって重なりはなく、間が空きます。
- 凍結されて解凍された保持者、あるいは切断されて再接続した保持者は、リースがなくなっていることを知り、書き込みを拒否し、ほかと同じようにリースを要求します。
- リースがいつ終わるかはデータベースの時計が決めるので、時計が合っていない 2 台のマシンでも、誰が保持しているかについては一致します。

問いを立てる書き込みは、設備に命令できるものです。`modbus write`、`s7 write`、`opcua write`、`ethernetip write` が、直接でも HotLoop の書き込みゲート経由でも対象で、`hotloop script` と `hotloop recipe` ノード、そして FlowLab ダイアグラムではシリアル書き込み、書き込みを行う計器コマンド(その計器自身の書き込みスイッチに加えて)、HotLoop への書き込みが含まれます。MQTT ブローカー、データベース、通知へのメッセージ送信はフェンスの対象ではありません。設備への命令ではなく、繰り返しても、繰り返された設定値のような害がないからです。フローテストは外の世界の代わりを務めるので、保留されることはありません。

## コストと、得られないもの

- **引き継ぎ時間**はおおよそリースの長さです。既定値(リース 15 秒、5 秒ごとに更新、マージン 5 秒)では、ライターを強制終了してから 14.7 秒後にスタンバイが引き継ぎました。リース 6 秒では 5.7 秒でした。きれいに停止したライターはリースを手放し、スタンバイは 0.35 秒で引き継ぎました。
- **`writeMargin` より長くかかる書き込み**は、リースより長く生き残ることがあります。書き込みを行うノードのプロトコルタイムアウトは、これより短く保ってください。プロセスが凍結されたときにすでに送信中の書き込みは、確認をすでに通過しており、まだ届く可能性があります。
- **少なくとも 1 回。** 確認応答が失われた書き込みを受け取った PLC は、新しいライターがそれを再送するのを見ることがあります。設定値なら安全ですが、パルスやインクリメントではそうではないので、差分ではなく設定値を書いてください。
- **キューはローカルに残ります。** 耐久ワイヤーとコンテキストは、各インストール自身のディスクにあります。落ちたライターでキューにあったものは、スタンバイにはありません。
- **データベースは依存先です。** データベースに到達できないライターは更新できず、リースが残り少なくなると書き込みを止めます。リースは、守る設備と少なくとも同じ程度に可用性の高いデータベースに置いてください。

## 設定

Flow を 2 回、2 つの Helm リリースまたは 2 つの Quadlet ユニットとして、それぞれ独自のボリュームでインストールし、両方を同じリースに向けます。2 つ目には 1 つ目と同じフローファイルを渡し、ステーションへのプッシュ([テナントのステーションへプッシュ](/ja/flow/stations/))でそのまま保ってください。Flow は 2 つの間でフローをコピーしません。

| 設定 | 環境変数 | 内容 |
|---|---|---|
| `failover.urlFile` | `HOTLOOP_FLOW_FAILOVER_URL_FILE` | リースデータベースの PostgreSQL URL を収めたファイル。これを設定するとフェイルオーバーがオンになります。 |
| `failover.name` | `HOTLOOP_FLOW_FAILOVER_NAME` | リース。両方で同じです。既定は `flow`。 |
| `failover.holder` | `HOTLOOP_FLOW_FAILOVER_HOLDER` | このインストール自身の名前。2 つの間で異なる必要があり、既定はホスト名です。 |
| `failover.ttl` | `HOTLOOP_FLOW_FAILOVER_TTL` | 1 回の付与が続く時間で、したがっておおよその引き継ぎ時間です。既定は `15s`。 |
| `failover.renewEvery` | `HOTLOOP_FLOW_FAILOVER_RENEW_EVERY` | 保持者が再び要求する頻度。既定は ttl の 3 分の 1。 |
| `failover.writeMargin` | `HOTLOOP_FLOW_FAILOVER_WRITE_MARGIN` | 書き込みに残っているべきリースの量。既定は `5s`。 |

設定によって保持者が更新の合間にマージンを下回ってしまう場合、たとえばマージンが ttl と同じ長さの場合、Flow は起動を拒否します。

チャートでは `failover.urlSecret`(キーに URL を持ち、ファイルとしてマウントされ、ConfigMap には決して入れない Secret)、`failover.name`、`failover.ttl`、`failover.renewEvery`、`failover.writeMargin` です。Quadlet では上の環境変数で、URL はファイルとしてマウントされる Podman シークレットです。

```ini
Environment=HOTLOOP_FLOW_FAILOVER_URL_FILE=/run/secrets/flow-lease-url
Environment=HOTLOOP_FLOW_FAILOVER_NAME=line3
Secret=hotloop-flow-lease-url,type=mount,target=flow-lease-url
```

## 確認する

- `GET /failover`(および MCP ツール `get_failover`)は、このインストールが `active`、`standby`、`lost` のどれか、誰がリースを保持しているか、保持しているフェンシング番号、何が書き込んでいたかによる保留した書き込み数を伝えます。`status.read` が必要で、フェイルオーバーが設定されている場合にのみ存在します。
- エディターは、スタンバイと、リースを失った保持者にバナーを表示します。
- メトリクスのエンドポイントには、`hotloop_flow_failover_active`、`hotloop_flow_failover_epoch`、`hotloop_flow_failover_takeovers_total`、`hotloop_flow_failover_refused_total{op}` があります。
- 両方のインストールが、リースを取得したときと奪われたときにログを残します。

## 実証されたことと、されていないこと

2 つの実際の Flow プロセスを、実際の PostgreSQL と、すべての書き込みを記録する Modbus TCP サーバーに対して動かして実証しました。各インストールは 200 ms ごとにタグ付きの値を書き込みました。ライターをストリームの途中で強制終了すると、スタンバイは 1 リース後に引き継ぎ、スタンバイの書き込みはライターの最後の書き込みより前にも後にもありませんでした(0 と 0)。ライターをリースより長く凍結して解凍しても、再び書き込みませんでした。ライターをきれいに停止すると、スタンバイは 0.35 秒で引き継ぎました。上記の各書き込み経路のテストは、スタンバイや失効した保持者の書き込みが、何かが送られる前に拒否されることと、ゲートが開いていれば同じ書き込みが送られることを示しています。

実証されていないこと: 繰り返された書き込みに対する実際の PLC の動作、リースの下でのデータベースのフェイルオーバー、片方向だけが切れたネットワーク。Modbus サーバーはプロトコルを話すシミュレーターです。フェイルオーバーはクラスターでは試しておらず、チャートの値と Quadlet の行はレンダリングして確認したもので、インストールはしていません。エディターのバナーの文言は、ネイティブスピーカーによるレビューを受けていません。
