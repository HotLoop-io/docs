HotLoop Flow がこれから何になるのかを、作る順に並べました。このリストにないものは作りません。必要なものはリストに載せてください。

Flow は HotLoop と並行して作られ、独立した製品のままです。FlowLab とそのダイアグラムであるフェーズ 9 は、メッセージランタイムの隣に置かれる別パックです。

## Flow の目的

工場の現場のための、ビジュアルなフローエンジンです。すべてのデプロイは差分が取られ、テストされ、ワンクリックで元に戻せます。午前3時に何かがおかしくなったとき、メッセージがどの経路を通り、各ホップでどんな状態だったかを正確に確認できます。1つの静的バイナリで動き、Pi に載るほど小さく、センサーがおしゃべりになっても止まりません。

既存の `flows.json` も変更せずにそのまま読み込めます。それは機能であって、主眼ではありません。

以下のすべての項目が守るルールは次のとおりです。

- スタブはありません。作られていない、実物でテストされていない、動いていないものにはチェックを付けません。
- 機器に指令を出せるものはすべて、拒否できるゲートを通り、拒否したときは理由を示します。
- 何も黙って捨てられることはありません。破棄、拒否、あふれはすべて数えられ、メトリクスに表示されます。
- フローファイルはバイト単位で同じまま読み込まれ、保存されます。新しいデータは他のツールが無視するキーに入り、往復テストはそれらを含むファイルも対象にします。

### フェーズ 0: 事実を伝える

README には、コードの裏付けがない主張があります。新しいことを約束する前に、まずそれを直します。一度でも嘘をついた README は、その後ずっと嘘のように読まれるからです。

- [x] WASM サンドボックスは実在しテスト済みですが、それを使うノードはなく、バイナリにも入っていません。フェーズ 6 で事実になるまで、そのように明記します
- [x] 存在しない組み込みのコンテキストストアを指すコードコメントが 2 か所ありました。削除しました
- [x] アイドル時と負荷時のメモリを同じ機器で同じ方法で測り直し、数値と一緒にそのコマンドを公開し、誰も再現できない数値は外します
- [x] CVE-2025-41656 は、別のフローエンジンを認証オフで出荷したベンダーの問題であり、そのエンジン自体の CVE ではありません。README と `docs/compatibility.md` の `exec` の行で出典を直します
- [x] README の冒頭を、Flow が何をするかを軸に書き直します。既存フローのインポートは下の独立した節に移し、バイト単位の往復と `hotloop-flow import` を裏付けとします
- [x] デプロイのドキュメントは、1 社の App Store ではなく Kubernetes、Podman、Quadlet を扱います
- [x] テストがなかったパッケージのテスト: `api`(ログイン、権限、古いデプロイに対する 409)、`config`(README に書かれたすべての起動拒否)、`cmd`(デプロイは古いランタイムを止める前にフローファイルを書きます)、そして同じくテストがなかった Function ノードのサンドボックスである `js`

### フェーズ 1: 履歴、差分、ロールバック

すべてのデプロイは 1 件の記録です。誰が、いつ、メモ、正確なバイト、何が変わったかが残ります。ラインが止まったあと誰もが最初に尋ねるのは「何が変わって、誰が変えて、元に戻して」ですが、今その答えは `.bak` ファイル 3 つです。

- [x] デプロイログ: すべてのデプロイは、ユーザー、時刻、任意のメモ、フローのバイト、そのときの暗号化された認証情報を持つ不変の記録です。保持期間は設定で決めます。`GET /deployments`
- [x] 意味単位の差分: ノードごと、プロパティごとに比べます。追加、削除、変更、配線の変更を区別します。ノードをドラッグして動かしても、ロジックの変更ではなくレイアウトとして表示されます。API と `hotloop-flow diff a.json b.json` で使えます
- [x] この差分は git difftool としても動くので、フローのプルリクエストが JSON の塊ではなく「ルール 2 のしきい値 7.5 から 8.0」のように読めます
- [x] ロールバック: 古い記録を新しい記録として再デプロイし、認証情報も戻すので、削除したノードがブローカーのパスワードごと戻ってきます。履歴は追記のみのままです
- [x] エディタ: 履歴パネル、キャンバスに描かれる差分、メモ付きの「レビューしてデプロイ」、ロールバックボタン。デプロイが衝突したときは、はい/いいえの箱ではなく、相手が何を変えたかを表示します
- [x] コードとしてのフロー: CI/CD 向けの `hotloop-flow deploy` と `hotloop-flow export`、そしてデプロイ専用トークンにより、パイプラインが管理者パスワードを持つことはありません
- [x] 任意の git ミラー: すべてのデプロイを、デプロイした本人を作者とするコミットとしてプッシュします。純粋な Go で、バイナリサイズの検査も引き続き通ります
- [x] 監査ログ: ログイン、ログイン失敗、デプロイ、ロールバック、インジェクトを、誰がどこからかとともに記録します。デプロイログがその最初のテーブルです
- [x] MFA(TOTP)は無料で、使いたい人なら誰でも有効にできます。安全にサインインするための機能は、決して有料の壁の向こうに置きません
- [x] ログインのレート制限とロックアウト、再起動後も続くセッション、そして URL ではなくサブプロトコルで送る WebSocket トークン。URL の中のトークンは既存のスクリプトのために引き続き動き、警告を記録します。アップグレードでスクリプトが壊れることのほうが、漏えいより悪かったためで、廃止はメジャーリリースまで待ちます

### フェーズ 2: フローテスト

「自分の変更でラインが壊れたか」には、デプロイのあとではなく前に答えます。テストはフローの隣に置く YAML なので、同じ方法で差分を取り、レビューできます。

- [x] `hotloop-flow test`: 本物のランタイムと本物のノードを、プロセス内で動かします。メッセージを注入し、期限内にポートから出てくるものを期待し、何も出ないことを期待し、エラーが Catch に届くことを期待します。CI/CD 向けに JUnit 出力があります
- [x] 仮想化された I/O: テスト中の MQTT out、データベースへの書き込み、HTTP リクエストは、送るはずだった内容を記録するだけで、ネットワークには触れません
- [x] 仮想クロック: 5 分の Delay が数ミリ秒で終わり、すべてのタイミングノードがこれを使って検証されています
- [x] コンテキストと認証情報のフィクスチャ、そしてその後のコンテキストに対するアサーション。1 つのテストが、別のテストの残したものに頼ることはできません
- [x] デプロイゲート: 有効にすると、テストに失敗したデプロイは失敗したアサーションとともに拒否され、すでに動いているフローは影響を受けません
- [x] エディタ: 取り込んだデバッグメッセージを 2 クリックでテストに変え、エディタからスイートを実行し、ノードに合格と不合格を表示します

### フェーズ 3: トレースとリプレイ

- [x] デバッグメッセージをクリックすると、キャンバス上でそのメッセージが通った経路が光り、分割、結合、サブフローを抜けて、各ホップの所要時間とペイロードが表示されます
- [x] 容量が決まったトレースバッファ。100 万メッセージのソークテストでもメモリは横ばいで、その数値を公開します
- [x] 取り込んだメッセージをフローの下書きにリプレイし、出力を比較します
- [x] 取り込んだトレースがフェーズ 2 のテストになります
- [x] OpenTelemetry エクスポート、本物のコレクターで検証済みです

### フェーズ 4: 永続的な状態

ヒストリアンが 1 時間止まっても、1 時間分の測定値を失うべきではありません。

- [x] SQLite による永続コンテキスト: 純粋な Go で cgo はなく、アトミック操作(比較して入れ替え、加算、更新)を備えます。ストアは、今はコンテキスト用、次は永続キュー用に、2 つではなく 1 つです。現状ではフローとグローバルのコンテキストが再起動のたびに消え、誰かが最初につまずく可能性の高い穴です。30 秒ごとに 1 回のトランザクションで遅延書き込みし、すでに同じ値の値は書き込みません
- [x] 永続ワイヤー: ワイヤーを永続にすると、そのキューは止まったり捨てたりする代わりに、同じストアへあふれ出ます。再起動後も残り、順序を守り、ディスククォータに従い、深さはメトリクスになります。フローファイルでは `ew_durable` で印が付くので、往復はバイト単位で同じままです。エディタでワイヤーをダブルクリックすると印が付きます
- [x] 保存と転送を最も厳しい方法で検証しました。一定の入力のもとで本物の InfluxDB を 10 分間止めてから戻し、行を数えます。欠けも重複もありませんでした。次にキューの途中でランタイムを kill -9 で落とし、もう一度数えます。スクリプト、件数、1 時間あたりのディスク書き込みは [durable/](/ja/flow/durable-state/) にあります
- [x] 本物の Pi 5 で検証: メモリ、起動時間、持続スループットは [docs/bench](/ja/flow/benchmarks/#raspberry-pi-5-での結果) にあり、見られたスロットリングも載せています
- [ ] Pi 4 と Zero 2 W での検証と、カードでの 1 時間あたりの SD カード書き込み量。SD カードを削り続けるコンテキストストアはバグだからです。ボードが必要なので未完了です。Pi 5 は測定済みで、ほかの機器の数値はでっち上げになってしまいます

### フェーズ 5: 工場の現場

`scan` は今 PLC を見つけますが、パレットのどのノードもそれと通信できません。工場向けに作られた製品として、いちばん大きな穴です。

- [x] Modbus TCP の読み取りと書き込み
- [x] OPC UA の読み取り、サブスクライブ、書き込み
- [x] S7 の読み取りと書き込み
- [x] Sparkplug B、エッジノードとしてもホストとしても
- [x] EtherNet/IP の読み取りと書き込み
- すべてシミュレーターです。どの Siemens CPU も Logix コントローラーも、これらの前に置かれたことはありません
- [x] HotLoop ノード: エンティティの変更の受信、エンティティの状態、スクリプトの呼び出し、レシピの適用。すべての指令は HotLoop の書き込みゲートを通り、`flow:<node id>` としてログブックに記録され、ゲートが拒否した書き込みは、ゲートの理由とともに Catch ノードに届きます
- [x] HotLoop がある場合、Flow の機器への書き込みは PLC に直接ではなく HotLoop のゲートを通ります。どちらも 2.3.0 で出荷されました。本物のゲートを通る書き込みは、公開されている HotLoop イメージに対して Modbus で検証済みです。OPC UA、S7、EtherNet/IP の書き込みノードも同じコードで送信し、それぞれがゲートを提供することをテストが確認します。

### フェーズ 6: npm なしのプラグイン

- [x] すでにあるホスト上の `wasm` ノード: メモリには厳格な上限とタイムアウトがあり、どちらかを超えたゲストは、ほかに影響を与えずにトラップされます
- [x] プラグイン形式: モジュール、エディタがダイアログを描くための記述子、そして署名。署名のないプラグインや改ざんされたプラグインは、読み込みを拒否し、その理由を伝えます
- [x] ケイパビリティ: プラグインは、マニフェストが要求し、オペレーターが許可しない限り、ホストに触れません。許可されていないものを要求すると、デプロイが失敗します

### フェーズ 7: 型付きワイヤーと MCP

- [x] `json` ノードでのスキーマ検証、最初の一歩
- [x] ポートの任意のスキーマ。エディタが見つけられる不一致はデプロイで拒否され、見つけられないものは、問題のあるフィールドのパスとともに Catch ノードとメトリクスへ送られます
- [x] エディタでワイヤーの上に型を表示します
- [x] ツールとしてのフロー: tool ノードが名前、説明、入力スキーマを宣言すると、Flow が `/mcp` を提供します。フローを呼び出すエージェントは、人と同じ権限と同じ監査ログを持ちます
- [x] MCP クライアントノード: フローが、HotLoop を含む他のサーバーのツールを呼び出せます
- [x] Flow 自身の MCP ツール: フローの一覧、読み取り、デプロイ、ロールバック、デプロイの一覧、inject ノードの押下。管理 API 自身のハンドラーを通すので、同じ権限、同じデプロイ検査、同じ監査証跡が適用されます。フローの作者が配線したものしか呼べない MCP では、Flow 自体を読むことも書くこともできないからです
- [x] ダイアグラムと計測器のための Flow 自身の MCP ツール: ダイアグラムの一覧と読み取り、実行と停止、デバッガーの操作、パネルのコントロールの設定、ブレークポイントとプローブの設定、サブダイアグラムの作成、計測器の書き込みの確認と切り替え。それぞれ管理用のルートを、そのルートが求める権限(`status.read`、`diagram.run`、`instrument.write`)で、自身のハンドラーを通して実行します。これまでダイアグラムのルートにはツールがなく、エージェントはダイアグラムをデプロイできても実行はできませんでした。今ではすべての管理ルートがツールであるか、人が行うべきものとしてテストに名前が挙げられており、ツールなしで新しいルートが追加されるとテストが失敗します。ステーション、フェイルオーバー、トレースのツールを含めて、ツールは 44 個になりました

### フェーズ 8: Astro で書き直したエディタ

完了し、前倒ししました。もともとは最後の予定でしたが、Flow の最初のスクリーンショットより前に移しました。別の会社のもののように見えるエディタで、最初の画面を見せるべきではないからです。

HotLoop のすべてのプロジェクトが 1 つの現代的な UI を持つことになり、このエディタだけが合っていませんでした。ネイティブ SVG の上に手作りした素の TypeScript で、監査すべきものがない小さな静的バイナリが目標だった当時は正しい選択でした。今は Svelte アイランドを使う Astro で、Cascade のエディタと同じスタック、同じ HotLoop トークン、ライトとダークの両対応です。

- [x] Astro のコードを 1 行書く前に、まずデザインの検討。エディタが HotLoop のほかの部分と並んだときの見た目と使い心地を、紙と共有トークンの上で決めておき、作り直しは進めながら決める作業ではなく、すでに決まったものを作る作業になります
- [x] キャンバス、ダイアログ、履歴、レビュー、テスト、トレース、検索、グループをすべて引き継いで Astro で作り直したエディタ。どれ一つ悪くなってはいけません。`web/e2e` のブラウザテストが基準で、新しいエディタに対して変更なしで通ります
- [x] 引き続き 1 つの静的バイナリに組み込まれ、エッジ機器でもネットワークが不要で、バイナリサイズの予算内に収まり、ライセンスゲートはバンドルに含まれるすべてを引き続きカバーします

キャンバスとその下のグラフは書き直していません。元の TypeScript のまま `web/src/lib` に移し、新しい外観を着せたので、配線、ドラッグ、元に戻す、バイト単位のフローファイルの往復は、すでにテスト済みのコードです。その周りはすべて Svelte です。

この間もずっと、Flow は独立した製品のままです。見た目は HotLoop と共有しますが、コードは共有せず、HotLoop に組み込まれることもありません。

### フェーズ 9: FlowLab、ダイアグラム

タブを実行する 2 つ目の方法で、メッセージ方式の隣に置かれ、その代わりにはなりません。ダイアグラムでは、配線されたすべての入力に値がそろったときにすべてのノードが 1 回実行され、互いにワイヤーでつながっていない分岐は同時に実行されます。テストベンチやデータロガーに必要なのは、まさにそれです。ある回から次の回へ値を運ぶループ、専用のワイヤーを通るエラー、オペレーターがスマートフォンで開けるパネル、実行を一時停止してすべてのワイヤー上の値を表示できるデバッガーがあります。既存のフローは変わらず、フローファイルも引き続きバイト単位で同じまま読み込み、保存できます。ダイアグラムは `ew_diagram` キーを持つタブで、ワイヤーがどの入力に届くかは、ワイヤーの出ていくノードの `ew_in` に保存されます。詳しくは [FlowLab](/ja/flow/flowlab/) をご覧ください。

- [x] スケジューラー: 配線されたすべての入力がそろったら実行、独立した分岐は並列、データが流れない場所の順序のための `after` ワイヤー
- [x] 値を引き継ぐ while ループと for ループ、そして、エラーのあとのノードを飛ばし、ループを止め、その発生元とコードを運ぶエラーワイヤー
- [x] シリアルポート: 終端文字またはバイト数までの読み取り、エラーワイヤーへのタイムアウト、ケーブルが抜かれたあとに開き直され、その回数が数えられるポート
- [x] 読み取り値のパーサー、安定値の検出、時刻列付きのテキストログ
- [x] Flow が提供するパネル: コントロール、インジケーター、チャートやグラフが、実行中にスマートフォンで開け、デスクトップの 2 人目の閲覧者も 1 秒以内に実行に追従します
- [x] 実行、停止、実行のハイライト、任意のワイヤー上のプローブ、ノード、ワイヤー、パスへのブレークポイント、ステップイン、ステップオーバー、ステップアウト
- [x] エディタは名前付きポートを描き、ドロップした先のポートにワイヤーをつなぎます。同じページで実行とデバッグを行います
- [x] ケース構造、レコードと共有型、波形
- [x] TDMS とバイナリのロギング、そしてデータベースと MQTT への出力
- [x] 計測器セッション: 生のソケットとシリアルを介し、シミュレーターと pty に対して検証済みです
- [ ] NI 自身のサーバーに対して検証したデータ収集クライアント。作って出荷済みですが、代役のサーバーでしかテストしていないため、NI のサーバーと機器で動かすまで未完了のままです
- [x] 解析: 統計とフィルター
- [x] サブダイアグラム、CI/CD のエラー一覧、エディタのズームとレイアウトの作業
- [x] 終わった実行のリプレイ: すべてのノードの開始と終了、すべてのワイヤーの値が記録され、ダイアグラムバーが直前の実行をキャンバス上で再生します。`GET /diagrams/{id}/trace`、`get_diagram_trace` ツール
- [x] データベースが取りこぼしたものを保持するデータベースシンク: `postgres out`、永続的で、データベースが戻ると順番どおりにバッチで書き込まれます。本物の TimescaleDB で検証済みです
- [x] 1 つのフローファイル、つまり 1 組のダイアグラムを、テナントが EmberNet で動かしているすべての Flow インストールへ配り、それぞれを確認し、失敗したものは元に戻します([テナントのステーションへのプッシュ](/ja/flow/stations/))。本物の Flow プロセス 3 つで検証済みです
- [ ] Pi で 1 日動かした検証。ボードと長時間の実行が必要です

2026-10-03 に決定:

- **産業用ノードは Flow の中で作ります。**HotLoop のドライバーが使うのと同じオープンソースのライブラリを使います。HotLoop のドライバーは HotLoop のものです。Flow は独自のライセンスを保ち、それは決定当時は別のものでしたが、今は HotLoop Source License Agreement 1.0 です。これは EmberNet Source License 1.0 に代わるもので、その前は 2.2.0 から引き継いだ Business Source License 1.1 に代わるものでした。
- **Flow は独立した製品のままで、HotLoop に組み込まれることはありません。**HotLoop の隣で動き、外から HotLoop の API と話します。フェーズ 5 の HotLoop ノードがしているのがそれで、両者の関係はそれがすべてです。
- **README は Flow が何をするかで始めます。**「工場をつなぐ。コードのようにレビューする。」既存フローのインポートは「手持ちのフローを持ち込む」の中にあり、先頭では Flow を何とも比べません。Flow は自分の力で立ちます。
- **永続コンテキストは最初から SQLite です。**純粋な Go で cgo はありません。先にファイルストア、あとで 2 つ目のストアではなく、今はコンテキスト、あとは永続キューのための 1 つのストアです。
- **ワークフロー自動化の製品は別のものです。**Flow のエンジンは共有しません。履歴、差分などはここではエンジンのパッケージのままです。API、CLI、エディタ、git のすべてが同じ答えを得なければならないからです。
