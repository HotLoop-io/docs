FlowLab は、テストベンチとデータロガーのための Flow の機能で、単位はダイアグラムです。Flow がタブを実行するもう一つの方法です。フローではメッセージがノードを通り、どの入力でもノードが動きます。ダイアグラムでは、ワイヤーがあるすべての入力に値が入ったとき、各ノードが1回の実行につき1回だけ動きます。間にワイヤーがない2つのノードは同時に動きます。こうしてテストベンチやデータロガーを作ります。機器を読み、値を解析し、安定しているかを判断し、表示し、記録します。

フローはこれによる影響を受けません。`ew_diagram` を持つタブはメッセージランタイムの対象外になり、ほかのタブはこれまでとまったく同じように動きます。

つまり、ロジックを一度描いて実行を押し、ワイヤー上を値が動くのを見られます。パネルのアドレスを知っていれば、誰でもスマートフォンで同じ実行を見られます。

## ファイル

ダイアグラムは `ew_diagram` オブジェクトを持つタブです。そのノードはフローファイルの通常のエントリーです。`wires` はこれまでどおりワイヤーの行き先のノードを指定し、送り側ノードの `ew_in` は、各ワイヤーが接続先のどの入力につながるかを同じ形で示します。

```json
{ "id": "a", "type": "dia-const", "z": "d", "value": "1", "x": 100, "y": 80,
  "ew_in": [["a"], []], "wires": [["sum"], []] }
```

ファイルは、これらのキーを含んだままバイト単位で読み込まれ、保存されます。タブの設定は次のとおりです。

| キー | 内容 |
|---|---|
| `autostart` | `true` にすると、Flow の起動時と各デプロイ後に、ブラウザーを開かずに実行を開始します。 |
| `role` | ループが実行するダイアグラムには `"body"` を指定します。ボディは単独では実行されません。 |

すべてのノードには、任意の入力 `after` と出力 `done` もあります。あるノードの `done` を別のノードの `after` につなぐと、後者は前者を待ち、間には何も入りません。順序が目に見えて diff で比べられるワイヤーになります。

## 実行

ダイアグラムはデプロイされた内容から実行されます。エディターでダイアグラムのタブを開き、実行を押してください。キャンバスの上のバーには次の項目があります。

- **実行をハイライト**: 追いかけられるように各ノードが実行前に少し待ち、値が通ったワイヤーが点灯します。10分たつと自動で切れます。
- **一時停止、再開、ステップイン、ステップオーバー、ステップアウト**: ステップ実行はノードごとに進みます。ステップオーバーはループの本体全体を実行します。ステップインはその中の最初のノードで止まります。
- **選択範囲でブレーク**: 選択したノードにブレークポイントを置きます。ワイヤーをダブルクリックするとプローブになり、直近の100個の値を保持します。値がワイヤーに載ったときに止めることもできます。プローブが実行を変えることはありません。
- **パネルを開く**: オペレーター用のページです。

実行後に任意のワイヤーにポインターを重ねると、そのワイヤーが最後に運んだ値を確認できます。問題ボタンには、ダイアグラムが実行できないすべての理由が、ノードと入力の名前つきで並びます。

| 呼び出し | 内容 |
|---|---|
| `GET /diagrams`, `GET /diagrams/{id}` | デプロイされている内容、パネル、各ワイヤーの最後の値です。 |
| `GET /diagrams/{id}/trace` | 直近の実行の内容を順に返します。開始または終了したすべてのノードと、ワイヤーを通ったすべての値を、実行開始からのミリ秒つきで含みます。デプロイ後に一度も実行されていないダイアグラムは 404 を返します。 |
| `POST /diagrams/{id}/run`, `/stop`, `/debug` | `diagram.run` が必要です。それぞれ、実行者つきで監査ログに記録されます。 |
| `POST /diagrams/{id}/sub` | `{flows, nodes, name}` を送ると、そのノードをサブダイアグラムにしたフローファイルが返ります。読み取りと計算だけを行い、保存もデプロイもしません。 |
| `PUT /diagrams/{id}/controls/{node}` | コントロールの値を設定します。種類、範囲、選択肢に照らして検査されます。 |
| `PUT /diagrams/{id}/breakpoints`, `/probes` | キーはノード ID、`wire:<wire key>`、または `diagram:<tab>` です。 |

実行のイベントは、エディターと同じソケットで `diagram/<id>/node`、`token`、`run`、`paused`、`values` として送られます。

| `dia-wait` | 待ってから、入力をそのまま渡します。 |
| `dia-bundle`, `dia-field`, `dia-array` | レコードと配列です。 |
| `dia-while`, `dia-for` | ループです。ボディはタブの名前で指定する独立したダイアグラムです。持ち越し値はワイヤーまたは Start values から始まり、最後の周回の値のまま出てきます。for ループは回数または配列を受け取ります。while ループは少なくとも1回実行されます。 |
| `dia-case` | ケース構造です。`selector` の値が実行するボディを1つ選び、そのボディだけが実行されます。ブール値は `true` か `false` を選び、数値は書き方に関係なくその値のケースを選び、文字列や enum はその名前のケースを選びます。ケースはケース名からダイアグラムへの JSON オブジェクトで、どのケースにも当たらない値はデフォルトを実行します。デフォルトがないとノードはエラーワイヤーにエラーを出し、デプロイ時にデフォルトがないと警告します(両方のケースを持つブール値は対象外です)。各ボディは同じ名前ですべての結果を出す必要があり、出さないボディはデプロイ時の問題になります。出力 `case` は実行されたケースを示します。 |
| `dia-body-in`, `dia-body-out` | ボディの両端です。`iter` は周回番号です。`stop` は while ループを終わらせます。持ち越し値の名前が、その値を次の周回へ送ります。 |
| `dia-serial-open`, `dia-serial-read`, `dia-serial-write` | シリアルポートです。読み取りは終端文字またはバイト数で終わります。 |

| `dia-parse-reading`, `dia-stable` | 1行から数値と単位を取り出し、直近の値が一致しているかを知らせます。 |
| `dia-log-text` | レコードをテキストファイルの1行として追記し、時刻の列を付けます。 |
| `dia-daq-read` | NI の gRPC Device Server を通じて、NI ハードウェアのデータ収集タスクからサンプルを読み取ります。下の「データ収集」を参照してください。 |
| `dia-mqtt-out` | フローファイルで設定した MQTT サーバーを通じて値を発行します。MQTT ノードと同じ接続です。durable にすると、ブローカーが受け取れなかったメッセージがディスクに書かれ、ブローカーが戻ったときに順番どおり送られ、再起動をまたいでも保たれます。 |
| `dia-postgres-out` | フローファイルで設定したサーバーを通じて、レコードを PostgreSQL または TimescaleDB のテーブルに1行として書き込みます。postgres ノードと同じ接続です。durable にすると、データベースが受け取れなかった行がディスクに保管され、戻ったときに順番どおり書き込まれます。下の「停止するデータベース」を参照してください。 |
| `dia-log-tdms` | フィールドごとに1チャネルで、レコードを TDMS ファイルに追記します。下を参照してください。 |
| `dia-control`, `dia-indicator`, `dia-chart` | パネルです。 |
| `dia-stats` | 配列の平均、RMS、最小、最大、標準偏差です。標準偏差は n から 1 を引いた値で割るため、2つの値が必要です。 |
| `dia-integral` | 台形則による配列の下の面積で、1つの数値、またはサンプルごとの累積面積として出ます。 |
| `dia-derivative` | 配列の各サンプルでの傾きです。 |
| `dia-filter` | 遮断周波数をヘルツで指定する、次数 1 から 10 の Butterworth ローパス、ハイパス、バンドパス、バンドストップフィルターです。 |

### フィルター

フィルターノードは Butterworth フィルターです。通過帯域は平坦でリップルがなく、遮断周波数で 3 dB 下がります。アナログフィルターから双一次変換で設計し、遮断周波数をプリワープするため、3 dB の点は入力した周波数に合い、2次セクションの連なりとして動くので高次でも精度が保たれます。次数 n のバンドパスまたはバンドストップは極が 2n 個あります。遮断周波数は 0 より大きく、サンプリング周波数の半分より小さい必要があり、作れない設計は実行前に問題として一覧に出ます。サンプリング周波数はプロパティか、それに優先する入力です。フィルターは1回の実行の中で呼び出しをまたいで状態を保つため、ループで細かく切った配列も一括でフィルターしたかのように出てきて、新しい実行は静止状態から始まります。

できないこともあります。線形位相フィルターではないため周波数ごとに遅れ方が違い、前後に通す零位相モードもありません。2つの信号のタイミングを合わせたい場合や波形の形を保ちたい場合は、このフィルターは向きません。積分と微分は、サンプル間の時間を、秒単位の `dt` 入力、ヘルツ単位の `rate` 入力、または Samples per second プロパティから取ります。

### TDMS へのログ

`dia-log-tdms` は、テストベンチが取った測定値を TDMS ファイルに書き込みます。データ収集や解析のツールが開ける形式です。レコードを `row` につないでください。レコードの各フィールドは1つのグループ内のチャネルになるので、`pressure`、`ok`、`operator` を持つレコードは3チャネルになります。数値は 64 ビットの float、真偽は bool、それ以外はテキストとして保存されます。数値のリストを持つフィールドはリスト全体を追加し、これでサンプルのブロックが入ります。設定は次のとおりです。

| 設定 | 意味 |
|---|---|
| `path` | ファイルです。すでにあるファイルには追記されるので、実行を重ねても1つのファイルになります。 |
| `group` | チャネルを入れるグループです。 |
| `columns` | ログするフィールドを順に指定します。空ならすべてのフィールドを名前で記録します。 |
| `properties` | ファイルのプロパティの JSON オブジェクトで、たとえば `{"title": "bench 4", "station": 4}` のように書き、実行の開始時に書き込まれます。 |
| `sync` | 既定でオンです。ノードが終わる前に各行がディスクに届きます。 |

各行は1つのセグメントで、一度に書き込まれます。途中で電源が落ちても、ファイルにはどこで切れたかが示され、リーダーはその前のすべての行を返し、次の実行がファイルの末尾を修復して続けます。フィールドの型は、実行の最初の行で決まります。数値の列にテキストが来るなど、合わない後続の行は不正な入力としてエラーワイヤーへ送られ、ファイルには手を付けません。欠けた数値は not-a-number として書かれます。

ファイルを開くには、任意の TDMS リーダーを使います。`unit_string` などのチャネルプロパティと、波形のプロパティ `wf_start_time`、`wf_increment`、`wf_samples` はライブラリが対応していますが、ノードはまだ設定しません。

リーダーが受け付けるのは、little endian と big endian のセグメント、インターリーブ形式と連続形式のデータ、変更がないときにセグメントから省かれたメタデータ、新しいオブジェクトリスト、8、16、32、64 ビットの整数、32、64 ビットの float、bool、テキスト、タイムスタンプです。ファイルを途中まで読むことなく、名前を示して拒否するのは、データ収集ドライバーが書いた生データ、スケーリングまたは圧縮されたデータ、拡張精度の float、固定小数点数と複素数です。ライターが書くのは、little endian、連続データ、そして同じ型です。big endian は書きません。

### エラーワイヤー

外部と通信するノードには、入力の `err` と出力の `err` があります。エラーはレコードで、フラグ、数値コード、元のテキスト、発生したノードからなります。エラーが入力されたノードは何も処理せずエラーを渡すので、連鎖の先頭での1つの障害はそれ以降をすべて飛ばし、最後に1回だけ現れます。エラーをループの `err` ボディ出力につなぐと、ループはそこで止まり、エラーはループのエラー出力に出ます。パネルのエラーインジケーターは障害で赤くなり、次の値がエラーなしで届くと消えます。

### 停止する接続先

durable の `dia-mqtt-out` は、ブローカーが応答している間はそのまま送ります。応答がないときは、ノードが終わる前にメッセージが Flow の durable ストアにコミットされ、接続が戻ると、ポンプが古いものから順にキューを配信します。ほかが待っている間に入ったものはその後ろに付くため、追い越しは起きません。キューからの配信は少なくとも1回です。クライアントが接続断に気づかず送信がタイムアウトしたメッセージも、クライアントが再接続したときに配信されることがあり、タイムアウトした送信ごとに1回ずつ、2回届く場合があります。キューは durable ワイヤーと同じストアと同じディスククォータにあり、実行もブラウザーもなくても再起動後に空になります。durable でない場合、ブローカーが受け取れなかったメッセージはエラーワイヤーのエラーになります。

### 停止するデータベース

`dia-postgres-out` は、受け取ったレコードを `hotloop-flow-postgres` サーバーを通じて、指定したテーブルに1行として書き込みます。レコードのフィールドは同名の列に入るので、`n` と `sensor` を持つレコードは `n` 列と `sensor` 列を埋めます。一部の列だけ書く場合や順序を決める場合は、列をカンマ区切りで並べます。リストを空にすると、ノードはレコードのフィールドを使います。ノードはループの周回ごとに1回実行されるので、ループは周回ごとに1行を書き込みます。通常の名前でないテーブルや列は、実行の途中の文になるのではなく、デプロイ時の問題になります。整数は integer、float、numeric のどの列にも入り、レコードや配列はそのまま入るので、json や jsonb の列が受け取れます。

**時刻の列** の名前を指定すると、各行にノードへ届いた時刻が入ります。これは書き込んだ時刻ではなく、値が測定された時刻なので、ディスクで5分待った行も、作られた分の時刻を保ちます。

**データベースが取りこぼした分を保持** がオフの場合、データベースが受け付けなかった行はノードのエラーワイヤーにエラーとして出て、失われます。オンの場合、データベースが応答している間は行はそのまま入ります。データベースが応答しないときは、ノードが終わる前に行が Flow の durable ストアにコミットされ、ノードの `sent` 出力は `false` になります。行はディスクで待ち、再起動に耐え、データベースが戻ると、後から入ったものに追い越されることなく順番どおり書き込まれます。滞留分は1文あたり最大 256 行でまとめて書かれるため、データベースが不在の間にたまった分も、1行ごとに1往復する速度ではなく数秒で追いつきます。テストでは、毎秒 100 行で5分に相当する 30,000 行をディスクに待たせ、データベースが戻ってから数秒以内にすべてが順番どおり書き込まれます。

ディスクからの配信は少なくとも1回です。接続が切れたときに insert が送られた行は、応答が失われたままコミットされている可能性があり、再送されるので、最大でバッチ1つ分、2回書かれることがあります。それが問題になる場合は、テーブルに一意キーを付け、競合時で **行をスキップ** を選んでください。そうすると2つ目はデータベースが捨てます。

列に対して大きすぎる値や、競合時がエラーを発生させるのままで既にあるキーなど、内容が原因でデータベースが拒否する行は、毎回拒否されます。その行は行を含む監査イベント `diagram.row_rejected` とともに手放され、後ろの行が書き込まれます。そうしないと、不良な行1つでログが止まります。停止しているデータベース、まだないテーブル、間違ったパスワードはこれに当たらず、その行は待ちます。

### 計器

`dia-instr-open` はアドレスを受け取ります。生ソケットの LAN 計器は `10.0.0.5:5025`、シリアルの計器は `serial:///dev/ttyUSB0?baud=19200&data=8&parity=E&stop=1`、9600 8N1 なら `/dev/ttyUSB0` または `COM3` だけで指定します。実行が終わるとセッションを閉じます。接続が切れた場合は、次のクエリで開き直し、切断はセッションに数えられます。

`dia-instr-query` はコマンドと終端文字を書いてから応答を読みます。テキスト(`reply` から出る1行)、none(単なる書き込み)、block から選びます。block は `#41024...` のバイナリブロックを読み、サンプルを `samples` から配列として出します。int8、uint8、int16、uint16、int32、float32、float64、big または little endian に対応します。長さ不定の `#0` ブロックは最初の行末で終わります。時間内に来ない応答は、アドレスを示すタイムアウトとしてエラーワイヤーに出ます。

`dia-scpi-parse` はテキストの応答を、数値のリスト、1つの数値、識別情報(`*IDN?` をメーカー、モデル、シリアル番号、ファームウェアへ)、またはステータスバイト(`*STB?` や `*ESR?` を立っているビットの名前へ)として読みます。

### シリアル

ケーブルを抜いた、アダプターを外したなどでポートが消えると、読み取りのエラーワイヤーの障害になります。次の読み取りは1秒に1回開き直しを試み、切断と復帰を数えます。ポートにはフロー制御として、なし、ハードウェア(RTS と CTS)、ソフトウェア(XON と XOFF)があり、Linux ではターミナル自体に設定されます。疑似端末では設定が届いたことまでは確認できており、実際のアダプターでラインがどう動くかは確認できていません。

### データ収集

`dia-daq-read` は、CompactDAQ シャーシなどの NI ハードウェアのタスクを、NI 自身のオープンな gRPC Device Server を通じて読み取ります。Flow はネットワーク経由でそのサーバーと通信するため、ハードウェアは Flow と別のマシンにあっても構わず、Flow に NI のドライバーやベンダーのライブラリは要りません。静的なバイナリ1つのままです。

**ハードウェアをつないだマシン** に、NI の DAQmx ドライバーと NI の gRPC Device Server(https://github.com/ni/grpc-device、MIT ライセンス)をインストールします。サーバーは、設定ファイルで変えない限りそのマシン上(`localhost`、ポート 31763)だけで待ち受けます。別のマシンの Flow から接続するには、サーバーの `server_config.json` で `address` を `[::]` または使いたいインターフェースに設定し、設定の隣の `certs` フォルダーにファイルを置いて `server_cert`、`server_key`、相互 TLS では `root_cert` を設定して TLS を有効にします。お使いのバージョンの詳細は NI の README にあります。サーバーの既定の保護されていないポートを工場のネットワークに開けたままにしないでください。到達できる人は誰でもハードウェアを操作できます。

**ノードでは** 次を設定します。

* `address` はサーバーの `host:port` です。
* `tls` は `off`(同じマシン上のサーバーのみ)、`on`(Flow がサーバー証明書を `caFile` で、空ならシステムの認証局で検証)、`mutual`(Flow が `certFile` と `keyFile` も提示し、サーバーが自分の `root_cert` で検証)のいずれかです。`serverName` は、`address` のホストと異なるときにサーバー証明書で探す名前です。
* `device` と `channels` でハードウェアを指定します。たとえば `cDAQ1Mod1` と `ai0:3`、または `ai0, ai2` のようなリストです。`kind` は `voltage`、`current`、`thermocouple` で、想定する範囲に `min` と `max`、配線に `terminal` を使います。熱電対は `tcType` と `unit` を取り、モジュール自身の冷接点補償を使います。
* `mode`、`rate`、`samples` です。有限モードは、呼び出しのたびにチャネルあたり `samples` 個を `rate` で1回収集し、毎回やり直します。連続モードは最初の呼び出しでタスクを開始し、呼び出しごとに次の `samples` 個を読むので、ループのボディ内のノードはストリームをブロック単位で読めます。`trigger` は、`/cDAQ1/PFI0` のような端子のデジタルエッジでタスクを開始します。

`y` は1チャネルのサンプルの配列、または指定した順にチャネルごと1つずつ並べた配列の配列です。`dt` はサンプル間の秒数で、周波数の逆数なので、ブロックの長さ(秒)はサンプル数に `dt` を掛けた値です。毎秒 1,000 サンプルで 1,000 サンプルなら 1.000 s です。サンプルの時刻はいつもどおりデバイス自身のクロックが決め、Flow はデータを運ぶだけです。サーバーやドライバーからの拒否は、ドライバー自身のコードとテキストとともに `err` に出て、`callTimeoutSec` 以内に応答しないサーバーはタイムアウトです。タスクは実行の間だけ存在し、実行が終わるとサーバー側で消去されるので、ハードウェアは再び空きます。

できていること: アナログ電圧入力、アナログ電流入力、熱電対温度入力で、有限または連続、サンプルクロックと任意のデジタル開始トリガーに対応します。できていないこと: デジタル入出力とカウンターは別の読み取り呼び出しを使うため未実装で、書き込み、ほかのトリガー種別、モジュール自身が行う以上のスケーリングも未実装です。

このノードは、同じ呼び出しを話して正弦波で応答する代替サーバーに対して、また実機で、実行しています(2026-11-17)。

## パネル

ランタイム上の `/panel/<diagram id>` は、ダイアグラムのコントロール、インジケーター、チャートのページを開きます。サインインはエディターと同じ方法です。親指で使えるように作られており、指より小さいものはありません。チャートは変更しない限り直近の 1,024 点を保持し、捨てた数を表示します。グラフは配列のたびにデータを置き換えます。XY チャートは x を y に対してプロットし、履歴も保持します。強度チャートは、すべて同じ長さの数値の行からなる配列であるグリッド(最大 512 × 512)を受け取り、その中の最小から最大までの色で各値を描き、グリッドごとに絵を置き換えます。平坦な配列や不揃いなグリッドは、ノードのエラーワイヤーのエラーになります。

複数の人が1つの実行を見られます。ブラウザーからコントロールを設定するには `diagram.run` が必要で、サーバーで検査され、監査ログに書かれます。

## コントロール

`dia-control` には、**種類**(何を保持するか)と **見た目**(パネルがどう描くか)があります。サーバーは見た目に関係なくすべての値を種類に照らして検査するので、`PUT /diagrams/{id}/controls/{node}` を呼ぶスクリプトも、指と同じ規則に従います。オペレーターが設定した値は、ダイアグラムをデプロイした時点で、最初の実行より前にパネルに現れ、コントロールノードは実行のたびにその値をダイアグラムに渡します。

| 種類 | 見た目 | ダイアグラムが読む値 |
|---|---|---|
| `number` | `entry`(入力)、`spin`(入力、`step` ずつ動き範囲で止まるマイナスとプラスのボタン付き)、`slider`、`knob` | 数値で、`min` と `max` が設定されていればその範囲に制限されます |
| `bool` | `switch`、`button`(押すと true になり、ダイアグラムが読むと `latch` が戻す)、`led`(押せる LED) | 真または偽 |
| `string` | テキストボックス | テキスト |
| `enum` | `options` のドロップダウン | 選択肢のうちの1つ |
| `array` | オペレーターが項目を追加、削除するリスト | `elem` に応じた数値、スイッチ、テキストのリストで、`min` と `max` が各数値を、`maxlen` が長さを制限します |
| `record` | フィールドごとに1つの入力 | ちょうど `fields`(`rate:number, on:bool, note:string`)を持つオブジェクトで、すべてのフィールドが常に存在します |

slider と knob には最小値と最大値が必要です。両方ない knob はデプロイ時の警告になり、揃うまで入力欄として描かれます(slider はすでにそうでした)。knob は 270 度回るダイヤルです。マウスや指で回すようにドラッグするか、押してそこに置くか、矢印キー(`step` 1回分)、Page Up と Page Down(10ステップ)、Home と End を使います。放したときに書き込まれます。配列の初期値は JSON(`[1, 2, 3]`)または単純なカンマ区切りのリスト(`1, 2, 3`)で、レコードの初期値は JSON オブジェクト(`{"rate": 3}`)です。省略したフィールドは空で始まります。フィールドのないレコード、未知のフィールド名、合わない初期値は、デプロイ時の問題になります。

パネルのすべてのボタン、入力、スイッチ、ダイヤルは、縦横とも 44 ピクセル以上あり、幅 390 ピクセルのスマートフォンでもページは横にスクロールしません。

コントロールは変更されたときに書き込まれ、ダイアグラムはコントロールノードが動いたときにそれを読みます。変更されたときに自分で実行を開始したりノードを起動したりするコントロールはありません。それがイベント構造であり、まだ実装されていません。

## これは何ではないか

ダイアグラムは汎用 OS 上の Go プロセスで動きます。ガベージコレクションとスケジューラーが、ノードを数ミリ秒遅らせることがあるため、ノードは締め切りを約束できません。締め切りを守る必要がある処理は、PLC やそのために作られたランタイムの役目です。データ収集デバイスのサンプルのタイミングは、これらの影響を受けません。デバイス自身のクロックが担い、Flow はデータを運ぶだけです。

## ダイアグラムのテスト

フローのテストファイルには、メッセージのテストと並べて、ダイアグラムのテストを書けます。ダイアグラムのコントロールを設定し、本物のダイアグラムエンジンで1回実行して、インジケーターが保持する値を確認します。

```yaml
tests:
  - name: weighs and flags a heavy load
    diagram:
      name: Scale logger          # the diagram's name or id
      controls: {Limit: 10}       # by label or id, checked like an operator's entry
      expect:
        Weight: 12.5              # a number matches to within a millionth
        Heavy: true
        Reading: {min: 12, max: 13}
```

ダイアグラムにないコントロール、拒否される値、インジケーターではないもの、2つの要素が共有する名前、実行できないダイアグラムは、理由つきのエラーになります。テストの外に出るノード(シリアルポート、計器、データ収集デバイス、MQTT 出力、HotLoop への書き込み、ログファイル)を含むダイアグラムは拒否されます。ダイアグラムのテストにはそれらの代役がないからです。ケーブルを抜く、ごみのフレームが続くといった状況を試すスクリプト化されたシリアルデバイスは、実装されていません。

## CI/CD のエラー一覧

`hotloop-flow test` とデプロイゲートは、フローファイル内のすべてのダイアグラムにエディターの検査を実行します。実行できないダイアグラムは `--- DIAGRAM: <diagram>: <node> input <port>: <reason>` として一覧に出て、すべてのテストが通ってもファイルを失敗にします。JUnit レポートは、それぞれを `diagram` 型のエラーとして含みます。デフォルトのないケース構造のような警告は一覧に出ますが、失敗にはしません。

## 波形

波形は、等間隔のサンプルのブロックで、いつ始まり、どれだけ間隔があるかを持ち、ワイヤー上ではレコードとして流れます。`{"type": "waveform", "t0": "2026-11-14T12:00:00Z", "dt": 0.001, "y": [...], "attrs": {"unit_string": "V"}}` の形です。`dia-wave` は配列から波形を作り(間隔は `dt`、なければ `rate`、なければ設定から。開始は `t0`、なければ実行された瞬間から)、`dia-wave-parts` は波形を分解し、継続時間も出します。波形は最大 `maxSamples` 個のサンプル(既定で 1,048,576)を保持し、残りは切り捨てられて `dropped` に数えられます。解析ノードは、配列を受け取る場所で波形も受け取り、その間隔を使います。`dia-log-tdms` は波形の列を、`wf_start_time`、`wf_increment`、`wf_samples` を持つチャネルとして書き、属性をチャネルプロパティにします。

## サブダイアグラム

`dia-sub` はノードとして使うダイアグラムです。その入力と出力がコネクターで、各入力はボディ内の同名の `dia-body-in`、各出力は `dia-body-out` です。入力は、名前が `?`(任意)または `~`(推奨: なくても動き、つながっていないとデプロイが警告)で終わらない限り必須です。ノードを選択してサブダイアグラムにすると(`POST /diagrams/{id}/sub`)、ノードが新しいボディのタブに移り、その場所に `dia-sub` が入り、コネクターは選択範囲の境界を横切るワイヤーから決まります。選択範囲に入ってくる元の出力ごとに入力が1つ、外側のノードへ出ていく選択された出力ごとに出力が1つです。外側のワイヤーはつなぎ直されるので、実行結果は以前と同じです。

## 共有レコード型

レコード型は、ダイアグラムのタブの設定の `types` の下で1回だけ名前を付けます。`shape` にその名前を設定したすべての `dia-bundle` や `dia-field` は、その1つの定義に照らして検査されます。

```json
{"types": {"Reading": {"fields": {"pressure": "number", "ok": "boolean", "state": {"enum": ["idle", "run"]}}}}}
```

フィールドは `number`、`integer`、`boolean`、`string`、`timestamp`、`array`、`waveform`、`record:Name`(別の共有型)、または enum です。定義でフィールド名を変えると、古い名前を使っているすべての bundle が次のデプロイで問題になり、つながっていない入力と同じエラー一覧に、ノードとフィールドが並びます。bundle は実行時に各値をフィールドの種類に合わせ、合わない値はエラーワイヤーが運びます。`Set.Schema` は同じ型を JSON Schema として返し、型付きワイヤーが検査するのはこれです。

## ローテーションと保持

`dia-log-text` と `dia-log-tdms` は、使用中のファイルが `rotateMB` メガバイトまたは `rotateHours` 時間に達したときに新しいファイルを始め、完了した最新の `keep` 個のファイルだけを残せます。完了したファイルは、拡張子の前に閉じた時刻を付けたログ名になり(`bench.csv` は `bench-20261114T120000Z.csv` になります)、ログは新しいヘッダー付きで、TDMS ではファイルのプロパティを書き直して `bench.csv` で続きます。保持は、そのパターンに一致するファイルだけを削除し、使用中のログや、ただ隣にあるだけのファイルは決して削除しません。経過時間は、実行がそのファイルに最初に書いたときから数えます。テキストのログはスプレッドシートで開け、TDMS ログは大きなデータ向けのバイナリ形式です。

## ケース構造の編集とダイアグラムの選択

ケース構造のケースは、ケース名とダイアグラムのピッカーからなる行で、デフォルトケース用に2つ目のピッカーがあります。ループやサブダイアグラムが実行するダイアグラムを指定するプロパティもピッカーです。ピッカーはフローファイルの FlowLab ダイアグラムを一覧にし、タブの ID を保存します。古いフローファイルに手で書かれた名前は、そのタブとして表示され、ID として保存され、ランタイムも同じように読みます。保存される値は以前と同じ JSON(`cases` はケース名からダイアグラムへのオブジェクト)なので、ダイアログで編集したフローファイルと手で編集したものは同じファイルです。

## サブダイアグラムをその場で開く

サブダイアグラムのノードの右上には小さなボックスがあります。これを押すか、ノードを選んでダイアグラムバーの **その場で開く** を押すと、ノードがあった場所に開いた状態で描かれます。サブダイアグラムの名前が付いたフレーム、両端に名前が付いたコネクター(左に入力、右に出力、ほかのノードと同じく `after` と `done` のポートとエラーワイヤー)、そしてその中にボディのノードとワイヤーが入ります。2つ目のウィンドウは開かず、今のタブも変わりません。ノードにつながっていたワイヤーはフレームのコネクターにつながり、各コネクター名から同名の body in または body out ノードへ、薄い破線が走ります。フレームのタイトルバーのボックス(または **その場で閉じる**)で、再び閉じます。

フレームの中に描かれるのは、コピーではなく、ボディ自身のノードです。1つ選び、ドラッグし、ダブルクリックしてプロパティを開き、値を変えたり削除したりすると、ボディを編集したことになり、元に戻せる1ステップで、デプロイすると保存されます。フレームをタイトルバーで動かすとサブダイアグラムのノードが動き、ボディも一緒に動きます。ワイヤーは1つのダイアグラムの2つのノードをつなぐので、外側のノードから内側のノードへのワイヤーは、言葉で説明して拒否されます。フレームのコネクターにつないでください。ズーム、パン、全体表示、範囲選択はほかの場所と同じように動きます。

どのサブダイアグラムが開いているかは、ダイアグラムの見方にすぎません。フローファイルには入らず、元に戻すステップでもなく、再読み込みですべて閉じるので、開いてもデプロイが送る内容は変わりません。開いたサブダイアグラムの中のサブダイアグラムにも自分のボックスがあり、3階層まで開けます。すでにどこかで開いているボディは2回目は開かれず、ボディがすでに開いているダイアグラムに戻るサブダイアグラムは閉じた状態で描かれるので、自分自身を含むダイアグラムがエディターをループさせることはありません。何にも指定されていないボディや、2つのダイアグラムが共有する名前で指定されたボディには、ランタイムも見つけられないため、ボックスがありません。ループとケース構造もボディを持ちますが、まだその場では開けません。

## エディターでサブダイアグラムを作る

ダイアグラムでノードを選択した状態で、バーの **選択範囲をサブダイアグラムに** を押すと名前を尋ね、エディターが持つフローファイルで `POST /diagrams/{id}/sub` を呼び、その応答を元に戻せる1回の編集として読み込みます。ノードは専用のタブに移り、その場所にサブダイアグラムのノードが入り、入力と出力は選択範囲を横切るワイヤーから決まります。デプロイするまで何も保存されません。

## 実行を再生する

実行をハイライトは、実行中に速度を落とします。キャンバスの下部の **直前の実行を再生** は、すでに終わった実行を、記録した内容から再生するので、あとから追いかけられます。ライブの実行と同じようにワイヤーを点灯させてノードに印を付け、イベントを1つずつ、選んだ速度(遅い、標準、速い、とても速い)で再生し、終わるとキャンバスに実行の結果が残ります。**再生を停止** で早く終えられます。ランタイムでは何も変えず、何も開始しません。実行中はボタンがオフになり、ほかのタブへ移ると再生は終わります。

すべての実行は、ノードの開始と終了、およびワイヤーを通ったすべての値を、最大 20,000 件のイベントまで記録します。それより長い実行は最初の 20,000 件を保持し、再生時にそのことを知らせ、再生はその先頭を表示します。途中から始まる再生には起点がないからです。値は、ワイヤーが表示する短いプレビューとして保存されるので、数千サンプルの配列は、長さと最初の数個の値になります。記録は直近の実行のもので、新しい実行が置き換え、再起動をまたいでは保存されません。`GET /diagrams/{id}/trace` は、スクリプト向けの同じ記録です。

## レイアウトを整える

タブバーの **レイアウトを整える** は、表示中のノードを、データが左から右へ読め、どのワイヤーもノードを貫かないように配置します。ノードの列は、そのノードに至る最長のワイヤーの連なりで決まります。列を飛ばすワイヤーはその間を通るレーンを得て、列内のノードは交差がほどけるよう並べ替えられ、そのあと各長いワイヤーが、実際に描かれる曲線に沿って、横切る列のノードと照合され、邪魔なノードは脇へ動かされます。ブロックは左上の角を保ち、全体が元に戻せる1回の編集になります。配線にループがあるときは、それを閉じるワイヤーが順位付けから外れるので、レイアウトがループする代わりに逆向きに走ります。

## ワイヤーの名前

ダイアグラムのワイヤーは、中央に、出てきた出力の名前(`sum`、`result`、`iterations`)で表示され、どちらかの端が型を宣言していればその横に型も表示され、ポインターを重ねると、そのワイヤーが最後に運んだ値が今も表示されます。

## ズーム

キャンバスはポインターを中心に 5 パーセントから 400 パーセントまでズームし、倍率をキャンバスの `data-zoom` として読みます。

## 名前でパネルのオブジェクトを設定する

`dia-panel-set` は、ダイアグラムの実行中に、オブジェクトのラベル(または ID)でコントロールやインジケーターのプロパティを1つ変更します。`visible` と `enabled` は true か false、`color` は red、amber、green、blue、gray、default、`label` はテキスト、`min` と `max` は数値コントロール用の数値を受け取ります。無効にしたコントロールはオペレーターの設定を拒否し、隠したオブジェクトは描かれず、オペレーターが開いているパネルも追従します。どのオブジェクトにも合わない名前、または複数に合う名前は、ノードに直接入力した場合はデプロイ時の問題、ワイヤーで渡した場合はワイヤーのエラーになり、実行は設計されたままのパネルから始まります。

## シンボル

すべての FlowLab のノード型は、テキストラベルの隣、本体の中央に、独自のシンボルで描かれます(算術はプラス、統計はシグマ、波形はサイン波、シリアルポートはプラグ)。`web/src/lib/symbols.ts` に描かれた単純な線で、アイコンフォントでも他人の作品でもなく、ダイアグラムのノード型が描かれていないアイコンを指定するとテストが失敗します。

## 設備への書き込み: 書き込みゲート

ダイアグラムが設備に指令を出す方法は、`dia-hotloop-write` の1つだけです。値を HotLoop のタグ(`device/tag`、ノードに設定するかワイヤーで入力)へ、HotLoop の書き込みゲートを通して送ります。ゲートは自分の順序で、書き込みが有効か、タグがアームされているか、値が範囲内かを判断します。Flow は機械に直接書き込むことはありません。HotLoop は、拒否されたかどうかにかかわらずすべての試行を `flow:<diagram>/<node id>` という理由で記録するので、監査記録にダイアグラムとノードが残ります。拒否は、ゲート自身の理由(コード 5006)とともにノードのエラーワイヤーのエラーになり、HotLoop に到達できない場合も同様です。どちらの場合も書き込みは行われず、HotLoop を選んでいないノードはデプロイを拒否します。生のシリアルノードと計器ノードは、HotLoop にタグがないベンチ計器(マルチメーター、電源、負荷)と通信するので、専用のスイッチがあります(下記)。

## 計器の書き込みスイッチ

計器を読んでも何も変わらず、常に開いています。書き込みは変えることがあります。電源の出力、耐電圧試験器の高電圧、負荷の電流です。そのため、すべての計器は書き込み **オフ** で始まり、`instrument.write` 権限を持つ人がその計器の書き込みをオンにするまで、ダイアグラムからの書き込みは拒否されます。計器ごとに1つずつです。

- **書き込みとみなされるもの。** `dia-serial-write` は常に書き込みです。`dia-instr-query` は、コマンドがクエリ(中のすべての SCPI 文が `*IDN?` や `MEAS:VOLT?;MEAS:CURR?` のように `?` で終わる)なら読み取りで、そうでなければ(`OUTP ON`、`VOLT 5`、`*RST`、または `VOLT 5;MEAS:VOLT?`)書き込みです。ワイヤーで入ってくるコマンドは、書き込む可能性があるものとして数えます。
- **どの計器か。** 計器はそのアドレスです。`tcp://host:port` または `serial:///dev/ttyUSB0` で、シリアル設定は除くので、2通りの方法で開いた計器でもスイッチは1つです。
- **拒否** は、その計器への書き込みがオフであることを示すノードのエラーワイヤーのエラー(コード 5007)で、計器はコマンドを一切受け取りません。
- **オンにする。** `PUT /instruments/writes` に `{"instrument": "tcp://10.0.0.5:5025", "allowed": true, "note": "bench 2"}` を送ります。`instrument.write` が必要で(管理者が持っています)、データディレクトリーの `instrument-writes.json` に保存されるので、再起動しても何も変わりません。`GET /instruments` は、スイッチがある、またはそこへ書き込むデプロイ済みのダイアグラムがあるすべての計器を、設定した人と、関わるダイアグラムとノードとともに一覧にします。
- **監査。** スイッチの変更はすべて `instrument.switch`、ダイアグラムによる書き込みはすべて `instrument.write` で、拒否された場合は `instrument.refused` となり、ダイアグラム、ノード、計器、コマンドが付きます。
- **デプロイが知らせます。** 計器に書き込むノードは、ダイアグラムの注記(バーの **注記** と、`hotloop-flow test` が出力する一覧)になり、計器を示し、誰かがオンにするまで書き込みがオフであることを伝えます。読み取りだけのフローファイルは変わりません。

## LabVIEW の VI を取り込む

エディターのインポートダイアログ(または MCP の `import_vi`、または `POST /flows/import-vi`)で `.vi` を取り込むと、FlowLab は読めるものを読み、何かを追加する前に、読めなかったものを一覧にします。docs/labview-import.md を読んでください。何が取り込まれ、何が取り込まれないかが正確に書かれています。要点は、VI の名前、説明、バージョン、フロントパネルの名前、呼び出す VI が、独立したフローのメモとして取り込まれることです。ブロックダイアグラムのワイヤーとプリミティブは取り込まれないので、ダイアグラムはそれらの名前を横に置いて自分で描きます。
