---
title: "管理者向け API"
description: "エディターとコマンドラインが使用する HTTP と WebSocket の呼び出し、それぞれが必要とするものと返すもの。"
---

| メソッドとパス | 権限 | 備考 |
|---|---|---|
| `GET /health` | なし | 生存確認。kubelet はトークンを持たないため、このルートで認証を求めると Pod が永久に再起動を繰り返します。 |
| `GET /ready` | なし | 準備状態を別に報告するので、起動に失敗したランタイムは kubelet が Pod を停止しなくても Service から外れます。 |
| `POST /auth/token` | なし | ログイン。ロックアウト中は `Retry-After` 付きの 429。 |
| `POST /auth/revoke` | なし | ログアウト。 |
| `GET /auth/mode` | サインイン不要 | このランタイムが EmberCORE ダッシュボードから開かれているかどうか: `{"dashboard": bool, "hideLogin": bool}`。エディターは誰かがサインインする前にこれを問い合わせます。 |
| `GET /auth/mfa`, `POST /auth/mfa/setup`, `/confirm`, `/disable` | サインイン済みのユーザー | 自分自身の 2 要素サインイン。Setup はキー、`otpauth://` リンク、QR コードを返します。Confirm と disable は `{"code": ...}` を受け取ります。 |
| `POST /auth/mfa/reset` | `auth.admin` | 他のユーザーの 2 要素サインインを無効にします: `{"username": ...}`。 |
| `GET /metrics` | なし | Prometheus。件数とノード ID のみで、メッセージの内容や設定は含まれません。 |
| `GET /settings` | `settings.read` | |
| `GET /nodes` | `nodes.read` | エディターのパレットとダイアログを動かすレジストリ。 |
| `GET /plugins` | `nodes.read` | 読み込まれたプラグイン、それぞれが要求したものと許可されたもの、理由付きで拒否されたもの。 |
| `GET /flows` | `flows.read` | |
| `GET /flows/export` | `flows.read` | git 用に、ディスク上にあるとおりのフローファイル。 |
| `POST /flows` | `flows.write` | デプロイ。デプロイログ用の任意のメモを受け取ります。 |
| `GET /deployments` | `flows.read` | ペイロードを除いた、新しい順のデプロイログ。`?limit=N` で件数を制限します。 |
| `GET /audit` | `audit.read` | 誰がどこから何をしたかを新しい順に。`?event=`、`?user=`、`?since=`、`?limit=`。 |
| `GET /deployments/{seq}` | `flows.read` | フローを解析した 1 件の記録。認証情報は含まれません。 |
| `GET /deployments/{seq}/flows` | `flows.read` | そのデプロイのフローファイルをバイト単位でそのまま。 |
| `GET /deployments/{from}/diff/{to}` | `flows.read` | 2 つのデプロイ間のノード単位の差分。構造化形式とテキストの両方。 |
| `POST /flows/diff` | `flows.read` | 稼働中のものと本文のドキュメントとの差分。何もデプロイしません。 |
| `POST /flows/types` | `flows.read` | デプロイが行う型付きワイヤーの検査を、本文のドキュメントに対して行います: `{"wires": [...]}`、問題がなければ空。エディターが結果を描画します。何もデプロイしません。 |
| `POST /deployments/{seq}/rollback` | `flows.write` | その記録のフローと認証情報を新しいデプロイとして再度デプロイします。rev ヘッダーと任意の `{"note": ...}` を受け取ります。 |
| `GET /tests` | `flows.read` | フローファイルの隣に保管されたフローテストスイート、そのファイル名、デプロイがそれに依存するかどうか。 |
| `PUT /tests` | `flows.write` | スイートを置き換えます。本文は YAML で、解析できないものは理由付きの 400 になります。 |
| `POST /tests/run` | `flows.read` | スイート、または本文の `"tests"` を、本文の `"flows"` または稼働中のものに対して実行します。レポートを返します。何もデプロイしません。 |
| `POST /tests/from-debug` | `flows.read` | Debug ノードが表示したメッセージ `{"node", "msgId"}` からテストの下書きを作ります。何も保存しません。 |
| `POST /tests/cases` | `flows.write` | 本文のテスト、つまり独立したテストファイルを、スイートの末尾に追加します。 |
| `GET /traces` | `flows.read` | 保持されているトレースを新しい順に、バッファの内容と上限とともに返します。`?limit=N`。`trace.enabled: false` のときは 404。 |
| `GET /traces/find` | `flows.read` | `?msgId=` と `?node=`、つまりサイドバーに表示される ID と Debug ノードから、メッセージが含まれるトレースを探します。すべてのホップと、尋ねたホップまでの経路を返します。 |
| `GET /traces/{id}` | `flows.read` | 1 つのトレース。各ホップの所要時間と、ノードに渡されたとおりのメッセージ。 |
| `POST /traces/{id}/test` | `flows.read` | トレースからフローテストの下書きを作ります。何も保存しません。 |
| `POST /traces/{id}/replay` | `flows.read` | トレースを開始したメッセージを、本文の `"flows"` または稼働中のものに子プロセスで投入し、以前の到達先と比べてどこに到達するかを返します。何もデプロイしません。 |
| `GET /runtime/stats` | `status.read` | |
| `POST /inject/{id}` | `inject.write` | Inject ノードを実行します。 |
| `GET /comms` | `status.read` | エディターのステータスとデバッグ用の WebSocket。トークンを `hotloop-flow` と並べて提示するサブプロトコル `hotloop-flow.bearer.<token>` として送ってください。エディターはこの方法を使っています。URL の `?access_token=<token>` は、すでに使っているスクリプトのために引き続き動作しますが、URL はプロキシやアクセスログに残るため、そうした接続ごとに警告をログに記録します。 |
| `POST /mcp` (および旧版のプロトコル向けの `GET` と `DELETE`) | `mcp.call` | フローをツールとして提供する [MCP エンドポイント](/ja/flow/mcp/)。ほかと同じセッショントークンまたは API トークンを使います。呼び出し側に提示され、呼び出せるツールは、その権限が及ぶものです。認証を無効にしている場合は 403。 |

`/metrics` と `/health` に認証がないのは、見落としではなく判断です。Prometheus のスクレイパーは bearer トークンを持たないため、これを要求すれば、監視スタックに認証情報を渡すか、監視をあきらめるかのどちらかになります。

2 要素サインインが有効なユーザーは、ユーザー名とパスワードとともに `"code"` を `POST /auth/token` に送ります。これがなければ、応答は `"mfa": "required"` を伴う 401 です。

権限は、すべてを表す `"*"`、`flows.read` のような完全一致の文字列、または `flows.*` のようなプレフィックス付与です。フローを MCP ツールとして呼び出すエージェントには `mcp.call` が必要です。フローの状態を表示したいだけのダッシュボード用の読み取り専用アカウントは `["flows.read", "status.read"]` で、それ以上は必要ありません。

デプロイは任意の `HotLoop-Flow-Deployment-Rev` ヘッダーを受け取ります。最後に読んだリビジョンを送ると、別のエディターと競合したデプロイは、誰かの作業を黙って上書きする代わりに 409 で拒否されます。これは午後を無駄にした本人からしか耳に入らない類の失敗です。

デプロイが再起動するのは、変更したものだけです。ノードは、依存しているもの、つまり設定、タブ、グループ、環境、認証情報、そして名前を挙げているすべての設定ノードのどれも動いていなければ、動作し続けます。キャンバス上でドラッグしたり配線し直したりしても変更とは見なされません。新しいワイヤーは稼働中のノードに接続されるからです。そのため、関数ノード 1 つのタイプミスを直しても、ボックス上のすべての MQTT セッションが切れることはなく、10 分間分の測定値を保持している Delay ノードはそのまま保持し続けます。これが存在する理由のすべてです。保存のたびにプラントが揺れると、オペレーターはシフト中に保存しなくなり、修正は土曜日まで待たされます。

`HotLoop-Flow-Deployment-Type` ヘッダーで再起動の範囲を選びます。Node-RED の `Node-RED-Deployment-Type` も使えるため、すでにあるデプロイスクリプトは求めた再起動を得られます。

| 種別 | 再起動されるもの |
|---|---|
| `nodes` (既定) | 変更したノードと、変更した設定ノードを名前で参照するすべてのもの。 |
| `flows` | 変更を含むフローに属するすべてのノード。 |
| `full` | すべて。プロセスを再起動するのと同じです。 |

応答には、実行した内容が `type`、`started`、`restarted`、`stopped`、`unchanged` として示されます。処理中のものが途中で失われることはありません。置き換え中のノードにすでにキューされている作業は旧インスタンスで完了し、入れ替え中に届いたものは新しいインスタンスを待ち、削除したノード宛てのメッセージは、消えるのではなくカウントされてドロップとして表示されます。
