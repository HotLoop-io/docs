このページは 1.0.0 の実行記録です。タイムスタンプと `.package` を含む 1.1.0 の実行は、[1.1.0 のリリースノート](/ja/releases/transmitter-1-1-0/)にあります。その後、ライブラリはベアメタルでも実行しました (2026-11-17)。

## ビルド

* ライブラリ: CODESYS 3.5.22.30 (SP22 Patch 3) の ScriptEngine でエラー 0、警告 0 でコンパイルできます。
* インストール済みのライブラリに対してビルドしたサンプルアプリケーション。対象は CODESYS Control for Linux SL デバイス (4102, 0000 0005, 4.20.0.0): エラー 0、警告 0、ダウンロード可能。

## ランタイム

CODESYS Control for Linux SL 4.22.0.0 はアプリケーションをブートプロジェクトとして読み込み、`Application started`、`CODESYS Control ready` と報告します。ランタイムライセンスがないため、デモモードで動作します。

## 線路に流れたものと、それを読んだもの

サンプルアプリケーションにはパブリッシャーが 2 つあります。writer group 1 と dataset writer 1 は Variant エンコーディング (1142 バイト)、writer group 2 と dataset writer 2 は RawData エンコーディング (1144 バイト) です。それぞれ 17 フィールドで、ライブラリが対応する型を 1 つずつ、250 要素の REAL 配列、4 要素の INT 配列、カウンター 2 つです。

独立した 4 つのリーダーが読みました。

| リーダー | 内容 | Variant | RawData |
|---|---|---|---|
| 仕様から書いたデコーダー | OPC 10000-14 と 10000-6 だけから書いたもので、ランタイムの OPC UA サーバーから同じ変数も読んで比較する | すべてのフィールドが PLC の値と一致、キャプチャ中の NetworkMessage と DataSetMessage のシーケンス番号に欠落なし | 同じ |
| 独立した OPC UA PubSub スタック | 17 フィールドの DataSet メタデータを持つサブスクライバー | 確認した 15 個の値がすべて一致 (文字列、両方の配列、TIME を含む) | 数値スカラー 11 個が一致。そのスタックは、どんな長さの RawData 文字列も、RawData 配列も読めない |
| HotLoop core の UADP サブスクライバー | HotLoop core 4.19.4 とそれ以降のすべてのリリースのドライバー。稼働中のランタイムに対し、DataSet 型に RawData レイアウトを指定して実行 | 21 個の値が一致 (文字列、TIME、250 要素の REAL 配列の要素 0、1、124、249、INT 配列の 4 要素すべてを含む)。3 秒間隔の 2 回の読み取りの間に両方のカウンターが進んだ | 同じ 21 個の値と同じ 2 つのカウンター。key frame を 62 個受信、拒否なし |
| 2 つ目のデコーダー | 自社の受信側コードにある UADP デコーダー。17 フィールドのレイアウトでキャプチャした 222 個のデータグラムに対して実行 | 111 個のメッセージをすべてデコード、確認したすべての値が正しい | 111 個のメッセージをすべてデコード、確認したすべての値が正しい。配列は Int32 の長さとパディングつき |

## RawData の配列と文字列

このライブラリは、RawData 配列の前に Int32 の要素数を書き、文字列は Int32 の長さ、そのバイト列、そして MaxStringLength までのゼロパディングの順で書きます。OPC Foundation の参照スタックと同じ方法で、仕様の文面に沿っています。OPC 10000-14 7.2.4.5.11 ("handled like a Structure DataType"、パディングは "to the maximum size indicated by ArrayDimensions or MaxStringLength") と OPC 10000-6 5.2.5 ("One dimensional Arrays are encoded as a sequence of elements preceded by the number of elements encoded as an Int32 value") です。

HotLoop core のサブスクライバーと 2 つ目のデコーダーは、どちらも RawData 配列をこの方法、つまり長さとパディングつきで読み、どちらもこのライブラリの RawData をデコードできます。

参照スタックとの違いが 1 つあります。参照スタックは文字列が MaxStringLength より長いと例外を投げますが、PLC のタスクには例外を投げる先がないため、このライブラリは文字の境界で切り詰めます。

## 知っておくこと

* 実行は x86-64 上の CODESYS Control for Linux SL 4.22.0.0 で行いました。ライブラリは Structured Text で、ビッグエンディアンのターゲット向けのバイト順処理は書かれていますが、お使いのコントローラで確認してください。
* マルチキャスト: ブロックはマルチキャストグループ向けに TTL、ループバック、送信インターフェースを設定します。グループはご自身のネットワークで確認してください。
* ブロックは送信の失敗を数え、ネットワークが消えたりアドレスがなかったりすると待機し、プログラムはスキャンを続けます。
* デモモードでは、CODESYS の説明どおり、ランタイムは 2 時間の枠の終わりで停止します。
